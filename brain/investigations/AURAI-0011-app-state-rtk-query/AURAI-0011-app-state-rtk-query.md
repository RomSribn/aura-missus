# AURAI-0011 — состояние приложения: RTK Query или модульные хранилища (заглушка)

Дата: 2026-11-07 · Статус: **заглушка — не начато** · Выдано из `AURAT-0174` (aura-app slave-0) по решению владельца.

## Вопрос владельца

«а есть причина, почему мы не используем какой-то redux toolkit? c ним мы бы имели возможность кеширования с коробки с
помощью rtk query и так же инвалидацию кеша при смене языка, например, что удобно. Рассмотри варианты перехода сейчас
на него, критично или нет?» Ответ в `AURAT-0174`: для 0174 не критично; переход — отдельной задачей.

## Что известно на 2026-11-07

- В aura-app нет Redux / RTK Query: 11 модульных хранилищ на `useSyncExternalStore` (~1600 строк: каталог, профиль,
  кошелёк, кампании, гороскоп, карта дня, расклад, отзывы, промокод, витрина магазина, account-deleted); 42 из 216
  тестовых файлов работают с ними напрямую.
- Причина выбора — `AURAT-0014-002`: чтение вне React (FCM headless-обработчик пуша, стабильный колбэк сокета в
  `ChatProvider`). RTK этого не исключает (`store.dispatch(api.endpoints.x.initiate())`).
- Build rules (`.claude/aura-build-rules.md`) предписывают RTK + RTK Query — расхождение с кодом с самого начала.
  Веб — на RTK Query (`AURAD-0019`, `AURAI-0007`).
- Повторяющиеся в хранилищах ручные механизмы, которые RTK Query даёт из коробки: общий запрос, `generation` (смена
  пользователя), `latest` (опоздавший ответ, смена языка — `AURAT-0169`, `AURAT-0174`), статусы загрузки.

## Что исследовать

1. Что даёт RTK Query здесь: ключ кэша по языку / пользователю, `resetApiState` на выходе, теги, refetch; что из
   особой логики хранилищ не ложится (`isKnown`, оптимистичный `markDrawn`, headless-чтение, сокет).
2. Цена: Provider и обёртка тестов, test-support, бандл, Hermes, смешанный режим на время перехода.
3. Варианты: полный переход / пилот на каталоге советников / остаться на хранилищах и поправить build rules.
4. Итог — решение владельца (`AURAD`) и, если переход, задачи по слайсам.
