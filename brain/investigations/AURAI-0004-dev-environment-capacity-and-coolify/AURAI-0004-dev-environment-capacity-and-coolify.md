# AURAI-0004 — Хватит ли прод-хоста на dev-окружение, и чем это окружение оказывается в Coolify

Дата: 2026-09-08
Статус: **Research** — замеры сделаны, рекомендация есть, решение по веткам за владельцем
Источники: `AURAS-0004` (что running), `AURAD-0005` (один inbox на окружение),
`AURAT-0029` (переезд на Hetzner/Coolify)

## Вопрос

Хватит ли ресурсов на то, чтобы поднять ещё и dev-окружение.

Ответ короткий: **ресурсы — не ограничение**, и с большим запасом. Ограничение
одно, и оно не про железо: на этой же машине лежит append-only денежный ledger
прода.

## Как мерилось

Read-only, по SSH на `37.27.199.90` (ключ, пароли отключены), 2026-09-08 17:39 UTC:

```
free -h
df -h /
uptime
docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}\t{{.MemPerc}}\t{{.CPUPerc}}"
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}"
docker exec coolify-db psql -U coolify -d coolify \
  -c "SELECT id,name FROM projects;" \
  -c "SELECT id,name,project_id FROM environments;" \
  -c "SELECT id,name,fqdn,git_repository,git_branch,build_pack,source_id,source_type,environment_id,destination_id FROM applications;" \
  -c "SELECT id,name,ip FROM servers;"
```

Последняя команда — чтение служебной базы самой панели. Ни одной записи не
делалось.

## Что намерено — железо

| | |
|---|---|
| RAM | 7.6 Gi всего, **2.5 Gi занято, 5.1 Gi доступно** |
| Swap | **252 Mi из 4 Gi** — практически не тронут |
| Диск | 17 G из 75 G → **56 G свободно, 24 %** |
| Load average | **0.06 / 0.13 / 0.14** на 4 vCPU |
| Uptime | 20 дней |

По контейнерам, сгруппировано по смыслу:

| Группа | Контейнеры | Итого |
|---|---|---|
| **Chatwoot** | sidekiq 583 MB + rails 379 MB (`chatwoot/chatwoot:v4.15.1`) | **961 MB** |
| **Наш продукт** | BFF 99 MB + Postgres 78 MB (`pgvector/pgvector:pg16`) + Redis 11 MB (`redis:7.2`) | **188 MB** |
| **Сама панель** | coolify 168 + traefik 93 + realtime 63 + coolify-db 36 + sentinel 11 + coolify-redis 6 | **376 MB** |

Всего контейнеры ≈ 1.5 GB; остальное до 2.5 Gi — ядро и dockerd.

### Две поправки к тому, что было записано раньше

- **Chatwoot не ест 2 GB.** Цифра «rails один хочет ~2 GiB» из
  `AURAT-0029-012-paused-aws-pivot.md` — про **загрузку** на коробке в 1–2 GiB,
  где OOM-киллер забирал Postgres на старте. В установившемся режиме rails +
  sidekiq вместе весят 961 MB. При планировании второго окружения надо брать
  измеренное, а не загрузочное.
- **Вся наша половина весит 188 MB** — вдвое меньше, чем сама панель Coolify.
  Тяжёлое здесь — Chatwoot, и именно его дублировать не нужно (см. ниже).

### Оговорка, без которой цифры врут

`load average 0.06` означает, что трафика сейчас практически нет. Всё
измеренное — **пол, а не рабочая нагрузка**. Под живыми чаттерами первым
вырастет sidekiq. Замер надо повторить, когда пойдёт реальный поток, и до тех
пор не выдавать «5.1 Gi свободно» за постоянную величину.

## Что намерено — объектная модель Coolify

| Объект | Что есть |
|---|---|
| Project | **`aura`** (id 1) — единственный |
| Environment | **`production`** (id 1) — единственное |
| Applications | `aura-bff` (`dockerfile` → `https://bff.aura-app.cc`), `aura-chatwoot` (`dockercompose`) |
| Source | один GitHub App, `source_id = 1` у **обоих** приложений |
| Server | только **`localhost`** (id 0) |
| Services | ни одного (`aura-chatwoot` заведён как application с compose-паком) |

**Терминология, на которой легко ошибиться.** «Source» в Coolify — это
подключение к Git-провайдеру (GitHub App / deploy key), а не окружение.
Второй источник для dev не нужен: он уже один и обслуживает оба приложения.
Иерархия панели — **Project → Environment → Resources**, и dev это второе
**Environment** внутри того же проекта `aura`.

### Находка: прод деплоится с `develop`

`git_branch = develop` у **обоих** приложений. Отдельной продовой ветки нет — в
проде едет интеграционная. Это не мешало, пока окружение было одно, но dev не
может трекать ту же ветку, и вопрос встаёт первым:

- либо прод переезжает на `main`, а `develop` достаётся dev — тогда merge gate
  из правил манора начинает защищать ветку, которая едет в dev, а не сразу в
  прод, что ближе к его замыслу;
- либо dev трекает отдельную ветку, а `develop` остаётся продовым.

Первое честнее: сейчас `wts-finish` в `develop` — это деплой в продакшен.

## Варианты

| | **A — dev на этом же хосте** | **B — отдельная машина** |
|---|---|---|
| Что заводится | второе Environment `dev` в проекте `aura` | второй **Server** в Coolify + Environment `dev` с destination на него |
| Цена | **$0** | `CX22` (2 vCPU / 4 GB / 40 GB) ≈ **€4/мес** |
| Память | +~200 MB к 2.5 из 7.6 | своя |
| Панель | не дублируется | не дублируется — Coolify остаётся на проде, на dev только docker + sentinel |
| Chatwoot | общий, отдельный inbox | общий, отдельный inbox (свой влезет, но не нужен) |
| Риск | dev-эксперимент делит машину с денежным ledger'ом прода | изолировано |

Три аргумента против A, которые я приводил до замера, пережили его **не все**:

- **диск** — не выжил: 56 G свободно;
- **CPU** — сильно слабее, чем звучал: при load 0.06 сборочный всплеск на
  4 vCPU эта машина не заметит;
- **blast radius** — выжил целиком, и остался единственным настоящим.

## Рекомендация

**B — отдельная `CX22` за ~€4/мес**, но с честной формулировкой: это **покупка
изоляции денежного контура**, а не вынужденная мера по ресурсам. Место под A на
коробке есть.

Если вторую машину не хочется патчить и бэкапить — **A полностью рабочий
вариант**. И переход A → B потом не переделывает структуру: в Coolify это смена
destination у окружения `dev` на второй Server, а не пересборка проекта.

## Как это делается

Состав окружения `dev` (Chatwoot **не** дублируется — `AURAD-0005` уже описал dev
как отдельный `Channel::Api` inbox в том же инстансе):

- приложение `aura-bff` — тот же source, тот же репо `RomSribn/aura-bff`,
  `dockerfile`, **другая ветка**, `bff-dev.aura-app.cc`;
- Postgres — база `aura_bff_dev` со своей ролью, тем же приёмом, что уже
  применён к `aura_bff` / `chatwoot`, **включая**
  `REVOKE CONNECT ON DATABASE aura_bff_dev FROM PUBLIC` (без этой строки роли
  декоративны — `AURAS-0004`);
- **Redis отдельным контейнером, а не db 2 в общем.** Он стоит 11 MB, а общий
  живёт с `maxmemory 512mb` + `noeviction`: dev-очереди, выевшие бюджет, положат
  запись прода. Плюс риск `FLUSHALL` из чужой половины уже назван в `AURAS-0004`
  — третью руку на этот рубильник класть незачем;
- переменные — через **shared environment variables** (команда/проект/окружение):
  общее объявляется один раз, различающееся (`DATABASE_URL`, токен dev-inbox,
  домен, `BILLING_ENABLED`) переопределяется в `dev`.

Про webhook: он и в dev должен быть **публичным хостом**
(`https://bff-dev.aura-app.cc/webhooks/chatwoot`), а не именем в docker-сети —
причина та же, что в `AURAS-0004`: Coolify не даёт dockerfile-приложению
стабильного сетевого имени.

## Открытые вопросы

1. **Ветки** — решение выше, оно блокирует всё остальное.
2. **A или B** — за владельцем; техническая разница только в blast radius.
3. **Повторить замер под нагрузкой** — текущие цифры сняты на практически
   простаивающей машине.
4. Состав прод-замера стоит перенести в `AURAS-0004` («What is running» описывает
   состав, но не потребление).
