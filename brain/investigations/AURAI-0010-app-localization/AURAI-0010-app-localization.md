# AURAI-0010 — Локализация приложения: en + 23 языка ЕС

Дата: 2026-11-04. Где: `aura-app-manor` slave-1, aura-app `develop` @ `28633b4`, aura-web `develop` (манор),
aura-bff `develop` @ `c8d78cf`, `@aura/contracts` v0.27.0.
Метод: 8 параллельных расследований и критик полноты. Почти всё проверено на практике: JS запускали на той же
сборке Hermes, что в приложении (macOS-срез пода iOS, тот же код Intl), шрифты разбирали fontTools/fc-query,
исходники Hermes и AOSP читали на нужных тегах. На устройствах не запускали ничего — это проверки манора (§11).
Сырые данные с доказательствами (файл:строка, команды) — `AURAI-0010-evidence.json`.

## Decision

Приложение локализуется на те же 24 языка, что aura-web (en — исходный и запасной, плюс bg cs da de el es et fi
fr ga hr hu it lt lv mt nl pl pt ro sk sl sv), на i18next 26 + react-i18next 17 с типами и раскладкой веба, но
с рантаймом, переделанным под Hermes и React Native; выпуск — одним релизом под флагом, когда переведено всё.
Решения владельца — § «Решения владельца».

## Context

- Владелец (2026-11-04): «i18n, так же как aura-web, для тех же локалей… чтобы покрыть все страны Европы»;
  в первых итерациях дизайна был лист выбора языка.
- В приложении i18n нет: около 554 уникальных строк зашиты в код; строку `Languages` убрали из профиля в
  `AURAT-0041` («пока приложение на одном языке», `screens/profile/config/constants.ts:29`).
- На вебе i18n есть с `AURAT-0101-010` (владелец: «en, и все страны EC»), правило «каждая задача меняет строки
  во всех языках» — веб-правило 9. Переводы писали агенты, ревью носителей не было.

## Research / Analysis

### 1. Intl в Hermes (RN 0.85.3 → Hermes V1 250829098.0.10, обе платформы)

| API | Есть? | Следствие |
|---|---|---|
| `Collator`, `localeCompare` | да | Сортировка по правилам языка работает. **Но** `sensitivity: 'base'` на Apple сломан: в шведском `a == ä`, но `ä > z` — список сортируется неверно. Только чувствительность по умолчанию |
| `DateTimeFormat` | да | Названия месяцев и дней верные, в двух падежах (`listopad` / `4 listopada`). Нет `formatRange`, у месяца в `formatToParts` неверный тип части, на Apple часы с ведущим нулём и U+202F перед AM/PM |
| `NumberFormat` | да | Валюта USD на Apple побайтно совпала с V8 для всех 24 языков. Но `style:'unit'` сломан («5 minutes» → «300 seconds», «600 Sekunden»), игнорируются `signDisplay` / compact / `trailingZeroDisplay` / `roundingMode`, округление half-even (4.85 → 4.8). `formatToParts` на iOS нет |
| `PluralRules` | **нет** | i18next 26 молча выбирает английские one/other: «5 minuty» вместо «5 minut» (проверено end-to-end) |
| `DisplayNames`, `RelativeTimeFormat`, `ListFormat`, `Locale`, `Segmenter` | **нет** | Названия языков и стран — только заранее сгенерированные таблицы; «2 дня назад» и списки — ключами с плюралами |
| `normalize`, `\p{M}`, `\p{Script=…}` | да | Поиск без диакритики возможен (NFD + удалить `\p{M}` + карта для ł ø đ ħ ß æ œ, которые NFD не раскладывает). Свёртку делать один раз при загрузке языка |
| `toLocaleUpperCase('el')` | да | Убирает ударения в греческих заглавных правильно; `textTransform:'uppercase'` на iOS — нет (≈ 29 мест) |

Полифилы PluralRules (сверка с ICU 78 на 55 560 значениях × 24 языка):

| Вариант | Ошибок | Цена |
|---|---|---|
| `intl-pluralrules` 2.0.1 | 1 614 (lt, lv, mt, ro от 1000; es/fr/it/pt на 1e6) | — отвергнут |
| `@formatjs/intl-pluralrules` 6.3.16 | 1 | ~75× медленнее на Hermes; без `Intl.Locale` падает на языке без данных; ~96 КБ gz |
| **свой шим на `make-plural` 8.1.0** | **0** | ~3 КБ gz, без зависимости от Intl. 8.2.0 слишком свежий (10 дней) и расходится в порядковых bg/es |

Jest работает на Node с полным ICU и скрывает все эти пробелы, если в `jest.setup` не удалить то, чего нет в Hermes.

### 2. Язык устройства

- **iOS.** Язык по умолчанию в Intl — `NSLocale.currentLocale`, а его язык Foundation подбирает из списка
  предпочтений пользователя среди локализаций бандла. Сейчас Aura объявляет только `en` → у всех `en-<регион>`
  (`en-DE` у немца). После `CFBundleLocalizations` с 24 кодами — лучший вариант из списка: `[uk, pl]` → `pl-UA`,
  `[ga, en]` → `ga-IE` (проверено в `.app`-бандлах на macOS, тот же код CFBundle). Регион — из настройки
  «Регион», его нельзя считать страной языка. Отдельная настройка языка приложения в iOS это учитывает.
- **Android.** `Locale.getDefault()` и Intl — результат согласования с языками ресурсов APK. Сейчас APK несёт
  ~86 языковых папок из библиотек (ru, uk, ar…), но нет ga и mt: пользователь `[ru, es]` получит `ru`. Нужны
  `localeFilters` на 24 языка и `values-<lang>/strings.xml` (хотя бы `app_name`) — иначе ga/mt не выбираются.
  Это из исходников AOSP, на устройстве не проверено.
- `react-native-localize` не нужен. `I18nManager.localeIdentifier` не годится (только Android, только первый язык).

### 3. Шрифты

- 21 латинский язык покрыт полностью обоими семействами (все буквы CLDR 48 и все символы переводов веба).
  Исключение: в Hanken нет U+202F (французский разделитель групп) — подставится системный.
- **Греческого и кириллицы нет**: Bricolage — только π; Hanken — Δ Ω μ π и греческая пунктуация. el и bg уйдут
  в системный шрифт (на macOS это Helvetica; SemiBold и ExtraBold схлопываются в Bold), а наши π/μ будут
  вклеиваться посреди греческого слова. Самоназвания «Ελληνικά» и «Български» в листе языка — тоже.
- Апстрим: в Bricolage греческого и кириллицы нет нигде. В апстриме Hanken (marcologous/hanken-grotesk,
  `eff37d18`, 2026-09-02) появился полный греческий: те же имена, метрики и ширины латиницы; в Google Fonts ещё
  не попал (#11159), кириллицы нет.
- Подменять шрифт по языку через токены нельзя: 207 вызовов `fontFace()`, 91 файл считает их в модульных
  `StyleSheet.create` → смена языка без перезапуска не сработает, текст чата не покрыт, +290–790 КБ.
- Рабочий путь — дорисовать глифы при сборке (fontTools) под теми же PostScript-именами. Прототип с донором
  Commissioner: el/bg без единого системного фрагмента, +143 КБ, ноль изменений в JS (прототип не боевой:
  потерял GDEF и хинтинг). Доноры с греческим + кириллицей + болгарскими формами: Commissioner (ближе всего по
  x-height), Manrope, Geologica, IBM Plex Sans. Golos и Onest — только кириллица.
- Веб ничего особого не делает: Google Fonts + `system-ui`, el/bg уже системным шрифтом.

### 4. Строки приложения

- ≈ 554 уникальные строки (≈ 2 490 английских слов), 118 с подстановкой, 55 — подписи доступности; плюс 245
  названий стран, 69 названий дней и месяцев в трёх разных таблицах, 24 строки зодиака.
- По слоям: screens ≈ 375, features ≈ 179, shared ≈ 45, entities ≈ 29, app — 0. Где лежат: ui ≈ 52%,
  config ≈ 30% (21 файл, 7 из них `config/copy.ts` — переносятся почти механически), model ≈ 10%, lib ≈ 6%,
  shared/api ≈ 2%.
- Структурные проблемы (чинить в задачах переноса):
  - подписи — ключи состояния: `SEGMENTS`, `HOROSCOPE_DAYS`, `SESSION_SEGMENTS`; `SegmentedControl` рисует
    value как подпись;
  - `CheckoutVerb` (`'book' | 'start now' | 'extend'`) вставляется прямо в текст;
  - `AuthError.message` хранит готовую английскую строку;
  - модульные строки и `useMemo([])` замораживают язык;
  - фразы из кусков (юридическая строка, «Sent to … · change»), имена в падежных позициях («with {name}» ≈ 9
    строк, притяжательные);
  - ≈ 35 строк с числом и плюралом;
  - деньги — `'$' + toFixed` (`formatUsdMinor`: 42 вызова в 20 файлах), проценты и размеры файлов вручную;
  - английский источник смешивает US и UK порядок дат.
- Для блоков «число над сокращением месяца» CLDR не годится в bg и lt (месяц цифрой) и в cs/fi — нужны ручные
  сокращения.
- Вёрстка под длинные переводы (до 1,74× у ирландского): `DateStrip` 58pt, корешок билета 74pt, плашка
  «Biggest saving», `DailyCardBanner` фиксированной высоты 148pt, однострочные билеты и плитки оплаты, ряды с
  кнопкой, `ScreenTitle` 34px без переносов. Таб-бар без подписей (но им нужны `accessibilityLabel`).
- Пуши рисует headless JS (`index.js`), каналы Notifee «Messages» / «Announcements» — i18n нужен вне React.
- Тесты: 64 из 159 файлов сравнивают английский текст. Не сломаются, если i18n в Jest стартует синхронно с `en`
  и английские формулировки не меняются.
- Redux/RTK Query в приложении нет (хранилища — модульные + `useSyncExternalStore`), хотя build rules их
  упоминают; язык в Redux не класть.

### 5. aura-web как образец

- Брать: `LANGUAGES`, тип `Translation<typeof en>` (с плюралами), папку `config/locales/` на слайс,
  `ResourceNamespaceMap` для типизированного `t()`. Тип ловит пропущенный, лишний и вложенный ключ, неверную
  плюральную форму, отсутствующий язык; не ловит пропущенные `_few`/`_many` и потерянный `{{name}}` — это тест.
- Менять:
  - загрузчики: `import()` в RN бессмыслен (Metro всё равно кладёт все языки в бандл), а Jest 29 на нём падает →
    синхронные `de: () => (require('./de') as typeof import('./de')).default` (остаются ленивыми благодаря
    inline requires; отсутствующий файл → TS2307);
  - ловушка: импорт файла языка по умолчанию или как namespace выполняет все языки при старте (+2 МБ кучи);
  - init синхронный (`initAsync: false`, ресурсы en + стартовый язык);
  - один реестр пространств имён на приложение и Jest (у веба два списка, конфликтовали при слияниях).
- `<Trans>`: дефолты react-i18next создают `<strong>`/`<br>`/`<p>`, которых в RN нет — экран падает, а
  react-test-renderer это пропускает. Нужно `transSupportBasicHtmlNodes: false`, `defaultTransParent: Text` и тест
  на одинаковый набор тегов во всех языках.
- Переиспользование: ≈ 40–46% строк приложения дословно совпадают с английским веба → 23 перевода можно взять
  с указанием источника. Но 78 расхождений терминов внутри языков, болгарский смешивает «ты/вы», FR/PT по-разному
  переводят «chat» — сначала глоссарий.
- Обращение на вебе: «ты» — de, es, nl, sv, da, fi, et, hu, ro (и де-факто it, pl, mt, ga); «вы» — bg, cs, el, fr,
  hr, lt, lv, pt, sk, sl. Род пользователя на вебе не согласуется (pl без -łeś/-łaś, cs во мн. ч.) — в приложении
  поля пола тоже нет.
- Общий пакет переводов для веба и приложения — не сейчас: слайсы разные (совпадают 8 из 37), потоки разные,
  релизы раздельно, `AURAD-0019` делит только контракты.
- На вебе язык выбирается в Profile → Language автокомплитом (просьба владельца, `AURAT-0136-009`), хранится в
  браузере, на сервер не уходит.

### 6. Сервер и контракты

- В BFF и контрактах понятия языка нет: `Accept-Language` не читается, у User / профиля нет поля языка.
- Пуши уже без текста: FCM шлёт только `{type:'message.new', advisorId}`, текст рисует устройство → локализация
  пушей — работа клиента. Исключение — кампании из консоли Firebase (текст пишет оператор).
- Ошибки: приложение берёт только `code`, не `message` → серверной работы не нужно.
- Останется английским, если переводить только клиент: каталог консультантов (role, tagline, bio, specialties,
  приветствие), колода таро (78 карт; имя ещё и внутри фраз «I drew {name} today…»), два маркера сессии,
  сезонные тексты, подпись скидки кампании, серверный `'Anonymous'`, юридические страницы, SMS, сам чат.
  На вебе ровно так, по решению владельца.
- `Accept-Language` как сигнал не годится: iOS шлёт его сам из языка устройства даже из старых английских
  сборок (проверено только на macOS), браузеры — свой. Нужен явный `lang` в query: BFF его спокойно пропускает
  (нет глобального whitelist; схемы query не `.strict()`; `.strict()` только у `ProfilePatchRequest` и пресетов
  кампаний). В приложении две точки: `shared/api/bff/http-client.ts:58` и `upload.ts:73`.
- Маркеры сессии нельзя переводить на сервере: и приложение (регулярка тона `/\bstarted\b/i`), и веб (точное
  совпадение) парсят английский текст → нужен машинный `Message.marker`.
- На картинках карт таро напечатаны английские названия («THE SUN», «TWO OF CUPS») — конфликт с уже одобренным
  серверным переводом колоды (`AURAT-0137-006` §3A, `AURAF-0020-053`).
- Обновлений по воздуху нет — любая правка перевода идёт через ревью сторов. Страховка: список
  `disabledLanguages` в публичном `/v1/app-config` (приложение уже его читает и кэширует).

### 7. Нативная часть

- iOS:
  - `CFBundleLocalizations` (24) — обязательно для определения языка;
  - `InfoPlist.xcstrings` → `<lang>.lproj/InfoPlist.strings` (проверено `xcstringstool`) для
    `NSCameraUsageDescription` / `NSPhotoLibraryUsageDescription`;
  - knownRegions;
  - задать язык приложения программно нельзя (`AppleLanguages` — не API, Apple DTS); пункт языка в Настройках
    появляется, когда у пользователя ≥ 2 языков; смена языка в Настройках перезапускает приложение.
- Android:
  - `locales_config.xml` руками (AGP `generateLocaleConfig` выдаст ~87 библиотечных языков без ga/mt);
  - `android:localeConfig`;
  - `configChanges` + `locale|layoutDirection` (иначе смена языка пересоздаёт Activity и RN теряет навигацию);
  - `localeFilters`.
- Firebase: `auth().setLanguageCode(lang)` прямо перед `verifyPhoneNumber`. Веб делает так же.
  `useDeviceLanguage` в RNFB 24 падает, `setLanguageCode(null)` = язык устройства, а не выбор в приложении.
- Notifee: каналы пересоздать с тем же id и переведённым именем при смене языка.
- RTL: все 24 языка — слева направо; RN не зеркалит раскладку сам. На Android с арабским системным языком
  `Configuration` и Intl по умолчанию будут RTL / арабскими — всегда передавать язык в Intl явно.
- Сторы: App Store не поддерживает bg, et, ga, lv, lt, mt (описание на 17 наших языках), Google Play — ga, mt (21).

### 9. Инструменты, тесты, бандл

- Типы веба компилируются под `@react-native/typescript-config` (TS 5.9.3): +1,6 с к typecheck на масштабе
  веба. Селекторный API вдвое дешевле — переход, если станет медленно.
- `eslint-plugin-i18next` 6.1.5 работает с ESLint 8.57: режим `jsx-only` — 304 находки в ui/, режим `all` — 527
  (≈ 5% шума). Сейчас lint на нуле → правило выключено глобально и включается `error` по слайсам.
- Бандл: все 24 языка — +0,6…1,6 МБ байткода Hermes (+0,3…0,45 МБ в сжатом виде), +0,45 МБ кучи на регистрацию
  ~900 ленивых модулей. Допустимо; загрузка по сети не нужна, ленивость обязательна.
- Псевдоязык (+40%, акценты, скобки) для вёрстки — свой: `pseudo-localization` 3.1.3 портит `{{…}}`.
- В Jest полный ICU 78.2 / CLDR 48 → тесты полноты, сверка шима, drift-тесты таблиц идут в Jest.

### 10. Что разрешил критик

- iOS: противоречие «Intl идёт за регионом» снято — так ведёт себя голый бинарь без бандла; внутри `.app` язык
  подбирается по бандлу (три прогона).
- Новое:
  - дефекты `Collator 'base'` на Apple;
  - `<Trans>` в RN;
  - английские названия на артах таро;
  - нет OTA;
  - сторы не покрывают 6 и 2 языка.
- Не применимо: первый день недели (месячного календаря нет, `DateStrip` — 14 дней от «Today»; если появится —
  брать из региона, не языка), десятичный ввод, имена (валидация только длины), часовые пояса в UI, виджеты,
  текст в PNG.
- Регистр: де-факто «ты/вы» на вебе соответствует его таблице; для переводчиков — не согласовывать с родом
  пользователя.

### 11. Не проверено (манор, устройство, владелец)

- Android вживую:
  - выбор языка по ресурсам;
  - Intl на ICU4J (API 24 = CLDR 28);
  - округление;
  - системная настройка языка приложения на 13+;
  - арабская система (RTL виджетов);
  - сплиты языков в AAB.
- iOS вживую:
  - Intl внутри приложения;
  - когда появляется пункт языка в Настройках;
  - перезапуск при смене;
  - системный шрифт для el/bg.

## Решения владельца (2026-11-04)

Владелец: «делай по рекомендациям». Принято:

1. **Где хранится выбор.** На устройстве, как на вебе: файл `{language, osLanguage}` в Documents. Действует
   правило «последнее изменение побеждает»: если системный язык (или язык приложения в системных настройках)
   сменился после выбора в приложении, выбор сбрасывается. В аккаунт и на сервер — не сейчас (серверная часть).
   *Уточнение (владелец, 2026-11-07, `AURAT-0181-006`):* на Android 13+ выбор хранит системная настройка языка
   приложения (`LocaleManager`) — Profile → Language пишет туда же, «последнее изменение побеждает» обеспечивает
   система; файл — только Android 12 и ниже и iOS (на 13+ переносится в систему один раз). Выбор по-прежнему только
   на телефоне и теряется при переустановке (`allowBackup="false"`).
2. **Форматы.** Время 24h во всех языках, как сейчас. Суммы (USD) и даты — по CLDR языка интерфейса, как на
   вебе (`1,99 $` de, `1,99 $US` fr). Источник — заранее сгенерированные таблицы с drift-тестом против Node, не
   Intl во время работы. Язык форматирования — язык интерфейса, без региона.
3. **Лист.** Первой строкой «Язык устройства» (по умолчанию). Подпись строки в профиле — `Language`
   (ед. ч., как на вебе). Без поиска. Самоназвание + название на языке интерфейса; порядок: «Язык устройства»,
   English, остальные 23 по самоназванию — фиксированным массивом. Черновик + «Choose», применение после
   закрытия листа без перезапуска навигации.
4. **Шрифты el/bg.** Дорисовать глифы при сборке. Греческий для Hanken — из апстрима; кириллица и греческий для
   Bricolage — из донора. Донора выбирает дизайнер по образцам (кандидат — Commissioner).
5. **Серверный контент в v1 — английский** (персоны, таро, сезоны, юридические страницы), как на вебе. Маркеры
   сессии переводит клиент по точному совпадению; `'Anonymous'` — клиент по флагу `anonymous`.
6. **Названия стран при вводе телефона — на языке интерфейса.** Генератор `countries.ts` выпускает 24 таблицы с
   поиском без диакритики.
7. **Ревью носителями** в целом не блокирует. Тексты оплаты, возвратов, отмены, удаления аккаунта и юридические —
   ревью до маркетинга в стране. Законы о государственном языке — вопрос к юристу (за владельцем).
8. **Открыто:** на каком языке отвечают чаттеры. До ответа v1 не говорит ничего; решение нужно до перевода персон.
   **Решено 2026-11-07 — Б:** чаттеры отвечают на языке клиента через машинный перевод (ИИ, провайдер через DI) —
   `AURAF-0024`, исследование `AURAI-0012`; тексты персон — `AURAT-0184`.

## Implementation Notes

- Не вызывать `t()` на уровне модуля: config отдаёт ключи, компоненты и хуки зовут `t` при рендере.
- Файл языка — только через `require`-загрузчик в `index.ts` своего слайса, никогда через import по умолчанию
  или namespace.
- Форматирование — только через `shared/lib` с явным `language`. Для отображения не использовать `Intl` во время
  работы (кроме `Collator` с чувствительностью по умолчанию). Никогда — `unit`, `formatRange`, `formatToParts`
  для чисел, `signDisplay`, compact, `Collator 'base'`.
- Греческие заглавные — `toLocaleUpperCase(lang)` в JS, не `textTransform`.
- Румынский — только ș/ț с запятой снизу; все строки в NFC; не использовать U+00AD в заголовках Bricolage.
- Логи и диагностика — коды ошибок и ключи, не переведённые тексты.
- Пробник Hermes: `AURAI-0010-hermes-probe.md` — запускает любой JS на точной сборке Hermes приложения без
  симулятора.
