# AURAF-0018 — Удаление сообщения: удалил в Chatwoot — пропало в приложении
Type: product
Status: done — app `AURAT-0097` (`aura-app` `develop` @ `9f75e34`), BFF `AURAT-0098` (`aura-bff` `develop` @ `bb00d30`); проверено владельцем на устройстве 2026-10-18
Priority: P1
Source spec: none (слова владельца, `AURAT-0097-001`)

## What
Чаттер удаляет сообщение в дашборде Chatwoot — у пользователя оно исчезает из
чата приложения: сразу, если чат открыт; при возврате приложения из фона; после
перезапуска и на другом устройстве. Удалённое не возвращается ни историей, ни
поллингом, его текст и вложения больше не отдаются BFF. Сам пользователь в
приложении ничего не удаляет.

## NOT in scope
- Удаление сообщения самим пользователем из приложения — не просили; контракт
  оставляет для этого место, но эндпоинта нет.
- Редактирование текста — в Chatwoot 4.15.1 у оператора его нет
  (`AURAF-0012-002`). `TECH-DEBT` #9 в части правок остаётся открытым.
- Отзыв уже показанного пуш-уведомления — оно безтекстовое («sent you a new
  message»), утечки нет; id у уведомлений нет, это отдельная работа.
- Удаление маркеров сессии (активити Chatwoot) — Chatwoot не шлёт для них вебхук.
- Старые сборки приложения: живьём не уберут, но после перезапуска удалённого не
  увидят (история фильтруется на сервере).
- Вычистка текста из данных выполненных задач Redis (24 ч, `TECH-DEBT` #28 BFF).

## Решения (1, 2, 4 — владелец 2026-10-18, `AURAT-0097-006`; 3, 5 — технические)
1. **Сообщение исчезает без следа**, а не превращается в плашку «Сообщение
   удалено» — так и сказано в задаче («так же удалить»). Альтернатива — плашка
   на месте сообщения (нужен дизайн, поле `deletedAt` в `Message`).
2. **Удаление действует в обе стороны** — оператор может удалить и сообщение
   пользователя (спам, персональные данные); у пользователя оно тоже пропадёт.
3. **На сервере — мягкое удаление с вычисткой**: строка остаётся (на неё могут
   смотреть курсоры `after`/`before` клиентов), `deletedAt` проставлен,
   `content` → `''`, вложения и расклад таро удалены. Жёсткое удаление строки
   ломает курсоры.
4. **Потеря удаления при простое BFF** (вебхуки Chatwoot без ретраев, поллинг
   читает только новое) — запись в `TECH-DEBT.md` BFF, бэкстоп не строим.
5. **Пропущенные удаления — без часов**: приложение шлёт в синке
   `deletedFrom=<самый старый id в треде>`, BFF отвечает id удалённых в этом
   окне. Окно ≤ ~50 сообщений + новые, ответ маленький; водяные знаки времени и
   журнал удалений не нужны.

## Контракт (`aura-contracts` v0.22.0, только аддитивно)
- `WsServerEvent` += `{ type: 'message.deleted', advisorId: string, messageId: string }`.
  Старые сборки роняют неизвестный тип через `safeParse` — безопасно.
- `HistoryQuery` += `deletedFrom?: string` (наш id сообщения).
- `HistoryResponse` += `deletedIds: string[]` с `.default([])` — id удалённых
  сообщений с позицией ≥ `deletedFrom`; без `deletedFrom` — пусто.
- `Message` **не меняется**: удалённые сообщения за пределы BFF не выходят.
- `MessagePushData` не меняется: пуша на удаление нет.
