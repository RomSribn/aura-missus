# AURAF-0017 — First-session offer: −50% на первую сессию
Type: product
Status: in-progress — app готово (`AURAT-0093`, `develop` `5428c49`), ждёт BFF `AURAT-0094`
Priority: P0
Source spec: `/Volumes/Work/personal/design_handoff_aura 2/OFFER.md` (+ `rn/AuraOffer.tsx`, экраны `42…46-offer-*`)

## What
Новый клиент получает **первую платную сессию за полцены** — любой советник,
любая длительность, без кода, применяется автоматически. Это заменяет плоский
кредит −$5 (`AURAD-0009`). Пока оффер действует, приложение везде показывает
обычную цену зачёркнутой коралловой линией и акционную рядом, а в бронировании —
купон «50% OFF First Session» и экономию в долларах. После использования всё
возвращается к обычному виду.

## Контракт (предложение; исполнение — `aura-contracts` + `aura-bff`)

Обратная совместимость с уже выпущенными сборками — обязательна: старые сборки
читают `creditMinor` и рисуют строку «First-session credit −$X». После
изменения они покажут там скидку 50% — честно и без поломок.

`aura-contracts` → **v0.21.0**:

```ts
// WalletResponse (GET /v1/wallet) — грузится приложением при входе
firstSessionOffer?: { active: boolean; pct: number }   // pct = 50

// SessionPricing — без новых полей
blocks[].creditMinor              // смысл меняется: «скидка первой сессии», = subtotal − cost
                                  // имя поля оставляем ради старых сборок
```

*Уточнено при исполнении (`AURAT-0093-008`):* `offerPct` в pricing и
`discountMinor` в `Session` **не нужны**. Приложение показывает оффер, когда
кошелёк говорит «активен» **и** блок со скидкой (`creditMinor > 0`); экономия
сессии — `bookedMinutes × priceMinorPerMinute − costMinor` (продление идёт по
полной цене и в разность не попадает). Контракт v0.21.0 = одно поле в
`WalletResponse`.

Почему признак в `WalletResponse`, а не в `Advisor`/профиле: кошелёк уже
грузится при входе (`use-wallet-sync`), закрыт тем же `BILLING_ENABLED`, что и
бронирование (при выключенном биллинге оффер не показывается вовсе), и это
пер-юзерное денежное состояние — его место рядом с балансом.

## Сервер (`aura-bff`)
- `session-policy.ts`: `FIRST_SESSION_CREDIT_MINOR` → `FIRST_SESSION_DISCOUNT_PCT = 50`;
  `cost = eligible ? floor(subtotal × (100 − 50) / 100) : subtotal`,
  `discount = subtotal − cost` — округление в пользу клиента (вопрос 2).
- Хранение не меняется: `sessions.creditMinor` = сумма скидки, `costMinor` = списано.
  Миграции не нужны.
- Право на оффер (вариант «возвращается при полном возврате»): нет ни одной
  сессии с `creditMinor > 0`, **кроме** отменённых с `refundedMinor = costMinor`.
  Проверка остаётся внутри транзакции брони под локами.
- `GET /v1/wallet` добавляет `firstSessionOffer` (тот же предикат, что и в брони).
- Тесты с захардкоженными 500 (`sessions.service.spec.ts`, `session-policy.spec.ts`)
  переписываются.
- Решение `AURAD-0009` (плоский −$5) — помечается замещённым новым решением
  (ID — при одобрении).

- Иконки `percent`, `sale` — в `shared/ui/AuraIcon.tsx` (пути из handoff).
- Токены: размеры/радиусы/тень купона — в `shared/config/theme.ts`

## Вопросы (история)
1. **Возврат оффера при отмене.** Дизайн: полная отмена (≥24 ч) возвращает
   оффер. Сейчас по решению `AURAT-0023` кредит при отмене сгорает.
   Рекомендация: **возвращать** — денег это не создаёт (возврат = реально
   списанные `costMinor`), а человек, отменивший заранее, не теряет приветствие.
2. **Округление.** Рекомендация: клиент платит `floor(subtotal/2)` — на нечётных
   центах полцента в пользу клиента.
3. **Продление первой сессии.** Рекомендация: по полной цене (как сейчас с
   кредитом); «вся первая сессия» = забронированный блок.
4. **Барьер первой оплаты (`AURAI-0005`).** С −50% самый дешёвый вариант —
   10 мин у ivan = **$11.00**, а минимальный тир пополнения — **$10**. Новичку
   всё ещё надо класть $25. Варианты на отдельную задачу: блок 5 мин, тир $15,
   или ничего. В эту задачу не включаю.
