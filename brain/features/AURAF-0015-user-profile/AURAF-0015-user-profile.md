# AURAF-0015 — Личные данные пользователя
Type: product
Status: in-progress
Priority: P0
Source spec: `.claude/design_handoff_aura/PROFILE_FORMS.md` (+ `screens/28-create-account.png`, `screens/29-edit-profile.png`)

## What

Приложение спрашивает у человека, кто он: сразу после проверки кода из SMS
открывается «Tell us who you are» — ворота, за которые пускает только имя.
Емейл, дата рождения и согласие на рассылку необязательны, но если введены —
проверяются и сохраняются. Позже те же данные правятся из настроек на отдельном
экране; нижний шит правки удаляется. Данные живут на нашем сервере, а не в
дизайнерской заглушке `'Vasya'`.

## NOT in scope

- **Фотография профиля** — заведена как `AURAT-0064`. Дизайн рисует «Change
  photo», но хранить файл негде: у BFF нет ни загрузки аватаров, ни их раздачи.
  Решение владельца: кнопку не рисовать, пока её нечем обслужить; аватаром
  остаётся фирменный орб.
- **Нативный date picker.** Дата вводится с клавиатуры той же маской, что у
  гороскопа. Причина записана в `AURAT-0044`: нативный модуль ради одного поля
  перед релизом не берём.
- **Второй шаг «место и время рождения»** под натальную карту — развилка из
  `AURAT-0039-003`, не решена и не нужна для этой фичи.
- **Нижний шит даты рождения на Home** остаётся как есть: он — вход для тех,
  кто дату при регистрации не ввёл. Свести его к экрану правки профиля — вопрос
  на потом, здесь только требование, чтобы обе точки писали через один стор.
- **Проверка емейла письмом** (verification link). Мы проверяем форму адреса,
  не владение им.

## Context

- Шов даты рождения спроектирован в `AURAT-0039` и наполовину построен в
  `AURAT-0041`: приложение умеет `PATCH /v1/me { birthDate }`, **сервер этот
  маршрут не отвечает** — контроллера `me` в `aura-bff` нет, в `User` нет ни
  одного из четырёх полей. Оттуда же правило, которое здесь снимается: `GET`
  не строили, потому что не было читателя. Теперь читатель есть — экран правки
  профиля.
- Имя сегодня живёт в Firebase (`displayName`) и подставляется заглушкой
  `'Vasya'`. Firebase остаётся провайдером личности (uid, телефон), но
  **профиль после этой фичи принадлежит BFF** — иначе на один профиль два
  источника правды.
- Порядок половин тот же, что в `AURAF-0014`, и он **выбран владельцем
  2026-09-08**: сервер первым (`AURAT-0063`), клиент за ним (`AURAT-0062`). В `develop` мёрж — это боевой
  деплой (`AURAS-0004`), поэтому клиент, влитый раньше сервера, будет
  собирать емейл в никуда.
