# AURAD-0015 — Тестовое окружение `development`; прод создаётся с нуля, а не переименованием

Status: **решено владельцем 2026-09-14; прод создан 2026-09-14…16**, раньше
запуска — тоже решением владельца
Дата: 2026-09-14 · обновлено 2026-09-16
Контекст: `AURAI-0004` (dev-окружение и топология Coolify), `AURAT-0068`
(target `staging` в приложении)
Затрагивает: Coolify, `aura-bff`, `aura-app`, Chatwoot
Связано: `AURAD-0016` (Chatwoot — один, аккаунт на окружение)
Механика: `AURAS-0004` → *Environments*

## Решение

Окружение, которое до 14.09 называлось `production`, оказалось тестовым. В
Coolify оно переименовано в `development`, BFF отвечает на
`bff-dev.aura-app.cc`, приложение собирается с target `staging`. Прод **не**
получают обратным переименованием этого окружения: он создан с нуля отдельным
environment на том же хосте, из ветки `main`, на `bff.aura-app.cc`. Сначала
планировалось сделать это при запуске, но владелец решил создать прод сразу,
14–16.09.

## Как это устроено

| | `development` | `production` |
|---|---|---|
| Coolify | environment `development`, проект `aura` | новое **пустое** environment, не *Clone Environment* |
| Ветка `aura-bff` | `develop` | `main` (перед первым деплоем подтянута до `develop`, `1fa9fbe`) |
| BFF | `https://bff-dev.aura-app.cc` | `https://bff.aura-app.cc` |
| Приложение | target `staging`, `npm run aab:staging` / `apk:staging` | target `prod`; `aab:prod` ещё не заведён |
| Postgres | свой `aura-postgres`: `aura_bff` | свой `aura-postgres`: `aura_bff` и `chatwoot` |
| Redis | свой `aura-redis`, BFF на db 1 | свои `aura-redis` (BFF) и `aura-chatwoot-redis` |
| Бакет аватаров | `aura-user-media` | `aura-user-media-prod` |
| Chatwoot | аккаунт 2 «Aura Dev» | аккаунт 1 «Aura»; сам Chatwoot живёт в `production` (`AURAD-0016`) |

- Релиз в прод — merge `develop` → `main`, каждый раз с подтверждения владельца
  (merge gate). `wts-finish` в `develop` деплоит только в `development`.
- Имя `dev` в приложении уже означает BFF на Mac, поэтому target называется
  `staging`. В Coolify и DNS используются `development` и `bff-dev`.
- Postgres у прода свой, а не отдельная база в общем сервере, как планировалось
  14.09: так денежный ledger прода не делит процесс с dev, и имена ролей и баз
  совпадают в обоих окружениях.

## Почему

- **Данные на хосте тестовые.** По замеру 14.09 там 5 пользователей,
  13 диалогов, 8 сессий и 10 пополнений через Play. Все 10 заказов тестовые:
  владелец проверил это в Play Console → Order management 14.09. Флага
  тестовой покупки в базе нет, поэтому ответ мог дать только Play Console.
- **Прод должен начаться с чистой базы.** Триггер разрешает в `ledger_entries`
  только вставку, и тестовые проводки потом не удалить без снятия этой защиты.
  Если переименовать тестовое окружение обратно в прод, они останутся там
  навсегда.
- **Тот же хост, без отдельной машины** (вариант A из `AURAI-0004`, выбор
  владельца). Ресурсов хватает, а риски общего хоста снимаются отдельными
  Postgres и Redis и переменными, заведёнными с нуля. Если позже понадобится
  отдельный сервер, это смена destination, а не пересборка проекта.

## Что произошло с dev-данными

16.09, при переходе dev на свой аккаунт Chatwoot, dev-база BFF была сброшена и
в тот же день восстановлена из дампа вместе с диалогами Chatwoot, с прежними id.
Не вернулись файлы 35 вложений: Chatwoot удалил их из R2 вместе со старым inbox
(`AURAS-0004` → *Backups*).
