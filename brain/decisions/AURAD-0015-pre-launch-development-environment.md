# AURAD-0015 — До запуска одно окружение `development`; прод создаётся с нуля

Status: **решено владельцем 2026-09-14**
Дата: 2026-09-14
Контекст: `AURAI-0004` (dev-окружение и топология Coolify), `AURAT-0068`
(target `staging` в приложении)
Затрагивает: Coolify, `aura-bff`, `aura-app`, Chatwoot
Механика: `AURAS-0004` → *Environments*

## Решение

Единственное окружение на хосте до запуска считается тестовым. В Coolify оно
переименовано `production` → `development`, BFF отвечает на
`bff-dev.aura-app.cc`, inbox Chatwoot называется `Aura (dev)`, приложение
собирается с target `staging`. Прод **не** получают обратным переименованием
этого окружения. При запуске он создаётся с нуля: отдельное environment на том
же хосте, ветка `main`, адрес `bff.aura-app.cc`.

## Как это работает

| | `development` (сейчас) | `production` (при запуске) |
|---|---|---|
| Coolify | environment `development`, проект `aura` | новое **пустое** environment, не *Clone Environment* |
| Ветка `aura-bff` | `develop` | `main` (создана 14.09 на `daf42bd`, пока ничего не деплоит) |
| BFF | `https://bff-dev.aura-app.cc` (старый `bff.aura-app.cc` снят 14.09) | `https://bff.aura-app.cc` |
| Приложение | target `staging`, `npm run aab:staging` | target `prod`, `aab:prod` заводится при запуске |
| Postgres | `aura_bff` в `aura-postgres` | своя база и роль там же, `REVOKE CONNECT … FROM PUBLIC` |
| Redis | `aura-redis`, db 1 | отдельный контейнер |
| Chatwoot | общий инстанс, inbox `Aura (dev)` | тот же инстанс, новый inbox из `provision-prod.rb` с отдельным `AURA_SERVICE_USER_EMAIL` |

- После запуска релиз в прод — это merge `develop` → `main`, каждый раз с
  подтверждения владельца (merge gate). До запуска `wts-finish` в `develop`
  деплоит только в `development`.
- Имя `dev` в приложении уже означает BFF на Mac, поэтому target называется
  `staging`. В Coolify и DNS используются `development` и `bff-dev`.

## Почему

- **Данные на хосте тестовые.** По замеру 14.09 там 5 пользователей,
  13 диалогов, 8 сессий и 10 пополнений через Play. Покупки, скорее всего,
  тестовые: сборки идут через internal testing, а на 19–20.08 Play Console
  сообщал о проблеме с платёжным профилем, которая блокирует реальные оплаты.
  Флага тестовой покупки в базе нет, поэтому подтвердить это в Play Console →
  Order management должен владелец. Если там найдётся реальный заказ, решение
  пересматривается.
- **Прод должен начаться с чистой базы.** Триггер разрешает в `ledger_entries`
  только вставку, и тестовые проводки потом не удалить без снятия этой защиты.
  Если переименовать тестовое окружение обратно в прод, они останутся там
  навсегда.
- **Второе окружение до запуска ничего не изолирует**, потому что изолировать
  пока нечего. `AURAI-0004` исходил из того, что на хосте работает прод.
- **Тот же хост, без отдельной машины** (вариант A из `AURAI-0004`, выбор
  владельца). Ресурсов хватает, а риски общего хоста снимаются отдельной базой,
  отдельным Redis и переменными, заведёнными с нуля. Если позже понадобится
  отдельный сервер, это смена destination, а не пересборка проекта.
