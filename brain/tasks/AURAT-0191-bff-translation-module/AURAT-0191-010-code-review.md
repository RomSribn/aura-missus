Дата: 2026-11-07. Ревью кода из `009-execute.md` от координатора (бывший `slave-1-ac`, теперь «Локализация i18n для

У исполнителя координатор проверил: `jest src/modules/translation src/config` — 13 сьютов, 225 тестов, все зелёные;
`tsc --noEmit` чистый. Дефекты 1–3 подтверждены по коду.

## Дефекты

**1. Деньги и предохранитель проверяются до очереди** — `translation.service.ts:158-166`.
`assertUnder()` и `breaker.admit()` вызываются раньше `semaphore.acquire()`. Кампания отдаёт 23 языка разом, поэтому
бюджет проходят все 23 до первого списания.
- При остатке $24.99 из $25 уходят все 23. Оценка спеки «≤ $2.3 при параллельности 3» не держится, худший случай
  ≈ $17.
- Неверный ключ: первые 3 получают 401 и открывают предохранитель, а 20 из очереди всё равно идут к провайдеру.
- Зависший провайдер: каждый вызов ждёт свои 60 с.
- Замок пробы (`timeout + 5 с`) истекает, пока проба стоит в очереди.

Правка: бюджет и `admit()` — после `acquire()`, при отказе слот освобождается. Порядок шагов §2 (4 и 5) поправить в
009.

**2. Фантомные списания** — `claude-errors.ts:18-24` и `claude.translator.ts:141-151`.
Любой обрыв превращается в `timeout` со списанием `abortedCostMicroUsd` (≈ $0.75 на Opus), даже когда провайдер
ничего не выставил.
- SDK по 429 / 529 ждёт `retry-after` между своими повторами. Если 60 с кончаются в этой паузе, получается
  `APIUserAbortError`: списано $0.75 и засчитано в серию предохранителя. А `rate_limited` по спеке в серию не идёт.
- То же самое, если запрос не дошёл до API.
- Вместе с п. 1: одна кампания во время сбоя «съедает» ≈ $17 из $25 при реальном расходе ≈ 0, и перевод выключен до
  конца месяца.

Правка — на выбор исполнителя, решение записать:
- либо `maxRetries: 0` у этого клиента и повторы на нашем уровне — тогда обрыв означает, что запрос был в полёте;
- либо паузы SDK не длиннее остатка времени.

В обоих случаях оценку обрыва списывать, только когда запрос точно ушёл, а запасную модель учитывать в оценке только
при отказе. Тест: отмена во время паузы SDK между повторами.

**3. Глоссарий проверяется по тексту в капсе** — `translation.service.ts:193-195` → `translation-checks.ts:88-93`.
К моменту проверки `finishText()` уже применил `letterCase: 'upper'`, а `toLocaleUpperCase('el')` снимает тонос.
Формы `avoid` el пишутся с тоносом (`αναγνώστ`, `συνεδρίαση`), поэтому в «ΑΝΑΓΝΩΣΤ» / «ΣΥΝΕΔΡΙΑΣΗ» они не находятся
(проверено прогоном node). el-надзаголовок с запрещённым словом проходит молча.

Правка: проверять `glossary` на тексте до капса (после NFC / ro / fr) или сравнивать без диакритики. Тест: el +
`upper` + `avoid`.

## Мелочи

4. `translation-breaker.ts:72-81` — `succeeded()` шлёт «restored» и снимает `tripped`, пока ключ паузы `breaker` ещё
   жив: вызовы ещё до 5 мин получают `provider`. Закрывать только для `admission.probe` или когда паузы нет.
5. `translation-breaker.ts:94-97` — `INCR` и `PEXPIRE` идут двумя командами. Если `PEXPIRE` упрётся в `bounded`
   (1 с), счётчик останется без срока, и окно «5 за 2 мин» сломается. Правка: `SET NX PX` перед `INCR` или
   Lua / MULTI. Заодно оценить и записать: при параллельности 1 и таймауте 60 с пять таймаутов в окно 2 мин не
   помещаются.
6. `claude-errors.ts:42-44` — 408 / 409 после повторов SDK сейчас дают `provider` с `retryable: false`, а должны быть
   повторяемыми. Код ответа на исчерпанный spend limit workspace (решение 3) по документации не подтверждён. Если это
   не 402, вместо `credit` получится `provider` — внести в план живой проверки §8.
7. `translation-checks.ts:48` — fr `typography` ложно срабатывает на ссылке с «?» (`https://x.fr/a?b=1`); спека
   ссылки исключает.

- «Тексты отдельным блоком» сделаны XML-секцией в том же текстовом блоке — на грани буквы спеки, записать почему.
