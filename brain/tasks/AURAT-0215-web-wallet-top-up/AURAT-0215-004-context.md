# AURAT-0215-004 — Context

Date: 2026-11-13.

## Источники

- `001-initial.md` (координатор, `aura-app-manor`) — заглушки, что нужно, BFF без изменений.
- Хендофф веба: README §«Top up sheet» и NAVIGATION §1.1, §Profile — шторка «Top up balance»:
  текущий баланс, $10 / $25 / $50 / $100 (по умолчанию $25), «Pay $X» → «Balance topped up», новый
  баланс, «+$X added», Done. Чип в шапке «$4.00 · Top up» — **только десктоп, на телефоне скрыт**.
  Сохранённой карты («Visa ···· 4242 Change») в нашей схеме нет (`AURAD-0023`).
  Kind диалога `topup` уже есть в `shared/model/dialog.ts`, в хосте не зарегистрирован.
- Приложение: `store-topup/config/products.ts` — те же $10 / $25 / $50 / $100.
- `AURAT-0212` v2 (принята): `features/pay` — `useCardSession` (сессия на сумму, debounce 300 мс,
  закрытие старой, 429, истечение 60 мин), `useCardCheckout` (шаг choice/payment, `confirm`, запись
  попытки только при `confirm`), `settleTopUp` (опрос BFF, затем бронь тем же ключом), UI
  `CardChoice` / `PayStep` / `card-elements`. Всё завязано на бронь: `PayAttempt` — советник, минуты,
  слот; `PendingPayment` — тоже бронь; `/checkout` (`usePaymentReturn`) после зачисления всегда бронирует.
- `AURAT-0114` (продление): `useExtendSession` — ключ на попытку, хранится в `sessionStorage`
  (`attempt-store`), BFF сверяет ключ и минуты; блоки сверх баланса выключены (`blocker: 'balance'`),
  строка нехватки + «Top up in the Aura app». Окно второго списания («Choose another block» после
  обрыва) принято владельцем для v1 (`AURAT-0114-007` «Открыто»).
- `AURAT-0214` (заготовка): в sandbox включены банковские методы (Bancontact, BLIK, EPS, Klarna…) — они
  уводят со страницы и возвращают на `/checkout?payment=`. Значит, запись попытки пополнения без брони
  и продления должна знать свою цель.
- BFF `develop` `cd0975b`: `CardTopUpRequest` с бронью не связан; `returnPath` — любой путь сайта;
  $5–$120 целыми долларами; 429 после 20 стартов за 10 минут.

## Выводы

- FSD: шторка продления — фича `extend-session`, оплата — фича `pay`; одна фича другую импортировать
  не может. Шторку продления с картой собирает слой выше — как Book (`widgets/book-sheet`).
- Порт пополнения обобщается: «пополнить → потом действие цели» (бронь / ничего / продление).
- `043` (поля недостачи в 402 продления) не нужен: недостача считается по кошельку, как сейчас.
