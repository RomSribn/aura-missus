## 1 · Что строим

Приём отзывов от людей — фаза 2, которую `AURAF-0014` отложила и под которую
завела три колонки. Дизайн: `.claude/design_handoff_aura/REVIEWS.md` в
`aura-app-manor` (там же экраны 37–41).

Правила продукта, все из §0 и §4 спеки:

- **оценка публикуется сразу** и входит в агрегат советника;
- **текст модерируется** человеком, до 24 часов, отклонение **молчаливое** —
  автору не приходит ничего и в API нет ничего, по чему приложение могло бы
  показать статус;
- **право на отзыв** даёт переписка с этим советником, платная или
  бесплатная, — и проверяется **на сервере**: «don't rely on the client
  hiding the link»;
- **один отзыв на пару (человек, советник)**; повторная отправка **правит**
  прежний и заново ставит текст в очередь.

## 2 · Схема: что меняется в `advisor_reviews`

Сейчас (`prisma/schema.prisma:378`) заготовка под фазу 2 выражает **другое**
правило — «один отзыв на оплаченную сессию». Правки:

```prisma
model AdvisorReview {
  ...
  // Было: sessionId String? @unique  ← снять @unique.
  // Поле остаётся: «какая сессия подтолкнула отзыв», для модерации и разбора.
  // Живой ключ теперь — пара:
  sessionId    String?
  userId       String?
  quote        String                  // '' допустимо: оценка без текста
  anonymous    Boolean         @default(false)
  quoteStatus  ReviewQuoteStatus @default(PUBLISHED) // засеянные — PUBLISHED
  @@unique([userId, advisorId])        // NULL-userId у засеянных строк не мешает
  ...
}

enum ReviewQuoteStatus { PENDING PUBLISHED DECLINED }
```

Почему `quoteStatus` отдельно от `published`: `published` гасит **строку**
целиком (модерация может убрать отзыв совсем), а оценка обязана считаться
сразу, даже пока текст не прочитан. Разбор — `AURAD-0014`.

Миграция безопасна: 42 засеянные строки имеют `sessionId = NULL` и
`userId = NULL`, снятие уникального индекса ничего не ломает, `@@unique` по
паре с NULL в Postgres не конфликтует.

## 3 · Контракты — `@aura/contracts` `v0.18.0`, аддитивно

Форма советника в BFF не переобъявляется (`AURAT-0034`), поэтому начинать с
пакета.

```ts
// AdvisorReview — одно новое поле:
anonymous: z.boolean().default(false)   // default → старый сервер парсится
// quote может быть '' — это оценка без текста либо текст на модерации.
// authorName у анонимной строки = 'Anonymous'. Имени человека на проводе нет.

export const REVIEW_MAX_TEXT_LENGTH = 400;   // одно число на обе стороны
export const REVIEW_RATING_STEP = 10;        // десятые, как везде

export const SubmitReviewRequest = z.object({
  ratingTenths: z.number().int().min(10).max(50)
    .refine(n => n % 10 === 0),          // 1..5 звёзд, без половинок
  text: z.string().max(REVIEW_MAX_TEXT_LENGTH),   // '' допустимо
  anonymous: z.boolean(),
  sessionId: z.string().optional(),      // если пришли из строки сессии
});

/** Свой отзыв — то, что приложение знает о собственной записи. */
export const MyReview = z.object({
  advisorId: z.string(),
  ratingTenths: z.number().int(),
  anonymous: z.boolean(),
  hasText: z.boolean(),      // человек что-то написал. НЕ статус модерации.
  createdAt: z.string(),
  updatedAt: z.string(),
});
export const MyReviewsResponse = z.object({ reviews: z.array(MyReview) });
export const SubmitReviewResponse = z.object({ review: MyReview });

export const ReviewRefusalCode = z.enum(['review_not_eligible']);
```

**`hasText` — это не статус.** Он говорит «я написал текст», а не «текст
опубликован». §5 запрещает второе: приложение не должно уметь отличить
`PENDING` от `DECLINED`, иначе кто-нибудь однажды это нарисует.

## 4 · Роуты

### `PUT /v1/advisors/:advisorId/review`

Идемпотентный upsert **моего** отзыва об этом советнике. `PUT`, а не `POST`,
именно потому, что правило «один на пару» и повторная отправка правит:
повтор после потерянного ответа не создаёт второй строки.

1. Проверить право: у пары (user, advisor) есть переписка, **в которой
   человек отправил хотя бы одно сообщение** (`direction: 'user'`).
   Нет → `403 { code: 'review_not_eligible' }`.
   *Почему не «тред существует»: `PUT /v1/advisors/:id/conversation` заводит
   тред по нажатию «Chat», до единого слова. Право на отзыв по такому треду
   делает бейдж «Verified client» неправдой (`AURAT-0066-004` A3).*
2. Советник неизвестен или неактивен → `404`.
3. Upsert строки по `(userId, advisorId)`:
   - `authorName` = **первое слово** `displayName` из профиля, снимок на
     момент записи (переименование потом не переписывает историю); при
     `anonymous: true` → `'Anonymous'`, имя не хранится вовсе;
   - `source = USER`, `published = true`;
   - `quote` = присланный текст; `quoteStatus = PENDING` если текст непустой,
     иначе `PUBLISHED` (публиковать нечего);
   - при правке: новая оценка применяется сразу, изменённый непустой текст
     снова уходит в `PENDING`.
4. **В той же транзакции** пересчитать агрегаты советника:
   `ratingTenths = round(sum / count)`, `reviewsCount = count` по строкам с
   `published = true`. Логика уже написана для сида (`AURAF-0014`) — её место
   теперь в сервисе, а сид зовёт тот же код.
5. Ответ — `SubmitReviewResponse`.

### `GET /v1/reviews/me`

`MyReviewsResponse` — мои отзывы по всем советникам. Приложению нужно, чтобы
три точки входа рисовали состояние «уже оценил» синхронно, без запроса на
каждый экран. Объём — не больше числа советников.

### `GET /v1/advisors` — что меняется в выдаче

`reviews[]` отдаёт строки с `published = true` (как сейчас), у каждой:

- `quote` = текст, если `quoteStatus = PUBLISHED`, иначе **`''`**;
- `anonymous`, и `authorName = 'Anonymous'` у таких строк.

`reviewsCount` остаётся длиной `reviews[]` — инвариант `AURAF-0014` не
трогается (в этом и смысл варианта 2 из `AURAD-0014`).

## 5 · Модерация

Интерфейса нет и в v1 не заводим. Три скрипта, модератор — владелец:

- `reviews:pending` — что ждёт: id, советник, оценка, текст, возраст строки;
- `reviews:publish <id>` — `quoteStatus = PUBLISHED`;
- `reviews:decline <id>` — `quoteStatus = DECLINED`, **и больше ничего**:
  ни письма, ни пуша, ни поля в API. Оценка остаётся засчитанной.

Обещание «до 24 часов» напечатано в форме — очередь надо смотреть.

## 6 · Тесты

1. Отзыв без переписки → `403`, строка не создана, агрегаты не тронуты.
2. Переписка есть, но человек не написал ни слова (только приветствие
   советника) → `403`.
3. Первый отзыв: строка создана, `ratingTenths`/`reviewsCount` советника
   пересчитаны, среднее сходится с рядом до десятой.
4. Повторная отправка: строк по-прежнему одна, оценка новая, `quoteStatus`
   снова `PENDING`, счётчик **не** вырос.
5. Только звёзды: `quote = ''`, `quoteStatus = PUBLISHED`, карточка попадает
   в `reviews[]`, счётчик = длине списка.
6. `PENDING`-текст не виден в `GET /v1/advisors` (пустая `quote`), но строка
   в списке есть и в счётчике учтена.
7. `DECLINED` ведёт себя ровно как `PENDING` на проводе — отличить нельзя.
8. Аноним: `authorName = 'Anonymous'`, имени человека нет ни в ответе, ни в
   строке БД.
9. Сид прогоняется дважды — 42 засеянные строки не удваиваются (свойство из
   `AURAF-0014`, проверить после миграции уникальности).
