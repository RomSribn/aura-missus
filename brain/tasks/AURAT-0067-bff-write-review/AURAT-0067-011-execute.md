# AURAT-0067-011 — засеянные отзывы выведены

Дата: 2026-09-08 · ветка `feature/AURAT-0067-bff-write-review` (после мержа `084a2f8`)

## Миграция

`prisma/migrations/20260908190000_drop_seeded_reviews/`:

```sql
DELETE FROM "advisor_reviews" WHERE "source" = 'SEED';
UPDATE "advisors" … SET "reviewsCount" = agg."count", "ratingTenths" = agg."rating"
  FROM (COUNT/AVG по оставшимся published-строкам) …
```

Удаление, а не `published = false`: строки, которые надо объяснять каждому
следующему читателю, дороже удалённых, а тексты не потеряны — они в истории
репозитория и в `AURAT-0058-002-reviews.json`. Фильтр по `source` — живые
строки, если они где-то уже появились, остаются нетронутыми, и счётчики
пересчитываются по ним.

`ROUND(AVG(...))` — та же арифметика, что в `ratingTenthsFromTotals`: половинки
вверх, все значения положительные. Одно правило округления на сервис и на
миграцию.

## Сид

- `seedAdvisorReviews` **удалён** вместе с `advisor-review-seed.data.ts`
  (правило 8 — мёртвого кода не держим). Сид больше не может вернуть строки;
  это и есть разница между «убрать из кода» и «очистить константу».
- `seedAdvisors` пишет `ratingTenths` / `reviewsCount` **только в `create`**,
  нулями. Логика вынесена в чистую `advisorUpsert(advisor)` — чтобы свойство
  можно было проверить без базы.

**Это чинит баг, которого до приёма отзывов не существовало.** Сид бежит на
каждом старте контейнера (`docker-entrypoint.sh`), и `update` с агрегатами
означал: живой отзыв поднимает счётчик до 5, ближайший деплой возвращает
засеянные 4. Пока отзывы были только засеянными, константа и была правдой —
безвредно. С `AURAT-0067` перестало быть.

## Что ещё поменялось

- `advisor-review-aggregate.ts` ужался до одной функции —
  `ratingTenthsFromTotals`; `aggregateAdvisorReviews` / `aggregateFor` жили
  только ради сид-константы и ушли с ней.
- `contracts/advisor.spec.ts` — сид-советник теперь проверяется как `0/0` и
  `reviews: []`; тест «счётчик равен длине списка» остался и продолжает держать
  инвариант, просто на нуле.
- README и комментарий в `advisor-seed.data.ts` — почему агрегаты пишутся
  только при создании и почему отзывы бывают только настоящими.
- `AURAF-0014` — приписка про вывод засеянных и снятая строка `-004`.

## Ворота

`lint` · `tsc --noEmit` · `jest` · **855 тестов**, 64 набора. Было 865: ушли 15
тестов, проверявших засеянные отзывы (42 строки, длина цитат, четвёрки среди
пятёрок), добавились 5 про `advisorUpsert` и переписанные про округление.

Новое, что стоит знать: `seed.spec.ts` проверяет ровно то, что нельзя увидеть
за один прогон сида — что `update` не несёт агрегатов.
