# AURAT-0175-005 — spec: веб — подписи советников на языке запроса

Дата: 2026-11-07 · Status: **approved** 2026-11-07 (`006-approval.md`)
Фича `AURAF-0023` строка 011 (подписи советников) · Сервер `AURAT-0173` (done, BFF `167f0b9`) · Контракты `v0.29.0`
(тег на GitHub есть). Тип — задача, без новой фичи. Контекст — `004-context.md`.

## Что получится
- На `/match` советник другой категории попадает в «also» по `Advisor.topics`, на любом языке — как сегодня на
  английском (паритет закреплён тестом BFF).
- Смена языка перечитывает каталог: тип и специализации советника — на новом языке во всём вебе (каталог, Home,
  профиль, сессия), без перезагрузки страницы. Ответ, опоздавший на старом языке, ложится под свой ключ и не
  перекрывает новый.
- Новых строк нет — переводы не трогаются.

## 1. Контракты — отдельным коммитом (правило 6)
- `package.json` / `package-lock.json`: `@aura/contracts` → `github:RomSribn/aura-contracts#v0.29.0`.
- Фикстуры `Advisor` получают `topics` (в выходном типе поле обязательно): `const MIA: Advisor` в

  всё равно; в `match-advisors.test.ts` — настоящие (§3). Фикстуры — в коммит кода, если без них не компилируется
  коммит контрактов, — в коммит контрактов (решу по `typecheck`, чтобы каждый коммит был зелёным).

## 2. Язык в ключе кэша каталога
- `entities/advisor/api/advisors-api.ts`: `getAdvisors: build.query<Advisor[], Language>` — аргумент только для
  ключа; сам язык, как и у всех запросов, ставит `?lang` базовый запрос (`AURAT-0170`). JSDoc — как у
  `daily-card-api.ts`: зачем язык в ключе.
- `entities/advisor/model/use-advisors.ts`: внутренний `useCatalogLanguage()` — `useTranslation()` (подписка на смену
  языка) + `currentLanguage()`; `useAdvisors` и `useAdvisor` передают его в `useGetAdvisorsQuery`. Публичный API
  слайса не меняется.
- Пока каталог на новом языке грузится, RTK Query отдаёт прежний `data` (последний результат) — экран не мигает
  скелетоном, подписи меняются, когда придёт ответ.
- Тег `Advisors` (`write-review`) инвалидирует все языковые ключи — как и нужно.

## 3. Подбор по `topics`
- `pages/match/lib/match-advisors.ts`: `readsOn = advisor.topics.includes(topic)`; комментарий `MatchReason.also` —
  «the topic is among their topics (`Advisor.topics`, `AURAT-0173`)».
- `pages/match/config/match.ts`: `TOPIC_WORDS` удаляется (других потребителей нет).
- `match-advisors.test.ts`: фабрика с `topics`; каталог — персоны сида с их настоящими специализациями и темами
  (olivia LOVE·PSYCHIC, sunshine TAROT·PSYCHIC, veronica TAROT·PSYCHIC, may PSYCHIC, marta LOVE, ivan LOVE·TAROT);
  ожидания подбора — те же, что сейчас. Новый тест: специализации на другом языке (de) — подбор тот же, решают
  `topics`; советник без `topics` (старый сервер, `[]`) — только «own».

## Решение владельца

**Глоссарий v3.** У веба копии глоссария нет вовсе — ни v1, ни v2, и нет проверки, которая её читала бы (`004`).
Новых строк в задаче нет; el-строки веба о psychic уже «Διόραση», проблемы v2 у веба нет.
- **А (рекомендую): не в этой задаче.** Принять глоссарий в веб — отдельной задачей (минт в aura-app-manor):
  копия по `version` + тест «перевод не содержит `avoid`» + правка известных расхождений (`AURAF-0023-glossary.md`
  «Расхождения веба»), иначе тест сразу красный. 0175 не ждёт `0174`.
- **Б: только копия файла.** `glossary.json` v3 → в веб (например `scripts/i18n/glossary.json`) без проверки, когда
  `0174` закоммитит. Задача ждёт `0174`; файл ничем не читается.
- **В: копия + проверка здесь.** Тянет за собой правку ~20+ строк в нескольких слайсах × языках — не по теме задачи.
