# AURAT-0176-005 — spec (v3)

Тип: задача (без новой фичи), фича — `AURAF-0007`. Образец — веб `AURAT-0105` (решение 1 — Б), контекст — `004`.
Решения владельца внесены (внизу), ревью координатора slave-1-ac — тоже.

## Что видит человек

1. **Строка диалога в Chats** (`ChatListRow`): справа в строке превью — коралловая «таблетка» с числом новых сообщений
   советника; текст превью при этом — `ink`, 600 (как в вебе), без непрочитанного — как сейчас (`ink3`). Предела
   «99+» нет, как в вебе (за один визит столько не набирается; таблетка растёт по ширине).
2. **Вкладка Chats** (`AuraTabBar`): такая же таблетка поверх иконки справа сверху — число **диалогов** с
   непрочитанным. Нет — нет бейджа. Видна и на активной вкладке, её точку не прячет. Сезон её не красит
   (`SEASONAL.md` §5: только активная иконка и точка).
3. **Голос** (VoiceOver / TalkBack): у строки после превью — «3 new messages» вместо цифры; у вкладки — label «Chats»,
   значение (`accessibilityValue.text`) «2 conversations with new messages». Цифра голосу отдельно не читается.

## Что считается

- +1 — каждое **новое сообщение советника** (`direction === 'advisor'`, вместе с раскладом и приглашением; маркеры
  сессии и свои — нет), пришедшее в тред, который **не читается**: по сокету (`message.new`), догоном (возврат из
  фона, переподключение сокета, пинг FCM), раундами удалений того же чтения.
- **Не считается история** — то, что пришло чтением, начатым как первое чтение треда: `after === undefined &&
  firstSync !== 'done'`, решается один раз на вызов `readThread`, до `await`. Курсор признаком не служит: пустая
  страница его не пишет (`ChatProvider.tsx:259-263`), и у пустого треда (новый советник) всё последующее считалось
  бы историей. Поэтому после холодного старта (в том числе из пуша) непрочитанного нет; пришедшее, пока приложение
  было **в фоне** (процесс жив), — помечается на возврате.
- **«Читается»** = экран треда в фокусе **и лента внизу** (зона `bottom` из `use-thread-scroll`). Тред открыт, но
  человек листает старые страницы, — новое считается (решение 2), вместе с точкой на кнопке «вниз». Закрыт другим
  экраном поверх (профиль советника) — тоже считается. В фоне с тредом внизу — не считается (как в вебе).
- **Сброс:** тред стал «читается» (открытие — тред открывается внизу; доскролл вниз; кнопка «вниз») — его счётчик в
  ноль; смена или выход аккаунта — всё (тот же эффект `userUid`, что сбрасывает треды). Уйти в список, не долистав, —
  число остаётся.
- **Удалённое столом** до прочтения — убирается из счётчика (решение 3).
- В памяти, ничего не хранится — серверной отметки прочтения нет (вариант Г — бэклог, `AURAT-0105-005` стр. 6).

## Как (код)

- `features/chat/model/ChatProvider.tsx` — владелец.
  - Непрочитанное — ref `Record<advisorId, Set<messageId>>` + зеркало в state. Id добавляется, только если
    `direction === 'advisor'`, его нет в треде (`threadsRef`) и в `deletedServerIds`, тред не читается и пришло не
    историей. Так одно сообщение, пришедшее и сокетом, и догоном до рендера (на возврат из фона идут два
    `syncAllThreads` — `AppState` и `onOpen` сокета), не считается дважды.
  - `removeServerMessages` удаляет id из набора, пустой набор — ключ. Смена `userUid` — всё.
  - «Читается» — ref (`advisorId | null`). Действия `threadReading(id)` / `threadLeft(id)` стабильные, на ref, от
    состояния непрочитанного не зависят; `threadLeft(id)` сбрасывает «читается», только если там всё ещё этот id;
    `threadReading` треда без непрочитанного state не ставит.
  - **Два контекста:** `useChatUnreadSummary()` → `{ unreadThreads, threadReading, threadLeft }` (вкладка не
    перерисовывается на каждое засчитанное сообщение — только когда меняется число диалогов) и
    `useChatUnread()` → `unreadOf(advisorId)` (читает список). Экспорт — через `features/chat/index.ts`.
- `screens/chat-thread/model/use-chat-thread.ts` — `useFocusEffect` + зона ленты: эффект с ключом
  `[advisorId, atBottom]` → `threadReading` / `threadLeft`. Повторный `openThread` меняет params на том же экране без
  blur / focus (`use-chat-thread.ts:194-196`), поэтому ключ — `advisorId`, не фокус. После смены `advisorId` зона
  считается «внизу» (или перемеряется) до решения `threadReading` — тред B не наследует «далеко» от A.
- `screens/chats/model/use-chats.ts` — `unread` в `ChatListItem`; `ChatListRow` (memo) — таблетка и вес превью.
- `app/navigation/AuraTabBar.tsx` — бейдж на `SCREENS.CHATS`: обёртка размером с иконку (25), смещения top / right
  токенами, обводка 2 pt цвета фона бара (как `theme.jumpToLatest.dotRing`) — без неё бейдж сливается с сезонной
  активной иконкой (#A82A40 / #B4284A против #DA3557 — 1,5 / 1,4:1).
- `shared/ui` — `CountBadge` (одна таблетка на оба места, правило 3). Токены темы: `minWidth = minHeight` 18 (**без
  `height`** — растёт с крупным системным шрифтом), `paddingHorizontal` 5, `theme.radius.pill`, body 700 11; у Text —
  `maxFontSizeMultiplier` токеном 1.3 (как `StatsCard`). Обводка — опция (для вкладки).
- `shared/config/theme.ts` — токен `accentStrong` #DA3557 **только для `CountBadge`** (белая цифра 4,54:1 против 3,26:1
  у `accent`); комментарий: Button primary (`button/styles.ts:62`) и OffChip (`OffChip.tsx:32`) остаются на `accent`
  по решению владельца («кнопки оставь как есть»).
- Голос: строка — `accessibilityLabel` у Text бейджа (`t('row.unread', {count})`), стоит после превью (iOS берёт его
  вместо цифры, Android собирает contentDescription детей); вкладка — label кнопки уже маскирует детей, число — в
  `accessibilityValue.text` (на RN 0.85 обе платформы; при 0 label не теряется).
- Числа: целые < 1000 у всех 24 языков без группировки — цифра как есть; в `t()` — `{{count}}`, как `row.sessionLive`.

## Тесты (Jest)

Провайдер:
- +1 по `message.new` вне «читается»; при «читается» — 0; маркер / своё — 0;
- первое чтение (история) — 0; догон — +N;
- пустое первое чтение → догон без курсора с сообщением советника → +1;
- один id по сокету и догоном в одном `act()` → 1; два пересекающихся догона → 1;
- в фокусе и внизу — 0 и сброс; в фокусе, но наверху — +1; доскролл вниз — сброс;
- фокус на A, rerender с params B — сообщение A считается, B — нет;
- удаление столом — минус; смена аккаунта — сброс.

UI:
- `ChatListRow`: `getByLabelText('3 new messages')` без отдельной «3»; без непрочитанного — нет таблетки.
- `AuraTabBar`: бейдж только у Chats, с числом диалогов; `accessibilityValue` `{text}`; при 0 — бейджа нет, label
  «Chats» на месте.
- `CountBadge`: у Text есть ограничение шрифта, у коробки нет `height`; размеры из темы.

Затем lint, typecheck, весь Jest. Живая проверка (A50) — в manor после мёржа.

## Решения владельца (2026-11-07)

1. «Визит» — Б, жизнь процесса (как в вебе).
2. Тред открыт, лента не внизу — новое **считается**.
3. Удалённое столом — убрать из счётчика (по id).
4. Цвет — `accentStrong` #DA3557; только для бейджа, кнопки остаются на `accent`.

## Что поменялось после ревью координатора (v2 → v3)

- «История» — по `firstSync` на вызов `readThread`, не по курсору; «ответ на отправку» из флагов убран.
- Ключ эффекта — `advisorId` (экран треда переиспользуется), зона после смены треда — «внизу».
- Хранение — `Set` по id (нет двойного счёта, удаление убирает).
- Два контекста вместо одного.
- `CountBadge` без `height`, `radius.pill`, `maxFontSizeMultiplier` 1.3; на вкладке — обёртка и обводка 2 pt.
- Механизм голоса в RN назван; `_two` для ga / mt / sl; JSDoc «только голос».

## Не здесь

Серверная отметка прочтения (контракты + BFF + оба клиента); сортировка Chats по непрочитанному; бейдж на иконке
приложения (launcher); перевод остальных коралловых заливок на `accentStrong`.
