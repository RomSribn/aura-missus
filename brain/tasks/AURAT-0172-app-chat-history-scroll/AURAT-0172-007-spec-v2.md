# AURAT-0172-007 — spec v2: лента треда как в Telegram (подгрузка старых, разделители по дням, кнопка «вниз»)

Дата: 2026-11-06 · Status: **draft** — ждёт одобрения владельца
Заменяет `005-spec.md`: решения владельца и 13 замечаний ревью (`006-review.md`).
Слот `slave-3`, ветка `feature/AURAT-0172-app-chat-history-scroll` от `develop` @ `74755ee`. Только приложение; веб —
отдельно. Контракт не меняется (`HistoryQuery.before` есть, BFF отдаёт его как описано — `004-context`).

## Что получится

1. Тред открывается внизу, на последних сообщениях, без анимации прокрутки и без pop-in у уже лежащих сообщений.
2. Прокрутка вверх: за ~экран до верха загруженного подгружается следующая страница старых (`before=<самое старое
   серверное в треде>`, 50). Позиция не прыгает. Сверху, пока страница идёт, — маленький индикатор. Не удалось — на его
   месте строка «Couldn’t load earlier messages · Tap to retry»; повтор **только нажатием** (без петли, п. «Подгрузка»).
3. Начало истории: страница короче 50 — история кончилась, больше запросов нет; наверху — приветствие персоны.
   Короткий тред (< 50) — как сейчас: всё сразу, приветствие наверху, ни одного лишнего запроса.
4. Над первым сообщением каждого дня — подпись дня: «Today», «Yesterday», дальше дата языка — «November 4» /
   «4 November» / «4. listopadu»; прошлых лет — с годом («November 4, 2025»). День — по часовому поясу телефона.
   Вид — как нынешний «Today» (по центру, 11.5, ink-3), не как маркер сессии.
5. Новые сообщения: внизу — лента остаётся внизу, новое видно; читаешь старое — позиция не сбивается; своё
   отправленное — лента идёт к нему, когда его строка уже на экране.
6. **Кнопка «вниз»** (решение владельца, B). Отъехал от низа больше чем на высоту ленты — справа над
   `DraftAttachmentBar` / `ChatInputBar` (и вместе с ними над клавиатурой) — круглая кнопка со стрелкой;
   нажатие — `scrollToOffset({ offset: 0 })`. Пришло сообщение собеседника, пока человек читает старое, — на кнопке
   маленькая точка «есть новое», без счётчика; гаснет, когда человек внизу.
7. **Плавающая дата (A) — отложена** (решение владельца). Не делаю.

## Лента

**Перевёрнутый RN `FlatList`** (`inverted`; решение владельца). Низ — нулевое смещение, старые страницы дописываются в
конец данных, позиция не меняется сама. `maintainVisibleContentPosition` (`minIndexForVisible: 0`,
`autoscrollToTopThreshold` ≈ 80) держит место, пока человек читает старое, и доводит до нового, если он внизу.
`onContentSizeChange={scrollToEnd}` уходит. Индикатор / повтор — `ListFooterComponent` (визуально сверху),
«печатает…» — `ListHeaderComponent` (снизу).

**Почему не `LegacyFlatList` из заглушки.** Жест в ленте есть: веер таро — legacy `PanGestureHandler` в строке
(`features/tarot-spread/ui/SpreadStage.tsx:205-216`, `activeOffsetX` / `failOffsetY`). Он разводит себя со
скроллом по смещениям, а не через `simultaneousHandlers` / `waitFor` к ScrollView, и уже сейчас работает внутри RN
`FlatList`. RNGH-список нужен только для такой связки по ссылкам; тип списка не меняется. Правило 7 соблюдено: v3 не
используется. Перевёрнутый список меняет только направление ScrollView (Android — `scaleY: -1`, ячейки
переворачиваются обратно), горизонтальный жест это не трогает — проверить на устройстве (ниже).

**Логика — в model (правило 4).** `screens/chat-thread/model/use-thread-scroll.ts`: `onEndReached` → `loadOlder`,
видимость кнопки и точки (из `onScroll`, состояние меняется только на пересечении порога), прокрутка после отправки
(флаг ставит `send`, `onContentSizeChange` при поднятом флаге делает `scrollToOffset(0)` и снимает его — строка уже
смонтирована). `model/use-today-key.ts` — «сегодня» (ниже). В `ui/` — только props.

**Pop-in** (`usePopIn`) — только у сообщений, пришедших в конец ленты после открытия треда; подгруженные сверху и
бывшие при открытии появляются без него (флаг пропом в строку).

## Данные — `features/chat` (`ChatProvider`)

У треда — состояние истории `{ loadingOlder, reachedStart, olderFailed }` и `loadOlder(advisorId)`, `retryOlder(advisorId)`.

**Подгрузка (замечание 1).** `VirtualizedList` зовёт `onEndReached` снова на каждую смену длины контента в пороге
(`VirtualizedList.js:1584-1590`), а смена подвала «индикатор → ошибка» её меняет. Поэтому:
- в полёте не более одного запроса на тред; при `reachedStart` или `olderFailed` автоматический `loadOlder` ничего не
  делает; `retryOlder` (нажатие на строку) снимает `olderFailed` и просит снова;
- страница фильтруется как досинхронизация: дедуп по id (BFF на неизвестный `before` молча отдаёт новейшую страницу) и
  `deletedServerIds` (удалённое не воскресает); кладётся **перед** всем (локальные pending/failed остаются в конце);
- страница короче 50 **или без новых после дедупа** → `reachedStart` (второе — защита от бесконечной подгрузки на
  молчаливой подмене курсора);
- курсор досинхронизации (`lastServerIds`) не трогается.

**Поколение треда (замечание 2).** У треда — номер поколения; растёт при обрезке (смена языка), сбросе (выход / смена
пользователя — `ChatProvider.tsx:262-266`) и перечитывании `AURAT-0169`. `loadOlder` запоминает номер при запросе и
**отбрасывает ответ**, если номер сменился (и снимает `loadingOlder`): иначе страница ляжет перед новейшей с дырой, на
старом языке или в тред того же советника у другого пользователя. Совпадение `before` с текущим самым старым id
не проверяется — удаление самого старого в полёте отбросило бы нормальную страницу.

**Первая страница и приветствие (замечание 6).** Первая страница треда (без курсора) короче 50 → `reachedStart` сразу.
Треды из `initialThreads` стартуют с `reachedStart = true`. Без входа (`userUid` нет) `loadOlder` ничего не делает.
Пустой тред без серверных сообщений (первое открытие офлайн) — `loadOlder` = обычная синхронизация. Приветствие
показывается при `reachedStart` **или** когда в треде нет серверных сообщений.

**Удаления, предел 200 (замечание 4).** `deletedFrom` = самое старое серверное, и с каждой старой страницей оно уходит
назад; BFF отдаёт ≤ 200 id по возрастанию (`chat.service.ts:44`) — при > 200 надгробий в загруженном свежие удаления
не дошли бы. Досинхронизация: пришло ровно 200 — дозапросить с `deletedFrom = последний полученный id` (и тем же
`after`), пока ответ не короче; не больше 5 дозапросов за синхронизацию. Обычный тред (< 200 удалений) — без
лишнего запроса.

**Смена языка (`AURAT-0169`).** 0169, скорее всего, вливается раньше; тогда вливаю `develop` и подключаю: на смену
языка **каждый** тред со старыми страницами (не только открытый — 0169 перечитывает остальные при открытии,
`0169-007:134-136`) обрезается до новейших 50 серверных + локальные, `reachedStart` сбрасывается, если что-то
обрезано, поколение растёт. Перечитывание 0169 новейшей страницей с `replaceSpreads` покрывает всё оставшееся; старые
страницы подгрузятся заново на новом языке. Если первой вливается 0172 — правило записываю для 0169.

Подгруженное держится в памяти, пока приложение живо; при повторном входе тред открывается внизу.

## Разделители — `screens/chat-thread`

**Раскладка (замечание 7).** Чистая функция в `lib/` раскладывает тред в строки: сообщение или разделитель дня. Тред
лежит в порядке прихода, не времени (`ChatProvider.tsx:174`), поэтому разделитель ставится там, где локальный день
сообщения отличается от дня предыдущего, а **ключ — по первому сообщению под ним**: `day-<messageId>` (около полуночи
05 → 06 → 05 даёт три разделителя без повторного ключа). Локальные pending/failed датируются своим `sentAt`.
Приветствие без `sentAt` — под разделителем самого старого сообщения (пустой тред — под «Today»).

**«Сегодня».** `todayKey` (локальный `YYYY-MM-DD`) — в `model/use-today-key.ts`: таймер до следующей локальной полуночи
(календарной арифметикой — `setDate(+1)`, `setHours(0,0,0,0)`, не `+86 400 000`), обновление на `AppState 'active'`
и при сообщении с более поздним днём. В memo-строку разделителя `todayKey` идёт пропом; строка сама зовёт
`useTranslation` / язык (правило перевода для memo-строк).

**Подпись.** `dayLabel` в `shared/lib/dates.ts` рядом с `relativeDay`: `today` / `yesterday` / `dayMonthLabel` (этот
год) / новый `dayMonthYearLabel` (прошлые). Шаблон с годом — в генератор CLDR-таблиц
(`scripts/i18n/generate-formats.mjs` → `formats.generated.ts`, тот же Node 22.23.0 / ICU 78.2), `{y}` — в
`fillDatePattern`. Таблицу руками не правлю.

## Доступность (замечания 3, 8; решение владельца)

- **Порядок диктора — «сначала новое».** Данные и ячейки перевёрнутого списка идут от нового к старому
  (VirtualizedList переворачивает только ScrollView), VoiceOver и TalkBack идут по дереву: свайп ведёт от новых к
  старым, подпись дня звучит после сообщений своего дня. **Для чата это принято владельцем.**
- Разделитель — `accessibilityRole="header"`, подпись — сам день («Yesterday», «November 4, 2025»): диктор прыгает по
  дням заголовками.
- Подвал, пока `!reachedStart`, — **один постоянный View**, меняется только содержимое (индикатор ↔ строка повтора) —
  фокус не теряется. Индикатор — `accessibilityLabel` `history.loading`. Строка повтора — `accessibilityRole="button"`,
  подпись `history.failedLabel`, подсказка `history.retryHint`; ошибка объявляется
  (`AccessibilityInfo.announceForAccessibility`; Android — плюс `accessibilityLiveRegion="polite"`).
- Кнопка «вниз» — `accessibilityRole="button"`, подпись `jumpToLatest` или, с точкой, `jumpToLatestNew`.

## Строки (24 языка, глоссарий, `@max`)

- `shared:day.yesterday` — «Yesterday», `@max 18`. JSDoc `day.today` / `day.yesterday` дописываю: это и подпись дня в
  ленте треда.
- `chatThread:history.loading` — a11y индикатора: «Loading earlier messages».
- `chatThread:history.failed` — видимое: «Couldn’t load earlier messages · Tap to retry». По центру ленты, **две
  строки допустимы** (ширина ленты, не кнопка), `@max 70`.
- `chatThread:history.failedLabel` — a11y: «Couldn’t load earlier messages» (первые слова видимого).
- `chatThread:history.retryHint` — a11y-подсказка: «Loads them again» (результатом, без «Tap»).
- `chatThread:jumpToLatest` — «Go to the latest messages»; `chatThread:jumpToLatestNew` — «Go to the latest messages,
  new messages» (целой строкой, не склейкой).

## Проверка на устройстве (манор, iOS и Android)

1. Длинный тред открывается внизу.
2. Свайп до верха — страница без прыжка; куда встаёт фокус диктора, когда страница пришла.
3. Новое сообщение, пока читаешь старое (позиция стоит, точка на кнопке), и когда ты внизу (видно сразу).
4. Отправка, пока читаешь старое, — лента идёт к своему.
5. Клавиатура: кнопка «вниз» над полем; лента внизу и посередине.
6. Авиарежим наверху — без петли, строка не мигает, повтор нажатием.
7. Короткий тред с приветствием.
8. Порядок диктора, заголовки дней, действия прокрутки TalkBack / VoiceOver.
9. Веер таро внутри списка: горизонтальный жест; вертикальная прокрутка, начатая на веере; анимация высоты расклада
   (`SpreadStage.tsx:190-201`).
10. Часы через полночь — «Today» становится «Yesterday».

Главный риск — `maintainVisibleContentPosition` в перевёрнутом списке на Android; смотреть прицельно пп. 2–5.
