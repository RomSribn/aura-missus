# AURAT-0172-005 — spec: лента треда как в Telegram (подгрузка старых, разделители по дням)

Дата: 2026-11-06 · Status: **draft** — ждёт одобрения владельца
Слот `slave-3`, ветка `feature/AURAT-0172-app-chat-history-scroll` от `develop` @ `74755ee`. Только приложение;
веб — отдельно. Контракт не меняется (`HistoryQuery.before` уже есть, BFF отдаёт его как описано — `004-context`).

## Что получится

1. Тред открывается внизу, на последних сообщениях, без анимации прокрутки при входе.
2. Прокрутка вверх: когда до верха загруженного остаётся около экрана, подгружается следующая страница старых
   (`before=<самое старое серверное сообщение в треде>`, 50 штук). Позиция не прыгает. Сверху, пока страница идёт, —
   маленький индикатор загрузки. Запрос не удался — на его месте строка «Не удалось загрузить ранние сообщения ·
   Нажмите, чтобы повторить».
3. Начало истории: если страница пришла короче 50 — история кончилась, больше запросов нет; наверху появляется
   приветствие персоны (сейчас оно всегда первое — теперь только когда история действительно дочитана). Короткий тред
   (< 50) — как сейчас: всё сразу, приветствие наверху, ни одного лишнего запроса.
4. Вместо одной подписи «Today» — подпись над первым сообщением каждого дня: «Today», «Yesterday», дальше дата в
   формате языка — «November 4» / «4 November» / «4. listopadu»; не этого года — с годом («November 4, 2025»).
   День — по часовому поясу телефона. Выглядит как нынешняя подпись (по центру, 11.5, ink-3) — не как маркер сессии.
5. Новые сообщения:
   - внизу ленты — лента остаётся внизу, новое видно сразу (как сейчас);
   - человек читает старое — позиция не сбивается; новое ждёт внизу;
   - своё отправленное — всегда вниз, к нему.
6. **Решить владельцу** (Telegram делает оба):
   - **A. Плавающая дата.** Пока лента прокручивается, сверху по центру висит плашка с днём верхнего видимого
     сообщения; через ~1 с после остановки гаснет.
   - **B. Кнопка «вниз».** Отъехал от низа больше чем на экран — справа над полем ввода круглая кнопка со стрелкой;
     нажатие — к последним сообщениям. Без счётчика новых (счётчик — отдельная задача, если нужен).

## Как устроено

**Лента — `inverted` `FlatList`** (RN, не RNGH — правило 7 здесь не при чём, жестов в ленте нет). Стандарт чатов: низ —
нулевое смещение, подгрузка старых — дописывание в конец данных, позиция при этом не меняется сама.
`maintainVisibleContentPosition` (`minIndexForVisible: 0`, `autoscrollToTopThreshold` ≈ 80) держит место, пока
человек читает старое, и сам доводит до нового, если он внизу. `onContentSizeChange={scrollToEnd}` уходит — он и сейчас
дёргает ленту вниз на любое изменение размера. Индикатор/повтор сверху — `ListFooterComponent`, «печатает…» снизу —
`ListHeaderComponent` (в перевёрнутом списке они меняются местами).

**Данные — `features/chat`.** В `ChatProvider` у каждого треда — состояние истории `{ loadingOlder, reachedStart,
olderFailed }` и `loadOlder(advisorId)`:
- в полёте не более одного запроса на тред; `reachedStart` — больше не просим;
- страница проходит тот же фильтр, что и досинхронизация: дедуп по id (BFF на неизвестный `before` молча отдаёт
  новейшую страницу — дубли отсекаются) и `deletedServerIds` (удалённое не воскресает); кладётся **перед** всем, что
  есть (локальные pending/failed остаются в конце);
- курсор досинхронизации (`lastServerIds`) не трогается; `deletedFrom` досинхронизации и так берёт самое старое
  серверное — удаления в подгруженных страницах ловятся без нового кода;
- первая страница треда (без курсора) короче 50 → `reachedStart` сразу;
- пустой тред после неудачной первой синхронизации: `loadOlder` без серверных сообщений = обычная синхронизация.

Подгруженное держится в памяти, пока приложение живо (как в Telegram; при повторном входе тред снова открывается внизу).

**Разделители — `screens/chat-thread`.** Чистая функция в `lib/` раскладывает сообщения в строки ленты: сообщение или
разделитель дня (ключ `day-YYYY-MM-DD`, локальная дата). Приветствие без `sentAt` — под разделителем дня самого старого
сообщения (пустой тред — под «Today»). «Сегодня» пересчитывается при возврате приложения на передний план — тред,
открытый со вчера, не врёт. Строка-разделитель — `React.memo`, `renderItem` / `keyExtractor` стабильны (правило 5).
Подпись — `dayLabel` в `shared/lib/dates.ts` (рядом с `relativeDay`): `today` / `yesterday` / `dayMonthLabel` / новый
`dayMonthYearLabel`. Шаблон с годом добавляется в генератор CLDR-таблиц (`scripts/i18n/generate-formats.mjs` →
`formats.generated.ts`, тот же Node 22.23.0 / ICU 78.2), `{y}` — в `fillDatePattern`. Руками таблицу не правлю.

**Смена языка (`AURAT-0169`).** 0169, скорее всего, вливается раньше; тогда я вливаю `develop` и подключаю: при смене
языка тред **обрезается до новейшей страницы** (`reachedStart` сбрасывается, если что-то обрезано), и перечитывание
0169 этой страницей с `replaceSpreads` покрывает всё, что осталось. Старые страницы подгрузятся заново уже на новом
языке, когда человек прокрутит. Обход всех подгруженных страниц `before`-курсорами не нужен. Если первой вольётся
0172 — то же правило записываю для 0169.

## Строки (24 языка, глоссарий, `@max`)

- `shared:day.yesterday` — «Yesterday» (`@max 18`, как `today`).
- `chatThread:history.loading` — a11y-подпись индикатора: «Loading earlier messages».
- `chatThread:history.failed` — «Couldn’t load earlier messages · Tap to retry» (одна строка, как `file.failed`).
- если B: `chatThread:jumpToLatest` — a11y-подпись кнопки «вниз»: «Go to the latest messages».

Текст плашки A — та же подпись дня, новых строк не нужно.

## Тесты

- `lib`: раскладка по дням (смена дня, полночь, DST, приветствие, пустой тред, локальные сообщения — сегодня);
  `dayLabel` по языкам, год.
- `ChatProvider`: `before` = самое старое серверное; дедуп; удалённое не возвращается; `reachedStart` по короткой
  странице и по первой странице; один запрос в полёте; ошибка → `olderFailed`, повтор; курсор `after` не сдвинут.
- Экран: разделители вместо «Today»; приветствие только при `reachedStart`; индикатор / повтор сверху; отправка ведёт
  вниз.
- Всё в слоте: lint, typecheck, jest. **Живая проверка — в маноре** на обеих платформах: `maintainVisibleContentPosition`
  в перевёрнутом списке на Android — главный риск, смотреть прицельно (подгрузка, новое сообщение во время чтения
  старого, клавиатура).

## Не в этой задаче

- Счётчик новых на кнопке «вниз», «перейти к первому непрочитанному», поиск по треду.
- Досинхронизация после долгого офлайна: `after` берёт одну страницу (50); остальное приходит со следующим триггером.
  Было и до этой задачи; подгрузка старых его не трогает. Если нужно — отдельная мелкая задача (качать `after`, пока
  страница полная).
- Веб.
