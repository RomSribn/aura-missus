## План проверки (`005`, «Проверка в маноре»), уточнённый

Восстановление идёт **в отдельную базу `restore_0073`** на dev-сервере
Postgres, а не поверх живой `aura_bff`. Путь кода тот же (`--journal` против
базы, снятой до удаления), а тестовые данные dev не теряются.

0. Найти dev-контейнеры: BFF по ресурсу `mtnsnawmogikfwm0uvl1g1yc`, Postgres
   по хосту из его `DATABASE_URL`. Убедиться, что на этом сервере нет базы
   `chatwoot`, то есть это не прод.
1. `pg_dump -Fc` базы `aura_bff` до удаления.
2. Удалить тестовый аккаунт из приложения (staging-сборка → `bff-dev`). Затем:
   `account_erasures` (`source = APP`, через ~6 мин `completedAt`); объект
   `erasures/<время>_<userId>.json` в бакете, в теле три поля; в логе нет
   `erasure journal write failed`.
3. `CREATE DATABASE restore_0073 OWNER aura`, `pg_restore` от роли `aura`;
   аккаунт в `restore_0073` живой.
4. `--journal` в контейнере BFF с `DATABASE_URL`, направленным на
   `restore_0073`: аккаунт → `erased`, код выхода 0, в базе надгробие. Побочно
   джоба уйдёт в dev Redis, живая база записи не найдёт, и джоба ничего не
   сделает.
5. `--user` по второму тестовому аккаунту на живом dev → объект с
   `"source":"operator"`.
6. Убрать `restore_0073` и дамп (в нём личные данные тестовых аккаунтов).
