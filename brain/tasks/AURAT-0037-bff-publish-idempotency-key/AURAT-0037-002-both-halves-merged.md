# AURAT-0037-002 — Обе половины замержены, приёмка в поле не пройдена

Дата: 2026-08-21
Записано из: `aura-app-manor` (проверка состояния, не исполнение)

## Что есть в коде

**BFF** — `aura-bff`, `develop`, синхронен с origin:

- `b0d0ac2 feat(chat): return the idempotency key, and only on messages we sent`
- `fc62f29 Merge feature/AURAT-0037-bff-publish-idempotency-key` (17:10 +0200)

Оговорка «and only on messages we sent» — ровно то, что просила постановка:
`null` для всего, что пришло от чаттера.

**Контракт** — `@aura/contracts` v0.11.0, тег запушен: `Message.idempotencyKey`
nullable с `.default(null)`.

**Приложение** — `aura-app`, `develop`, синхронен с origin: `mapMessage`
переносит ключ в модель, `mergeServerMessages` вычитает из треда локальные
ожидающие копии, чьи ключи вернулись опросом. Оба замержены в составе
`AURAT-0036`.

## Чего нет

**Приёмки на устройстве.** Единственный прогон — авиарежим посреди отправки —
владелец гонял **до** мёржа половины BFF, и тогда он показал ровно тот симптом,
из-за которого задача и заведена. Повторить на развёрнутом BFF:

> отправка при выключенной сети, доехавшая до Chatwoot: после возврата сети
> сообщение появляется, и «Not delivered» исчезает **само**, без нажатия. В
> Chatwoot по-прежнему один файл.

Отдельно неизвестно, крутится ли на проде сборка с `fc62f29`: деплой у BFF
ручной, `feature/AURAT-0029-aws-deploy` до сих пор не замержена. Пока код не
развёрнут, приложение видит старый ответ и ведёт себя по-старому — это не баг
приложения.
