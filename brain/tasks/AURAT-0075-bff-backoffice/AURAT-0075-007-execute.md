## Что сделано

Раздел `/backoffice` на хосте BFF по спеке `005` с ответами `006`: учётки в
базе и CLI, полная модерация.

**Вход.** Таблица `backoffice_operators` (миграция
`20260917120000_backoffice_operators`, только новая таблица). Команда
`backoffice:operator -- add|reset|remove|list`, пароль генерируется (24 знака,
без похожих символов) и печатается один раз; в базе — scrypt
(N=2^15, r=8, соль на учётку, параметры в строке хэша). Сессия — 32 случайных
байта в cookie `aura_backoffice` (`HttpOnly`, `SameSite=Lax`, `Secure` на
задеплоенных, `Path=/backoffice`), в Redis — sha256 токена → оператор, 12 часов
без продления. Сброс пароля или удаление учётки гасит сессии на следующем
запросе: в сессии лежит отпечаток хэша пароля.

**Отзывы.** `ReviewModerationModule` (отдельно от `ReviewsModule`, чтобы CLI не
тянул auth/chat/Chatwoot) — сервис + репозиторий:
- очередь как у `reviews:pending`;
- «Остальные» — написанные в приложении, кроме очереди, по 50;
- решение по тексту — условный `updateMany` по состоянию, которое показала
  страница (`expected`), и только для непустого текста;
- скрыть/вернуть — условный `published` + пересчёт в одной транзакции.

Пересчёт вынесен в `recount-advisor.ts` и общий с `upsertAndRecount`.
`reviews-moderation.ts` переписан на `OperatorCliModule` + тот же сервис;
команды и вывод прежние.

**Удаления.** `ErasureReportService` в `AccountModule`: сводка (всего, 7/30
дней, источники, не завершено, «застряло» > 1 ч) и список по 50 с фильтром.
Проекция `ErasureReportRow` без `firebaseUid` и `chatwootContactId` — на уровне
типа.

**Страницы.** HTML собирается на сервере тегом `html`: он экранирует всё, и
сырой вставки нет вовсе. CSS — токены `theme.ts`. Шрифты — 5 начертаний

отдаются страницей, без сессии — 303 на вход. Все страницы идут с `no-store` и
`noindex`.

Превью обеих ширин сняты headless Chrome со статических страниц на тестовых

## Отступления от спеки `005` (решено по ходу, стоит глянуть)

1. **`SameSite=Lax`, а не `Strict`.** Strict не отправляет cookie при переходе
   по ссылке с другого сайта: ссылка из веб-мессенджера каждый раз вела бы на
   вход. Подделку POST закрывают Lax (cross-site POST без cookie) и проверка
   `Sec-Fetch-Site`/`Origin` на каждом POST, включая форму входа.
2. **POST без сессии → 303 на вход, а не 403.** Истекла сессия, нажал
   «Опубликовать» — попадаешь на вход, ничего не выполнено. Чужой `Origin` —
   по-прежнему 403.
3. **Блокировка входа — свой счётчик в Redis, а не `@fastify/rate-limit`.**
   Считаются только неудачи: 10 за 15 минут с адреса, дальше страница «через
   N минут» и `Retry-After`. Адрес в ключе захэширован. Через плагин ответ был
   бы JSON-ом, а не страницей.
4. **`recountAdvisor` берёт `FOR UPDATE` на строку советника до SUM.** Без этого
   параллельные «скрыть» и «отправить отзыв» могли бы записать устаревшую пару
   чисел. Порядок блокировок прежний (строка отзыва → советник: раньше этот
   замок брал `advisor.update`), так что новых дедлоков нет.
5. **`reviews:pending <что-то>`** теперь отказ, раньше лишний аргумент
   молча игнорировался.
6. **`.prettierrc`: для `src/modules/backoffice/views/*.ts` выключен
   `embeddedLanguageFormatting`.** Prettier переформатировал разметку внутри
   `html`-шаблонов и вставил пробелы в `<blockquote>` с `pre-wrap` — упали 6
   тестов. Шаблоны восстановлены.
