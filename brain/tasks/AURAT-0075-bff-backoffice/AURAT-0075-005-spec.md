## Коротко

Раздел `/backoffice` на том же хосте, что API:
`https://bff-dev.aura-app.cc/backoffice` на dev, адрес прод-BFF — в проде. Две
вкладки: **«Отзывы»** — модерация текста кнопками вместо `reviews:*`, и
**«Удаления»** — список удалённых аккаунтов без личных данных, только чтение.
Вход по логину и паролю. Регистрации на странице нет: учётку заводит владелец
командой в терминале контейнера. Вёрстка — палитра и шрифты `aura-app`,
компьютер и телефон. JavaScript на странице нет.

## 1. Доступ

**Адрес.** `/backoffice` без версии (`VERSION_NEUTRAL`), как `/health`. Под
`/v1` раздел не кладём: там API устройства. В Swagger раздел не попадает
(`@ApiExcludeController`).

**Учётки (вопрос Q1, рекомендация — A).** Таблица `backoffice_operators`:
`id`, `login` (уникальный), `passwordHash` (scrypt из `node:crypto`, своя соль
на каждую учётку), `createdAt`. Экрана управления учётками нет: заводит,
сбрасывает и удаляет их только команда.

```
npm run backoffice:operator -- add <login>     # печатает пароль один раз
npm run backoffice:operator -- reset <login>   # новый пароль, старые сессии гаснут
npm run backoffice:operator -- remove <login>
npm run backoffice:operator -- list
```

В проде та же команда запускается как `node dist/backoffice-operators.js …`,
как `account:erase`. Пароль генерирует команда (24 символа): аргумент попал бы
в историю shell, а придуманный вручную оказался бы слабее.

**Сессия.** Случайный токен (32 байта) в cookie `aura_backoffice` с флагами
`HttpOnly`, `SameSite=Strict`, `Path=/backoffice` и `Secure` на всех
задеплоенных окружениях. В Redis лежит `sha256(токен) → operatorId`. Срок
12 часов от входа, не продлевается. Выход удаляет запись. Если учётку удалили
или сбросили пароль, сессия умирает на следующем запросе.

**Защита.**
- Глобальный Firebase-guard для раздела выключен (`@Public()`), вместо него
  работает свой guard сессии. Без сессии `GET` отвечает 303 на
  `/backoffice/login`, `POST` — 403.
- `POST` принимается, только если `Origin` (или `Sec-Fetch-Site`) указывает на
  свой хост. Это вторая защита от CSRF вдобавок к `SameSite=Strict`.
- На вход — не больше 10 попыток за 15 минут с одного адреса
  (`@fastify/rate-limit` на маршрут). Неверный логин и неверный пароль дают
  один и тот же ответ. Для несуществующего логина хэш тоже считается, чтобы
  время ответа не выдавало, есть ли такая учётка.
- Ответы раздела: `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`.
  CSP helmet не меняется.

**Логи.**
- Заголовок `cookie` вырезается из лога запросов. Сейчас pino пишет заголовки
  целиком, и токен сессии попал бы в лог.
- Действия пишутся как `backoffice review moderated` с полями `reviewId`,
  `operatorId` и решением. Текста отзыва, логина и пароля в логе нет.
- Неудачный вход пишется `warn` без полей.

**Не делаем:** 2FA, роли, смену пароля и восстановление доступа на странице.

## 2. Отзывы

**«Ждут»** — то же, что `reviews:pending`: `quoteStatus = PENDING`,
`published = true`, сначала самые старые правки.

Карточка показывает:
- советника по имени;
- звёзды;
- сколько текст ждёт, считая от последней правки. Больше 24 часов — метка
  coral «дольше суток»;
- подпись в том виде, в каком она выйдет: имя или `Anonymous` с пометкой
  «анонимно»;
- текст целиком, с переносами строк.

Кнопки: **«Опубликовать»** и **«Отклонить»**. Правила те же, что у CLI:
- меняется только строка в `PENDING`. Если её уже решили (другой оператор или
  CLI), страница показывает «уже решено» и ничего не меняет;
- отклонение молчаливое, агрегаты не трогаются (`AURAD-0014`).

**Вопрос Q2, рекомендация — полный вариант:**
- **«Решённые»** — отзывы, написанные людьми (`source = USER`), с непустым
  текстом в `PUBLISHED` или `DECLINED`, новые сверху, по 50 на страницу. Решение
  можно переключить: опубликованный текст отклонить, отклонённый опубликовать.
  Автору по-прежнему ничего не приходит.
- **«Скрыть отзыв» / «Вернуть»** — `published = false/true`. В той же
  транзакции пересчитываются `ratingTenths` и `reviewsCount` советника тем же
  SUM/COUNT, что в `upsertAndRecount`. Это `reviews:hide` из `AURAT-0067-013`.
  Скрытая оценка уходит из рейтинга, и число на профиле меняется. Повторная
  отправка отзыва автором скрытие не отменяет: так уже устроен upsert.

**CLI остаётся** и работает через тот же сервис: одна реализация, а не две. Как
`account:erase`, CLI поднимает `OperatorCliModule`. Команды и их вывод не
меняются. Шапка `reviews-moderation.ts` («no interface, by the owner's
decision») и `AURAD-0014` получают дополнение со ссылкой сюда.

## 3. Удаления

Данные берутся только из `account_erasures`. В `users` страница не ходит, в
R2 тоже.

**Сводка:**
- всего удалено, за 7 и за 30 дней;
- откуда пришёл запрос: из приложения, от оператора, «не записано» (удаления
  до `AURAT-0073`);
- сколько не завершено. Отдельно — «застряло»: не завершено дольше часа. Обычно
  удаление завершается за ~5,5 минуты (`IN_FLIGHT_GRACE_MS` + 30 с), так что
  час без завершения — это сбой, который сейчас виден только по `warn` sweep.

**Список:** новые сверху, по 50 на страницу, фильтр «все / не завершённые».
Колонки:
- id пользователя — надгробие, моноширинным шрифтом; именно его принимает
  `account:erase -- --user`;
- когда запрошено, в UTC;
- источник;
- статус: «завершено за N мин» (teal), «в процессе» или «застряло» (coral).

**Не показываем:** `firebaseUid` (хранится до завершения), `chatwootContactId`,
телефон, имя.

Журнал R2 не читаем. `completedAt` ставится только после записи в журнал, так
что «завершено» уже значит «в журнале».

**Действий на вкладке нет.** Удаление по просьбе и повтор из журнала остаются
командами `account:erase`.

## 4. Вёрстка

- HTML собирается на сервере, стили — один CSS-файл. Скриптов и сборщика нет.
- Действие — это форма `POST`, после неё 303 на `GET` той же вкладки с
  сообщением «опубликовано» и т. п.
- Всё, что подставляется в шаблон, экранируется тегом `html` по умолчанию.
  Текст отзыва — чужой ввод, и ни одна ветка шаблона не вставляет его сырым.
- Дизайн-код `aura-app`. Токены `theme.ts` переносятся в CSS-переменные:
  - фон `paper`, карточки белые, радиус 22;
  - текст `ink` / `ink2` / `ink3`, линии — `line` / `line2`;
  - основное действие — `accent` (coral), «опубликовано» и «завершено» —
    `teal`, звёзды — `gold`;
  - шапка и экран входа — plum-градиент;
  - шрифты: заголовки Bricolage Grotesque, текст Hanken Grotesk. Файлы с OFL
    копируются из приложения (4 начертания, ~400 КБ) и отдаются самим BFF, без
    Google Fonts.
- **Компьютер:** шапка с логотипом «aura», вкладками и «Выйти». Контент
  шириной до ~960 px. Удаления — таблицей.
- **Телефон (< 720 px):** вкладки внизу, как таб-бар приложения. Таблица
  превращается в карточки, кнопки растягиваются на всю ширину.

## 7. Деплой

Миграция накатывается сама при старте контейнера. Переменные Coolify не
меняются. После релиза в `main` владелец заводит учётку на проде той же
командой.

## Вопросы владельцу

- **Q1 — как входить.**
  - **A** *(рекомендую)*: учётки в базе, заводятся командой, свой экран входа.
  - **B**: список `логин:хэш` в переменной Coolify. Без таблицы, но новая
    учётка или сброс пароля требуют редеплоя.
  - **C**: HTTP Basic Auth из переменной. Окно браузера вместо экрана входа,
    выйти нельзя, одна общая учётка.
- **Q2 — объём модерации.**
  - «Ждут» + «Решённые» с переключением + скрыть/вернуть *(рекомендую)*;
  - «Ждут» + «Решённые» без скрытия;
  - только «Ждут», как CLI.
