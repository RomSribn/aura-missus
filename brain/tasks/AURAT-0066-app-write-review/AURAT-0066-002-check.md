# AURAT-0066-002 — что уже есть в brain и в коде

Дата: 2026-09-08

## В brain

Свежей папки под «оставить отзыв» нет — задача новая. Но фича **предусмотрена
заранее** и это самая ценная находка проверки:

- `features/AURAF-0014-advisor-reviews/` — отзывы на профиле (показ). Статус:
  обе половины влиты (`AURAT-0058` сервер, `AURAT-0059` приложение). В разделе
  «Чтобы фаза 2 не потребовала переписывать смысл строк» **прямым текстом
  описана эта задача**: три колонки (`source`, `published`, `sessionId`+`userId`)
  заведены заранее, и названа предполагаемая форма фазы 2 —
  `POST /v1/sessions/:id/review`, пересчёт агрегатов на записи, роут с
  пагинацией, экран-предложение после сессии.
- Строки `AURAF-0014-006` («человек оставляет отзыв после оплаченной сессии»)
  и `-007` («модерация и жалобы») помечены «не в v1, фаза 2» — их закрывает
  эта работа, и таблицу scope в `AURAF-0014` надо будет обновить.
- `AURAT-0013` D5/D6 — откуда взялись `ratingTenths` / `reviewsCount` и почему
  тинт монограммы остаётся на клиенте.
- `AURAD-0011` — вложения выдаются только внутрь переписки. Отзывов не
  касается, но объясняет, почему в контракте `AdvisorReview` нет ни аватара,
  ни ссылок.
- Прецедент раздачи серверной половины в другой манор: `AURAT-0064` /
  `AURAD-0013` (фотография профиля) и `AURAT-0058` (сервер отзывов).

## В коде приложения (ground truth, ветка `develop` = 67d235f)

Показ отзывов построен и живой:

- `entities/advisor` — `Advisor.reviews[]` приезжает внутри `GET /v1/advisors`;
  `AdvisorReview` принадлежит `@aura/contracts` (сейчас `v0.17.0`).
- `screens/advisor-profile/ui/ReviewCard.tsx` — карточка отзыва;
  `AdvisorProfileScreen.tsx:104` — секция «Reviews» (заголовок без ссылки);
  `StatsCard.tsx` — три ячейки, «—» вместо «0.0» у советника без отзывов.
- `shared/ui/stars` — `Stars` (только показ, не ввод).

Приёма отзывов нет нигде: ни экрана, ни роута, ни состояния. Grep по `review`
в `src/` даёт только показ и `SCREENS.BOOK_REVIEW` — **это шаг подтверждения
брони, а не отзыв**; имя занято, новый экран назвать так нельзя.

## В схеме BFF (`aura-bff`, `prisma/schema.prisma:378`)

```prisma
model AdvisorReview {
  id String @id            // рукописный у засеянных ("olivia-01")
  advisorId String
  authorName String        // только имя, никогда хэндл
  quote String
  ratingTenths Int
  source AdvisorReviewSource @default(SEED)
  published Boolean @default(true)
  sessionId String? @unique   // «отзыв за оплаченную сессию, один на сессию»
  userId String?
  sortOrder Int @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  @@index([advisorId, published, sortOrder])
}
```

42 засеянных строки на восьмерых советников, `ratingTenths` / `reviewsCount`
в `advisors` — агрегаты по этим строкам (`AURAF-0014`).

## Первое противоречие, найденное на этом шаге

Заготовка `sessionId @unique` выражает правило **«один отзыв на оплаченную
сессию»**. Новый дизайн (`REVIEWS.md` §0 и §4) требует другого правила:
право на отзыв даёт **любая переписка, платная или бесплатная**, и отзыв
**один на пару (человек, советник)**, а повторная отправка его **правит**.

Это не деталь — это разные ключи уникальности. Разобрано в `004-context`.
