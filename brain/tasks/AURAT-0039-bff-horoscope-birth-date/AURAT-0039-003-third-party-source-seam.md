# AURAT-0039-003 — Q1: сторонний сервис, и какой шов под него оставить

Дата: 2026-08-25
Отвечает на: Q1 из `AURAT-0039-001` («откуда берётся текст прогноза»)
Статус: **направление выбрано, решение не ратифицировано.** Владелец
2026-08-25: «планирую использовать 3rd party сервис для получения данных о
гороскопе, пока оставь возможность для интеграции. Думаю за Kerykeion, по идее
будет отдавать текст вида "Солнце в Овне, Луна в 5-м доме, угол между Марсом и
Венерой 90 градусов"». Строить интеграцию **сейчас не нужно** — нужен шов.

## Что такое Kerykeion на самом деле (проверено 2026-08-25)

Две разные вещи под одним именем, и для нас они противоположны:

| | Что это | Нам |
|---|---|---|
| `kerykeion` | **Python-библиотека** на Swiss Ephemeris. **AGPL-3.0**: «If you import this library directly into a project, that project should be open-sourced under a compatible license» | **Не подходит дважды.** BFF — NestJS/TypeScript, импортировать питон в него нечем; и AGPL на закрытом продукте — это отдельный разговор с владельцем, а не деталь реализации |
| **Astrologer API** | Хостинг того же движка по REST (RapidAPI), автор тот же. Репозиторий прямо говорит: «Using the hosted API via RapidAPI is allowed in any app, including closed-source since is a third-party service» | **Это и есть «3rd party сервис»** из формулировки владельца. Юридически чисто, по стеку нейтрально |

Если когда-нибудь возникнет мысль «поднимем kerykeion у себя, чтобы не платить»
— это будет питон-сайдкар рядом с NestJS **плюс** AGPL на сетевой сервис.
Названо здесь, чтобы не открывать заново.

## Главное: сервис отдаёт данные, а не текст

Владелец описал вывод точно — «Солнце в Овне, Луна в 5-м доме, угол между
Марсом и Венерой 90 градусов». Это буквально то, что возвращает API, и это
**не гороскоп**. Карточка на Home показывает абзац прозы («The cards favour
quiet courage today…»), а API возвращает только структуру: положения, дома,
аспекты, плюс SVG. Прозы нет ни в одном эндпоинте.

Причём сам вендор это не скрывает: у него есть отдельный эндпоинт **«AI Context
XML — structured output ready for GPT/Claude prompts»**. То есть ответ автора на
вопрос «а где текст» — «скормите это LLM».

**Следствие: источник прогноза — двухступенчатый.** Ступень 1 — расчёт (сторонний
сервис). Ступень 2 — превращение расчёта в читаемый абзац (шаблоны или LLM), и
её всё равно придётся выбрать отдельно. Q1 в `001` этим **не закрыт**, он
разделился надвое: ступень 1 выбрана, ступень 2 — нет.

## Это ломает критерий приёмки из `001`

В `001` записано: «два разных пользователя с одним знаком в один день получают
идентичный текст», и кэш по паре (знак, дата). **Для натальной карты это
неверно**: карта индивидуальна, значит и прогноз индивидуален, и два Близнеца
получат разные тексты — законно.

Развилка, которую придётся пройти до кода:

- **Прогноз по знаку** (12 текстов в сутки). Кэш по (знак, дата), критерий `001`
  остаётся, сторонний сервис вызывается 12 раз в сутки, дата рождения нужна
  только чтобы определить знак. Дёшево.
- **Прогноз по натальной карте** (текст на пользователя). Критерий `001`
  **отменяется** и заменяется на «одинаковый вход даёт одинаковый выход», кэш по
  (пользователь, дата). Дороже во всём, но это то, ради чего вообще берут
  Kerykeion — иначе платить за эфемериды незачем.

Пока развилка не пройдена, **приёмку `001` про «одинаковый текст у одного знака»
считать недействительной**.

## И это упирается во ввод, который делается прямо сейчас

Проверено по документации API: обязательны **год, месяц, день, час, минута** плюс
**место** (координаты либо город/страна) — валидация строгая, запрос без
компонентов времени отклоняется.

А владелец просил собирать **дату рождения**. Дома («Луна в 5-м доме») и
асцендент без времени и места **не вычисляются в принципе** — это не «менее
точно», это неопределено. `AURAT-0041` (slave-0) строит сейчас шит ввода
**только даты**.

Решать это сейчас не нужно (владелец сказал «пока»), но зафиксировать надо:
**день рождения без времени и места поддерживает только знак Солнца и транзиты
к нему** — то есть автоматически ветку «прогноз по знаку». Ветка «по натальной
карте» требует спросить у пользователя ещё время и место рождения, а это другой
экран, больше трения на онбординге и больше персональных данных.

## Какой шов оставить (это и есть работа по этому шагу)

1. **Источник — за портом, как Chatwoot.** В этом сервисе уже есть ровно такой
   прецедент и он возведён в жёсткое правило 1: «Chatwoot is sealed in the
   chatwoot module… the adapter translates, Chatwoot stays swappable». Источник
   прогноза запечатать так же: интерфейс в модуле гороскопа, реализация —
   отдельно. v1 живёт на любой заглушечной реализации, сторонний сервис
   подключается заменой реализации, **не трогая ни маршрут, ни контракт, ни
   приложение**.
2. **Контракт не должен знать про поставщика.** `HoroscopeResponse` остаётся
   `{ sign, entries: [{ date, text }] }`. Ни аспекты, ни дома, ни SVG в него не
   протекают. Захотим позже показывать детали карты — добавочно и nullable, как
   `width` / `height`.
3. **Схему не «готовить заранее».** `users.birthDate` остаётся **date**. Время и
   место, если понадобятся, приходят **отдельными nullable колонками**
   (`birthTime`, координаты + IANA-зона), а не превращением даты в timestamp:
   дата рождения — это дата, и timestamptz здесь соврёт про то, чего мы не
   спрашивали.
4. **Кэш — уже сейчас, и с расчётом на ступень 2.** Натальная карта для
   пользователя **неизменна**: считается один раз и хранится, ежедневно
   пересчитываются только транзиты. Это разница между «один вызов на
   пользователя в сутки» и «вызов на каждое открытие Home».
5. **Ключ RapidAPI — секрет из окружения, валидируемый на старте** (жёсткое
   правило 3), и **отсутствие ключа не должно ронять сервис**: без него маршрут
   отвечает как «источника нет», а не 500.

## Что это добавляет в AURAT-0040

Отправка даты (а тем более времени и места) рождения в сторонний сервис — это
**передача персональных данных третьей стороне**, и её нужно назвать в политике
приватности и в декларации Data Safety в Play. Отдельно стоит проверить
юрисдикцию: EU выбрана осознанно (`AURAD-0005`, дампы в R2 EU), а RapidAPI — нет.
И в запрос **не класть ничего опознающего**: у API есть поле `name`, оно нам не
нужно.

## Когда минтить AURAD

Когда пройдены обе развилки — «по знаку или по карте» и «ступень 2: шаблоны или
LLM». Сейчас решение неполное, и файл решения с половиной ответа хуже, чем его
отсутствие. ID минтится из `aura-app-manor`.
