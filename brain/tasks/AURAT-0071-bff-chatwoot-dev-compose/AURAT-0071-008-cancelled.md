# AURAT-0071-008 — Отменена

Дата: 2026-09-14
Статус: **отменена**

## Причина

Владелец изменил решение (передано из `aura-app-manor`, будет записано как
`AURAD-0016`). Chatwoot остаётся **один**: production, ветка `main`,
`chat.aura-app.cc`. Dev получает в нём **свой аккаунт** «Aura Dev» со своим
inbox и сервисным пользователем. Изоляцию даёт граница аккаунта: Chatwoot API
пускает токен только в аккаунты, где состоит пользователь, а контакты
принадлежат аккаунту. Второго экземпляра не будет, так что задача этой ветки —
развести два экземпляра в сети `coolify` — больше не нужна.
`deploy/coolify/chatwoot.compose.yml` не меняется.

## Что успели сделать (в `develop` не попало)

- Спека одобрена (`005`, `006`), исполнение описано в `007`.
- Коммит `4aeaecc` на `feature/AURAT-0071-bff-chatwoot-dev-compose`
  (`aura-bff`), **не смёржен и не запушен**. В нём: `CW_RAILS_ALIAS` /
  `CW_FRONTEND_URL` с прод-умолчаниями в compose, обязательный
  `AURA_WEBHOOK_URL` в `provision-prod.rb`, комментарии под два экземпляра.

## Что остаётся полезным знанием

- Как Coolify 4.3.19 обрабатывает compose (`004`): `networks` сервиса
  переносится без изменений, `${…}` раскрывает `docker compose --env-file .env`,
  в панели автоматически появляются только переменные из `environment:`,
  а `:?` ломает шаг сборки.
- Дефолт `AURA_WEBHOOK_URL=http://bff:3000/…` в `provision-prod.rb` никогда не
  работал. Правка ушла вместе с отменённой веткой. Для аккаунта «Aura Dev»
  адрес webhook всё равно нужно передать явно. Скрипт берёт **первый**
  аккаунт, если не задан `AURA_ACCOUNT_ID`, поэтому для dev-аккаунта его нужно
  задавать.
