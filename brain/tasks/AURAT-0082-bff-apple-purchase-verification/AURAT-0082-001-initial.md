# AURAT-0082-001 — Проверка покупок Apple и начисление кредитов

Дата: 2026-09-25
Статус: **заведена, не начата**
Репозиторий: `aura-bff` (`aura-bff-manor`). Заведена из `aura-app-manor` при
подготовке релиза в App Store (`AURAT-0079`).
Решение: `AURAD-0017`. Приложение — `AURAT-0081`.

## Что есть и чего нет

Есть рельс Google: `POST /v1/wallet/top-ups/google` спрашивает у Play про
`purchaseToken`, сверяет `obfuscatedExternalAccountId` с `purchaseAccountId`
кошелька, берёт сумму из своей таблицы тиров и пишет одну запись в журнал денег
(`AURAT-0027`); возврат списывает кредиты компенсирующей записью
(`AURAT-0077`). Apple не умеет ничего из этого.

## Часть 1 — начисление

`POST /v1/wallet/top-ups/apple`, тело `{transactionId, productId}` — ни суммы,
ни bundle id, по тем же причинам, что и на Play.

Сервер спрашивает **App Store Server API**
(`GET /inApps/v1/transactions/{transactionId}`), а не верит подписи, присланной
приложением. Начислять только если сходится всё:

| Проверка | Отказ |
|---|---|
| Подпись JWS проверяется до корня Apple, `bundleId` = `cc.silvermind.aura` | 400 |
| `productId` есть в таблице тиров сервера (сумма — оттуда) | 400 |
| `appAccountToken` = `purchaseAccountId` вызывающего | 409 |
| Тип — расходуемая покупка, не отозвана | 409 |
| `transactionId` не выкупался раньше | повтор: тот же баланс, новых записей нет |

Таблица тиров — **одна на оба магазина**: идентификаторы продуктов совпадают
(`aura.topup.usd10 / usd25 / usd50 / usd100`), рельс различается ручкой, а не
идентификатором.

**Два окружения.** Покупка из TestFlight и у песочного тестировщика живёт в
песочнице Apple, из магазина — в проде. Порядок Apple: спросить прод, при
промахе спросить песочницу. Не флаг сборки — иначе сборка для TestFlight
окажется сборкой, которая в проде не начисляет ничего.

## Часть 2 — возвраты

App Store Server Notifications V2: ручка для Apple, проверка подписи
уведомления, `REFUND` → компенсирующая запись в журнале (баланс может уйти в
минус), `REFUND_REVERSED` → обратно. Ровно та же форма, что `AURAT-0077` сделал
для Play; различается только источник события.

URL уведомлений ставится в App Store Connect на **прод и на песочницу
отдельно**.

## Доступ к App Store Server API — есть

Ключ **In-App Purchase** создан владельцем 2026-09-30:

| Что | Значение |
|---|---|
| Key ID | `CSNPA77W6Y` |
| Issuer ID | `9bc0ba73-046e-410f-9499-ecfedfebab2a` — **тот же**, что у ключа загрузки сборок; отдельного issuer у In-App Purchase нет |
| Файл | `~/.appstoreconnect/private_keys/SubscriptionKey_CSNPA77W6Y.p8`, права `600`, в репозитории его нет |
| Токен | ES256, заголовок с `kid`, тело с `iss`, `iat`, `exp`, `aud: appstoreconnect-v1` и **`bid: cc.silvermind.aura`** — последнее отличает токен для Server API от токена для App Store Connect API |

**Проверено в маноре 2026-09-30**, `GET /inApps/v1/transactions/0`:

| Хост | Ответ |
|---|---|
| `api.storekit-sandbox.itunes.apple.com` | `400 {"errorCode":4000006,"errorMessage":"Invalid transaction id."}` — **ключ принят**, ошибка про сам идентификатор |
| `api.storekit.itunes.apple.com` | **`401`, тело пустое** |

**Ловушка на 401 в проде.** Приложение ни разу не продавалось, и прод-хост
Server API отвечает на такой ключ `401`. Это **не** признак неверного ключа и
не повод чинить подпись: порядок «спросить прод, при промахе спросить
песочницу» (`AURAD-0017`) должен считать `401` от прода такой же «не здесь»,
как и `404`, — иначе сборка из TestFlight будет валиться с ошибкой
конфигурации там, где всё настроено правильно. Пересмотреть после первой
реальной продажи.

## Что ещё нужно от владельца

- **Paid Applications Agreement** — без него покупки не продаются вовсе.
  На 2026-09-30 в состоянии `Processing`: банк (Wise, бельгийский IBAN на
  Silvermind OÜ) и обе налоговые формы США поданы и `Active`.
- **Песочный тестировщик** (Users and Access → Sandbox) для прогона.

Идентификаторы, которые уже есть: приложение `6813629245`, bundle id
`cc.silvermind.aura`, продукты созданы 2026-09-25 (`AURAT-0079-004`).

## Чем считать сделанным

- Покупка в песочнице начисляет ровно один раз; повтор не начисляет.
- Чужой `transactionId` (с другим `appAccountToken`) — отказ, и в журнале
  ничего.
- Неизвестный `productId` — отказ до того, как база тронута.
- Уведомление о возврате списывает ровно ту сумму, что была начислена.
- Прогон по обоим окружениям: песочница через TestFlight, прод — после релиза.
