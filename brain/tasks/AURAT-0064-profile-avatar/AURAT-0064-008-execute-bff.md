# AURAT-0064-008 — Этап B: сервер

Дата: 2026-09-08
Ветка: `feature/AURAT-0064-profile-avatar` (slave-2). **Не закоммичено.**

Контракты `v0.17.0` запушены тегом `7a8d71a` (гейт 1 пройден).

## Проверки

`tsc --noEmit`, `eslint`, `nest build` — чисто. **819 тестов** (было 749).

## Что построено

**Схема.** Три колонки в `users`: `avatarId`, `avatarKey`, `avatarContentType`,
все `TEXT NULL`, индексов нет. Миграция `20260908160000_user_avatar` написана
руками и **сверена с канонической** через
`prisma migrate diff --from-empty --to-schema` — совпала по именам и типам.

**Общий слой.** `attachment-sniffer.ts` переехал в
`src/common/media/content-sniffer.ts`: второй потребитель появился, а импорт из
`modules/chat` в `modules/profile` связал бы две фичи через голову общего слоя.
Рядом — `image-dimensions.ts`: ширина и высота из заголовка JPEG/PNG/WebP без
декодирования, ~60 строк, руками, по тем же доводам, что у сниффера.

**Хранилище.** `modules/storage`: порт + единственная реализация на
`@aws-sdk/client-s3`. Имя бакета и слово «S3» не выходят за этот файл. Модуль
`@Global`, потому что клиент один — второй был бы вторым пулом соединений.
Четыре переменные, **обязательные в проде и необязательные вне его**.

**Маршруты** (в `modules/profile`, третьего репозитория поверх `users` не
заводил): `PUT /v1/me/avatar`, `DELETE /v1/me/avatar`,
`GET /v1/avatars/:avatarId`.

**Копия для стола.** `setContactAvatar` / `deleteContactAvatar` в клиенте
Chatwoot + очередь `avatar` (BullMQ) с двумя задачами и повторами.

## Решения, принятые по ходу

**Проверка окружения не могла жить в существующем `superRefine`.** У него в
начале ранний `return` при `BILLING_ENABLED=false` — а прод сегодня ровно
такой. Написанная внутри, проверка аватара **не исполнилась бы в проде ни
разу**. Обе проверки вынесены в именованные функции; на это есть отдельный тест
(«отказывается стартовать в проде и при выключенном биллинге тоже»).

**Порядок записи при замене** — `put` → `setAvatar` → `remove` → очередь.
Проверяется утверждением на порядок вызовов, а не на факты по отдельности:
любой другой порядок теряет либо фотографию, либо объект, на который она
ссылается. В этом худший исход отказа — объект, на который никто не ссылается.

**Раздача по `avatarId` в пути**, а не `GET /v1/me/avatar`. Стабильный адрес с
`immutable` — ложь: после замены устройство показывало бы старое лицо, и на
Android заголовками это не чинится. Владение всё равно проверяется: непрозрачный
id — не авторизация, чужой = 404 без запроса в базу.

**HEIC и GIF исключены**, и это не вкусовщина. Стол (`Avatarable`) не принимает
HEIC вовсе — принятый нами файл упал бы **на фоновой задаче**, то есть молча.
GIF стол принял бы, но анимированный портрет — решение, которого никто не
принимал. Инвариант «наш список ⊆ списка стола» закреплён тестом, а не
комментарием.

**Отправка в стол не входит в успех загрузки.** Ни отказ очереди, ни отказ
удаления старого объекта не роняют запрос: фотография у владельца уже есть.
На оба случая есть тест.

**Найденный шов: `chatwootContactId` пуст до первого разговора.** Задача с
пустым id — no-op, а `ProvisioningService` прикладывает фотографию в момент
создания контакта. Без этого у всех, кто поставил фотографию до первого чата,
стол не увидел бы её **никогда**. Три теста. Очередь туда внедрена напрямую, а
не через `AvatarService`: импорт `ProfileModule` в `ChatwootModule` замкнул бы
цикл.

**Задача, которую обогнали.** Две быстрые замены ставят две задачи; та, что
отработает последней, оставила бы столу старое лицо. Поэтому в payload едет
`avatarId`, и задача с устаревшим ничего не делает. Симметрично: purge не
срабатывает, если между удалением и задачей приехала замена.

## Ловушка, на которую наступил

`npm install` после правки `package.json` **не обновил зависимость**: lock
держал коммит `250f61e` (0.16.0), и `AvatarLimits` в установленном пакете не
было. Это ровно то, что в `AURAT-0062` стоило дня разбора — отсутствие
зависимости выглядит как что угодно другое. Снялось явным
`npm install github:...#v0.17.0 --save`; проверено чтением
`node_modules/@aura/contracts/package.json`, а не `package.json` репозитория.

записано, что стирать теперь нужно и объект, и что объекты одного аккаунта
лежат под общим префиксом `avatar/<userId>/`.
