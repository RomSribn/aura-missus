# AURAT-0178-001 — initial (заглушка)

Дата: 2026-11-07
Выдан: сессия app slave-2 по просьбе владельца после закрытия `AURAT-0176`: «заведи задачу на серверную отметку
прочтения». Не запущена — ждёт команды владельца.
Фича: — (ближайшая — `AURAF-0007` real chat backend; решит спека).

## Откуда

Счётчик непрочитанного сейчас у обоих клиентов свой и в памяти — «новое за этот визит» (`AURAT-0105` веб, решение 1 — Б;
`AURAT-0176` приложение). Отметки прочтения на сервере нет, поэтому:
- после холодного старта (в том числе из пуша) и после перезагрузки страницы непрочитанного нет — пришедшее, пока
  клиент был закрыт, не помечается;
- прочитанное в одном клиенте другой не знает.
Вариант Г из `AURAT-0105-005-spec.md` («Решения», п. 1) — «серверная отметка прочтения, contracts + BFF + оба клиента,
одинаково везде», рекомендован тогда в бэклог.

## Что нужно (на спеку)

1. **Модель (BFF):** отметка прочтения на диалог пользователя — например, последний прочитанный id сообщения
   советника (курсор, как `after` догона) или время. Считается только `direction === 'advisor'`; маркеры сессии и свои
   — нет; удалённое столом (`AURAF-0018`, tombstone) — не считается.
2. **Контракты (`@aura/contracts`, сейчас v0.28.0 в приложении):** как клиент ставит отметку
   (`POST …/read {messageId}` или поле в ответе истории) и как узнаёт непрочитанное — число в ответе истории / в
   `GET /v1/conversations` (долг `AURAT-0009` D6: публичный список диалогов отложен — «last message? unread count?»;
   решить, не делать ли их вместе) — и событие сокета, чтобы второй клиент гасил бейдж (`read.updated`?).
3. **Приложение:** `ChatProvider` берёт число с сервера вместо Set в памяти (`AURAT-0176`); ставит отметку, когда тред
   «читается» (в фокусе и лента внизу — решение 2 `AURAT-0176`); бейдж Chats и строки остаются как есть.
4. **Веб:** то же в `entities/message/model/chat-live.ts` (`unread`, `threadOpened`).
5. **Пуш:** бейдж иконки приложения (launcher) по числу с сервера — в задаче или отдельно (в `AURAT-0176` — «не здесь»).

## Вопросы владельцу к спеке

- Курсор (id) или время; на диалог или на сообщение.
- Делать ли вместе `GET /v1/conversations` (счётчики для Chats одним запросом вместо догона каждого советника).
- Бейдж на иконке приложения — сюда или отдельно.
- Разбивка по репо (как `AURAT-0115/0116/0117`): контракты + BFF в `aura-bff-manor`, приложение — здесь, веб — в
  `aura-web-manor`; ID для частей — на спеке.

## Не здесь

Read receipts для советника (стол Chatwoot видит, что клиент прочитал) — отдельно, если владелец решит.
