## Решения владельца — переданы из `aura-app-manor` (сессия slave-0)

Решения в передаче из `aura-app-manor`:

- Таблица «Решения владельца» 1–8 из спеки — по рекомендации.
- 3DS для всех карт — включить: `payment_method_options.card.request_three_d_secure = 'any'` на

- Замечания ниже — внести, как рекомендовано.

## Замечания (внесены в спеку v2)

1. Конфиг: отдельный флаг `CARD_TOP_UP_ENABLED` (по умолчанию `false`); ключи обязательны только
   при нём — иначе прод-BFF (`NODE_ENV=production`, биллинг включён) не стартует до live-ключей.
2. Идемпотентность старта: все параметры сессии (`expires_at`, `locale`, `customer_email`, url-ы)
   пишутся в строку до первого вызова Stripe; повтор строит запрос из строки.
3. Возвраты: `CARD_REFUND` при `pending` и `succeeded`, `CARD_REFUND_FAILED` при `failed` и
   `canceled`; добавлены `refund.updated` (и `refund.created`).
4. Проверка в маноре: USD-счёт для выплат в sandbox (без него Adaptive Pricing не включится),
   чеки на email.
5. Сверка — курсор по таблице `stripe_events`, а не все события за 72 ч каждые 5 минут.
6. Возвраты charge — через `GET /v1/refunds?charge=`.
7. `cancelled=1` — через `URL` API (в `returnPath` уже есть `?payment=`).
8. Повтор старта: перед той же `redirectUrl` спросить Stripe, что сессия `open`.
9. Один постоянный продукт (`price_data.product`, `STRIPE_TOP_UP_PRODUCT_ID`) вместо
   `product_data` на каждую сессию (параметр сверен в API Stripe).
10. Курс возврата покупателю — помечен непроверенным (в `004-context` написано «по текущему
    курсу» — это поправка к нему; на код не влияет).

Брейн: `AURAF-0020`, `AURAD-0023`, `AURAT-0208-001` здесь не правятся — их правит `aura-app-manor`.
