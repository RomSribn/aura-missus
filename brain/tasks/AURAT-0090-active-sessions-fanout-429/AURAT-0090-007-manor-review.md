# AURAT-0090-007 — Проверка спеки манором

Дата: 2026-11-20. Проверял `manor-8e`. A1–A3 по сути верны, сверено с кодом приложения и BFF.

**IP 22:11:** один IP, один пользователь — у всех 67 отказанных `/messages` одни и те же 8
курсоров `after`, а по прод-базе это 8 диалогов одного человека. Cloudflare перед Traefik нет,
CGNAT не подтверждается, о ключе лимитера говорить не нужно. Похоже на петлю: экраны падали от
429, человек ходил между чатами и бронью.

Замечания, все внесены в `AURAT-0090-spec.md`:
1. A1: формулировку предела 100 поправить — «≥ 100 более поздних, включая отменённые».
2. A2.2: таймер проверяет «соединение сейчас не открыто»; при живом сокете (iOS inactive →
   active) sweep не нужен. Добавить на это тест.
3. A2.3: «каталог приехал» при открытом сокете — только советники, которых не читали с последнего
   `onOpen`.
4. A3: те же ворота в `bffPublicRequest`.
5. Критерии: брони и возвраты — в две отдельные минуты (140 > 120); прод — сравнение 429 до и
   после, а не «0 от okhttp».
6. B: после A, отдельной парой, без `lastMessageId`; заодно перевести лог 429 из error в одну
   строку warn.

Дальше — одобрение владельца: часть A и решение по B.
