# AURAT-0118-043 — Панель iOS над клавиатурой: проверки на iPhone и вывод

Date: 2026-10-21

## Проверки владельца (iPhone, iOS 26 Safari, http://192.168.31.114:5173)

1. Тап в пустую полосу, где была бы ✓ — «скрытой кнопки там нет».
2. Временная страница `kb-test.html` (голые `textarea`, `contenteditable`, `input`, `textarea` в `form`) —
   «Нигде панели нет».
3. Та же страница + поля с `autocomplete` (`name`, `email`, `tel`, `one-time-code`), `textarea autocomplete=on`,
   `contenteditable` как у Telegram — «Теперь везде есть панель» (и у полей 1–4).
4. Страницы A (только `textarea`), B (+ видимое поле `name`), C (+ скрытое) — «А есть, B есть, С есть, теперь
   появилось и у нас в инпутах везде, в чате тоже».

## Вывод

Панель ˄ ˅ ✓ не зависит от типа поля и атрибутов (WebKit даёт её всем текстовым полям, `042`) — её
показывает или прячет Safari (закрытый код), и решение, судя по проверкам, принимается для сайта /
вкладки: после того как на адресе встретилось поле, которое Safari умеет заполнять (`autocomplete`),
панель показывается у всех полей адреса, включая чат. До того — нет, но место под неё над клавиатурой
остаётся («пустая полоса»). У Telegram Safari, по-видимому, в этом состоянии давно (вход по телефону). Кодом
не подтверждено — это вывод из наблюдений; проверить можно новой приватной вкладкой (ожидаем: в чате
панели нет, пока не встретится поле с `autocomplete`).

У пользователей поле с `autocomplete` встречается при входе (`tel`, `one-time-code`). В коде ничего не
меняем; скрытое поле с `autocomplete` ради панели — нет (Safari может подставить туда данные человека).

Тестовые страницы удалены (в git не попадали).

показывается у всех полей, включая чат; в коде ничего не меняем.
