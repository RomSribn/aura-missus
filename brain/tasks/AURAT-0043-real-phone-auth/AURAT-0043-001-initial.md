# AURAT-0043-001 — Реальная авторизация по телефону: не одна причина, а пять

Дата: 2026-08-28
Исполняет: **половина приложения** — `aura-app-manor`, slave-1,
ветка `feature/AURAT-0043-real-phone-auth`
Заводится из: запроса владельца — «сейчас работает только с тестовым телефоном,
который занесён в Firebase»
Размер: средний по коду; **упирается в три решения владельца и три действия в
консолях**, а не в объём
Критичность: **вход в приложение — единственный**. Телефонный OTP это не одна
из возможностей входа, это она и есть

---

## Что именно работает сегодня

Измерено вживую в проекте `aura-2781b` 2026-08-28 (Identity Toolkit
`admin/v2/projects/aura-2781b/config`):

```json
"phoneNumber": {
  "enabled": true,
  "testPhoneNumbers": { "+34699001112": "111111" }
}
```

Это и есть «тестовый телефон». **Ровно один номер, ровно один код.** Всё, что
описано ниже, объясняет, почему кроме него не проходит никто — и это **не одна
причина, а пять независимых**. Каждой в отдельности достаточно, чтобы реальный
номер не вошёл. Поэтому чинить их надо все; починка одной ничего не изменит, и
это главный вывод разведки.

## Пять стен, по порядку, в котором в них упирается реальный номер

### 1. Ввести не-испанский номер физически нечем

`screens/phone-auth/model/use-phone-auth.ts:20-21` — код страны **зашит
константой**:

```ts
const countryCode = '+34';
const countryFlag = '🇪🇸';
```

Плитка страны в `PhoneAuthScreen.tsx:65` — `TouchableOpacity` **без
`onPress`**: нажимается и не делает ничего. Длина проверяется как
`phoneNumber.length >= 9` (`use-phone-auth.ts:30`), ввод обрезается на 9
(`:33`), а `formatPhoneGroups` (`shared/lib/format.ts:19`) группирует `3-3-3` —
испанский формат и только он.

То есть до Firebase дело не доходит вовсе: **немецкий, украинский, эстонский
номер невозможно набрать**. Дизайн это предвидел — `AUTH_PHONE_SMS.md` §1
прямо пишет про плитку страны: «Static in prototype; **make it a tappable
country picker in production**», и там же: «production should let the user
change it and adjust the max-length/validation per country».

### 2. Firebase принимает SMS ровно в одну страну

Из того же живого конфига:

```json
"smsRegionConfig": { "allowlistOnly": { "allowedRegions": ["ES"] } }
```

Это **строка №1 в `TECH-DEBT.md`**, заведённая ещё 2026-08-18 и с тех пор не
тронутая: поставлено на `AURAT-0001`, чтобы ограничить расход на SMS на плане
Spark. Следствие названо там же и остаётся верным: каталог Play по `AURAS-0002`
опубликован примерно в 150 странах, а войти может только испанский номер.

Важное для приёмки: **тестовые номера обходят и это ограничение тоже**. Пока
проверка идёт тестовым номером, стена невидима.

### 3. iOS не может подтвердить приложение — вообще, ни в какой сборке

Телефонный вход на iOS проверяет подлинность приложения тихим APNs-пушем, а
когда не может — уводит в reCAPTCHA в браузере. У проекта **нет ни того, ни
другого**, и это измерено в `project.pbxproj`:

- `CODE_SIGN_ENTITLEMENTS` **отсутствует в обеих конфигурациях** — файла
  entitlements у таргета нет;
- `SystemCapabilities` / `com.apple.Push` в проекте **не встречаются ни разу**;
- значит нет `aps-environment`, значит возможности Push Notifications нет,
  значит APNs-проверка недоступна навсегда.

Это **строка №6 в `TECH-DEBT.md`**, проверенная на устройстве 2026-08-21 на
релизной сборке: reCAPTCHA-запасной путь упирается в `about:blank`. Схема URL
для возврата (`Info.plist`, `app-1-1022442840784-ios-d75cb17b01adfc8ed734d5`) и
приёмник в `AppDelegate.swift` (`Auth.auth().canHandle(url)`) **уже на месте** —
не хватает именно возможности пуша и ключа APNs в проекте Firebase.

Отдельно, и это придётся решить раньше ключа: **iOS-приложение
зарегистрировано в Firebase под шаблонным идентификатором**. Измерено через
Firebase Management API — в проекте ровно одно iOS-приложение:

| | bundle id |
|---|---|
| Firebase iOS app `1:…:ios:d75cb17b01adfc8ed734d5` | `org.reactjs.native.example.PsychoApp` |
| `project.pbxproj`, обе конфигурации | `org.reactjs.native.example.PsychoApp` |
| Android (после `AURAT-0026`) | `cc.silvermind.aura` |

### 4. Android проверяет приложение запасным путём, потому что основной выключен

Здесь новость наполовину хорошая. Отпечатки подписи **зарегистрированы, и
щедро** — у приложения `cc.silvermind.aura` в Firebase лежат **5 SHA-1 и 5
SHA-256** (Management API, 2026-08-28). Эта половина в порядке.

А вот **`playintegrity.googleapis.com` в проекте не включён** — его нет в
списке из 42 включённых API (`gcloud services list --enabled`). Включены
`identitytoolkit`, `fcm`, `fpnv` (Firebase Phone Number Verification), Play
Integrity — нет. Значит проверка приложения на Android падает на запасной путь
через reCAPTCHA в веб-вью: работает, но это лишний экран посреди входа и лишняя
точка отказа.

### 5. Каждая дев-сборка явным флагом выключает проверку подлинности

`shared/api/firebase/auth.service.ts:22-24`:

```ts
if (__DEV__) {
  auth().settings.appVerificationDisabledForTesting = true;
}
```

Комментарий над ним честно называет назначение: чтобы **тестовые** номера
Firebase Console «резолвились без настроенного пуша и reCAPTCHA». Это ровно то,
что документация Firebase описывает как режим для вымышленных номеров.

Следствие, которое стоит проговорить: **`__DEV__` — это флаг бандлера, а не
среда**, и `shared/config/env.ts` уже написал об этом целый абзац по поводу
адреса BFF (`AURAT-0028`). Здесь та же ошибка в другом месте: невозможно
собрать дев-сборку, которая проверяет настоящий номер по-настоящему. Разработчик
физически не может воспроизвести то, что увидит пользователь, — и именно поэтому
стена №3 просидела незамеченной до релизной сборки в августе.

## Что из этого делает slave, а что может сделать только владелец

Граница проходит там же, где всегда: код — здесь, живые проекты и деньги — у
владельца.

### Половина кода (эта задача)

**A. Выбор страны и валидация E.164** — `shared` + `screens/phone-auth`

- `shared/config/countries.ts` — список стран: ISO-2, dial code, флаг, правило
  длины национального номера, схема группировки для отображения.
- `screens/phone-auth/ui/CountryPickerSheet.tsx` — лист выбора с поиском;
  `FlatList`, строка — `React.memo` (правило №5 из build-rules).
- `use-phone-auth` — выбранная страна в состоянии, длина и валидация из её
  правила, сборка E.164 из `dial + national`.
- `formatPhoneGroups` перестаёт быть испанской: группировка приходит из страны,
  нейтральный fallback для остальных. Существующие тесты в
  `shared/lib/__tests__/format.test.ts` остаются зелёными.
- Выбранная страна запоминается между запусками.
- Плитка страны получает `onPress` — сегодня его нет.

**B. Тестовый режим становится настройкой сборки, а не `__DEV__`**

- новый ключ `AURA_AUTH_TEST_MODE` в `env/resolve.js` (KEYS), значение по
  умолчанию `false` во **всех** целях, включая `.env.dev`;
- `shared/config/env.ts` объявляет и экспортирует его — как `BILLING_ENABLED`;
- `auth.service.ts` читает его вместо `__DEV__`.

Смысл ровно один: **дев-сборка по умолчанию проверяет настоящий номер
по-настоящему**, а тестовый номер становится осознанным включением через
`.local`-файл. Без этого приёмка любой из остальных правок невозможна —
проверять будет нечем.

**C. Возможность Push Notifications у iOS-таргета** — та половина
`TECH-DEBT` №6, которая живёт в репозитории

- `ios/PsychoApp/PsychoApp.entitlements` с `aps-environment`
  (`development` в Debug, `production` в Release);
- `CODE_SIGN_ENTITLEMENTS` прописывается в обе конфигурации `project.pbxproj`.

Это снимает и вторую половину строки №6 заодно: без этой возможности
`@react-native-firebase/messaging` и notifee на iOS не могут принять **ничего**,
то есть пуши о сообщениях на iOS сегодня не работают по той же причине.

**D. Ошибки, которые пользователь наконец увидит**

Сегодня `use-phone-auth.ts:61` показывает `Alert.alert` с сырым текстом от
Firebase. Реальные номера начнут приносить коды, которых `handleAuthError`
(`auth.service.ts:130-163`) не разбирает: отказ по региону,
`auth/invalid-app-credential`, `auth/missing-client-identifier`,
`auth/app-not-authorized`. Их надо назвать по-человечески, и показать **в
экране**, а не в системном диалоге.

Плюс то, что дизайн просил, а код не сделал: `AUTH_PHONE_SMS.md` §4 — при
неверном коде **тряхнуть четыре ячейки и очистить** (`withSequence` ±6px, ~300
мс). Сейчас `use-verify-otp.ts:51` только очищает.

**E. Гигиена повторной отправки**

`resendOTP` (`auth.service.ts:63`) просто зовёт `sendOTP` заново. С реальными
номерами вступает в силу лимит Firebase на номер, и `auth/too-many-requests`
станет обычным, а не экзотическим ответом. Таймер 48 с уже есть
(`shared/ui/ResendTimer`), не хватает поведения при отказе.

**F. Тесты** — юнит на валидацию по странам, сборку E.164 и карту ошибок.

### Действия владельца (в консолях, из slave недоступны и не должны быть)

## Три вопроса, которые надо решить до кода

**Q1. Какие страны.** От ответа зависит и список в пикере, и пункт 1 владельца.
Предлагать в интерфейсе страну, чей SMS Firebase откажется отправлять, — это
поменять «нельзя набрать» на «набрал и не пришло», что хуже. Варианты: только
ES (тогда пикер — работа впустую, и надо честно это сказать); короткий список
рынков; всё, где продаёт Play.

**Q2. Bundle id для iOS.** Оставить шаблонный
`org.reactjs.native.example.PsychoApp` — значит уйти с ним в App Store навсегда.
Переименовать в `cc.silvermind.aura` — значит завести **новое** iOS-приложение в
Firebase, забрать новый `GoogleService-Info.plist`, поменять схему возврата в
`Info.plist` (она выводится из GOOGLE_APP_ID) и завести App ID у Apple. Решать
надо **раньше** загрузки ключа APNs, иначе она делается дважды.

**Q3. Play Integrity или reCAPTCHA на Android.** Включить Integrity — вход без
лишнего веб-экрана; не включать — работает, но через веб-вью посреди
авторизации. Рекомендация: включить, отпечатки уже на месте.

## Приёмка

Проверяется **в маноре после мержа**, на устройстве, и обязательно **не тестовым
номером**:

1. Дев-сборка с `AURA_AUTH_TEST_MODE=false` и реальным номером разрешённой
   страны — SMS приходит, код проходит, приложение открывается.
2. Смена страны в пикере меняет правило длины и формат отображения.
3. Номер страны вне allowlist даёт понятную строку в экране, а не системный
   диалог с текстом от Firebase.
4. Неверный код — тряска и очистка, экран остаётся на месте.
5. iOS: релизная сборка проходит вход (это и есть закрытие `TECH-DEBT` №6);
   попутно проверить, что пуш о сообщении на iOS наконец доходит.
6. Повторная отправка до истечения 48 с недоступна; после — работает.
