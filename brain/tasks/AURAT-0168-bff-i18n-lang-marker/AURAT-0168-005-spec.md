# AURAT-0168-005 — spec: язык на сервере — контракты v0.28.0 + BFF

Дата: 2026-11-06 · Status: **draft** — ждёт одобрения владельца
Фича: `AURAF-0023` строка 009 + язык клиента для чаттеров. Основа для `AURAT-0169` / `0170` / `0171`.
Тип: задача (новая фича не нужна — строка 009 уже есть).

## Что получится

- Приложение и веб шлют `?lang=<код>` в каждом запросе; BFF понимает его одним способом везде.
- Маркер сессии приходит данными: `Message.marker = 'session_started' | 'session_finished'` — клиент переводит его
  сам, английский `content` остаётся для старых сборок.
- Язык можно выключить с сервера: `disabledLanguages` в `/v1/app-config`.
- Чаттер видит язык клиента в карточке контакта Chatwoot — **если владелец решит делать это сейчас** (решение 2).

## 1. Контракты `v0.28.0` (`aura-contracts`)

Только добавления — ответ `v0.27` разбирается новым клиентом, ответ `v0.28` — старым.

**Новый модуль `language.ts`:**
- `LANGUAGES` — `['en', 'bg', 'cs', 'da', 'de', 'el', 'es', 'et', 'fi', 'fr', 'ga', 'hr', 'hu', 'it', 'lt', 'lv',
  'mt', 'nl', 'pl', 'pt', 'ro', 'sk', 'sl', 'sv'] as const` — тот же набор и порядок, что в приложении и вебе
  (`shared/config/languages.ts`); `type Language`;
- `DEFAULT_LANGUAGE = 'en'`;
- `isLanguage(value: unknown): value is Language` — точное совпадение, без нормализации (`DE`, `de-AT` — не язык;
  клиент шлёт свой код из того же списка);
- `resolveLanguage(value: unknown): Language` — язык из списка или `en`. Неизвестное значение — **не 400**, как `tz`
  у `GET /v1/tarot/daily`;
- `LANGUAGE_QUERY_PARAM = 'lang'` — имя параметра, чтобы клиенты не писали его строкой.

**`chat.ts` — `Message.marker`:**
- `MESSAGE_MARKERS = ['session_started', 'session_finished'] as const`, `type MessageMarker`;
- `marker: z.string().min(1).optional()` — строка, не `z.enum`: новый маркер не роняет разбор сообщения у старого
  клиента (как `SEASON_EFFECTS`). Отсутствует, а не `null`, на обычном сообщении — как `spread` / `sessionInvite`.
  Неизвестное значение клиент рисует по `content`.

**`app-config.ts` — `AppConfigResponse.disabledLanguages`:**
- `z.array(z.string()).default([])` — строки, не `Language`: код, которого старый клиент не знает, не роняет весь
  конфиг. Сервер шлёт только коды из `LANGUAGES` и никогда `en` (английский — запасной, его не выключить).
  Правило клиента (0169 / 0170): выбранный или системный язык в списке → английский.

Выпуск — как всегда: версия в `package.json`, абзац «`v0.28.0` adds…» в README и строка `language` в таблице модулей,
коммит «Язык на проводе (v0.28.0)», тег. **Пуш `main` + тега в GitHub — с отдельного одобрения владельца**
(публичный репозиторий, потребители ставятся с тега).

## 2. BFF: резолвер `lang`

**Решение спеки: декоратор параметра, не глобальный хук.**
- `@RequestLanguage()` (`src/common/decorators/`, рядом с `@CurrentUser()`) → `Language | null`: код из `LANGUAGES`,
  если клиент его прислал, иначе `null` (нет параметра или неизвестный). Маршрут, которому нужен язык ответа
  (таро в `0171`), берёт `language ?? DEFAULT_LANGUAGE`; запись языка пользователя (п. 5) пишет только явный
  известный код.
- `@ApiLanguageQuery()` — одно описание параметра для Swagger.
- `Accept-Language` не читается вовсе (iOS шлёт его сам из языка устройства — `AURAI-0010` §6).
- Почему не `onRequest` / interceptor: язык нужен двум-трём маршрутам (отправка сообщения, таро), а глобальный хук —
  неявная связь и работа на каждом запросе; декоратор виден в сигнатуре и тестируется как функция. Остальным
  маршрутам `lang` не мешает — проверено: схемы query нестрогие, `.strict()` только у тела пресета кампании.
- Сокет `lang` не нужен: кроме `Message` в нём нет серверного текста, а маркер приходит данными. → `0169`: в URL
  сокета `lang` не добавлять.

## 3. BFF: `Message.marker`

- Тексты маркеров переезжают из `sessions.service.ts` в `src/modules/chat/session-markers.ts`:
  `SESSION_MARKER_CONTENT: Record<MessageMarker, string>` (`session_started` → «Your session has started»,
  `session_finished` → «Your session has finished») и чистая `markerOf(direction, content)`. **Формулировки не
  меняются** (`AURAT-0167` и веб узнают их по точному совпадению); `SessionsService.announce` берёт текст оттуда.
- `toDto` (`chat.service.ts:337`) — единственное место, где строка становится DTO: `marker` добавляется, если
  `direction === 'system'` и `content` точно равен тексту маркера. Вся история получает поле без миграции; удалённое
  сообщение (`content: ''`) — без маркера; пользователь, набравший «Your session has started», — без маркера
  (направление `user`).
- `messageOpenApi` — свойство `marker`.

## 4. BFF: `disabledLanguages`

**Рекомендация: env.**
- `DISABLED_LANGUAGES` — коды через запятую, по умолчанию пусто. Проверка при старте (fail fast): каждый код из
  `LANGUAGES`, `en` — запрещён; дубли схлопываются, порядок — как в `LANGUAGES`.
- `buildAppConfig` получает список в контексте; поле в ответе всегда (`[]`, если пусто). ETag считается от тела —
  смена списка меняет ETag сама; кэш процесса живёт до перезапуска, а перезапуск и есть смена env.
- Выключить язык = поменять переменную и передеплоить (минуты), без релиза в сторах. Случай аварийный и редкий.
- Альтернатива (решение 1): настройка в бэкофисе — таблица, маршрут, экран, журнал, `invalidate()` — включается за
  секунды без деплоя, но это в разы больше кода ради редкого случая.

## 5. BFF: язык клиента для чаттеров — **решение владельца (2)**

Хранение языка на сервере противоречит пункту NOT in scope `AURAF-0023` «язык в аккаунте или на сервере в v1» и
требует строки в политике конфиденциальности. Если делаем сейчас — **рекомендую атрибут контакта**:

- `users.language String?` (миграция). Пишется **только** когда запрос прислал известный код и он отличается от
  сохранённого: в `POST /v1/advisors/:advisorId/messages` (и текст, и файл — один маршрут). Условный `UPDATE … WHERE
  language IS DISTINCT FROM …` → изменилось → в очередь.
- Пуш в Chatwoot — существующая очередь `contact-name`: задача читает строку при запуске и пишет в контакт имя и
  `custom_attributes.client_language` одним `PUT /contacts/:id`. Атрибуты контакта Chatwoot **сливает**, а не
  заменяет (проверено по исходнику, `contacts_controller.rb:177-193`) — ни атрибуты разговора, ни чужие атрибуты
  контакта не задеты. Задача уже ставится при первом создании контакта — язык попадёт и туда. Имя очереди не
  меняется (переименование живой очереди BullMQ бросит задачи в полёте).
- Значение — английское название языка («German»), не код: чаттер читает по-английски. `desk:setup` создаёт
  определение `client_language` (`contact_attribute`, тип list, 24 названия) — сейчас он умеет только атрибуты
  разговора, добавится модель контакта.
- Удаление аккаунта: `language` — в `CLEARED_PROFILE`. В логах — не пишется.
- Чего не будет: старые сборки и пользователи, ещё не писавшие с новой сборки, — без атрибута («---» в панели);
  бэкфилла нет. Чаттер видит язык в панели контакта, но **не может отфильтровать** по нему список разговоров.
- Альтернатива — атрибут **разговора**: фильтруется в списке, но запись заменяет всю карту → язык придётся
  добавлять в каждый `syncSessionState` и переписывать все разговоры пользователя при смене языка. Больше кода и
  точек отказа; имеет смысл, если чаттеров будут распределять по языку (решение 8 владельца ещё не принято).
- Отложить — `users.language` и атрибут не делаем; п. 2–4 от этого не зависят.

## 6. Пуши

Работы нет: FCM шлёт только `{type: 'message.new', advisorId}`, текст рисует устройство.

- В маноре после мёржа: `GET /v1/app-config` с `DISABLED_LANGUAGES=mt`; история с маркерами; при п. 5 — атрибут
