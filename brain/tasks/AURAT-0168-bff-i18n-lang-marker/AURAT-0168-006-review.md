## Решения владельца (переданы координатором)

1. `disabledLanguages` — переменная окружения + передеплой.
2. Язык клиента для чаттеров — **отложить** (после решения 8 о языке чаттеров). П. 5 спеки остаётся отложенным, с
   замечаниями ревью к нему.

## Замечания ревью — все приняты, проверены по коду

1. Выключатель только у клиентов → резолвер возвращает `null` и для кода из `DISABLED_LANGUAGES`.
2. В `content` бывают и английские заглушки токенов (`spread-token.ts:20`, `session-invite-token.ts:27`) — правило:
   при `spread` / `sessionInvite` клиент показывает своё слово, не `content`.
3. `?lang` — только JSON-запросы и загрузка; не адреса картинок / вложений (`immutable`, адрес = ключ кэша), не
   сокет.
4. Клиенты читают app-config по частям → экспорт `AppConfigDisabledLanguages`; поле в `appConfigResponseOpenApi`;
   передача для 0169 про `AppConfig` / `NO_CAMPAIGN`.
5. Маршруты, которым язык нужен в 0171, и настоящая причина, почему не сокету (fanOut — только новые вставки).
6. Имена: `SOURCE_LANGUAGE`; помощник «неизвестное → en» — в BFF; из контрактов — `LANGUAGES`, `Language`,
   `isLanguage`, `LANGUAGE_QUERY_PARAM`.
7. Значения маркеров vs клиентские `started` / `finished` — оставляю `session_started` / `session_finished` (поле
   общее для системных сообщений, значения с пространством имён не столкнутся с будущими); клиенты сопоставляют
   типизированной таблицей, неизвестное → `content`.
8. Порядок выпуска и заморозка контракта — в «Проверки».
9. `DISABLED_LANGUAGES` — trim + нижний регистр.
10. Чистая `languageFromQuery`, декоратор — обёртка; тесты на нет / неизвестный / `DE` / массив.
11. Формулировки: кэш 30 с на реплику + `invalidate()`; `.strict()` ещё у `ProfilePatchRequest` (тело).
