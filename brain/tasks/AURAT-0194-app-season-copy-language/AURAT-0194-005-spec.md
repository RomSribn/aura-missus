# AURAT-0194-005 — spec: сезон, подпись скидки и цена — на языке приложения

Дата: 2026-11-07 · Статус: **draft — ждёт ревью координатора и одобрения владельца** (решение 1)
Слот: slave-2, `feature/AURAT-0194-app-season-copy-language` от `develop` `3bee447`. Факты — `004-context.md`.
Передача: `AURAT-0189` `007-spec-v2` §11 (решения 0189: 2 = А, 3 = А, 5 = А, 6 = Б). Фича: `AURAF-0023` строка 011,
`AURAF-0022`.

## Что получится

- Человек сменил язык в приложении → hero, билеты, подпись скидки в каталоге и в брони перечитываются **сразу**, без
  ожидания 60 с и возврата в приложение. Ответ, ушедший на прежнем языке и пришедший последним, не перебивает новый.
- Сумма в текстах сезона пишется как в остальном приложении: fr «5 $ sur votre solde», а не «$5 sur…» (решение 6 = Б
  у 0189). По-английски — «$5», как сейчас.
- Подпись скидки на билете без сезона рисуется капсом по правилам своего языка (`upperLabel`): el — без тонуса.
  Читается с экрана обычным регистром.
- Пометка языка для чтения с экрана у hero — язык текстов из ответа (`copyLanguage`), а не `'en'` (iOS; у Android
  такого свойства нет).
- Контракты — `#v0.30.0`. Без новых строк для человека — переводы и линтер строк не затрагиваются.

## 1. app-config за языком — `entities/campaign`

**`model/campaign-store.ts`** — по образцу `advisor/model/catalog-store.ts` (`AURAT-0174`):
- каждый запрос получает номер (`latest`) и язык, на котором ушёл (`askedLanguage`; `null`, пока i18n не стартовал —
  `http-client` возьмёт язык только тогда). Ответ (и 404) ложится, **только если запрос последний**: иначе он не
  публикуется, не пишется в кэш и не греет арт;
- новый `followLanguage(language)`: ничего, если последний запрос уже ушёл (или уйдёт — ждёт i18n) на этом языке —
  холодный старт в сохранённом языке спрашивает один раз, не два. Иначе — новый запрос **мимо** `inFlight` и троттла
  (`lastAskedAt` сбрасывается). То, что на экране, остаётся до ответа (как каталог);
- `refresh()` без изменений снаружи: присоединяется к запросу в пути, не чаще раза в минуту.

**`model/use-app-config-sync.ts`** — `onLanguageChange(language => campaignStore.followLanguage(language))`, как
`use-advisor-catalog-sync.ts`. Конфиг публичный — без условия на вход.

**Кэш `aura-app-config.json`** — формат не меняется (его читает и старт i18n, `readCachedDisabledLanguages`). Ответ
`v0.30` сам говорит язык своих текстов (`copyLanguage` / `labelLanguage`) — по нему ставится пометка и форма суммы. Что
рисовать из кэша чужого языка на холодном старте — **решение 1**.

## 2. Язык текстов из ответа

- **`lib/copy-language.ts`** (новый, чистый): `textLanguageOf(code: string): Language` — `isLanguage(code) ? code :
  SOURCE_LANGUAGE`. Контракт отдаёт строку; язык, которого приложение не знает, пишется английской формой.
- **`SEASON_COPY_LANGUAGE`** (`config/constants.ts`) удаляется. **`lib/hero-content.ts`**: `SeasonHeroContent.language`
  = `textLanguageOf(season.copyLanguage)`. **`ui/SeasonHero.tsx`**: `accessibilityLanguage={hero.language}` (4 места).
- **`{amount}`** — `fillSeasonCopy(…, { code, amountMinor, amount: formatUsdMinorCompact(amountMinor, language) })`, где
  `language` — язык текстов сезона: `hero-content.ts` (`heroBody`, `cta`), `ticket-content.ts` (`ticketCode*`).
  `formatUsdMinorCompact(…, 'en')` совпадает с `formatSeasonAmount` («$5», «$5.50») — английский не меняется.

## 3. Капс подписи — `shared/ui/offer`

- **`CampaignTicketContent`** получает `eyebrowLanguage: Language` (обе разновидности): у сезона — язык его текстов, у
  подписи скидки без сезона — `textLanguageOf(discount.labelLanguage)`, у своих слов билета (`ticket.codeEyebrow`) —
  язык на экране. Заполняет `ticket-content.ts`.
- **`CampaignTicket.tsx`** рисует `upperLabel(content.eyebrow, content.eyebrowLanguage)`; в `accessibilityLabel` —
  `content.eyebrow` обычным регистром (как `UpcomingSessionCard`). Надзаголовки сезона el уже капсом — `upperLabel` их не
  меняет. `textTransform` в `ticketText.eyebrow` остаётся: его делит `CouponTicket` (свои слова, el в переводе уже капсом),
  поверх `upperLabel` он ничего не делает.
- Подпись внутри фраз («20% OFF · Winter sale» — профиль, приглашение в чате, разбивка цены, экран «Забронировано») —
  обычным регистром, как есть: капса там нет.

## 4. Цена за языком — `features/booking`

- **`model/use-pricing-follows-language.ts`** (новый): `usePricingFollowsLanguage(advisorId, apply, enabled)` — на
  `onLanguageChange` тихо перечитывает `fetchPricing(advisorId)` и отдаёт ответ в `apply`. Без спиннера: суммы те же, на
  другом языке только подпись. Ложится только последний ответ и только у смонтированного хука; ошибка — оставляет
  прежнюю цену.
- Подключается там, где цена своя: `use-booking` (`enabled` — цена уже есть), `use-quick-booking` (так же),
  `use-booking-confirm` (только когда `pricing` не дали снаружи — иначе перечитывает владелец). `use-paid-session`
  подпись не показывает — не трогается. `BookedScreen` — снимок подписи на момент брони, остаётся.
- Известное ограничение: если язык сменился, пока **первая** загрузка экрана ещё в пути, она может лечь после
  перечитывания и вернуть прежний язык подписи до следующей смены. Смена языка — в настройках, не на экране брони;
  чинить ценой переписывания трёх загрузок не предлагаю.

## Решение владельца

**1. Холодный старт, кэш на другом языке** (язык сменили, пока приложение закрыто: язык Android при выборе «как на
устройстве»; или приложение убили сразу после смены). Запрос на старте уходит всегда — вопрос только о том, что видно до
ответа (обычно доли секунды, чаще всего ещё под заставкой) и без сети.

- **А (рекомендую).** Рисовать кэш как есть, с его собственным языком: пометка для чтения с экрана и сумма — по
  `copyLanguage` / `labelLanguage` из ответа. Ответ сети заменяет его на новый язык. Без сети — сезон на прежнем языке, пока
  сеть не появится. Формат кэша не меняется. Так же ведёт себя смена языка на ходу: что на экране, остаётся до ответа.
- **Б.** Запомнить язык запроса в том же JSON (лишнее поле; старт i18n его не замечает) и из кэша чужого языка **не
  рисовать сезон**: Home без hero, билеты — своими словами на языке экрана, сфера заставки — по-прежнему из кэша. Сезон
  появляется с ответом сети (как в первый запуск сезона); без сети — его нет. Подпись скидки на билете без сезона всё
  равно из кэша — запасного слова на её языке у приложения нет (можно «Seasonal sale», но это ещё одна ветка).

Передача 0189 говорила «кэш чужого языка не рисовать как свой». При А он и не рисуется как свой: ответ v0.30 несёт язык
текстов, по нему ставятся пометка и сумма. Б убирает и сами чужие слова, ценой hero, который «выпрыгивает» после ответа.

## Проверка в маноре (координатор, Android, bff-dev)

Перед проверкой — `npm ci`; кампания на bff-dev с текстами пресета (владелец меняет свой текст на пресетный — иначе
`copyLanguage: en` и сезон по-английски на любом языке, это верно).
1. Холодный старт по-английски — hero и билет как сейчас («$5 on your balance»).
2. Профиль → язык → Deutsch → назад на Home: hero и билет по-немецки за секунду, без выхода из приложения. fr — сумма
   «5 $». el — надзаголовки капсом без тонуса.
3. Открыть бронь советника (вкладка «Советники»), сменить язык во вкладке «Профиль», вернуться: строка скидки
   («20% OFF · …») с подписью на новом языке, суммы те же. Профиль советника и приглашение в чате — так же.
4. Быстрая смена de → fr → de: в конце всё немецкое (ответ fr не перебил).
5. Решение 1: язык «как на устройстве», убить приложение, сменить язык Android, запустить — А: до ответа прежний язык, потом
   новый; в авиарежиме — прежний. Б: hero появляется с ответом; в авиарежиме — нет hero, сфера заставки сезонная.
6. Подпись капсом на билете без сезона (el) — если на bff-dev есть кампания со скидкой без сезона; иначе — тест.
