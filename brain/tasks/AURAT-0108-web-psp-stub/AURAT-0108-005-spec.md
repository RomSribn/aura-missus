# AURAT-0108-005 — Spec: заготовка под PSP в aura-web

Date: 2026-10-20
Type: task (строка `AURAF-0020-007`, колонка UI; Р4 `AURAD-0019`). Новой фичи нет.
Status: approved 2026-10-20 (`006`, все рекомендации; песочница и тестовая шторка кошелька — на английском) — исполнено (`007`), правки ревью (`008`) — на проверке

## Цель

Оплата картой и Apple Pay / Google Pay готова и выключена: способы `card` и `wallet` порта
`features/pay` работают против **фейкового провайдера** за `VITE_PSP_ENABLED`. PSP — это
**пополнение недостачи** (целыми долларами вверх, остаток — на балансе, как `CHECKOUT.md` и
`AURAF-0019`), затем **та же бронь** `POST /v1/advisors/:id/sessions` с ключом попытки
(`AURAD-0009`: кошелёк — рельс). `/checkout` — маршрут возврата с hosted page; «Still
confirming…» — с опросом; «Booked» — только после ответа сервера на бронь (правило 7).
С выключенным флагом поведение `AURAT-0107` не меняется ни в одном пикселе.

BFF и contracts **не меняются**. Решения 1–7 — в конце, у каждого варианты и рекомендация;
«Что делаем» написано по рекомендациям.

## Что делаем

### 1. Флаг (решение 2)

- `env.pspEnabled = VITE_PSP_ENABLED && !PROD` — пока единственный провайдер фейковый, прод-сборка
  флаг игнорирует (как `VITE_FIREBASE_AUTH_TEST_MODE`). Комментарий в `env.ts`: настоящий
  провайдер снимает это условие. `.env.development`, `.env.test`, `.env.example` — `false`, как
  сейчас.
- В маноре для проверки: `VITE_PSP_ENABLED=true` в `.env.local` манора и перезапуск `npm run dev`;
  выключить — удалить строку. `npm run build` / `vite preview` — всегда выключено.
- Код фейка (провайдер, песочница) грузится динамическим `import()` только при включённом флаге —
  в прод-бандл его чанк не попадает в загрузку.

### 2. Порт (`features/pay/model`)

- `PaymentMethodId = 'balance' | 'card' | 'wallet'`.
- Новый **порт провайдера пополнения** `TopUpProvider` — то, что потом реализует настоящий PSP
  через BFF (`AURAF-0009`):
  - `startCard({ amountMinor, paymentId, returnUrl }) → { redirectUrl }` — hosted page;
  - `payWithWallet({ amountMinor, paymentId }) → 'approved' | 'cancelled' | 'failed'` — шторка
    кошелька;
  - `status(paymentId) → 'pending' | 'credited' | 'declined' | 'cancelled'` — то, что опрашивается;
    у настоящего — `GET` статуса пополнения в BFF после вебхука (пробел 2).
  `paymentId` — UUID попытки пополнения (ключ идемпотентности пополнения у провайдера).
- `card` и `wallet` — это «пополнить через провайдер → дождаться `credited` → `balance.pay(attempt)`
  с **тем же ключом брони**». Исходы — те же `PayOutcome` + новые `declined`, `cancelled`,
  `processing`; после зачисления — `taken`, `notBookable`, `unknown` несут «деньги на балансе».
- **План пополнения** — `features/pay/lib/top-up-plan.ts`: перенос `payPlan` приложения (шапка
  `// Ported from aura-app src/features/store-topup/lib/pay-plan.ts (AURAT-0099)` + тесты), без
  лестницы SKU (она — сторов): `topUp = ceil((cost − fromBalance) / 100)` долларов, долг баланса
  гасится первым, `remainderMinor` < $1 остаётся на балансе. Источник пока в незамёрженной ветке
  приложения — при изменениях до merge `AURAT-0099` синхронизирую. Клиент только показывает план:
  зачисляет провайдер / BFF, списывает бронь по цене сервера (правило 7).

### 3. Попытка, переживающая уход со страницы

- `features/pay/model/pending-payment.ts` — запись в `sessionStorage`: `{ paymentId,
  idempotencyKey, method, advisorId, minutes, startsAt, amountMinor, startedAt }`. Пишется **до**
  ухода на hosted page; ключ брони — из неё (не новый). Удаляется только на определённом исходе.
  Битое / чужое значение — `null`, не ошибка (как черновик `AURAT-0107`).
- Черновик брони `features/book-session` не меняется: он и так переживает перезагрузку.

### 4. Оплата в шторке (`PayActions`, `usePay`)

- **Флаг выключен** — ровно как сейчас (временная строка «пополните в приложении» остаётся, её
  пометка — до настоящего PSP).
- **Флаг включён, баланс покрывает / неизвестен** — как сейчас: «Confirm & pay $X» с баланса.
- **Флаг включён, не хватает** — вместо временной строки:
  - строка плана: «We'll add $26.00 to your balance — $0.60 stays on it after the session.» (без
    остатка — «We'll add $26.00 to your balance and pay from it.»);
  - кнопка кошелька — «Apple Pay» на устройствах Apple, иначе «Google Pay» (имена брендов не
    переводятся; `aria-label` «Pay $26.00 with Apple Pay» — переводится); `isAvailable` у фейка —
    всегда, у настоящего — `canMakePayment`;
  - кнопка карты — «Pay $26.00» (coral, замок) → hosted page;
  - под кнопками: «Card payments open our payment partner's secure page» · политика отмены.
- **Wallet** не уходит со страницы: фейковая «системная шторка» — панель на месте кнопок внутри
  `PayActions` («Test wallet · $26.00» — Approve / Decline / Cancel), не второй диалог (у настоящего
  её рисует браузер). Approve → опрос статуса (§6) прямо в шторке → бронь → Booked.
- **Card** → запись попытки (§3) → `window.location.assign(redirectUrl)`. Шторка ничего не ждёт.
- Нажатие во время оплаты ничего не шлёт; ключ брони — как в `AURAT-0107` (до определённого
  исхода, переживает смену слота).

### 5. `/checkout` — маршрут возврата (решения 4, 5)

- `/checkout?payment=<paymentId>` (параметр — в `shared/config/routes.ts`): есть запись с этим
  `paymentId` → страница возврата; нет записи или параметра → как сейчас (шторка черновика /
  каталог).
- Страница (`pages/checkout`, приватная по смыслу — запись есть только у вошедшего): шапка
  «Confirming your payment», `SessionSummary` (советник, минуты, время), сумма пополнения, статус;
  на телефоне — без таб-бара (pushed).
- Исходы:
  - `credited` → бронь с ключом записи → `booked` — `replace` на `/booked/:id`, запись и черновик
    удалены;
  - `declined` → `replace` в шторку `/advisors/:id?book=1&slot=` со строкой над кнопками «Your
    payment didn't go through. Nothing was charged — try again or choose another way to pay.»
    (NAVIGATION §2.4: «Stay; inline error above the buttons; the draft is kept»);
  - `cancelled` → в шторку молча (`CHECKOUT.md`: закрытие без сообщения);
  - после зачисления `taken` → «That time was just taken. $26.00 is on your balance — pick another
    time.» + «Pick another time» (шторка без времени);
  - после зачисления `unknown` → «The booking didn't go through. $26.00 is safely on your balance.
    Try again — it will pay from your balance.» + «Try again» (тот же ключ);
  - после зачисления `notBookable` → «This advisor isn't taking sessions right now. $26.00 is on
    your balance.» + «Browse advisors»;
  - `processing` (окно опроса вышло, §6) → «Your payment is processing. We'll add it to your
    balance when it clears. No session is booked until then.» + «OK» (профиль советника).
- Перезагрузка / Back на `/checkout?payment=` до исхода — опрос продолжается по записи.

### 6. «Still confirming…» и опрос (решение 6)

- `features/pay/model/use-payment-status.ts`: опрос `status(paymentId)` раз в 2 с; дольше 10 с —
  «Still confirming…» (`STILL_CONFIRMING_MS`, уже есть); через 60 с без `credited` — исход
  `processing`, запись удаляется, **бронь потом сама не создаётся** (`AURAF-0019`: «бронь — только
  в рамках той же попытки»), деньги лягут на баланс. Интервал и окно — в `config/pay.ts`.
- Ошибка сети при опросе — не исход, опрос продолжается. Таймеры — только в `model/` (правило 4).

### 7. Фейковый провайдер (решения 1, 7)

- `features/pay/model/fake-provider.ts` реализует `TopUpProvider`: состояние каждой попытки — в
  `sessionStorage` (переживает уход на «hosted page» и возврат).
  - `startCard` → `redirectUrl` = песочница `/psp-sandbox?payment=<id>&return=/checkout?payment=<id>`.
  - **Зачисление** — dev-заглушкой BFF `POST /v1/wallet/top-ups` (`TopUpRequest.parse`,
    `TopUpResponse.parse`, ключ = `paymentId`; эндпоинт в `entities/wallet/api`, вызывает его
    только фейк). Это «вебхук» фейка: деньги кладёт сервер, бронь списывает сервер — Booked
    остаётся подтверждением сервера. Заглушка ответила ошибкой (на bff-dev сейчас 503) — статус
    остаётся `pending` (провайдер взял, зачисление не пришло) → через окно — `processing`.
- **Песочница** — страница `pages/psp-sandbox` (`/psp-sandbox`, маршрут регистрируется только при
  флаге, ленивый чанк), вне шапки и таб-бара, явно подписана «Test payment provider — no real
  money moves». Сумма и сценарии:
  - **Approve** — зачисление сразу;
  - **Approve slowly** — зачисление через 15 с (проверка «Still confirming…»);
  - **Never confirm** — остаётся `pending` (проверка окна → `processing`);
  - **Decline** — `declined`;
  - **3-D Secure** — шаг проверки: **Pass** → как Approve, **Fail** → `declined`;
  - **Cancel** — `cancelled`, возврат на сайт.
  Каждый сценарий возвращает на `return` полной загрузкой страницы (как настоящий провайдер).
- Шторка кошелька фейка (§4) — те же Approve / Decline / Cancel.

### 8. Строки

Дополнения `pay` (план, кнопки, `aria-label`, исходы, «processing»), новые namespace
`checkout-page` и `psp-sandbox` — сразу на 24 языках (правило 9). Деньги — `Intl` на языке
интерфейса. Brand names (Apple Pay, Google Pay, Aura) не переводятся.

## Решения (владельцу)

**1. Что фейк делает против настоящего bff-dev.** Эндпоинта PSP-пополнения нет; dev-заглушка
`POST /v1/wallet/top-ups` на bff-dev отвечает **503** (образ BFF — `NODE_ENV=production` на всех
стендах; пункт 8 пробелов `AURAT-0107-005` был ошибкой).
- А. **Фейк зачисляет через dev-заглушку** (контракт v0.22.0 уже есть). Сейчас на bff-dev
  проверяются переход и возврат, отказ, 3-D Secure, отмена, «Still confirming…», окно
  `processing`; успешное зачисление — тестами и на локальном BFF. Для сквозной проверки успеха на
  bff-dev — **BFF-задача**: открыть заглушку отдельным флагом (например
  `WALLET_DEV_TOPUP_ENABLED`, по умолчанию выключен, на проде никогда), а не `NODE_ENV`. ID — в
  `aura-app-manor`.
- Б. Фейк ничего не зачисляет и после «успеха» сразу бронирует: на bff-dev бронь получит 402, а
  экран скажет «$26 на балансе» — неправда.
- В. Только Playwright с перехватом денежных эндпоинтов (пополнение, бронь): UI проверен, сервер — нет.
- **Рекомендация: А + BFF-задача** (попрошу выдать ID). Без неё задача всё равно закрывается: успех
  покрыт тестами, ветки ошибок — в маноре.

**2. Как флаг включается для проверки в маноре.**
- А. **`VITE_PSP_ENABLED=true` в `.env.local` манора + перезапуск dev-сервера**; прод-сборка флаг
  игнорирует, пока провайдер фейковый.
- Б. Переключатель в рантайме (`?psp=fake` → `sessionStorage`) без перезапуска — проще проверять,
  но включается у любого человека по ссылке.
- **Рекомендация: А.**

**3. «Use balance».** Хендофф — тумблер (вычесть баланс из суммы); приложение — тумблер при
`0 < balance < cost`, включён по умолчанию.
- А. Как приложение: тумблер, выключенный — пополнение на всю стоимость.
- Б. **Без тумблера: всегда пополняется только недостача.** Бронь всё равно списывает с баланса —
  выключенный тумблер лишь делает пополнение больше, а остаток так же лежит на балансе.
- **Рекомендация: Б** (меньше UI, тот же результат для человека). Если хочешь паритета с
  приложением — А, это одна строка и `Toggle` из `shared`.

**4. Hosted page карты: redirect или iframe-шторка.**
- А. **Redirect** на страницу провайдера и возврат на `/checkout` — 3-D Secure работает у всех
  провайдеров, и это как раз тот маршрут возврата, который задача должна приготовить.
- Б. iframe в `Sheet` — человек не уходит, но 3-D Secure в iframe ломается у части банков, а
  возврат всё равно нужен (Safari, блокировщики).
- **Рекомендация: А**; iframe — вариант настоящего провайдера, когда он будет выбран.

**5. `/checkout`: что на странице.**
- А. **Только страница возврата** (сводка, статус, исход); без записи — как сейчас.
- Б. Полная страница хендоффа (гарантии, разбор цены, `PayActions`) как вход в оплату.
- **Рекомендация: А** — все входы ведут в шторку (`AURAT-0107-006` §3–5), Б — второй путь оплаты.

**6. Окно опроса.**
- **Рекомендация: опрос каждые 2 с, «Still confirming…» после 10 с, через 60 с — «processing»
  без брони потом** (`AURAF-0019`: бронь только в той же попытке; деньги лягут на баланс).
  Альтернатива — держать запись и бронировать, когда деньги придут позже; не рекомендую: слот
  к тому времени мог уйти, а человек уже ушёл со страницы.

**7. Песочница провайдера.**
- А. **Страница приложения `/psp-sandbox`** (ленивый чанк, только при флаге), строки на 24 языках —
  правило 9 исключений не делает.
- Б. Статичный `public/fake-psp.html` на английском (чужая страница не обязана быть на языке Aura),
  исключённый из прод-сборки.
- **Рекомендация: А** — чище по правилам и тестируется Testing Library; Б — меньше переводов.

## Пробелы BFF / contracts (владельцу → `aura-app-manor`, ID там)

В этой задаче BFF не меняется.

1. **Dev-заглушка пополнения закрыта на bff-dev** (`NODE_ENV=production` везде) — открыть её
   флагом окружения (решение 1А). Исправление к `AURAT-0107-005` п. 8.
2. **Для настоящего PSP** (`AURAF-0009`, форма — порт §2): создание пополнения картой / кошельком
   (`→ redirectUrl | clientSecret`), статус пополнения `GET /v1/wallet/top-ups/:id` (опрос),
   вебхук провайдера, белый список `returnUrl`; правило суммы (целые доллары — правило сторов; PSP
   может брать центы — решить вместе с ним, в вебе это одна функция `top-up-plan.ts`).
3. К сведению: 402 несёт стоимость и баланс только в тексте сообщения — веб считает недостачу из
   кошелька и pricing; структурное поле — вместе с кодами отказов (`AURAF-0020-025`).

## Тесты (Vitest)

- `top-up-plan` — перенос тестов `pay-plan` приложения (покрывает, частично, долг, остаток < $1).
- `pending-payment` — запись, чтение, битое значение, чужой `paymentId`.
- `fake-provider` — сценарии статусов, зачисление заглушкой с ключом `paymentId`, ошибка заглушки
  → `pending`.
- Сквозные (как `booking.test.tsx`, флаг включён через мок `env`):
  - недостача → строка плана, кнопки Apple / Google Pay и «Pay $X»; флаг выключен → временная строка,
    кнопок нет (старые тесты не меняются);
  - карта: запись попытки, `location.assign` на песочницу; возврат `/checkout?payment=` →
    опрос → зачисление (`POST /v1/wallet/top-ups`) → бронь с ключом записи → Booked;
  - отказ → шторка со строкой над кнопками, черновик цел; отмена → шторка без строки;
  - медленное зачисление → «Still confirming…» после 10 с; окно 60 с → «processing», брони нет;
  - после зачисления: 409 → «That time was just taken…», 5xx → «Try again» тем же ключом, 404;
  - кошелёк: панель Approve → опрос в шторке → Booked; Cancel — без сообщения;
  - перезагрузка `/checkout?payment=` до исхода — опрос продолжается; без записи — редирект как раньше;
  - песочница — сценарии и возврат.
- `env` — прод-сборка игнорирует `VITE_PSP_ENABLED`.
- `npm run lint && npm run typecheck && npm test && npm run build` — зелёные.

## Проверка в маноре (после merge)

`VITE_PSP_ENABLED=true` в `.env.local` манора, аккаунт с балансом меньше цены сессии. Шторка →
план и кнопки → «Pay $X» → песочница → Decline / 3-D Secure Fail / Cancel → шторка с нужным
текстом; Approve slowly → «Still confirming…»; Never confirm → «processing» через минуту. Approve —
до BFF-задачи (1А) заглушка ответит 503 → «processing»; после неё → Booked, баланс вырос на
пополнение и уменьшился на сессию. Кошелёк — те же ветки в шторке. Флаг убран — всё как в
`AURAT-0107`.
