# AURAT-0069-001 — Ключи колоды таро: `.png` → `.jpg`

Дата: 2026-09-14
Статус: **заведена, не начата**
Репозиторий: `aura-bff` (`aura-bff-manor`). Заведена из `aura-app-manor` —
найдено проверкой `AURAT-0068` (`012`–`015`).

## Что сломано

Карты таро в приложении рисуются без арта: **все 78** адресов
`https://assets.aura-app.cc/tarot/*.png` отдают 404.

Владелец перезалил колоду в R2 (`aura-assets/tarot/`, 10 Sep 2026 16:41) под
теми же именами, но **`.jpg`**: `cups-02.jpg`, `major-00-fool.jpg` … Прежние
`.png`-объекты в бакете больше не лежат. Проверено 14.09 с Mac, с обходом кеша:

| Ключи | Ответ |
|---|---|
| 78 × `tarot/<card>.png` (из манифеста `AURAD-0012`) | **404** |
| те же 78 × `tarot/<card>.jpg` | **200 image/jpeg** |

Приложение здесь не участвует: `imageUrl` приходит от BFF готовым
(`TAROT_ASSETS_BASE_URL` + `imageKey`).

## Что менять

- `src/modules/tarot/tarot-deck.data.ts` — 78 `imageKey` `.png` → `.jpg`.
- Спеки с этими ключами (`chat.service.spec.ts`, `tarot.service.spec.ts`,
  `tarot.smoke.spec.ts`) — по месту.
- **Базу руками не править**: `src/seed.ts` делает `tarotCard.upsert` с
  `update: { ...card }` на каждом старте контейнера — ручная правка затрётся
  ближайшим деплоем, а правка данных, наоборот, доедет сама.
- `brain/decisions/AURAD-0012-deck-manifest.json` описывает `.png` с их
  `sha256` / `bytes` — после перезалива неверен; пересчитать по `.jpg`-файлам,
  которые залиты (на диске в `/Volumes/Work/personal/lightseerstarot/` лежат
  `.png`, источник `.jpg` — уточнить у владельца). `AURAD-0012-upload.sh` —
  тоже под новые ключи.

Мёрж в `develop` `aura-bff` — это деплой (`AURAS-0004`). Пересборка приложения
не нужна.

## Проверка

После деплоя: все 78 `imageUrl` из `GET /v1/tarot/...` отдают 200; на
устройстве у карты дня и в веере чата есть арт.

## Урок

Ровно сценарий `AURAD-0012` («новый арт едет **новыми объектами**, `imageKey`
переставляется на них»), но в обратном порядке: старые объекты ушли раньше, чем
переставили ключ — и 78 карт разом остались без картинки.
