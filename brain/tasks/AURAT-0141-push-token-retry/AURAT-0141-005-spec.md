# AURAT-0141-005 — spec (draft)

Тип: задача (без feature-спеки), только приложение. BFF не меняется.

## Цель

Вошедший пользователь на живой установке всегда имеет FCM-токен в BFF, даже если запрос
разрешения завис, а сеть или BFF не ответили при старте.

## Изменения — `src/features/push/`

1. **Токен не ждёт разрешения.** `register()` сначала делает `getToken()` → `registerDevice`, а
   `notifee.requestPermission()` запрашивается отдельно, без `await` перед токеном (`.catch(() => {})`).
   Момент показа системного запроса не меняется: он появляется при входе, как сейчас. FCM выдаёт токен
   без разрешения; без разрешения не будет только показа, а токен в BFF будет, и пуш появится сразу,
   как только человек включит уведомления в настройках.
2. **Повтор при возврате на экран.** Пока пользователь в аккаунте — подписка на `AppState` `active`:
   регистрация повторяется, если прошлая попытка не удалась или с последней удачной прошло больше
   `TOKEN_REFRESH_INTERVAL_MS` (12 ч, в `config/constants.ts`). `PUT` идемпотентный, так что повтор
   заодно возвращает токен, если BFF его удалил (например, второй аккаунт на том же телефоне).
   Одновременно идёт не больше одной попытки.
3. При выходе из аккаунта и при смене пользователя состояние «последняя удача» сбрасывается, подписка
   на `AppState` снимается (как сейчас `onTokenRefresh`).
4. Тесты: новый `model/__tests__/push-registration.test.ts` — токен регистрируется, даже когда
   `requestPermission` не разрешается никогда; повтор на `active` после сбоя; нет повтора на `active`
   в пределах интервала; повтор после интервала; ничего не делается без пользователя; нет второй
   параллельной попытки.

## Не входит

- **Диагностика в BFF** (шаг, на котором сорвалась регистрация) — нужен новый эндпоинт и контракт,
  то есть отдельная задача в `aura-bff-manor`. Предложение: сначала выпустить эту правку и через неделю
  повторить запрос «писали советнику за 7 дней, а токена нет». Если цифра не упадёт почти до нуля —
  тогда заводить диагностику. Решает владелец.
- iOS (нет iOS-токенов вообще — отдельный вопрос при проверке iOS-сборки).
- Хранение статуса разрешения в BFF.
