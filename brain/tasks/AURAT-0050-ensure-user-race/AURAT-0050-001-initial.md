# AURAT-0050-001 — Гонка в `ensureUser`: P2002 на параллельных первых запросах нового пользователя

Дата: 2026-09-01
Статус: заведена
Репозиторий: **aura-bff**
Слот: `slave-2`, ветка `feature/AURAT-0050-ensure-user-race`
ID: выдан владельцем; счётчик забамплен в `aura-app-manor` (`AURAT: next free = AURAT-0051`)
Приоритет: P1 — не косметика: страдает первый холодный старт нового
пользователя, включая регистрацию FCM-токена

## Запрос владельца

> Починка гонки в `ensureUser` — P2002 на параллельных первых запросах нового
> пользователя. Найдено манорским прогоном эндпойнтов таро (`AURAT-0049`)
> 2026-09-01. Это **не** баг таро — таро только вскрыло его.

Воспроизведение (в маноре, не гипотеза): четыре одновременных первых запроса
`GET /v1/tarot/daily?tz=Europe/Madrid` с ID-токеном **нового** Firebase UID —
один 200, три 500:

```
PrismaClientKnownRequestError P2002
  Unique constraint failed on the fields: ("firebaseUid")
  originalMessage: duplicate key value violates unique constraint "users_firebaseUid_key"
  at prisma-users.repository.js:23 → this.prisma.user.upsert(
  at TarotService.getDailyCard
```

Окно узкое: только пока строки в `users` нет. Как только пользователь заведён,
upsert идёт по ветке update и всё в порядке.

## Требования владельца к работе

- Правка идемпотентности **на уровне репозитория** (поймать P2002 и перечитать
  строку либо вернуть нативный `ON CONFLICT` — выбрать обоснованно и описать
  почему).
- Тест именно на **параллельный** `ensureUser`, иначе регрессия вернётся
  незамеченной. В слейве только чистые юнит-тесты: без БД, Redis и Chatwoot.
- Поправить комментарий над `ensureUser`, если он перестанет врать.
- Рассмотреть запись в `TECH-DEBT.md`, если что-то остаётся незакрытым.
- Гипотезу о причине **проверить, а не поверить на слово**.

## Что не трогать

Розыгрыш карты дня гонку держит: шесть параллельных первых запросов на
нераспределённую дату — все 200, одна и та же карта, одна строка. PK
`(userId, localDate)` работает как задумано, `dealDailyCard` корректно уступает
тому, кто успел первым.

## Чем критично

Первый холодный старт нового пользователя сразу после регистрации по телефону —
самая дорогая точка воронки, приложение стреляет запросами одновременно. Хуже
косметики: регистрация FCM-токена — один из этих параллельных запросов, а в
приложении она висит в `useEffect` и **глушит ошибку без ретрая**
(`aura-app`, `src/features/push/model/push-registration.ts:31`, `catch {}`),
повторяясь только при следующем запуске приложения или обновлении токена. Если
гонку проиграл именно он — устройство остаётся незарегистрированным и весь
первый сеанс человек молча не получает пуши.
