# AURAT-0114-005 — Spec: живая платная сессия в треде aura-web

Date: 2026-10-20
Type: task (строка `AURAF-0020-029`, колонка UI). Новой фичи нет.
Status: approved 2026-10-21 (решения 1–9 по рекомендациям; правки по ревью: ключ продления, 404,
номера строк бэклога — 036, 042)

## Цель

Когда у человека идёт платная сессия с советником, тред этого советника это показывает и даёт
ею управлять, как в приложении (`AURAT-0010`, `AURAT-0015`, мобильный `SESSIONS_BOOKING.md` §5b):
баннер с обратным отсчётом от `endsAt` по часам BFF, предупреждение в последние 120 с, продление
блоками сервера (Extend), раннее завершение с предупреждением о сгорающих минутах. Сессия берётся
из кэша сессий (`AURAT-0110`) и двигается `session.updated` — **ни одного запроса по советникам**
(`AURAT-0090`). Деньги — сервера (правило 7): цену показываем по формуле, по которой BFF
списывает, «продлено» — только по ответу сервера, ключ попытки — до определённого исхода.
BFF и contracts **не меняются**; пробелы — в конце, владельцу для `aura-app-manor`.

Решения 1–9 — в конце, у каждого варианты и рекомендация. «Что делаем» написано по рекомендациям.

## Что делаем

### 1. Данные — `entities/session` (дополнение)

- **lib** `live-session.ts` (веб-собственное, + тест): `liveSessionFor(sessions, advisorId, now)` →
  `{kind: 'live', session}` — ACTIVE этого советника с `remainingSeconds > 0`; иначе
  `{kind: 'soon', session}` — ближайшая SCHEDULED этого советника не позже чем через 24 ч
  (решение 2), включая только что прошедший слот, ещё не начатый метром («Starting…», как
  `sessionState`); иначе `null`. Состояние — по `sessionState` (уже перенесён), часы — `serverNow()`.
- **lib** `countdown.ts` — перенос копией `formatCountdown` из `features/paid-session/lib/format-countdown.ts`
  с тестами, шапка `// Ported from aura-app … (AURAT-0010, AURAT-0015)`. `formatMinutes` не
  переносится — «N min» это строка локали с плюралом.
- **lib** `progress.ts` — доля прошедшего блока (формула баннера приложения
  `(bookedSec − remaining) / bookedSec`, clamp 0..1) + тесты баннера приложения про проценты.
- **config** `sessions.ts`: `EXTEND_PROMPT_SECONDS = 120`, `COUNTDOWN_TICK_MS = 1000`,
  `STARTING_SOON_HOURS = 24` — перенос `config/constants.ts` приложения (то, что нужно). Пульс точки
  — CSS (`--dur-live-dot: 1.6s` в `tokens.css`, `orb-pulse` уже есть), не константа JS.
- **model** `useLiveSession(advisorId)` → `{kind, session, remainingSeconds, nearEnd, progress} |
  null`: читает тот же `getSessions` (одна выборка на приложение, тег `Session`), тикает раз в
  секунду **только** пока есть `live` / `soon`; в 0 баннер снимается сам, без запроса (как
  приложение), `session.updated` (FINISHED) приходит следом. Биллинг выключен (404) — `null`.
- **ui** `SessionBanner` (render-only, `React.memo`):
  - **live** — plum-градиент (`--plum` → `--plum-2`), плитка с золотыми часами, teal-точка с
    пульсом и «Paid session live» (gold, uppercase), «{N} min booked · tap for details», справа
    счётчик `20:57` (Bricolage 800, `tabular-nums`) и «Left», снизу полоса прошедшего (teal).
    Последние 120 с — счётчик `--accent-soft`, полоса коралловая (как приложение; ничего не
    открывается — отсчёт не прерывает разговор, `AURAD-0002`).
  - **soon** (решение 2) — белая карточка с линией, плитка `cal`, «Session scheduled» (ink-3), «Starts
    soon · {N} min booked», счётчик до старта и «Until start», без полосы; слот прошёл, метр ещё не
    запустил — «Starting…» вместо счётчика.
  - Вся карточка — `<Link>` на `/sessions?id=` (решение 8); `aria-label` «Paid session live, {t}
    left. Open the session.» / «Session with {name} starts in {t}. Open the session.». Счётчик —
    `role="timer"` (не объявляется каждую секунду); скрытая `aria-live="polite"` строка один раз
    говорит «2 minutes left in your session» на пороге. `prefers-reduced-motion` — точка без пульса.
- `entities/wallet`: `walletBalanceUpdated(balanceMinor)` — баланс из ответа сервера кладётся в кэш
  `getWallet` без перечитки (как приложение публикует его в стор).

### 2. Продление — `features/extend-session` (dialog `extend`)

- **api** `extendSession {sessionId, minutes, idempotencyKey}` — `POST /v1/sessions/:id/extend`,
  тело `ExtendSessionRequest.parse`, ответ `BookSessionResponse.parse`; успех → `sessionUpdated(session)`
  + `walletBalanceUpdated(balanceMinor)`; 402 → тег `Wallet`; 409 → тег `Session` (перечитать список).
- **lib** `blocks.ts` — перенос `features/paid-session/lib/blocks.ts` с тестами: `smallestBlockMinutes`
  копией; `toBlockOptions(pricing, session, balanceMinor)` — **цена блока
  `minutes × session.priceMinorPerMinute`** (формула `extendLocked` BFF), а не `costMinor` блока
  pricing (решение 4; расхождение с приложением — в просьбы); без английских `minutesLabel` /
  `costLabel` — их делает ui через локаль и `PriceTag`. `affordable` — как приложение (неизвестный
  баланс — всё доступно, настоящий страж — 402).
- **model** `useExtendSession(sessionId)` — по `use-paid-session` приложения:
  - на открытии — перечитка кошелька; блоки — минуты из `useSessionPricing(advisorId)` (уже есть),
    цена — по сессии; выбран первый доступный блок;
  - один ключ на попытку (`crypto.randomUUID()`), держится до определённого исхода; 400/402/404/409 —
    ключ сгорает; нажатие во время запроса ничего не шлёт;
  - **исход неизвестен** (сеть / 5xx / разбор) — «That didn’t go through. Please try again.», выбор
    блока заблокирован, повтор — **те же минуты и тот же ключ**. Иначе, чем у брони: BFF сверяет ключ
    продления с суммой (`replaysExtend`), и тот же ключ с другим числом минут — 409 «idempotencyKey
    was already used for a different charge», даже если первое списание прошло (веб принял бы его за
    наезд и выключил блоки, а 10 минут уже оплачены). Попытка (`sessionId`, минуты, ключ, `endsAt`
    до неё) переживает закрытие шторки. Шторку закрыли или выбрали другой блок («Choose another
    block») — сначала перечитать сессии: `endsAt` сдвинулся — продление засчитано («Added {N}
    minutes», попытка снята); не сдвинулся — попытка снята, следующая — с новым ключом;
  - успех — шторка закрывается, баннер берёт новый `endsAt` из ответа, скрытое объявление «Added
    {N} minutes» (тоста в вебе нет);
  - 402 — шторка остаётся, кошелёк перечитан, блоки сверх баланса выключены, строка нехватки
    (решение 6);
  - 409 — перечитать сессию; уже не идёт → шторка закрывается (баннер снят, маркер «Session ended»
    в треде); ещё идёт → шторка остаётся с «That much time isn’t free right after this session —
    try a shorter block.», выбранный и более длинные блоки выключены до закрытия шторки (решение 5);
  - 404 — `extend` советника не проверяет: это «сессии нет или она чужая» (`requireOwnedSession`)
    либо «биллинг выключен» (`BillingEnabledGuard`). Шторка закрывается без текста, сессии
    перечитываются — баннер снимается по кэшу;
  - сессия закончилась, пока шторка открыта (часы или `session.updated`) — шторка закрывается сама.
- **ui** `ExtendSheet` (`Sheet`): «Add more minutes», «{name} · {rate}/min» (`PriceTag`), сетка
  блоков `role="radiogroup"` («+{N} min», цена; выключенный — `aria-disabled` и причина), строка
  «Balance {amount}», заметка «The block starts right away and is non-refundable. Chatting between
  sessions stays free.», кнопка «Extend · {amount}» / «Choose a block» (coral), ссылка «End session
  early» → dialog `finish` (решение 7). Без PSP — строка «Top up in the Aura app — it’s the same
  balance here.» вместо ссылки Top up (пополнения в вебе нет).

### 3. Раннее завершение — `features/finish-session` (dialog `finish`)

- **api** `finishSession(sessionId)` — `POST …/finish` без тела, `FinishSessionResponse.parse` →
  `sessionUpdated(session)`. Ответ не FINISHED (сессия уже не шла — BFF отвечает 201 без изменений) —
  то же: кэш берёт серверную сессию.
- **model** `useFinishSession(sessionId)`: минуты, которые сгорят, — `minsLeft` по `serverNow`; один
  запрос за раз (повтор безопасен — BFF идемпотентен); ошибка — «That didn’t go through. Please try
  again.» в шторке.
- **ui** `FinishSheet`: «End this session?», «The remaining {N} min are non-refundable and won’t
  return to your balance. You can keep chatting for free afterwards.» (текст приложения), «Keep
  going» / «End session» (coral). Успех — шторка закрывается, баннер снят, маркер конца — в треде.

  наименьшего блока, без блоков — календарь; Extend шлёт минуты и UUID-ключ, берёт сессию и баланс из

  merge. Тест `advisors.test.tsx` «next 4 slots» не трогаю (`AURAT-0108`).

## Решения владельцу

1. **Где таймер.** (A) баннер под шапкой треда на всех ширинах — как приложение и мобильный §5b;
   (B) веб Plan: на desktop таймер и «Add more minutes» в правой колонке, баннер — только до 1180 px.
   **Рекомендую A**: колонка видна только ≥ 1180 px, а отсчёт, за который человек платит, должен
   быть в одном месте при любой ширине; один компонент, одна логика.
2. **Баннер до старта.** (A) нет — как приложение; (B) «Session scheduled · Until start» за ≤ 24 ч —
   мобильный хендофф §5b; (C) то же, но только за последний час. **Рекомендую B**: дизайн это
   рисует, данные уже в кэше, человек в треде видит, когда начнётся; приложению — просьба
   догнать (в просьбы).
3. **Шапка во время сессии.** (A) календарь меняется на «Extend +{наименьший блок} min» — как
   приложение и заглушка; (B) календарь остаётся, Extend — только кнопкой в баннере. **Рекомендую A**;
   бронь следующей сессии остаётся в правой колонке и в приглашении.
4. **Цена блока.** (A) `minutes × session.priceMinorPerMinute` — ровно то, что спишет BFF; (B)
   `costMinor` блока pricing — как приложение. **Рекомендую A**: pricing — цена брони по текущей
   цене советника; если советник сменил цену после брони, B покажет одну сумму, а спишется другая
   (правило 7). Это дефект и в приложении — в просьбы (по правилу переноса фикс — на обе стороны).
5. **409 продления.** (A) молча закрыть и перечитать — как приложение; (B) перечитать: сессия
   кончилась — закрыть; идёт — остаться с «That much time isn’t free right after this session — try a
   shorter block.» и выключить этот и более длинные блоки. **Рекомендую B**: причину различаем по
   состоянию сессии после перечитки, а не по английскому тексту отказа (кодов нет — `AURAF-0020-025`);
   молчаливое закрытие оставляет человека гадать, почему минуты не добавились. Наезд на свою сессию и
   на бронь советника — одной фразой. Работает только вместе с правилом ключа из §2: пока исход
   неизвестен, блок не меняется, иначе 409 «ключ потрачен» читается как наезд.
6. **402 / PSP.** (A) в этой задаче без PSP: блоки сверх баланса выключены, строка «Your balance is
   {amount} short for {N} min. Top up in the Aura app — it’s the same balance here.», 402 —
   перечитка кошелька и та же строка; PSP-пополнение недостачи при продлении — отдельной строкой
   после merge `AURAT-0108`; (B) ждать `AURAT-0108` и делать путь PSP сейчас. **Рекомендую A**: не
   блокируемся; `AURAT-0108` строит пополнение под бронь, под продление его порт придётся обобщать
   (пополнить → продлить тем же ключом) — это своя задача.
7. **Где раннее завершение.** (A) ссылка «End session early» в шторке Extend → подтверждение — как
   приложение; (B) ещё и в баннере / меню шапки. **Рекомендую A**: опасное действие не на виду, но в
   один шаг от продления.
8. **Куда ведёт баннер; список чатов.** (A) баннер → `/sessions?id=` (как приложение → Session
   Detail) и пилюля «Session live · N min left» в списке чатов с живыми сверху (`AURAT-0015`); (B)
   баннер → шторка Extend, список чатов не трогать. **Рекомендую A** — паритет с приложением, данные
   уже в кэше, запросов нет.
9. **Статус под именем.** (A) во время сессии «Online · paid session» / «Paid session» вместо «free
   chat»; (B) не менять. **Рекомендую A**: «free chat» во время платной сессии неправда.

## Пробелы BFF / contracts / приложения — владельцу для `aura-app-manor`

1. Отказы продления без `code`: четыре разных 409 одним статусом — дописать к `AURAF-0020-025`.
2. 402 продления без полей недостачи (`cost` и `balance` — только в тексте) — веб считает по
   перечитанному кошельку.
3. Нет цены продления на проводе: pricing — цена брони (текущая цена, оффер). Нужны блоки продления
   сессии с серверной ценой (или `extendBlocks` в `Session`).
4. Нет «насколько можно продлить» (следующая бронь советника / своя сессия) — узнаём только 409.
5. BFF: повтор продления ищется по кошельку, а не по сессии — тот же ключ и сумма на другой сессии
   засчитываются как повтор (мелкий дефект `replaysExtend`). Низкий приоритет: клиенты создают ключ
   на каждую попытку, на практике не срабатывает.
6. Приложение: цена блока из pricing (решение 4) — расходится со списанием при смене цены советника;
   шторка продления остаётся открытой после конца сессии; нет баннера «starting soon» (если решение
   2 = B); 409 продления молча — строка `AURAF-0020-036` (уже выдана).
7. Строка бэклога «PSP: пополнение недостачи при продлении» (если решение 6 = A) — после
   `AURAT-0108`, `AURAF-0020-042` (037–041 — пробелы PSP, их заняла `AURAT-0108`, brain `7e34925`).
   Номер сверить по `origin/master` в момент коммита закрытия: если 042 занят — следующий свободный.
