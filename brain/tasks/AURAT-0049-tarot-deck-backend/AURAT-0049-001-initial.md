# AURAT-0049-001 — Колода таро переезжает на сервер: карта дня, тексты, картинки

Дата: 2026-08-31
Статус: заведена, не начата
Репозиторий: **aura-bff** (+ `aura-contracts`, потом `aura-app`)
Приоритет: P2 — ничего не сломано, приложение работает; это то, что делает
механику настоящей

## Запрос владельца

> «Давай так же задачу беккенду, чтобы мы хранили инфу про карту дня для юзера
> там, мб так будет лучше. И тогда описание карт можно хранить на бекенде, для
> надёжности»

## Что сейчас и почему этого мало

Карта дня целиком живёт в приложении (`AURAT-0048`):

- колода — **семь** карт, зашиты в `entities/tarot/config/deck.ts`;
- выбор — `FNV-1a(uid + YYYY-MM-DD)` по этим семи, то есть **выводится**, а не
  хранится;
- «вытянута сегодня» — модульная переменная, **умирает вместе с процессом**;
- тексты (три ключевых слова и фраза напутствия) — в бинарнике, правка = релиз.

Всё это записано как `TECH-DEBT #9` в `aura-app`. Эта задача закрывает строку
целиком.

Что именно плохо, по убыванию:

1. **Повторы.** При колоде из семи карт повтор приходит примерно к четвёртому
   дню, и одна и та же карта два дня подряд возможна. Для механики, которая
   существует ради ежедневной привычки, это самое заметное.
2. **Тексты нельзя починить без релиза.** Опечатка в напутствии живёт до
   следующей выкатки в стор.
3. **Ничего не измеряется.** Сервер не знает, что кто-то тянул карту, — значит
   ни пуша «ваша карта ждёт», ни цифр по механике.
4. Флаг «вытянута» забывается при перезапуске (косметика: карта выводится, так
   что возврат всё равно показывает ту же).

## Что сделать

### 1 · Картинки — уже решено, `AURAD-0012`

Бакет `aura-assets`, плоско: `tarot/major-19-sun.png`, как `avatar/olivia.png`.
В базе **ключ**, базовый адрес — `TAROT_ASSETS_BASE_URL`, склейка при чтении,
ровно как `advisors.service.ts` делает с аватарами. Приложение адрес не строит.

Манифест на 78 карт (id, ключ, sha256, размер) —
`brain/decisions/AURAD-0012-deck-manifest.json`. **Заливка ждёт вопроса о
правах** — бакет публичный, так что заливка это публикация. Схему можно
проверить на любом своём плейсхолдере.

### 2 · Таблица карт

`tarot_cards` — справочник, не пользовательские данные:

```
id          text pk      -- 'major-19-sun', 'cups-02', 'wands-knight'
imageKey    text         -- 'tarot/major-19-sun.png'
name        text         -- 'The Sun'
keywords    text         -- 'Clarity · Warmth · Vitality'
daily       text         -- одна фраза общего напутствия
arcana      text         -- 'major' | 'minor'
suit        text null    -- 'wands' | 'cups' | 'swords' | 'pentacles'
rank        text null    -- 'ace' | '02'…'10' | 'page' | 'knight' | 'queen' | 'king'
sortOrder   int          -- порядок колоды, для админки и сидов
```

`id` — Райдер–Уэйтовский стандарт, он **не зависит от колоды**: сменится арт —
сменится `imageKey`, идентичность карты останется. Это то, что делает замену
колоды переставлением колонки.

**Локализации пока нет** — тексты по-английски, одним набором. Когда появится,
это отдельная таблица переводов, а не колонки `name_ru`; закладываться сейчас
не нужно, но `id` уже готов быть ключом перевода.

### 3 · Таблица вытянутых карт

`user_daily_cards` — вот ради чего задача:

```
userId    text     -- Firebase uid
localDate date     -- 'YYYY-MM-DD' в зоне пользователя (см. ниже)
cardId    text fk -> tarot_cards.id
dealtAt   timestamptz
drawnAt   timestamptz null   -- когда ритуал доиграли до раскрытия
pk (userId, localDate)
```

Первичный ключ — это и есть «одна карта в день на человека»: второй раздачи за
тот же день не будет, потому что её некуда записать.

### 4 · Чей день считается «сегодня» — решено владельцем

**По часовому поясу устройства.** Приложение шлёт IANA-зону (`Europe/Madrid`),
сервер по **своим** часам считает, какая в этой зоне дата.

Почему не проще:

- **Не дата от клиента.** Дату клиент назвать не должен: `AURAT-0048` только что
  закрыл ровно этот перекат — карту выбирает день, значит день, которым владеет
  телефон, это карта, которую телефон может перевыбрать. Зона такой ручкой не
  является: она сдвигает границу максимум на сутки, а запись `(userId,
  localDate)` не даёт раздать один и тот же день дважды.
- **Не UTC.** У пользователя в Испании карта менялась бы в 01:00 летом, в
  Калифорнии — в 17:00. Для «карты дня» это неверно по смыслу.
- Прецедент в коде уже есть: бронирование шлёт `tz` из `deviceTimeZone()` ровно
  за тем же — решить, к какому дню отнести слот.

Зону, которой сервер не верит (пустая, неизвестная), обрабатываем как отсутствие:
берём UTC и не падаем — граница дня хуже, чем могла быть, но карта есть.

### 5 · Как сервер выбирает карту

На первом запросе за день: если записи на `(userId, localDate)` нет — выбрать
карту, записать, отдать. Есть — отдать записанную, ничего не меняя.

**Выбор должен избегать недавних.** Это главная причина всей задачи: исключить
карты, выпадавшие этому пользователю за последние N дней (предлагаю N = 14 при
78 картах — примерно пятая часть колоды), и выбрать из оставшихся. Случайно, а
не по кругу: порядок, который пользователь может заметить, — это не гадание.

### 6 · Эндпойнты

```
GET  /v1/tarot/daily?tz=Europe/Madrid
  200 { card: { id, name, keywords, daily, imageUrl }, localDate, drawn }

POST /v1/tarot/daily/drawn        # ритуал доигран до раскрытия
  { tz }  ->  204
```

`imageUrl` приходит **готовым**, склеенным из `TAROT_ASSETS_BASE_URL`.

`POST` идемпотентен: второй вызов за тот же день ничего не меняет. Он же —
единственный сигнал ретеншена, который у механики появится.

Контракты (`@aura/contracts`) — zod-схемы рядом с остальными, как
`HoroscopeEntry`.

### 7 · Что меняется в приложении (отдельным шагом, после сервера)

- `entities/tarot`: `cardOfDay` и `dailyCardStore` заменяются на чтение, как
  `entities/horoscope`. Семикарточная колода и хеш **удаляются**, не остаются
  запасным путём — две колоды это два ответа на один вопрос.
- `TarotCardFace` рисует картинку; типографское лицо остаётся тем, что видно,
  пока она едет, и тем, что остаётся, если не доехала — как монограмма под
  аватаром советника. `Image.prefetch` на входе в экран: у ритуала 2,8 секунды
  форы.
- `TECH-DEBT #9` в `aura-app` удаляется.

**Без сети — честное «не загрузилось»** (решено владельцем). Второй колоды в
бинарнике не будет: советники, чат и гороскоп без сети тоже не работают, а
запасная колода — это ровно тот второй источник правды, ради избавления от
которого задача и делается.

4. Приложение.

Пункт 4 не начинать, пока 3 не отдаёт настоящие данные: половина приложения на
сервере и половина в бинарнике — это состояние, в котором никто не скажет,
какая карта настоящая.

## Чего не хватает — не код

**Тексты на 78 карт.** По-английски их в дропе нет: PDF — скан без текстового
слоя (`/Font 0`, страницы картинками JBIG2). Рядом лежит русский `.doc`, но
локализации нет. И даже с текстом это не извлечение: модели нужны **три
ключевых слова и одна фраза**, а книга даёт абзацы. Семь карт, которые уже
написаны (`AURAT-0048`), — образец тона; остальные 71 кто-то должен написать.

Пока их нет, таблицу можно завести на этих семи и раздавать из них — сервер
уже будет настоящим, повторы уже уйдут, а колода дорастёт по мере написания.

## Проверка результата

- Два запроса подряд за один день дают **одну и ту же** карту; запись в
  `user_daily_cards` одна.
- Смена зоны на границе суток не даёт второй карты за уже розданную дату.
- За 14 дней подряд у одного пользователя ни одного повтора.
- `imageUrl` отдаёт 200 с `assets.aura-app.cc`.
- `POST …/drawn` дважды — 204 оба раза, `drawnAt` не сдвигается.
