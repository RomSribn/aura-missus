# AURAT-0146-005 — spec: публичные промокоды (BFF + бэкофис + контракт v0.26.0)

Дата: 2026-10-31 · Статус: **approved** (`-006`), правка пояса срока — `-007`
Тип: задача (фича уже есть — `AURAF-0022` строки 001–002; новый feature-файл не нужен).
Основа: `AURAI-0009` §2 «A1» + §8, находки `-004`.

## 1. Что получится

- В бэкофисе на вкладке «Промокоды» рядом с «Новая партия» — кнопка **«Публичный код»**.
  Форма: **код** (`WINTER5`), **сумма**, **кампания**, **действует до**. Дальше — та же страница
  подтверждения: «`WINTER5` · $5 каждому аккаунту, один раз · без лимита погашений · до 31.12
  включительно (UTC)».
- Любой аккаунт вводит `WINTER5` (или `winter 5`, `Winter-5`) в приложении или на вебе — получает
  кредит `PROMO_CREDIT`. Повтор тем же аккаунтом — `200` c `replayed: true` («уже зачислено»).
- Клиенты не меняются: ни новых полей, ни новых отказов.

## 2. Правила публичного кода

| Правило | Значение |
|---|---|
| Имя | выбирает оператор; после нормализации (регистр, пробелы, дефисы — как сейчас) **4–20 символов `A–Z0–9`**, хотя бы одна буква |
| Уникальность | глобальная, навсегда (как у всех кодов): `WINTER5` второй раз не выпустить — в следующем году `WINTER26`. Занятое имя — ошибка поля формы |
| Сумма | от $1; не меньше самой дешёвой сессии — только с галочкой на подтверждении (§4) |
| Кто | все аккаунты; по одному разу на аккаунт (уже есть `@@unique([batchId, walletId])`) |
| Лимит, бюджет, старт | нет (решение владельца §8): код работает с момента создания до конца срока |
| Отключить | можно в любой момент, в т. ч. после погашений: новые погашения → `promo_code_disabled`, начисленное остаётся |
| Срок | как у партий: до 365 дней, по умолчанию 90 |
| Перебор | лимит «10 неизвестных кодов в час» без изменений |

## 3. Данные и погашение

**Схема** (миграция `20261031120000_public_promo_codes`, ничего не удаляет из данных):
- `enum PromoBatchKind { SINGLE PUBLIC }`; `PromoBatch.kind` `@default(SINGLE)` — все текущие партии
  становятся `SINGLE` без бэкфилла.
- `PromoRedemption.kind` — копия вида партии (как `batchId`, «чтобы правило было ограничением»).
- `codeId @unique` → обычный индекс + **частичный unique** `promo_redemptions(codeId) WHERE kind =
  'SINGLE'` (сырой SQL, прецедент — `sessions_one_active_per_conversation`). Связь
  `PromoCode.redemption?` → `redemptions[]`.
- Публичная партия = одна строка `promo_codes`, `quantity = 1`.

**Погашение** (`PrismaPromoCodesRepository.redeemIn`):
1. Код ищется по нормализованному имени; нормализация пропускает любой код формы `A–Z0–9{4,20}`
   (одноразовые 8-символьные — частный случай), дальше решает база.
2. Замок строки кода: одноразовый — `FOR UPDATE` (как сейчас); публичный — **`FOR SHARE`**, чтобы
   тысячи погашений `WINTER5` не вставали в очередь друг за другом, но отключение (`FOR UPDATE`)
   их всё равно сериализует.
3. Повтор ищется по паре (код, кошелёк) → `replayed`; одноразовый, погашенный другим → `already_used`.
4. Под замком кошелька найденное погашение той же партии: **тот же код → `replayed`** (гонка двух
   запросов одного аккаунта), другой код → `campaign_used` (как сейчас).
5. Ключ проводки `promo:<codeId>` **не меняется**: unique в `ledger_entries` —
   `(walletId, idempotencyKey)`, он уже на кошелёк (расхождение с `AURAI-0009` — в `-004` п. 4).

Отказы публичного кода: только `not_found`, `expired`, `disabled` — все три клиенты уже понимают.

## 4. Порог «меньше самой дешёвой сессии»

- В модуле sessions — `SessionPriceFloor.cheapestSessionCostMinor()` (в реализации `-008`): `min(priceMinorPerMinute)` по
  всем советникам (бронь не смотрит на `active`) × `min(SESSION_BLOCK_MINUTES)`, минус скидка первой сессии
  (`firstSessionDiscount`). Сейчас по умолчанию: 10 × $2.20 = $22 → **$11.00**. Считается на лету
  из базы и env, поэтому прод-значения подхватываются сами — сверка с Coolify не нужна для кода,
  но число видно на форме: «сейчас самая дешёвая сессия — $11.00, код должен быть меньше».
- Проверяется на подтверждении и на создании. Нет ни одного советника → публичный код не создаётся
  (порог не посчитать).
- Порог проверяется **при создании**: если потом цену снизят или блок станет 5 мин, уже живой код
  не пересчитывается — оператор отключает его вручную. Это же место пересчитает `AURAT-0147`, когда
  скидка кампании сможет быть больше 50%.
- **Решение владельца (`-006`):** предупреждение + галочка «понимаю: код без лимита оплатит сессию целиком»; без неё не создаётся.

## 5. Бэкофис (только вкладка «Промокоды», `layout.view.ts` не трогаем)

- Список: кнопка «Публичный код»; в колонке «Погашено» у публичных — «N погашений» вместо `N / 50`,
  метка «публичный».
- Сводка: «Выпущено» — только одноразовые (Σ сумма × количество) с подписью «без публичных»;
  «Погашено» — всё; «Активно сейчас» — одноразовые + строка «и N публичных кодов без лимита».
- Страница публичной партии: код крупно (без дефиса посередине), сумма, срок, погашений и сколько
  начислено, кнопка «Отключить код» (с той же галочкой). Таблица кодов и CSV — только у одноразовых.
- Отключение партии/кода для публичного кода отключает его, несмотря на погашения.

## 6. Контракт `@aura/contracts` v0.26.0 — только документация

Zod-схемы не меняются (клиенты без релиза). В `src/promo.ts`: шапка — два вида кодов; `code` —
«публичный код можно передавать и в URL веба» **не пишем** (это решение `AURAT-0149`); пояснения
у `already_used`/`campaign_used` — «только одноразовые»; у `replayed` — «и для публичного кода».
README, `package.json` 0.26.0, тег `v0.26.0`. BFF переходит на `#v0.26.0`.
**Push `main` + тега — только с твоего одобрения** (как merge gate).

## 7. Тесты (чистые, в слоте) и проверка в маноре

- Юнит: формат/нормализация vanity, черновик публичного кода (имя, сумма vs порог, пустой порог),
  `cheapestSessionCostMinor`, статус публичного кода, сервис погашения, view (публичная партия,
  сводка, экранирование), repository-спеки на ветки redeem (replay по паре, `FOR SHARE`).
- Манор после мёржа: миграция на dev-базе; создать `TEST5` → погасить двумя аккаунтами → повтор
  `replayed` → отключить → `promo_code_disabled`; одноразовые партии работают как раньше.
