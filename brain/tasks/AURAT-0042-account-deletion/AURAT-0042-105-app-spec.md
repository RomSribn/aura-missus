# A · Приложение

## Что получает человек

На экране Profile под `Sign out` есть тихая строка **Delete account**. Она
открывает лист, где **до** нажатия сказано: что стирается, что остаётся
обезличенным и почему, сколько денег сгорит (если есть), и что это
необратимо. Одно подтверждение → сервер удаляет → телефон выходит из аккаунта,
чистит кеш вложений и приводит на экран входа с тостом «Your account has been
deleted.» Вход по тому же номеру заводит новый пустой аккаунт.

Путь буквально тот, что обещают terms §04 и privacy §08: «from the profile
screen in the app».

## Контракт — утверждённый BFF (`008`), читается приложением

Выпускает половина BFF (`@aura/contracts` **v0.19.0**, `account.ts`). Код
вызова пишется **по выпущенной версии**, не по этой таблице.

| Ответ | Что делает приложение |
|---|---|
| `DELETE /v1/me` → `204` | ветка успеха |
| `204` на повтор тем же токеном | та же ветка успеха — потерянный ответ не оставляет человека в ошибке |
| `409 { code: 'account_has_live_sessions' }` | в листе объяснение и кнопка **Go to Sessions** вместо «Delete account» |
| сеть / `5xx` | «That didn't go through. Please try again.», повтор разрешён |
| `401` без запроса (токен не обновить — личность уже удалена джобой) | редкий край: повтор после потерянного ответа, когда кешированный токен истёк. `currentUser.reload()` → `auth/user-not-found` → ветка успеха; иначе обычная ошибка |
| `401 { code: 'account_deleted' }` на **любом другом** маршруте | второе устройство: автоматический локальный выход (`106` #5) |

## Поток

```
Profile ── Delete account ──► лист «Delete your account?»
                                   │ Keep it → закрыть
                                   │ Delete account (loading; жест не закрывает лист)
                                   ▼
                              DELETE /v1/me
                 ┌─────────────────┼───────────────────────┐
               204              409 live_sessions        сеть / 5xx
                 │                 │                       │
                 ▼                 ▼                       ▼
        локальный выход        текст + Go to Sessions   try again
        + чистка кеша вложений
        → вход + тост

 второе устройство: любой запрос → 401 account_deleted → локальный выход → вход
```

**Чего поток не делает — и почему:**

- **Не зовёт `unregisterCurrentDevice()`.** Токены устройства удаляет сервер,
  а `DELETE /v1/devices/:token` после удаления получит `401` (`008`, BFF
  `007` §1, `104` §5). Поправка к `001`, п. 3.
- **Не ждёт** Firebase, Chatwoot и R2: у BFF это повторяемая джоба
  (`008` §2). `204` = коммит базы.
- **Не удаляет личность в Firebase сам** — это BFF (`008` D2), повторной SMS
  нет.
- **Не упоминает отзывы** — звёзды остаются обезличенными (Q2), но об этом
  говорит только политика (`106` #6).

## Где это в коде (FSD)

| Слой | Что |
|---|---|
| `features/account-deletion/` (новый слайс) | `api/` — `DELETE /v1/me` по контракту; `model/use-account-deletion.ts` — состояния `idle / submitting / refused(code) / failed`, защита от двойного нажатия, край `401 → личности нет`; `lib/refusal-copy.ts` — код → текст (строками, не enum: сервер на версию впереди не должен ронять экран, как в `profile-photo`); `ui/DeleteAccountSheet.tsx` — по образцу `CancelSessionSheet` |
| `features/session-end/` (новый слайс) | **общий локальный выход**: `authService.signOut()` + сброс сторов с идентичностью (`profileStore`, `horoscopeStore`) + опционально чистка кеша вложений. Сегодня эта логика живёт внутри `screens/profile/model/use-profile.ts`; выносится, потому что ей теперь пользуются три пути — `Sign out`, удаление и слой `app` (второе устройство), а `app` не может импортировать из `screens`. Навигацию (`leaveApp`) делает вызывающий |
| `screens/profile` | строка под `Sign out` (render-only), ключ листа `'delete'`; `signOut` и успех удаления зовут `features/session-end`; переход на вкладку Sessions по `409` |
| `app/` | подписка на `account_deleted` от `bffRequest` → `features/session-end` → `leaveApp` от корневого навигатора |
| `shared/api/bff/http-client.ts` | `bffRequest` читает `code` из тела отказа (`ApiError` из `envelope.ts`) — сегодня его читает только `upload.ts` — и сообщает подписчику о `401 account_deleted` |
| `shared/api/bff/attachment-cache.ts` | `clearAttachmentCache()` — снести `CacheDir/aura-attachments` |
| `shared/api/firebase/auth.service.ts` | проверка «личности больше нет» через `reload()` |

Новых токенов темы и атомов не нужно: `BottomSheet`, `Button`, `AuraIcon`,
`Text`, `theme`, тост — всё есть.

## Приёмка части A

- Удаление из профиля без поддержки; лист называет цену до нажатия.
- Двойное нажатие — один запрос; жест не закрывает лист, пока идёт запрос.
- Потерянный ответ + повтор ведут на вход, а не в вечную ошибку.
- `409` объяснён словами и ведёт в Sessions, «try again» не предлагается.
- После удаления на телефоне нет кеша вложений; экран входа не показывает
  имени удалённого; чат не держит сокет.
- Второй телефон с тем же аккаунтом сам выходит на экран входа при первом же
  запросе.
- `Sign out` ведёт себя как раньше (кеш вложений **не** чистит, `106` #3).
- Create Account открывается с **выключенным** согласием на маркетинг.
- Экран входа говорит о возрасте 18+ до кнопки.
- Вход по тому же номеру → Create Account, пустой профиль.
- Тесты: модель удаления, лист, строка, `session-end`, `bffRequest` с кодом и
  событием, подписка `app`, очистка кеша; `tsc` и линт чисто.

# B · Юридические страницы и Data safety

## Почему здесь

Страница удаления и правка политики блокируют листинг Play вместе с экраном.
Спека BFF (`008`) отнесла их к `aura-app-manor`, владелец — в эту задачу
(`106`).

## Как устроены страницы

`aura-app.cc` — Netlify, личная учётка, деплой перетаскиванием, **исходника
нет** (`AURAT-0040-010`). Сняты 2026-09-16: `/`, `/privacy/`, `/terms/` —
бандлы Claude Design («Bundled Page»), Cormorant Garamond + Lora, фон
`#f4efe6`, текст `#221f1a`, коралл `#e0485f`, бирюза `#2ba39a`, слива
`#1f122b`, мера 68ch. Правка = пересборка страницы целиком.

## Что производит задача

1. **Бриф для Claude Design** — `AURAT-0042-claude-design-brief.md` в папке
   задачи. Самодостаточный: визуальный язык, структура, **полный финальный
   текст** `/privacy/`, `/terms/` и новой `/delete-account/`. Не патч к
   существующему тексту — Claude Design пересобирает страницы по нему.
2. **Ответы для Data safety** — таблица в том же брифе отдельным разделом
   (для консоли, не для Claude Design), сверенная с `AURAS-0002`.
3. **Текст пишется по свежей сверке кода** обеих половин на 2026-09-16
   (`107`): удаление аккаунта по `008`/`009`, карта `AURAT-0040-013` с тремя
   устаревшими строками, всё, что появилось после 28.08, советники как
   персоны (`106` #10), операторы видят имя, телефон и фото (`108` #12,
   #15), маркетинг только с согласия (#11), возвраты по запросу (#13).

## Что делает владелец (не сессия)

1. **Cloudflare Email Routing**: `privacy@` и `support@aura-app.cc` → свой
   ящик; проверочное письмо на оба адреса **до** публикации (`106` #9).
2. Бриф → Claude Design → проверка вёрстки → деплой на Netlify.
3. Data safety и URL удаления в Play Console.

## Когда публиковать

Текст описывает удаление, которое должно **работать** в момент публикации:
после релиза BFF в прод (`develop → main`) **вместе с `AURAT-0072`** (имя на
контакте Chatwoot) и сборки приложения с экраном в Play. До публикации — шесть
проверок в маноре из `107` §6 (логи Chatwoot, access log Traefik, письма
Resend, перевод в Chatwoot, публичность аватара контакта, Redis на диске):
каждая «да» добавляет в текст получателя или срок. До того опубликованная версия продолжает обещать то, чего нет, — как и
сегодня; раньше публиковать новую тоже нечестно, в ней обещание конкретнее.

## Приёмка части B

- Каждое утверждение в тексте сверено с кодом или решением (ссылки в
  брифе, раздел для владельца, не для страницы).
- Три верных предложения из «ЧЕГО НЕ ТРОГАТЬ» `AURAT-0040-013` сохранены по
  смыслу.
- Ни одного адреса без MX.
- Страница `/delete-account/` отвечает требованиям Play: название приложения
  и разработчика, шаги запроса, что удаляется, что и сколько хранится.
