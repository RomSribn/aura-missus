# AURAT-0042-117 — Проверка личности: решение владельца — вариант C

Дата: 2026-09-17
Статус: **решено**
Основа: черновик `116`

## Решение

Владелец: «да, C. Но ничего разрабатывать не нужно».

- **Вариант C.** Запросы на удаление без приложения приходят письмом на
  `privacy@`. Оператор проверяет личность по фактам из аккаунта и удаляет
  командой. Вариант B (страница со входом по SMS) не делается. К нему можно
  вернуться, если писем станет много.
- **Разработки нет.** Всё нужное уже есть:
  - текст раздела 02 страницы удаления из брифа («We may ask you for details
    to make sure the account is yours»);
  - CLI `account-erasure.js` в проде (`main` = `abe2039`);
  - почта `privacy@` (`AURAS-0004`, проверена 17.09).
- **Порядок и факты — как в `116`:**
  - первым ответом предложить путь A (удалить в приложении);
  - иначе попросить **два факта из трёх**: номер заказа Google Play (`GPA.…`),
    с какими советниками и примерно когда была переписка, имя в профиле и
    примерную дату регистрации;
  - удалять по `userId`.

## Что изменилось с `116`

**Шаг 6 «записать во внешний журнал» теперь выполняется сам.** Журнал удалений
сделан в `AURAT-0073`: сервис пишет запись с `source: operator` при удалении
через CLI (проверено на `development`, `AURAT-0073-016`). Прод-бакет
`aura-erasure-journal-prod` проверен 17.09 (`AURAT-0073-018`). Вручную
записывать ничего не нужно. Отдельный вопрос «где вести журнал» из `116`
закрыт.

Команда шага 5 в проде:

```
docker exec <контейнер aura-bff (production)> node dist/account-erasure.js --user <userId>
```

Отказ `account_has_live_sessions` значит, что у человека идёт или оплачена
сессия: дождаться её конца.
