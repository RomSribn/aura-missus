# AURAT-0042-116 — Черновик: проверка личности для запросов на удаление по почте

Дата: 2026-09-16
Статус: **черновик, ждёт решения владельца**
Откуда: пункт 6 в `114`; обещание политики (бриф): «write to
privacy@aura-app.cc with the phone number of your account … If you no longer
have the app, see Delete your account (/delete-account/)»; CLI из D5 (`008`)

## Зачем

Приложение подтверждает владение номером через SMS Firebase до удаления.
Письмо не подтверждает ничего: номер телефона может знать кто угодно, а
`account:erase -- --phone <E.164>` удалит аккаунт без вопросов (и без
пробного режима — отказ только при оплаченной или идущей сессии). Удаление
необратимо, поэтому без проверки чужой человек может стереть чужой аккаунт.

## Варианты

| | Как подтверждается личность | Цена |
|---|---|---|
| **A. Самообслуживание в приложении** | ответ на письмо: «установите приложение, войдите по этому номеру, Профиль → Удалить аккаунт» — SMS Firebase и есть проверка | ноль; но Google Play требует путь удаления **без переустановки приложения**, поэтому одного A для веб-пути недостаточно |
| **B. Веб-страница с входом по SMS** | `/delete-account/` входит по номеру через Firebase Web SDK (reCAPTCHA + SMS) и сама вызывает существующий `DELETE /v1/me` | код на странице, CORS на BFF, домен в Firebase; вручную ничего не проверяется |
| **C. Ручная проверка по тому, что знает только владелец** | оператор просит подтвердить факты из аккаунта и сверяет с базой | работа оператора, остаточный риск; см. ниже |

**Рекомендация:** B как целевой путь для Play, C — пока B нет, A — первым
ответом тем, у кого приложение есть.

## Процедура C (до появления B)

1. **Принять.** Письмо на `privacy@` или `support@`. Записать дату, адрес
   отправителя и заявленный номер (E.164). Никуда не пересылать.
2. **Предложить A.** Если у человека есть приложение — удаление там, проверка
   не нужна. Закончить.
3. **Найти аккаунт, ничего не удаляя.** Номер ищется в Firebase Console →
   Authentication (только чтение). Нет аккаунта — ответить, что аккаунта с
   таким номером нет.
4. **Проверить личность — два факта из трёх**, которые оператор видит, а
   посторонний знать не может:
   - номер заказа Google Play (`GPA.…`) из письма-квитанции Google — если были
     покупки;
   - с какими советниками была переписка и примерно когда;
   - имя из профиля и примерная дата регистрации.

   Не совпало — вежливый отказ с предложением пути A. Не просить копии
   документов: их хранение — отдельная обязанность, которой у нас нет.
5. **Удалить.** В проде: `docker exec <контейнер aura-bff (production)> node
   dist/account-erasure.js --user <userId>` (по id, а не по номеру — id уже
   сверен на шаге 4). Отказ `account_has_live_sessions` — дождаться конца
   сессии. Вывод команды — только id.
6. **Записать во внешний журнал удалений** дату и `userId` (см. `115`,
   находка 1) — без этого удаление нельзя повторить после восстановления
   бэкапа.
7. **Ответить** в течение месяца (обещание политики): аккаунт удалён; что
   остаётся обезличенным (денежный след, оценки без текста); что из резервных
   копий данные уходят в течение 30 дней.

## Особые случаи

- **Жалоба на несовершеннолетнего** (политика обещает удалить): решение
  принимает владелец, по записи в журнале, без проверки из шага 4.
- **Номер потерян** и A невозможен: процедура C; если фактов не хватает —
  отказ, аккаунт остаётся.
- **Запрос от третьего лица** (юрист, родственник): только через владельца.

## Решить владельцу

1. Вариант для Play: B (страница с SMS) или C (ручная проверка).
2. Список фактов для шага 4 и порог «два из трёх».
3. Где вести журнал удалений (`115`, находка 1) — это и опора шага 6.
