# AURAT-0102-001 — Initial (заглушка; исполняется в `aura-bff-manor`)

Date: 2026-10-20
Выдан в `aura-app-manor` для `AURAF-0020` (веб-клиент), этап 1 — строки 001, 002,
004 scope. Решения — `AURAD-0019`, разбор пробелов — `AURAI-0007`.

Что нужно от BFF, чтобы с ним мог говорить браузер:

- **CORS** — `@fastify/cors` с allowlist из env (dev / `bff-dev` / прод-домены веба),
  только нужные методы и заголовки (`Authorization`, `Content-Type`). Сейчас CORS
  нет вовсе.
- **`/ws`** — проверка `Origin` по тому же allowlist (браузер шлёт его всегда;
  мобильное приложение — нет, его поведение не меняется).
- **Гостевой доступ на чтение** — `@Public()` для каталога и всего, что нужно
  профилю советника гостю: сейчас есть только `GET /v1/advisors` (весь список, за
  глобальным `FirebaseAuthGuard`), нет `GET /advisors/:id` и публичного списка
  отзывов советника; `…/sessions/availability` и `…/pricing` тоже за гардом. Ответ
  гостю — без персональных полей (оффер, баланс, «мои» отметки).
- **Фильтры каталога** (`?cat&online&price&rating&lang&sort`, страница 24) — решить
  в спеке: персон немного, фильтрация на клиенте может быть достаточной; тогда
  сервер не меняется.
- Контракты: если появляется гостевой ответ или `GET /advisors/:id` — новые схемы в
  `@aura/contracts` (только добавления), новый тег, потребители — app и web.

Ops (не код): веб-домены в Firebase Authentication → Authorized domains,
reCAPTCHA / App Check для веб-входа по телефону.

Выкатывается **раньше** веб-экранов Advisors и Auth. Старт — `wts-task` в
`aura-bff-manor`, спека на одобрение владельцу.
