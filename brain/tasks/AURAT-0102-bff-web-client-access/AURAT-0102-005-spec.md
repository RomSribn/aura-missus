# AURAT-0102-005 — spec

Тип: task (строки `AURAF-0020-001`, `-002`, `-004`, колонка BE). Новой фичи нет.
Status: approved 2026-10-20 (`006`).

## Что делаем

### 1. CORS по allowlist

- Зависимость `@fastify/cors` (^11, под Fastify 5), регистрация в `app.setup.ts`
  рядом с helmet — так же её получают тестовые сборки приложения.
- Env `WEB_ALLOWED_ORIGINS` — список origin через запятую
  (`https://aura-web.app,https://dev.aura-web.app,http://localhost:5173`).
  Каждый проверяется при загрузке: только scheme + host[:port], без пути —
  как `AGENT_DESK_FRAME_ANCESTOR`. Не задан → CORS выключен (заголовков нет):
  мобильному приложению CORS не нужен, локальный стек работает как раньше.
- Политика: `origin` — точное совпадение со списком; методы
  `GET, POST, PUT, PATCH, DELETE`; заголовки `Authorization, Content-Type`;
  `credentials: false` (вход — bearer-токен, cookie вебу не нужны; backoffice с
  его cookie-сессией так остаётся недоступен чужим origin); `maxAge` 10 мин.

### 2. `Origin` на `/ws`

В `ChatGateway.handleConnection`, **до** проверки токена: соединение
принимается, если
- `Origin` нет (серверные клиенты, `wscat`), **или**
- `Origin` в `WEB_ALLOWED_ORIGINS`, **или**
- хост из `Origin` совпадает с `Host` запроса — это мобильное приложение: React
  Native сам ставит `Origin = https://<хост BFF>` (Android `WebSocketModule`,
  iOS SocketRocket), см. `004`.

Иначе — закрытие кодом `4403` (`forbidden origin`), токен не проверяется.
Чистое правило — функция `isAllowedWsOrigin(origin, host, allowlist)` с
юнит-тестами.

### 3. Гостевое чтение

| Эндпоинт | Сейчас | Станет |
|---|---|---|
| `GET /v1/advisors` | только с токеном | `@Public()` — ответ и так одинаков для всех, персональных полей нет |
| `GET /v1/advisors/:id/sessions/availability` | токен, `BillingEnabledGuard` | токен **необязателен**; без токена — занятость только советника, пользователь не создаётся |
| `GET /v1/advisors/:id/sessions/pricing` | токен, `BillingEnabledGuard` | токен **необязателен**; без токена — цены **с оффером** первой сессии (гость его ещё не использовал), пользователь не создаётся |

- Новый декоратор `@OptionalAuth()`: гард пропускает запрос **без**
  `Authorization`; если заголовок есть — полная проверка как сейчас (протухший
  токен → 401, удалённый аккаунт → `account_deleted`), а не молчаливый гость:
  иначе вошедший человек с протухшим токеном увидел бы чужую цену.
- Параметр-декоратор `@OptionalUser()` → `AuthUser | null`. Сервисы
  `getAvailability` / `getPricing` принимают `AuthUser | null`; для `null` нет
  `ensureUser`, нет чтения занятости и оффера пользователя.
- `BillingEnabledGuard` остаётся: без биллинга слоты и цена — 404 для всех.
- Для приложения (всегда шлёт токен) ответы не меняются ни на байт.

### 4. Профиль, отзывы, фильтры — сервер не меняется

- **`GET /advisors/:id` не добавляем.** Каталог — 8 персон, каждая уже несёт
  всё для профиля: рассказ, специализации, рейтинг, число отзывов, все
  опубликованные отзывы. Веб берёт персону из того же ответа (RTK Query кеширует
  один запрос на оба экрана).
- **Фильтры каталога — на клиенте.** Категория, цена, рейтинг, сортировка — по
  полям DTO; страница 24 больше всего каталога. Серверные фильтры — когда персон
  станет на порядок больше.
- **`@aura/contracts` не меняется**, нового тега нет: формы ответов те же.

## Что не делаем

- `POST /match`, web push (FCM web), PSP, отдачу вложений чата браузеру (это
  задачи чата и `AURAF-0020-005`).
- Фильтр «язык» — у советника нет такого поля (см. вопрос 2).
- Онлайн-статус гостю (см. вопрос 1).

## Тесты (чистые)

- env-схема: `WEB_ALLOWED_ORIGINS` — список разбирается; origin с путём или
  мусор → отказ загрузки; не задан → пустой список.
- `isAllowedWsOrigin`: нет Origin / в списке / тот же хост / чужой → отказ.
- `ChatGateway`: чужой Origin → `close(4403)` и токен не проверяется.
- `FirebaseAuthGuard`: `@OptionalAuth` без заголовка → пропуск без `authUser`;
  с плохим токеном → 401; без `@OptionalAuth` поведение прежнее.
- `SessionsService`: `getPricing(null)` — блоки со скидкой, `ensureUser` не
  вызван; `getAvailability(null)` — без занятости пользователя и без
  `ensureUser`.
- Конфигурация CORS: функция опций из env (allowlist пуст → плагин не
  регистрируется).

Живая проверка (preflight `OPTIONS` с веб-origin, `/ws` с браузера и из
приложения) — в маноре после merge.

## За владельцем (ops, не код)

- `WEB_ALLOWED_ORIGINS` в env dev и prod — когда будут известны веб-домены.
- Firebase Console → Authentication → Settings → Authorized domains: веб-домены
  (dev, prod; `localhost` там по умолчанию).
- Вход по телефону в браузере: reCAPTCHA (invisible) работает из коробки;
  App Check (reCAPTCHA Enterprise) — по желанию, решение отдельно.

## Вопросы владельцу

1. **Онлайн-точка гостю.** Сейчас онлайн — один флаг на весь пул чаттеров и
   приходит только по WS вошедшим. Предлагаю: гость точек и фильтра «онлайн» не
   видит, вошедший — видит по WS, как в приложении. Альтернатива — публичный
   `GET /v1/presence` (+ схема в contracts, новый тег).
2. **Фильтр «язык».** Данных нет. Предлагаю: веб этот фильтр не показывает, пока
   у персон не появятся языки (отдельная задача: поле в модели + контракт).
