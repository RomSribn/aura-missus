# AURAT-0107-005 — Spec: бронь с баланса в aura-web

Date: 2026-10-20
Type: task (строки `AURAF-0020-006`, `-007`, колонка UI). Новой фичи нет.
Status: done 2026-10-20 (`015`) — все рекомендации `006`; правки владельца при проверке: слот выбирается, Book открывает (`010`); `?book=1&slot=` в URL открытой шторки (`012`)

## Цель

Вошедший человек выбирает у советника длительность, день и время и платит с баланса кошелька —
из профиля, из чата (шапка, приглашение, rail) и по ссылке `?book=1&slot=`. «Booked» показывается
только после ответа сервера. Деньги — сервера (hard rule 7): цены, скидка и «You save» — только из
`pricing.blocks[]`, оффер вошедшего — из кошелька, клиент ничего не считает и не отправляет цену.
BFF и contracts **не меняются** (`004` §2); пробелы — ниже, владельцу для `aura-app-manor`.

Решения 1–11 — в конце, у каждого варианты и рекомендация. Описание «Что делаем» написано по
рекомендациям.

## Что делаем

### 1. Кошелёк — `entities/wallet` (новый)

- **api**: `getWallet` — `GET /v1/wallet` → `WalletResponse.parse`; тег `Wallet`. Только для
  вошедшего; 404 = биллинг выключен (кошелька нет, как `BillingState 'off'`).
- **model**: `useWallet()` → `{ balanceMinor | null, offerPct | null, status }`;
  `offerPct = firstSessionOffer?.active ? pct : null`. Перечитывается: при входе (кэш и так
  сбрасывается при смене человека), при открытии оплаты (по сокету баланс не приходит, пополняют в
  приложении), при возврате на вкладку (`visibilitychange`), после брони (см. §4).
- **ui**: `BalanceChip` — сумма через `formatUsdMinor` (решение 9).

### 2. Сессии — `entities/session` (дополнение)

- **api**: `bookSession` — `POST /v1/advisors/:id/sessions`, тело `BookSessionRequest.parse`, ответ
  `BookSessionResponse.parse`; `getSessions` — `GET /v1/sessions` → `SessionsResponse.parse`, тег
  `Sessions`. Теги `Pricing`, `Availability`, `Wallet`, `Sessions` объявляются в `shared/api`
  (`baseApi.tagTypes`), pricing и availability получают `providesTags`.
- После успешной брони: баланс из ответа кладётся в кэш кошелька (`updateQueryData`); при скидке
  (`creditMinor > 0` у выбранного блока) — кошелёк и pricing **всех** советников перечитываются
  (оффер израсходован везде: профиль, каталог, rail, приглашение); availability этого советника и
  `Sessions` — инвалидируются.
- **Оффер вошедшего** (правило 7): `useSessionPricing` для вошедшего берёт `pct` из кошелька и
  показывает его, только если pricing его подтверждает (`creditMinor > 0` хоть у одного блока) —
  как приложение («a live offer the price does not back is not shown»). Гость — как сейчас, из
  pricing (`AURAT-0103-006`).
- **lib** (перенос копией с тестами, шапка `// Ported from aura-app …`):
  - `features/booking/lib/slots.ts` → дополнить уже перенесённый `entities/session/lib/slots.ts`:
    `toBookingDays`, `toBookingSlots`, `toBookingDurations`, `slotRangeLabel` (+ тесты). Отличие
    (записано в шапке, как в `AURAT-0103`): подписи «Today», дни недели, месяцы и «HH:MM» руками не
    строятся — функции отдают данные (`date`, `isToday`, `startsAt`, `hasFreeSlots` …), текст —
    `Intl` на языке интерфейса в `shared/lib/dates.ts`.
  - `entities/session/lib/saving.ts` (`sessionSavingMinor`) с тестами — для Booked.
  - `shared/lib/dates.ts`: `localDateKey` (+ тест). `session-state.ts` **не** переносим — в этой
    задаче у него нет потребителя (правило 5), придёт с `/sessions`.
  - Своё (веб): `entities/session/lib/ics.ts` — .ics одной сессии (UTC, `UID` = id сессии), тест.
- **ui**: `SessionSummary` — аватар, имя, «{n} min private chat», «{Weekday, D Month} · 18:30 –
  19:00» (`Intl`, зона браузера); используется в шторке, Booked.

### 3. Шторка Book — `features/book-session` + `widgets/book-sheet`

- **Черновик** (`features/book-session/model`, NAVIGATION §5): `{advisorId, minutes, startsAt}` в
  `sessionStorage` (одна вкладка, переживает вход, смену маршрута и перезагрузку). `startsAt` —
  полный ISO-момент, не «HH:MM». Черновик другого советника не подставляется. Удаляется после брони.
- **Открытие**: диалог `book` (регистрируется в `app/config/dialogs.ts`), params `{advisorId,
  slot?, source}`. Одна и та же шторка из профиля и из чата (решения 3, 4). Пока шторка открыта, в
  URL профиля — `?book=1[&slot=]`: перезагрузка открывает её снова с черновиком; Back / × / Esc —
  закрывают (`dialog-host` уже это умеет). Гость — `gate('book')` с resume, как сейчас.
- **Данные**: pricing и availability **с токеном** (персональные: занятость самого человека,
  его оффер); сетка читается для выбранного блока, при смене длительности — перечитывается и время
  сбрасывается (как `use-booking` приложения); при смене дня время сбрасывается.
- **Содержимое** (README §4.1, NAVIGATION §2.3; ошибки зоны хендоффа не переносим):
  - шапка: фото, «Book a session with {first name}», рейтинг · «private paid chat» · `PriceTag`/min;
  - `CouponTicket` в варианте `saving` («You save $X» выбранного блока) — только при оффере;
  - **длительность** — блоки сервера (решение 2), на каждой `PriceTag` (subtotal / cost), ярлык
    «Biggest saving» — блок с наибольшим `creditMinor`, если оффер и блоков ≥ 2; по умолчанию —
    из черновика, иначе самый короткий;
  - **день** — 14 дней с сегодня (решение 1): горизонтальная лента, «Today» / «Tomorrow» / день
    недели + число; день без свободных слотов — приглушён, но выбирается («No times left this day»);
    по умолчанию — день слота из ссылки / черновика, иначе первый со свободным слотом;
  - **время** — сетка дня; прошедшие (по `serverNow()`) убраны, занятые — зачёркнуты и disabled;
    строка «Times are in your time zone · {зона}» (`Intl`, `timeZoneName: 'short'`);
  - **итог** — `PriceTag` блока (subtotal / cost) + «{Weekday, D Month} · {start – end}» + «You save
    $X» (teal);
  - **оплата inline** — `PayActions` (§4) прямо в шторке.
- **`?slot=` из ссылки**: слот с таким локальным ключом выбран, если он ещё свободен; занят или
  ушёл — выбран только его день и над сеткой строка «That time is no longer available — pick another
  one».
- Телефон: bottom sheet, `PayActions` прикреплены к низу шторки.

### 4. Оплата — `features/pay` (порт способа оплаты)

- **Порт** (`model/payment-method.ts`): способ оплаты = `{ id: 'balance' | 'card' | 'wallet',
  isAvailable(ctx), pay(attempt) → outcome }`; `attempt = {advisorId, minutes, startsAt,
  idempotencyKey}`; исходы — `booked(session, balanceMinor)` | `taken` | `insufficient` |
  `notBookable` | `unknown`. Живой — только `balance` (вызов `bookSession`). `card` и `wallet`
  — строка 007 (решение 11).
- **`usePay(attempt без ключа, costMinor)`** — порт `use-booking-confirm` приложения:
  - ключ попытки (`crypto.randomUUID()`) создаётся при первом нажатии и **держится до определённого
    исхода** (успех, 400, 402, 404, 409); сеть / 5xx / таймаут — ключ остаётся, повтор не спишет
    дважды. Смена слота или блока ключ **не** сбрасывает: BFF не сравнивает тело повтора, и если
    первая попытка на самом деле прошла, повтор вернёт её сессию, а Booked покажет именно её
    (а не выбор в UI) — двойного списания нет;
  - пока запрос идёт, кнопка «Booking…» заблокирована; дольше 10 с — «Still confirming…»
    (NAVIGATION §4), повторной отправки нет;
  - исходы: успех → черновик удалён, кэш (§2), переход на `/booked/:sessionId` (замена истории:
    Back с Booked не возвращает в шторку); 400 / 409 → строка «That time is no longer available —
    pick another one», сетка перечитана, время сброшено (приложение сетку не перечитывает — не
    копируем); 402 → перечитать кошелёк, состояние «не хватает»; 404 → «This advisor isn't taking
    sessions right now.»; прочее → «That didn't go through. Please try again.» (ключ тот же).
- **`PayActions`** при `PSP_ENABLED=false` (решение 8):
  - строка «Pay with · Aura balance» — «$12.00 · $3.00 left after» или «$2.00 · not enough»;
  - хватает → кнопка «Confirm & pay $X» (замок, coral); слот не выбран → «Pick a time» (disabled);
  - не хватает → кнопка не рисуется; вместо неё «Your balance is $X short. Top up in the Aura app —
    it's the same balance here.» (решение 8);
  - под кнопкой: «You save $X · Free cancellation up to 24 h before» или «Free cancellation up to
    24 h before · free reschedule up to 4 h before».
  - баланс неизвестен (кошелёк не ответил) — кнопка доступна, решает сервер (402 → «не хватает»),
    как приложение.

- **Чат**: календарь в шапке, Book в приглашении, Book в rail → та же шторка поверх чата
  (страница не меняется), с **ближайшим свободным слотом** уже выбранным: «Quick book» — одно
  нажатие «Confirm & pay», другое время — в той же шторке (решение 4).
- **`/checkout`** (решение 5): в этапе 1 своей страницы нет — маршрут ведёт в шторку из черновика
  (`replace` на `/advisors/:id?book=1&slot=`), без черновика — в `/advisors`. Страница появляется

Top up до PSP. Гость и телефон — не рисуется (NAVIGATION §1.1, hard rule 8).

## Пробелы BFF (владельцу → `aura-app-manor`, ID там)

В этой задаче BFF не меняется; веб их обходит, как описано.

1. **Повтор брони после lead-времени.** Проверки 400 идут до поиска повтора по ключу: если первая
   попытка прошла, а ответ потерялся, повтор, чей слот уже ближе lead, получит 400 вместо исходной
   сессии — клиент сочтёт исход определённым, сбросит ключ, и вторая бронь спишет ещё раз. Нужно
   искать повтор по ключу первым (касается и приложения). — **самый важный**; выдан `AURAT-0109`
   (`aura-bff-manor`), веб от него не зависит.
2. **Повтор не сравнивает тело** (тот же ключ, другой слот → исходная сессия). Веб опирается на это
   (§4), но контракт этого не обещает; стоит зафиксировать в contracts или отвечать 409/422.
3. У ошибок брони нет кодов причин (409 — три причины в одной; 402 без `code`) — `ApiError {code}`
   в contracts + BFF.
4. Нет `GET /v1/sessions/:id` (Booked после перезагрузки читает весь список).
5. Баланс не приходит по сокету (веб перечитывает кошелёк по фокусу вкладки).
6. Нет поля «вопрос» в брони (Ask, этап 2).
7. Для PSP (строки 007, 011): эндпоинт пополнения картой, вебхук, статус ожидания, резерв слота на
   время оплаты.
8. К сведению: `POST /v1/wallet/top-ups` на bff-dev (`NODE_ENV=development`) зачисляет деньги без
   оплаты; веб его не вызывает. Его можно использовать, чтобы положить деньги на тестовый аккаунт
   для проверки в маноре (curl с токеном) — если ты не против.
