# AURAT-0107-001 — Initial (заглушка; исполняется в `aura-web-manor`)

Date: 2026-10-20
Выдан в `aura-app-manor` для `AURAF-0020` (веб-клиент), этап 1 — строки 006 и 007 scope
(колонка UI), шаг «Booking» (Р5 `AURAD-0019`; Р4 — оплата балансом + заготовка под PSP).
Опирается на `AURAT-0103` (`entities/session`: pricing, availability, оффер гостя,
`?book=1&slot=`), `AURAT-0104` (gate с resume, `reason: 'book'`), `AURAT-0105` (CTA брони в
чате ведут на `?book=1`); `AURAT-0106` (BFF открывает `Date`) — в работе в `aura-bff-manor`.

Что нужно: человек бронирует сессию из профиля, чата или Quick book и платит с баланса;
«Booked» — только после подтверждения сервером — README §4.1–4.3, §5, NAVIGATION §1.1,
§2.3–2.5, §2.7, §2.8, §3.2, §3.4, §4, §5 веб-хендоффа; мобильные `SESSIONS_BOOKING.md`,
`CHECKOUT.md`, `OFFER.md`; приложение — `features/booking`, `screens/booking`; правила веба —
hard rule 7 и раздел «Payments».

- **Данные — BFF как есть.** Цена и слоты — уже в вебе (`…/sessions/pricing`,
  `…/availability?days&tz&minutes`: 14 дней, слот — предложение, сервер перепроверяет);
  перед оплатой — перечитать с токеном (гостевой ответ не персонален). Длительности — блоки
  сервера из pricing (глобальные, `SESSION_BLOCK_MINUTES`), не 30/45/60 хендоффа
  (`AURAF-0019`). Кошелёк — `GET /v1/wallet` (`balanceMinor`, `firstSessionOffer`): новый
  `entities/wallet`, оффер вошедшего — из него (правило 7); перечитывать перед оплатой —
  по сокету баланс не приходит. Бронь — `POST /v1/advisors/:id/sessions`
  `{startsAt | startNow, minutes, idempotencyKey}` → `{session, balanceMinor}`; ключ — на
  попытку, держится до определённого исхода (как `use-booking-confirm` приложения).
  Кодов причин нет: 400 (слот устарел, вне сетки), 402 (не хватает), 404 (нет биллинга или
  цены), 409 (слот заняли, человек занят в это время, ключ) — по статусу; после 400/409 —
  перечитать сетку (приложение этого не делает — не копировать).
- **Шторка Book** — диалог `book` (объявлен, не зарегистрирован), открывается по
  `?book=1&slot=` из профиля, чата и gate: длительность, дни, слоты в зоне браузера, оффер
  (купон, «You save» — суммы только из `pricing.blocks[]`, без расчётов на клиенте).
  Черновик (советник, длительность, слот) — в `sessionStorage` (NAVIGATION §5): сейчас
  `minutes` в URL нет и после входа сбрасывается. Ошибки зоны из `src` хендоффа
  (`toISOString().slice`) не переносить.
- **Оплата — `features/pay` с портом способа оплаты** (раздел «Payments»): `balance` —
  живой; `card` и `wallet` — на фейковом провайдере за `VITE_PSP_ENABLED` вместе с
  маршрутом возврата и «Still confirming…» (строка 007; флаг сейчас никто не читает).
  Флаг выключен: только баланс — хватает → подтверждение и оплата, не хватает → недостача
  и «пополните баланс в приложении Aura». Хендофф этот случай не рисует («Use balance» у
  него — вычет перед картой): опора — `CHECKOUT.md` и `AURAI-0007` «Заготовка под PSP».
  Пополнения из браузера нет (stub на bff-dev отвечает 503).
- **Где платят** — inline в шторке на профиле, `/checkout` (сейчас `element: null`),
  Quick book в чате (приглашение, rail) и «More dates»; решить в спеке, какая точка
  входа куда ведёт в этапе 1 и что делает `/checkout` без черновика. Баланс в шапке
  (NAVIGATION §1.1, отложен из `AURAT-0104`) — с `entities/wallet`; Top up без PSP — в
  спеку.
- **Booked `/booked/:sessionId`** — из `session` ответа брони, а не из выбора в UI (повтор
  с тем же ключом вернёт исходную сессию); после перезагрузки — поиск в `GET /v1/sessions`
  (`GET /v1/sessions/:id` нет). Add to calendar (`.ics`), «free chat» →
  `/chats/:advisorId`; «Go to session» ведёт в `/sessions` этапа 2 — решить в спеке. После
  брони со скидкой — перечитать кошелёк и pricing: оффер израсходован везде.
- **Решить в спеке:** 7 дней с завтра (хендофф) или 14 с сегодня (сервер, приложение) и
  слоты «Today» в профиле; мгновенный старт (`startNow`, `instantAvailable` — в BFF и
  Quick book приложения есть, веб-хендофф не рисует); вопрос советнику (в контракте брони
  поля нет, Ask — этап 2); тексты всех исходов оплаты.
- Перенос из aura-app только нужного, копией с тестами и шапкой
  `// Ported from aura-app <path> (<ID>)`: `features/booking/lib/slots.ts` (остальное),
  `entities/session/lib/{saving,session-state}.ts`, `shared/lib/dates.ts`
  (`localDateKey` и др.); сценарии — из `use-booking.test.tsx`,
  `use-booking-confirm.test.tsx`, `use-quick-booking.test.tsx`. Переносить из `develop`
  приложения: `AURAT-0099` (оплата в один тап) ещё не влит, API брони он не меняет. Новые
  строки — сразу на все 24 языка (правило 9).

BFF ожидается без изменений: бронь с баланса есть целиком. Найденные пробелы — владельцу и
в бэклог, ID выдаётся в `aura-app-manor`: нет `GET /v1/sessions/:id`; у ошибок брони нет
кодов причин (409 — три причины в одной); нет пополнения из браузера; баланс не приходит по
сокету; нет поля «вопрос» в брони; для PSP — эндпоинт пополнения, вебхук, статус ожидания и
резерв слота на время оплаты.

Вне задачи: пополнение баланса (строка 011, после PSP), `/sessions`, перенос, отмена и
отзыв (строка 009), продление и платная сессия в треде, `/match` и Ask, напоминания и web
push.

нужны деньги — пополнить можно только покупкой в приложении; новый аккаунт без оплаченных
сессий видит −50%; недостача — на аккаунте с малым балансом. Старт — `wts-task` в
`aura-web-manor`, спека на одобрение владельцу.
