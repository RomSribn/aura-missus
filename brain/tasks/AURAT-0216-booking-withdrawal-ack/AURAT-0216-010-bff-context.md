# AURAT-0216-010 — BFF: context

Дата: 2026-11-18. Прочитано: шаги `001`–`006`, `AURAD-0024`, `AURAT-0209-009/-011/-014/-015`,
`AURAT-0218-001/-002`, `AURAT-0213-005`; код BFF `develop` `cd0975b`, контракты `v0.34.0`, веб
`aura-web` `60bf412` (`features/pay`).

## Факты из кода

- Путь брони один: `POST /v1/advisors/:advisorId/sessions` (`startsAt` или `startNow`), повтор по
  `idempotencyKey` отвечается до любых проверок (`AURAT-0109`), тело повтора не сравнивается.
- Продление — `POST /v1/sessions/:id/extend`. Своей строки у продления нет: это `SESSION_CHARGE` в
  `ledger_entries` (ключ — `idempotencyKey`) плюс прибавка к `sessions`. Id продления = id строки
  журнала.
- Оплата картой — `POST /v1/wallet/top-ups/card`, строка `stripe_top_ups` по `paymentId`, только с
  web-`Origin`. На вебе бронь при нехватке баланса = сначала пополнение картой, потом бронь тем же
  ключом (`features/pay/model/use-pay.ts`); есть и пополнение без брони (`AURAT-0215`).
- Галочка Terms у Stripe — `STRIPE_TERMS_CONSENT` → `consent_collection.terms_of_service`; с live-
  ключом допускается только `required`. Веб рисует `TermsElement` и глушит его при ошибке загрузки.
- Версии клиента сервер не знает: заголовка версии и механизма «минимальная версия» нет. Веб от
  приложения отличается только `Origin` (`WEB_ALLOWED_ORIGINS`).
- Удаление аккаунта оставляет `users` надгробием с тем же id; сессии и журнал остаются. Privacy
  (`AURAT-0209-014`): записи покупок и платных сессий хранятся 7 лет без имени и телефона.
- Других путей, создающих сессию, нет (приглашение `::SESSION::` лишь открывает тот же лист брони).

## Противоречий нет

Одно уточнение к `AURAT-0218-001`: Terms Element у аккаунта закрыт — если веб покажет свою галочку
Terms, галочку Stripe в live придётся выключить, а BFF сейчас это запрещает. Решение 5 спеки.
