## Что

Клиент присылает согласие **вместе с самим действием** — бронью, сессией «сейчас», продлением, стартом
оплаты картой на вебе. BFF пишет его в **одну таблицу согласий** в той же транзакции, что и действие:
нет брони — нет записи, есть бронь с согласием — запись есть всегда. Запись: вид, версия текста, язык,
время по часам сервера, пользователь, канал (веб / приложение) и ссылка ровно на одно — сессию,
продление или попытку оплаты. Записи только добавляются.

## Решения (на одобрение)

| # | Вопрос | Предлагаю |
|---|---|---|
| 1 | Где хранить | **Одна таблица `consents`** для всех четырёх видов, `AURAT-0218` пишет туда же. Только добавление: триггер запрещает `UPDATE` / `DELETE`, как у журнала денег |
| 2 | Что такое «версия текста» | **Известные версии в контрактах**: `booking-v1`, `now-v1`, `extension-v1` — английский текст каждой лежит рядом с ней в `@aura/contracts`; `terms-v1` — Terms, опубликованные по `AURAT-0209` (не формулировка галочки). Новая формулировка **на любом языке** — новая версия; старые остаются допустимыми навсегда. Неизвестную версию сервер не принимает (400) — поэтому новая версия сначала выходит в BFF, потом в клиентах (обычный порядок выпуска контрактов). Пара «версия + язык» доказывает текст, только если переводы версии заморожены тестами клиентов — правило в контрактах (ниже) |
| 3 | Отказывает ли сервер без согласия | **Приложение — никогда.** Версию приложения сервер не знает, а старые Android-сборки согласия не пришлют: отказ закрыл бы им брони и продления. Такие брони проходят без записи, сервер пишет в лог `info` «без согласия» (вид, канал, id сессии; без людей). **Веб — да, по выключателю** `WEB_CONSENT_REQUIRED` (по умолчанию `false`), только для брони, «сейчас» и продления: `true` → без согласия **400 `consent_required`**, ничего не списано. Включать в каждой среде **после** выката веба с галочками — иначе прежний веб сломается между выкатами. Оплата картой — решение 5 |
| 4 | Как сервер отличает веб | По `Origin` из `WEB_ALLOWED_ORIGINS` — так же, как старт оплаты картой. `Origin` подделывается, поэтому выключатель — страховка от ошибки в вебе, а не защита. Доказательство в споре — сама запись |
| 5 | Галочка Terms у Stripe | **Третий режим `STRIPE_TERMS_CONSENT=client`** (название из `AURAT-0218-005` B1): `consent_collection` в Stripe не шлём, согласие собирает веб своей галочкой, и **`termsConsent` в старте оплаты обязателен** — без него 400 `consent_required`, ни строки, ни вызова Stripe. Режим разрешён с live-ключом; `none` с live-ключом по-прежнему запрещён — страховка от live вообще без согласия. В `required` / `none` поле необязательно и записывается, если пришло. Так в live нет двух галочек Terms, а Terms Element у аккаунта закрыт (`AURAT-0218-001`). Отдельного эндпоинта для согласия с Terms нет: веб открывает сессию Stripe после первой отметки, при смене суммы галочка остаётся (манор, `013` п. 2) |
| 6 | Повтор с тем же ключом | Отвечается до проверок, как сейчас (`AURAT-0109`): согласие повтора не сравнивается и второй раз не пишется (как `question`) |
| 7 | Версия не того действия | `now-v1` к брони на время, `booking-v1` к «сейчас», не `extension-v1` к продлению → **400 `consent_invalid`**, ничего не списано |
| 8 | Перенос брони (`PATCH`) | **Без согласия** — в скоупе `004` его нет: договор тот же, деньги не двигаются. Если нужно — отдельным шагом координатора |
| 9 | Удаление аккаунта | Записи остаются, как сессии и журнал: `userId` указывает на надгробие, в записи нет ничего личного. Назвать эти записи одной фразой в Privacy §02 (как уже названа запись согласия на чат) — манор передал в `AURAT-0209`; здесь текстов не правим |

## Контракт `@aura/contracts` `v0.35.0` — что шлют клиенты

Новый `src/consent.ts`:

```ts
export const BOOKING_CONSENT_VERSIONS = ['booking-v1'] as const;
export const NOW_CONSENT_VERSIONS = ['now-v1'] as const;
export const EXTENSION_CONSENT_VERSIONS = ['extension-v1'] as const;
export const TERMS_CONSENT_VERSIONS = ['terms-v1'] as const;

/** Английский текст галочки каждой версии — то, что человек подтвердил (в своём языке). */
export const CONSENT_TEXTS = {
  'booking-v1':
    'I want this session at the time I chose. I understand that once it has taken place, I can no longer withdraw from it.',
  'now-v1':
    'I want this session to start now. I understand that once it has taken place, I can no longer withdraw from it.',
  'extension-v1':
    'I want these minutes now. I understand that once they have been used, I can no longer withdraw from them.',
} as const;

/** Галочка была отмечена: какая версия и на каком языке её показали. */
export const SessionConsent = z.object({
  version: z.enum([...BOOKING_CONSENT_VERSIONS, ...NOW_CONSENT_VERSIONS, ...EXTENSION_CONSENT_VERSIONS]),
  language: z.enum(LANGUAGES),
});
export const TermsConsent = z.object({
  version: z.enum(TERMS_CONSENT_VERSIONS),
  language: z.enum(LANGUAGES),
});

/**
 * terms-v1 — Terms of Service, опубликованные по AURAT-0209 (Last updated — дата публикации;
 * снимок страницы — в брейне AURAT-0209). Клиент берёт версию только отсюда, своей константы нет.
 */

export const CONSENT_REQUIRED = 'consent_required'; // 400: согласие не прислали, а сервер его требует
export const CONSENT_INVALID = 'consent_invalid';   // 400: версия не того действия
```

Поля в запросах — **необязательные** (старые клиенты остаются валидными):

| Запрос | Поле | Версия |
|---|---|---|
| `BookSessionRequest` с `startsAt` | `consent?: SessionConsent` | `booking-v1` |
| `BookSessionRequest` с `startNow: true` | `consent?: SessionConsent` | `now-v1` |
| `ExtendSessionRequest` | `consent?: SessionConsent` | `extension-v1` |
| `CardTopUpRequest` | `termsConsent?: TermsConsent` | `terms-v1` |

Пример брони: `{ "startsAt": "…", "minutes": 20, "idempotencyKey": "…", "consent": { "version": "booking-v1", "language": "de" } }`.

Правила для клиентов (в JSDoc контрактов; исполняют веб и приложение):
- поле шлётся **только когда галочка отмечена** этим нажатием; без галочки кнопка неактивна (`004`) —
  поля без галочки не бывает;
- `language` — язык, на котором показан текст галочки;
- каждое продление — своя галочка и своё поле, «запомнить» согласие нельзя;
- **текст галочки меняется на любом языке только вместе с новой версией**: в вебе и в приложении тест
  фиксирует 24 перевода каждой версии (снимок или хеш), и правка перевода без новой версии роняет CI.
  Иначе пара «версия + язык» не доказывает, какой текст человек видел;
- `termsConsent` веб шлёт со стартом оплаты картой — с каждой новой попыткой (новый `paymentId`, в
  том числе при смене суммы); сессию Stripe открывает после первой отметки галочки Terms;
- на вебе при нехватке баланса — две записи: `termsConsent` со стартом оплаты картой и `consent` с
  бронью, которая идёт следом тем же ключом;
- ответы без изменений; новые — 400 `consent_required` (бронь / «сейчас» / продление — только веб и
  только с выключателем; старт оплаты — в режиме `client`) и `consent_invalid`. Повтор по ключу
  отвечает как раньше, даже без поля.

Совместимость: `v0.34.0`-клиенты ничего не шлют — сервер их принимает (приложение всегда, веб — пока
выключатель выключен и Stripe не в режиме `client`).

## BFF

1. **Схема.** `enum ConsentKind { BOOKING NOW EXTENSION CARD_TERMS }`, `enum ConsentChannel { WEB
   APP }`, `model Consent`: `id`, `userId` → `User` (Restrict), `kind`, `textVersion`, `language`,
   `channel`, `acceptedAt` (часы сервера в транзакции), `sessionId?` → `Session`, `ledgerEntryId?`
   `@unique` → `LedgerEntry` (строка списания продления), `stripeTopUpId?` `@unique` → `StripeTopUp`.
   Миграция: `CHECK` — ровно тот набор ссылок, что положен виду (`BOOKING`/`NOW` → только сессия,
   `EXTENSION` → сессия и строка журнала, `CARD_TERMS` → только попытка оплаты); частичный unique — одна
   запись `BOOKING`/`NOW` на сессию; триггер против `UPDATE` / `DELETE`.
2. **Репозитории.** `book` / `extend` (сессии) и создание строки `stripe_top_ups` принимают
   `consent | null` и пишут запись в своей транзакции; при повторе — ничего.
3. **Сервис.** После ответа на повтор и до остальных проверок: версия ↔ действие (решение 7), затем
   «нужно ли согласие» (решения 3 и 5). Без согласия и без требования — `info` в лог. Старт оплаты
   картой: в режиме `client` проверка `termsConsent` — до лимита частоты и до создания строки, только
   для новой попытки (повтор того же `paymentId` отвечается как сейчас).
4. **Транспорт.** Контроллеры сессий и оплаты читают `Origin` → канал маленьким общим помощником в
   `common/web` (рядом с `web-origins.ts`) и передают канал в сервис.
5. **Env.** `WEB_CONSENT_REQUIRED` (`boolean`, `false`) — бронь, «сейчас», продление с веба.
   `STRIPE_TERMS_CONSENT`: `required | none | client`; с live-ключом — `required` или `client`.
   Адаптер Stripe шлёт `consent_collection` только в `required`. `.env.example`, README.
6. **OpenAPI.** Поля `consent` / `termsConsent`, 400 с кодами в описаниях маршрутов.

### Тесты (чистые, без БД)

- сервис брони: с согласием — запись уходит в репозиторий с видом, версией, языком, каналом; «сейчас»
  — вид `NOW`; не та версия → 400 `consent_invalid`, репозиторий не вызван; веб без согласия при
  выключателе → 400 `consent_required`, ничего не списано; приложение без согласия при выключателе →
  проходит, лог `info`; повтор по ключу без поля → прежняя бронь;
- то же для продления;
- старт оплаты картой: `termsConsent` → запись `CARD_TERMS` (только при новой попытке); режим
  `client` без `termsConsent` → 400 `consent_required`, ни строки, ни вызова Stripe, лимит не тронут;
  повтор того же `paymentId` без поля → прежний ответ; `required` / `none` без поля → проходит;
- адаптер Stripe: `consent_collection` есть только в `required`, тела `none` и `client` без него;
- помощник канала: web-`Origin` → `WEB`, нет / чужой → `APP`;
- env: live-ключ + `none` → отказ при загрузке; live-ключ + `client` и `required` → допуск.

## Порядок выпуска

1. Контракты `v0.35.0` — ветка в `aura-contracts`; BFF проверяется на локально собранном пакете.
   **Тег и push — только с «да» владельца.**
2. BFF → `develop` (`wts-finish slave-1`) — отдельное «да»; миграция на bff-dev, выключатель `false`.
3. Координатор запускает веб (`aura-web-manor`, вместе с `AURAT-0218`) и приложение (`aura-app-manor`).
4. Прод: BFF (PR `develop → main`) → веб → **`WEB_CONSENT_REQUIRED=true` и
   `STRIPE_TERMS_CONSENT=client` в проде** → ворота 4 закрыты с BFF-стороны. Android шлёт согласие с ближайшего релиза; старые сборки — остаточный риск,
   уже названный в `AURAT-0209-015` п. 5.

## Проверка в маноре (после merge, на bff-dev)

- миграция применяется, `CHECK` и триггер на месте (`UPDATE consents` падает);
- бронь, «сейчас», продление с согласием → по записи у каждого, с верной ссылкой; повтор ключа —
  второй записи нет;
- без согласия с приложения (без `Origin`) → бронь проходит, в логе «без согласия»;
- `WEB_CONSENT_REQUIRED=true`: с web-`Origin` без согласия → 400 `consent_required`, баланс не
  тронут;
- `STRIPE_TERMS_CONSENT=client` (sandbox): старт оплаты без `termsConsent` → 400; с ним → запись
  `CARD_TERMS` на попытку, у сессии Stripe нет `consent_collection`, оплата проходит.
