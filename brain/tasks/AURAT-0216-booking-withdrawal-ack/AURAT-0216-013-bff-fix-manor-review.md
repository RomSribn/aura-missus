# AURAT-0216-013 — BFF: замечания манора к спеке `011`

Дата: 2026-11-18. Манор `aura-app-manor`: «в целом принята». Одна таблица, запись в транзакции
действия, граница «приложению не отказываем» совпадает с `AURAD-0024` и `AURAT-0209-015` п. 5.

Замечания (все вносятся в `014`, спека v2):

1. Решение 5 — отдельный режим `STRIPE_TERMS_CONSENT=client` (название из `AURAT-0218-005` B1):
   `consent_collection` не шлём, режим разрешён с live-ключом, `termsConsent` в `CardTopUpRequest`
   обязателен (иначе 400 `consent_required`). `none` с live-ключом по-прежнему запрещён.
   `WEB_CONSENT_REQUIRED` — только для брони, «сейчас» и продления с веба.
2. Согласие с Terms веб шлёт в `CardTopUpRequest`, отдельного эндпоинта нет: веб открывает сессию
   Stripe после первой отметки галочки, при смене суммы галочка остаётся. `AURAT-0218` B1–B2 (режим
   `client`, запись `CARD_TERMS`) делает BFF здесь.
3. Переводы как доказательство: в JSDoc правил для клиентов — правка текста галочки на любом языке
   только с новой версией; в вебе и приложении тест фиксирует 24 перевода каждой версии (снимок или
   хеш), правка без новой версии роняет CI.
4. `terms-v1` в JSDoc — Terms, опубликованные по `AURAT-0209` (Last updated — дата публикации, снимок
   страницы — в брейне `0209`). Веб берёт версию только из контрактов.
5. П. 1 BFF: вместо «ровно одна ссылка» — «ровно тот набор ссылок, что положен виду».
6. Решение 9: назвать записи согласий в Privacy §02 одной фразой — манор передаёт в `AURAT-0209`; в
   спеке убрать «правки текста не нужно», сослаться на `0209`.

Порядок выпуска — без замечаний. Веб-часть `0216` после контрактов `v0.35.0` манор отдаст слоту
`AURAT-0218` (`aura-web-manor` slave-2).
