# AURAT-0153-004 — context

## Что делает код сейчас (develop @ `6ff2530`)

`usePhoneStep` → `preferredCountry(navigator.languages)`: регион **первой локали, где он указан**,
если он в `SMS_REGIONS` (35 стран), иначе `DEFAULT_COUNTRY = 'ES'`.

Почему владелец видит +34:
- В браузерах регион в списке локалей часто не указан: Chrome по умолчанию отдаёт `['ru']`, `['en']`,
  `['uk']`, а `['ru', 'en']` вообще без регионов → всегда ES.
- Если регион указан, он часто не тот: `en-US` стоит в Chrome по умолчанию у людей в Испании,
  Германии и других странах → у русскоязычного человека в Испании с `['ru', 'en-US', 'en']`
  определяется US.
- `ru-RU` → RU, туда SMS не отправить → ES.

## Чем можно определить страну на вебе

| Источник | Плюсы | Минусы |
|---|---|---|
| Часовой пояс `Intl.DateTimeFormat().resolvedOptions().timeZone` | Мгновенно, без сети и без разрешений; показывает, **где человек сейчас** (`Europe/Madrid` → ES, `Europe/Kyiv` → UA); отдаёт и Hermes в RN — то же правило подходит приложению | Нужна таблица «пояс → страна» (≈92 пояса для 35 стран, из IANA `zone.tab`); у путешественника часы показывают страну поездки, а не его номера |
| Регион локали (как сейчас) | Уже есть | Часто пустой или по умолчанию `en-US` |
| IP-геолокация (заголовок CDN / BFF) | Точнее всего | Нужны задачи в BFF и contracts, сетевой запрос до показа экрана; VPN |
| Запомнить страну последнего входа (`localStorage`) | Точно для того, кто уже входил | Помогает только при повторном входе; в приложении хранилища нет (`AURAT-0087`), совпадения с приложением не будет |

## Решения в brain

- `AURAT-0087`: страна по умолчанию — из локали, но только если в неё можно отправить SMS; Испания —
  страна на крайний случай. Правило не трогаем, расширяем источники.
- Build rules: чистая логика переносится из приложения с тестами. Правило должно совпадать
  с `AURAT-0152`: что первым примет одна сторона, то перенимает другая.
