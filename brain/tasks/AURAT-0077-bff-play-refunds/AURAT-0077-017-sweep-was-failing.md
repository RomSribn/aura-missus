# AURAT-0077-017 — Проход просил ровно границу окна и падал молча

Дата: 2026-09-18, 19:30 CEST
Исправлено: `b708f29`

## Симптом

Строка `play refund sweep` не появилась ни разу: ни в 18:23 (первый запуск,
тогда ещё без логирования), ни в 19:23. При этом уведомление о возврате
обработалось нормально — `outcome: debited`, запись в журнале, баланс −300.

Асимметрия и указала на причину: **обработка уведомления не ходит в Google,
проход ходит**. Это единственное, чем два пути отличаются.

## Причина — наша

Адаптер просил `startTime = сейчас − ровно 30 дней`. Проверено на живом API
(с временно выданной ролью, снята сразу):

```
startTime = now − 30d       → HTTP 400
  "Start time [1787160724000] must be within [30] days of data."
startTime = now − 30d + 1ч  → HTTP 200
startTime = now − 7d        → HTTP 200
```

Пока запрос летит, часы Google уходят вперёд, и вычисленное нами значение
оказывается уже за границей. То есть проход падал **на каждом запуске**, с
первой секунды жизни фичи.

Раньше этого не было видно, потому что ручная проверка API делалась **без**
`startTime` — единственный параметр, который код добавляет, и был непроверен.

## Почему это прожило незамеченным

**Падения фоновых задач в этом сервисе не слушает никто.** Ни одного
`@OnWorkerEvent('failed')`, ни одного `try/catch` в процессорах, а
`@nestjs/bullmq` сам ничего не пишет. При `attempts: 1` упавший проход
неотличим ни от прохода, который ничего не нашёл, ни от прохода, которого не
было.

Это не привнесено задачей — так во всём сервисе. Но именно это спрятало баг.

## Что сделано

| | |
|---|---|
| Окно | просим `30 дней − 1 час`. Проход ходит раз в час, до дальнего края окна возврат не доживает — запас бесплатен |
| Тест окна | пиннит **«строго внутри»**, а не «не больше тридцати дней»; и что запас не съел окно целиком |
| Падения | `@OnWorkerEvent('failed')` на очереди возвратов: имя задачи и текст ошибки |
| Токен в логе ошибки | закрыт тестом — `job.data` не логируется никогда |
| Остальные очереди | `TECH-DEBT #31`, шире задачи |

`1207 тестов, 96 наборов` — зелено; lint, typecheck, build чисты.

## Подтверждено попутно

Ответ API с работающим `startTime` содержит **наш возврат**:

```json
{ "purchaseToken": "hjkda…", "orderId": "GPA.3343-8577-4981-61365",
  "voidedTimeMillis": "1789751199684", "voidedSource": 1, "voidedReason": 1 }
```

То есть отозванная тестовая покупка в Voided Purchases API **есть**. После
выкатки исправления проход её найдёт и **не тронет** — `refundEntryId` уже
стоит. Это и будет тот самый живой тест идемпотентности.

## Что это значит для релиза

Без этой правки подстраховка не работала бы вообще — на проде тоже. Быстрый
путь (RTDN) работает и проверен, но вся ценность схемы в паре, а половина была
мертва. Релиз в `main` имеет смысл только после `b708f29`.
