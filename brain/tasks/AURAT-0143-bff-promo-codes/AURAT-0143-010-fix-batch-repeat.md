# AURAT-0143-010 — Fix: повтор партии в бэкофисе (пост-мёрж)

Date: 2026-10-28

Владелец (проверка на bff-dev): две «Партия А» ($1 × 2, 23:52:27 и 23:53:01 UTC, разные
`creationKey`) — вернулся к списку и ввёл те же данные заново. И дыра против §4 спеки:
`creationKey` рождается на каждом `POST /confirm`, страницы no-store — «Назад» со страницы
партии переотправляет `/confirm`, получает новый ключ, «Создать» делает вторую партию. Защищён
только двойной клик.

Правка:
1. `creationKey` — при открытии формы (`GET /new`), скрытым полем через `/confirm` и
   «Исправить» до создания. «Назад» с переотправкой — тот же ключ → «Эта партия уже была
   создана». Новая форма из списка — новый ключ.
2. На подтверждении: если есть партии с той же кампанией (trim, без учёта регистра) —
   предупреждение со списком (когда, кем, N × $X, погашено, ссылка) и строкой «человек сможет
   погасить по коду из каждой партии»; кнопка — «Создать ещё одну партию». Не запрет.
3. Смоук: повтор `/confirm` с ключом формы → «Создать» → та же партия; предупреждение о той же
   кампании.

Решение по ходу: `/confirm` с ключом уже созданной партии → сразу 303 на неё с `notice=existing`
(страница подтверждения иначе сказала бы «Ещё ничего не создано»). «Создать» с тем же ключом —
по-прежнему та же партия.

Дальше — коммит в ветку, merge gate.

## Сделано

- `creationKey` рождается в `GET /new` (`randomUUID`), едет скрытым полем через форму,
  `/confirm`, «Исправить» (`POST /new`) и «Создать». Одна схема формы `promoBatchFormSchema`
  (поля + `creationKey` uuid) на всех четырёх шагах.
- `PromoCodesAdminService.confirm()`: ключ уже создал партию → `existing` (303 на неё,
  `notice=existing`); иначе проверка черновика → партии той же кампании.
- Репозиторий: `findBatchIdByCreationKey` (был приватным), `findBatchesByCampaign` —
  `equals` + `mode: 'insensitive'` по обрезанному имени (в базе имя хранится обрезанным),
  новые сверху, до 20.
- Подтверждение: `alert` «Партия с такой кампанией уже есть» / «Партий … уже N», строка
  «Человек сможет погасить по коду из каждой партии.», список (когда — ссылкой, кем,
  N × $X, погашено, статус); кнопка «Создать ещё одну партию». Не запрет.
- Тесты: вид (ключ в форме, предупреждение и кнопка), сервис (`confirm`: existing без
  проверки, ready с обрезанной кампанией, invalid без поиска), смоук (новая форма — новый
  ключ; ключ сквозь confirm / «Исправить»; повтор `/confirm` → 303 existing; повтор
  «Создать» → existing, создана одна партия; предупреждение о «  компенсация » и создание
  второй). README.
