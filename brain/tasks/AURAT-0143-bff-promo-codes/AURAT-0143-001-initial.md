# AURAT-0143-001 — Initial (исполняется в `aura-bff-manor`)

Date: 2026-10-27
Слот: `slave-1`, ветка `feature/AURAT-0143-promo-codes` (обе репы).
Фича: `AURAF-0021` «Промокоды» (документ фичи заводит этот слот).

Слова владельца: «нужно продумать реализацию работы промокодов. Для начала я хочу иметь на
нашем бекофисе функционал генерации промокодов, ввод суммы кредита, который будет начислен
когда введут промокод, после ввода аккаунт пользователя пополняется и промокод перестает быть
рабочим». На план манора `aura-app-manor` — «да, запускай».

ID выданы в `aura-app-manor` (`active-work.md`, абзац «AURAF-0021 / AURAT-0143 / AURAT-0144 /
AURAT-0145»); здесь новых ID не выдаём. `0143` — `aura-bff` + `aura-contracts` `v0.25.0`;
`0144` (app: строка «Coupons & Promo Codes» + шторка), `0145` (web: поле в `/me`) ждут форму
контракта из спеки этой задачи.

План манора, одобренный владельцем (кратко, детали — в спеке):
1. Бэкофис, вкладка «Промокоды»: форма (сумма $, количество, кампания — обязательно, срок),
   страница подтверждения «N кодов × $X = $Y»; список партий и кодов со статусами
   (активен / использован — когда и id пользователя / истёк / отключён), сводка выдано /
   погашено; «Отключить» код или партию (погашенный не отзывается); без JS, коды — в поле
   для копирования и CSV.
2. Погашение в BFF: одна транзакция с блокировкой строки кода; сумма из базы; новый тип
   проводки `PROMO_CREDIT`; код только в теле, в логах — id; лимит неверных попыток
   (~10/час/аккаунт); формат `K7QM-9XRT` без похожих символов, ввод нормализуется; из партии —
   один код на аккаунт; повтор своим — «уже зачислено», чужой — «код уже использован».
3. Контракты: запрос/ответ погашения, `PromoCodeRefusalCode`; `v0.25.0`.
4. Открыто для спеки: потолки (код ≤ $100, партия ≤ 500, срок 90 дней), показ кода оператору
   повторно или только хэш, путь и имя эндпоинта.
5. Вне задачи (модель не должна мешать): многоразовые публичные коды, коды для новых аккаунтов,
   ссылка с кодом, ручное списание погашенного, отдельный промо-баланс (`AURAF-0009`).
6. Владельцу в спеке: строка в Terms, коды только бесплатные (обход IAP — `AURAI-0006`), коды
   bff-dev на проде не работают.

Ограничения: слейв без стека и живой БД (тесты на фейках); живая проверка — манор после мёржа.
Merge gate и push в `aura-contracts` — только с разрешения владельца. Коммиты без
Co-Authored-By и упоминаний ИИ.
