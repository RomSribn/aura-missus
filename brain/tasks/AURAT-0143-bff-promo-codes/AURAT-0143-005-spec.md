## 1. Контракт — `@aura/contracts` `v0.25.0` (минорная, только добавления)

Новый модуль `src/promo.ts`, строка в таблице README, абзац `v0.25.0`.

**Запрос** `POST /v1/wallet/promo-codes/redeem` (Firebase-токен, под `billing_enabled`):

```ts
export const RedeemPromoCodeRequest = z.object({
  /** As typed. Case, spaces and dashes are the server's to normalise. */
  code: z.string().min(1).max(64),
});
```

- Код — **только в теле**: URL пишется в лог целиком, тело — никогда.
- Клиент код не проверяет и не нормализует (кроме «поле не пустое»): правило формата живёт
  на сервере, чтобы его можно было менять без релиза клиентов.

**Ответ 200** (и на первое погашение, и на повтор — как у Play/Apple):

```ts
export const RedeemPromoCodeResponse = z.object({
  /** The PROMO_CREDIT ledger entry — the original one on a replay. */
  entryId: z.string(),
  balanceMinor: z.number().int(),        // текущий баланс после зачисления
  currency: Currency,
  creditedMinor: z.number().int().positive(), // сколько дал код — из базы
  /** True: this account had already redeemed this code; nothing credited twice. */
  replayed: z.boolean(),
});
```

**Отказы** — `ApiError { code, message }`, `code` из:

```ts
export const PromoCodeRefusalCode = z.enum([
  'promo_code_not_found',          // 409 — нет такого кода (или не тот формат)
  'promo_code_already_used',       // 409 — погашен ДРУГИМ аккаунтом
  'promo_code_expired',            // 409 — срок партии вышел
  'promo_code_disabled',           // 409 — оператор отключил код или партию
  'promo_code_campaign_used',      // 409 — этот аккаунт уже погасил код из этой партии
  'promo_code_too_many_attempts',  // 429 + заголовок Retry-After (секунды)
]);
```

- Все отказы по сути — `409`, «слишком много попыток» — `429`. `404` без кода по-прежнему
  значит «биллинг выключен» (как у всего `/v1/wallet`), `400` — тело не той формы.
- `promo_code_campaign_used` — **новое относительно плана манора**: правило «из одной партии —
  один код на аккаунт» требует своего отказа (иначе клиент не объяснит, почему годный код
  не сработал).
- Тексты для людей клиенты берут по `code`; `message` — английский, для разработчика.

**OpenAPI** (`src/contracts/openapi.ts` BFF): `redeemPromoCodeRequestOpenApi`,
`redeemPromoCodeResponseOpenApi`; `@HttpCode(200)` — как у `top-ups/google`.

## 2. Модель данных (Prisma + миграция)

```prisma
enum LedgerEntryType { … PROMO_CREDIT }   // промо-кредит, не TOPUP: тип не исправить задним числом

// Партия (кампания) — то, что создаёт оператор одной формой.
model PromoBatch {
  id                   String   @id @default(cuid())
  campaign             String                 // «Блогер Анна, ноябрь», 1–80 символов
  amountMinor          Int                    // кредит одного кода, центы
  quantity             Int
  expiresAt            DateTime               // исключительная граница: до неё код годен
  createdByOperatorId  String                 // id оператора, БЕЗ FK (см. ниже)
  createdByLogin       String                 // снимок логина на момент создания
  creationKey          String   @unique       // одноразовый ключ страницы подтверждения
  disabledAt           DateTime?              // «Отключить партию» — для показа
  disabledByOperatorId String?                // без FK
  disabledByLogin      String?                // снимок логина
  createdAt            DateTime @default(now())
  codes                PromoCode[]
  @@map("promo_batches")
}

model PromoCode {
  id                   String   @id @default(cuid())
  batchId              String
  code                 String   @unique       // нормализованный: 8 символов, без дефиса
  disabledAt           DateTime?              // решает при погашении (а не batch.disabledAt)
  disabledByOperatorId String?                // без FK
  disabledByLogin      String?                // снимок логина
  createdAt            DateTime @default(now())
  redemption           PromoRedemption?
  @@index([batchId])
  @@map("promo_codes")
}

// Погашение — отдельная таблица, по образцу play_purchases: пишется в той же транзакции,
// что и проводка. Отдельная (а не колонки на коде) — чтобы многоразовые коды потом были
// снятием одного unique, а не перекройкой модели.
model PromoRedemption {
  id             String   @id @default(cuid())
  codeId         String   @unique             // одноразовость — на уровне базы
  batchId        String                       // денормализовано ради unique ниже
  walletId       String
  ledgerEntryId  String   @unique
  creditedMinor  Int                          // из партии, не из запроса
  createdAt      DateTime @default(now())     // «когда погашен»
  @@unique([batchId, walletId])               // из партии — один код на аккаунт
  @@map("promo_redemptions")
}
```

- **Оператор — без FK.** `backoffice:operator remove` удаляет строку оператора
  (`deleteMany`); FK на `backoffice_operators` уронил бы удаление (или, с `SET NULL`, список
  потерял бы «кем»). Поэтому id оператора — простой столбец, а рядом — снимок логина на момент
  действия; бэкофис показывает снимок.
- Ключ проводки — `promo:<codeId>` (серверный, с клиентским uuid заглушки не столкнётся).
- Удаление аккаунта (`AURAT-0042`) кошелёк и журнал не трогает — погашения тоже остаются;
  `users` остаётся надгробием, поэтому бэкофис покажет id пользователя и после удаления.
  Телефон и имя в погашении не хранятся.
- Миграция — только добавления (enum value + три таблицы); применяется при деплое.

## 3. Погашение в BFF

Модуль `src/modules/promo-codes/` (контроллер, сервис погашения, сервис оператора,
репозиторий + Prisma-реализация, формат кода, лимит попыток). Маршрут под
`BillingEnabledGuard`. Деньги пишет репозиторий модуля в той же форме транзакции, что и
кошелёк (как это делает репозиторий сессий).

**Формат кода.** Алфавит из 31 символа без похожих: `23456789ABCDEFGHJKMNPQRSTUVWXYZ`
(нет `0 O 1 I L`); 8 символов из `crypto.randomInt` (~8.5·10¹¹ вариантов); хранится
`K7QM9XRT`, показывается `K7QM-9XRT`. **Нормализация ввода:** верхний регистр; убрать
любые пробельные символы (`\s` — включая NBSP U+00A0 и прочие юникод-пробелы), невидимые
(U+200B–U+200D, U+2060, U+FEFF) и любые дефисы/тире (`-`, U+2010–U+2015, U+2212) — коды будут
копировать из Instagram и Telegram; если после этого не 8 символов алфавита — «не найден» (без
запроса в базу, но попытка считается).

**Порядок (одна транзакция):**
1. Лимит: Redis-счётчик неудачных попыток аккаунта (ключ — sha256 от id пользователя, как у
   входа в бэкофис). ≥ 10 за час → `429 promo_code_too_many_attempts`, код не проверяется.
   Считаются **только** `promo_code_not_found` — это и есть перебор; истёкший / чужой /
   отключённый код — настоящий код, и человек, повторивший его, не должен запирать себя.
2. Кошелёк — `getOrCreateByUserId` (до транзакции, как у Play).
3. `SELECT … FROM promo_codes WHERE code = $1 FOR UPDATE` — нет строки → `not_found`.
4. Погашение кода уже есть: **этим кошельком** → `200 replayed: true` (исходная проводка,
   текущий баланс); **другим** → `already_used`. Повтор проверяется раньше срока и
   отключения: «обрыв сети после зачисления» — успех, даже если код с тех пор истёк.
5. `code.disabledAt` → `disabled`; `batch.expiresAt ≤ now` → `expired`.
6. `SELECT … FROM wallets … FOR UPDATE`; погашение из этой партии этим кошельком уже есть →
   `campaign_used` (под замком кошелька — два разных кода одной партии одним аккаунтом
   одновременно сериализуются на нём).
7. Проводка `PROMO_CREDIT` на `batch.amountMinor` → строка `promo_redemptions` →
   `wallets.balanceMinor`. Unique (`codeId`, `batchId+walletId`, ключ проводки) — страховка:
   сработал → откат и повтор разбора по шагам 4–6 вне гонки.

Порядок замков — **код → кошелёк**; все прочие денежные пути берут только кошелёк, отключение
в бэкофисе — только код. Цикла нет. Двое с одним кодом одновременно — сериализуются на строке
кода: деньги получит первый, второй — `already_used`.

**Сумма** — только `batch.amountMinor`; в запросе суммы нет вообще.
**Логи:** код не пишется нигде — ни в лог, ни в текст исключения; при зачислении — `info` с
id кода, id партии и суммой (без id пользователя, по правилу PII). Тело запроса логгер не
пишет (проверено); ошибка валидации значение не эхает.

## 4. Бэкофис — вкладка «Промокоды»

Тот же каркас, что «Отзывы» / «Удаления» (`AURAT-0075`): серверный HTML без JS,
`SameOriginGuard` + сессия оператора, no-store/noindex, формы — строгие zod-схемы, после
действия — 303 с плашкой. Вкладка видна и маршруты отвечают только при `BILLING_ENABLED`
(иначе 404 — как у кошелька).

| Маршрут | Что |
|---|---|
| `GET /backoffice/promo-codes` | Сводка + список партий (новые сверху, по 50) + кнопка «Новая партия» |
| `GET /backoffice/promo-codes/new` | Форма: сумма $, количество, кампания, «действует до» (дата) |
| `POST /backoffice/promo-codes/confirm` | Проверка формы → страница подтверждения, **в базу ничего** |
| `POST /backoffice/promo-codes` | Создание из страницы подтверждения → 303 на страницу партии |
| `GET /backoffice/promo-codes/:batchId` | Партия: коды со статусами, поле для копирования, CSV |
| `GET /backoffice/promo-codes/:batchId/codes.csv` | CSV всей партии (attachment, no-store) |
| `POST /backoffice/promo-codes/:batchId/disable` | Отключить все неиспользованные коды партии |
| `POST /backoffice/promo-codes/:batchId/codes/:codeId/disable` | Отключить один код |

**Форма и подтверждение.**
- Сумма: `10` или `10.50` (точка или запятая) → центы; от $1 до **$100**. Количество: 1…**500**.
  Кампания: обязательна, 1–80 символов после trim. Срок: дата UTC, по умолчанию сегодня + **90**
  дней, не раньше завтра и не позже чем через 365 дней; код годен до конца этого дня UTC.
- Ошибка формы — та же форма с введёнными значениями и текстом ошибки (не 400-страница: здесь
  человек печатает руками).
- Подтверждение: «**50 кодов × $10 = $500** · кампания «Блогер Анна, ноябрь» · действуют до
  26 янв 2027 включительно (UTC)», кнопки «Создать» и «Исправить» (назад к форме с
  теми же значениями). Значения едут скрытыми полями + одноразовый `creationKey`; повторная
  отправка (двойной клик, «назад» + «отправить») не создаёт вторую партию — 303 на уже
  созданную.
- Генерация: N уникальных кодов в памяти, вставка партией в одной транзакции с партией;
  столкновение с существующим кодом (unique) → новая генерация, до 3 раз.

**Список партий:** кампания, кредит кода, «погашено 12 / 50», действует до, статус партии
(активна / истекла / отключена), создана (UTC) и кем (снимок логина).
**Сводка (все партии):** выпущено $ (Σ сумма × количество), погашено $ (Σ погашений),
активно сейчас $ (годные непогашенные коды — висящее обязательство).

**Страница партии:** заголовок, те же цифры по партии; поле `<textarea readonly>` с
**активными** кодами по одному в строке (`K7QM-9XRT`) — выделить и скопировать; ссылка
«Скачать CSV» (`code,status,redeemed_at_utc,user_id` — все коды партии; имя файла —
`promo-codes-<batchId>.csv`, из id партии, не из названия кампании); таблица кодов:
код, статус (активен / использован — когда (UTC) и id пользователя / истёк / отключён),
кнопка «Отключить» у активных; «Отключить все неиспользованные» — отдельная форма с
пояснением «погашенные коды не отзываются» и **обязательной галочкой** «Понимаю: включить
обратно нельзя» (`required` в разметке, без JS; сервер без галочки ничего не делает и
возвращает страницу с плашкой) — промах необратимо гасит уже розданную кампанию. Без
пагинации: партия ≤ 500 строк.

**Отключение** — транзакция: `SELECT … FROM promo_codes WHERE … ORDER BY id FOR UPDATE`
(партия блокирует коды в порядке id — две одновременные операции над одной партией не
сцепятся), затем
`disabledAt` только у кодов без погашения (погашенный не отзывается, отключённый не
перезаписывается). У партии ещё `disabledAt` — для статуса в списке. Гонка с погашением
решается замком строки кода: что первым взяло замок, то и случилось; плашка говорит, сколько
кодов отключено на самом деле.

## 5. Тесты (pure, в слоте)

- формат: алфавит и длина генерации, уникальность в партии; нормализация (`k7qm 9xrt`,
  `K7QM–9XRT`, `O`/`0` → не найден, 7/9 символов → не найден);
- сервис погашения на фейках: зачисление (сумма из партии, тип `PROMO_CREDIT`, ключ
  `promo:<id>`), повтор своим → `replayed`, чужой → `already_used`, истёк / отключён /
  `campaign_used`, не найден → счётчик +1, 10 неудач → 429 без обращения к репозиторию;
  истёкший код не увеличивает счётчик; сообщение исключения не содержит кода;
- нормализация: NBSP, U+200B…U+200D, U+2060, U+FEFF внутри и по краям кода;
- сервис оператора: снимок логина при создании и отключении; границы суммы/количества/срока, разбор `10,50`, повтор `creationKey` →
  та же партия, отключение не трогает погашенные;
- представления: экранирование кампании, строка подтверждения «50 кодов × $10 = $500»,
  статусы, поле с активными кодами, CSV (экранирование, заголовок, имя файла из id);
  «Отключить все» без галочки → ничего не отключено;
- контроллеры: 200 у redeem (и в OpenAPI), 404 при выключенном биллинге (и для вкладки),
  `SameOriginGuard` на POST бэкофиса (смоук по образцу `backoffice.smoke.spec.ts`);
- контракты: разбор запроса/ответа и enum (в `aura-contracts` раннера нет — проверяют спеки BFF).
- Prisma-транзакцию на живой базе не тестируем в слоте — это живая проверка манора (§7).

## 7. Живая проверка в маноре (после мёржа, bff-dev)

Вход в бэкофис → партия (подтверждение, двойная отправка не дублирует) → погашение кода →
баланс и проводка `PROMO_CREDIT` → повтор тем же аккаунтом (`replayed`) и другим
(`already_used`) → два погашения одного кода одновременно (одно зачисление) → второй код той же
партии тем же аккаунтом (`campaign_used`) → 10 неверных кодов → 429 → отключение кода и
партии → лог запроса без кода.

## 9. Решения на одобрение (рекомендации)

1. Потолки: код ≤ **$100**, партия ≤ **500**, срок по умолчанию **90** дней (макс. 365).
2. **Показ кодов оператору повторно — да**, только в бэкофисе (код хранится как есть,
   `unique`). Иначе потерянный CSV = потерянная партия; от утечки защищает «Отключить партию».
   Альтернатива — хранить хэш и показывать коды один раз при создании.
3. Эндпоинт — `POST /v1/wallet/promo-codes/redeem`, 200 и на повтор.
4. Шестой код отказа `promo_code_campaign_used`.
5. Лимит считает только «не найден» (10 в час на аккаунт), остальные отказы — нет.
6. Вкладка и погашение — за `billing_enabled` (как весь кошелёк).

## Правки владельца (2026-10-27)

1. Оператор без FK + снимок логина (`createdByLogin`, `disabledByLogin`).
2. «Отключить все неиспользованные» — обязательная галочка в той же форме.
3. Нормализация убирает все пробельные (вкл. NBSP) и невидимые U+200B–U+200D, U+2060, U+FEFF.
4. Отключение партии блокирует коды в порядке id; имя CSV — из id партии.
