Репо: `aura-app-manor` (приложение). Выдан координатором (сессия slave-1-ac). Владелец — на вопрос о панели эмодзи

## Что не так

`AURAT-0186-011`, п. 2 и 4: на Android 15+ (edge-to-edge, окно не сжимается) `KeyboardAvoider` (`shared/ui/keyboard-avoider`)
считает отступ только по `keyboardDidShow` / `keyboardDidHide`. RN шлёт их лишь при смене **видимости** IME
(`ReactRootView.checkForKeyboardEvents`, API 30+). Когда клавиатура меняет **высоту**, не закрываясь, отступ остаётся
старым:

- панель эмодзи Gboard (и буфер обмена) в треде: верх панели 1132 px против 1457 у клавиатуры (AVD API 36, 1080×2340)
  — **поле ввода целиком под панелью**, введённые эмодзи не видны до возврата на «ABC»;
- панель стилуса → полная клавиатура без закрытия: отступ остался от панели, кнопка phone-auth под клавиатурой.

TECH-DEBT 17 оценивает это как «Low — нижний край поля»: на деле закрыто всё поле.

## Что нужно (направление — уточнит спека)

1. Нативно (Android, `MainActivity` / пакет приложения): слушать IME-инсет (`WindowInsetsCompat` / `WindowInsetsAnimationCompat`)
   и сообщать в JS высоту / верх клавиатуры при **каждом** изменении, не только при показе / скрытии.
2. `use-keyboard-inset`: пересчитывать отступ по этому событию (тот же `measure` pageY), не ломая показ / скрытие, поворот
   (`Keyboard.dismiss`) и Android ≤ 14 / iOS (там прежний `KeyboardAvoidingView`).
3. TECH-DEBT 17 — переписать: что закрыто этой задачей, что остаётся до RN 0.86 (`react-native-keyboard-controller`,
   анимация вместе с клавиатурой).
4. Проверка — в маноре: AVD `Galaxy_A16_API36` (жесты и 3 кнопки; эмодзи, буфер, панель стилуса — см. память
   «AVD API 36 Gboard»), A50 (Android 11) — без изменений, Pixel 10 владельца.

## Не здесь

`react-native-keyboard-controller`, `edgeToEdgeEnabled=true` — после RN 0.86 (решение владельца). Иконки строки
состояния — `AURAT-0187`.

Не запущена — ждёт команды владельца.
