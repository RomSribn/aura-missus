## Что нужно

Та же Checkout Session, только показанная внутри страницы веба (Embedded Checkout), а не на странице
Stripe. Зачисление, вебхуки, сверка, возвраты и диспуты не меняются.

1. **Сессия.** Сейчас `createCheckout` в `src/modules/stripe/stripe-card-payments.ts` передаёт
   `success_url` / `cancel_url` (`:132–133`). Для встроенной формы:
   - `ui_mode: 'embedded_page'` и `return_url` вместо `success_url` / `cancel_url`: у встроенной формы
     нет `cancel_url`;
   - `redirect_on_completion: 'if_required'`. Карта и кошельки завершаются на месте. Банковские
     методы (iDEAL, Bancontact) уходят к банку и возвращаются на `return_url` — тот же
     `/checkout?payment=<id>`;
   - остальное как сейчас:
     - USD и Adaptive Pricing;
     - 3DS `any`;
     - `STRIPE_TERMS_CONSENT` (`AURAT-0207-011`);
     - metadata, `expires_at`, `integration_identifier`;
   - имена параметров и значений сверить по закреплённой версии API `2026-09-30.endive`.
2. **Ответ старта.** Сейчас он `{ redirectUrl }` (`src/modules/wallet/card-top-up.service.ts:160–236`).
   - Встроенной форме нужен `client_secret` сессии.
   - Повтор того же `paymentId`, пока сессия открыта, отвечает тем же секретом — как сейчас той же
     ссылкой.
   - Секрет хранить или каждый раз брать у Stripe — решить в спеке.
3. **Публичный ключ.** Форме нужен ключ `pk_test_…` / `pk_live_…` того же аккаунта, что и секретный ключ
   BFF. Откуда его брать — решение 2.
4. **Отмена.** На вебе нет ссылки «назад» со страницы Stripe. Человек закрывает шторку, и веб вызывает
   уже существующий `POST /v1/wallet/top-ups/card/:paymentId/cancel`: сессия закрывается, а если
   человек успел заплатить — зачисление. Проверить, что отмена открытой встроенной сессии работает
   так же, как у hosted.
5. **Контракты** — новая minor-версия `@aura/contracts` (`v0.33.0`): новые поля ответа, а при решении
   1Б — и запроса. Выпускается до кода веба, тег — с «да» владельца.
6. **Домены для кошельков.** Apple Pay во встроенной форме требует, чтобы домен был зарегистрирован в
   Stripe (Payment method domains):
   - `web-dev.aura-app.cc` — в sandbox;
   - `web.aura-app.cc` — в live.

   Карты работают и без этого. По документации Stripe для встроенной формы сверить, нужен ли файл
   ассоциации Apple на домене. Регистрацию в sandbox может сделать координатор через Stripe MCP.
7. **Тесты** — на моке Stripe:
   - параметры встроенной сессии;
   - `client_secret` в ответе;
   - повтор старта тем же `paymentId`;
   - отмена;
   - при решении 1Б — оба режима.

## Решения для спеки (с рекомендацией)

1. **Режим.**
   - А — только встроенная форма, hosted уходит сразу.
   - Б — оба режима на время перехода. Запрос говорит `ui: 'embedded' | 'hosted'`, по умолчанию hosted.
     Hosted убирается отдельной правкой, когда `AURAT-0212` попадёт в `develop`.
   - **Рекомендация: Б**: между мёржами BFF и веба `develop` и web-dev не ломаются.
2. **Публичный ключ.**
   - А — BFF отдаёт его в ответе старта, из `STRIPE_PUBLISHABLE_KEY` рядом с секретным. Ключи одного
     аккаунта не разойдутся, а вебу не нужна новая переменная сборки на каждое окружение.
   - Б — переменная сборки веба `VITE_STRIPE_PUBLISHABLE_KEY` для каждого окружения.
   - **Рекомендация: А.**
