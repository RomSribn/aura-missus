# AURAT-0206 — бэкофис: кто погасил промокод
Type: technical (backoffice UX)
Status: done — `aura-bff` `develop` @ `0638f5b`, принято владельцем на bff-dev 2026-11-11
Priority: P2
Slave: slave-1, ветка `feature/AURAT-0206-promo-redemptions`
Фича: `AURAF-0021` (промокоды), `AURAF-0022` (публичные коды) — новая строка в таблице скоупа
после исполнения.

## Что

На странице партии во вкладке «Промокоды» (`/backoffice/promo-codes/:batchId`) — и у
одноразовой партии, и у публичного кода — новый блок **«Кто погасил»**.

### Сводка «что было дальше» (по всем погасившим партии, не только по странице)

| Карточка | Значение |
|---|---|
| Пополнили после | `N из M аккаунтов · X%`, ниже — `на $Y` (сумма пополнений) |
| Сессий после | `K сессий`, ниже — `у L аккаунтов · без удалённых` (сессии удалённых аккаунтов к ним не привязать — цифра неполная, подпись это говорит) |

### Таблица — новые сверху, по 50, пейджер «Новее / Старше» (`?page=2#redeemers`)

Блок — `<section id="redeemers">`; ссылки пейджера ведут на якорь, чтобы у одноразовой партии
(над блоком — полная таблица кодов) оператор не оказывался вверху страницы.

| Колонка | Что |
|---|---|
| Погашен, UTC | время погашения |
| Код | только у одноразовой партии — какой код (у публичного он один) |
| Пользователь | имя или «без имени»; под ним id мелко. Удалённый аккаунт — метка «удалён» вместо имени |
| Контакты | телефон (`phoneE164` как есть) и email — двумя строками в одной ячейке, или «—» (исполнение: две колонки в 960 px не влезали, `-007`) |
| Аккаунт с, UTC | дата регистрации (`users.createdAt`) — видно, привёл ли код новых людей |
| Пополнения после | `2 · $40` или «—» |
| Сессий после | `3` или «—» (нет оплаченных или аккаунт удалён — у удалённого рядом метка «удалён») |
| Баланс | текущий баланс кошелька |

**Определения** (одни и те же для строки и сводки):
- *Пополнения после* — записи журнала `TOPUP` этого кошелька **позже** погашения: количество и
  сумма. Возвраты стора не вычитаются (подпись под заголовком колонки это говорит) —
  конверсия «Пополнили после» поэтому может быть чуть завышена; владелец в курсе.
- *Сессий после* — сессии человека с `sessions.createdAt` (момент брони, **не** `startsAt` —
  время слота) **позже** погашения; условие по статусу / цене — см. «Решение владельца» ниже.
  Промокод — это кредит на балансе: сессия на нём оплачивается с баланса как обычно и
  `costMinor > 0`; `costMinor = 0` бывает только когда скидка первой сессии или сезонной
  кампании (`creditMinor`) покрыла цену целиком. У удалённого аккаунта сессии от человека
  отвязаны (`conversationId = NULL`), и через журнал их тоже не найти (бесплатная сессия
  проводки не пишет) — в строке «—», в сводке не считаются (подпись под карточкой).
- *Аккаунт удалён* — есть `AccountErasure`; имя / телефон / email уже стёрты, id и деньги
  остаются (как сейчас).

Пусто — «Код ещё никто не погасил.»; страница дальше последней (`?page=99`) — «На этой странице никого нет.» (`-008`).

## Решение владельца (2026-11-11, `-006`)

*Сессий после* считаем **только оплаченные**: `status <> 'CANCELLED' AND costMinor > 0`.
Вопрос карточки — «потратил ли человек деньги на сессию»: сессия на промо-кредите сюда входит
(списана с баланса), бесплатная по скидке первой сессии / кампании — нет. Подписи: колонка
«Сессий после» — «оплаченных», карточка — «оплаченных, у L аккаунтов · без удалённых».

## Доступ

Ролей в бэкофисе нет: телефон и email видит любой оператор. Принято владельцем
(«контакты — только на экране», `-004`).

## Что не меняется

- **CSV** — как есть: `code,status,redeemed_at_utc,user_id` (решение владельца: контакты — только
  на экране).
- Таблица кодов одноразовой партии, сводка вкладки, список партий, формы, погашение, контракты,
  приложение / веб, схема базы (миграции нет — нужные индексы уже есть).
- Логи: ни телефона, ни email, ни id пользователя в лог не пишем.

## Как (слои)

1. `promo-codes.repository.ts` — доменные типы `PromoRedeemer` и `PromoRedeemersFollowUp`;
   методы `listRedeemers(batchId, { skip, take })` → `{ redeemers, hasMore }` и
   `redeemersFollowUp(batchId)`. Поправить комментарий «никогда кто» у `PromoCodeRow`.
2. `prisma-promo-codes.repository.ts` — два запроса через `$queryRaw` (страница: погашения
   партии `ORDER BY createdAt DESC, id DESC` + `users` + `account_erasures` + `wallets` +
   подзапросы по `ledger_entries` / `sessions ⋈ conversations`; сводка — те же подзапросы,
   агрегатом по партии). `bigint` → `number`, как в `totals`.
3. `promo-codes-admin.service.ts` — `redeemers(batchId, page)` (страница + сводка параллельно).
4. `backoffice-pages.service.ts` — `promoBatch` читает их вместе с партией; размер страницы — 50.
5. `backoffice.forms.ts` — в `promoBatchQuerySchema` добавить `page` (как у списка партий).
6. `promo-codes.view.ts` — `redeemersSection(...)` в обеих страницах партии; у публичной —
   поправить комментарий «охват, а не люди». Всё через `html```, имя и email экранируются.
   Пейджер сохраняет только `page` (плашка-notice после перехода не повторяется).
