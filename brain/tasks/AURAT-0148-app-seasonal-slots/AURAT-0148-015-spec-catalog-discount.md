# AURAT-0148-015 — дополнение к спеке: скидка кампании в ценах каталога (закрывает L-9)

Дата: 2026-11-01 · Статус: **одобрено владельцем 2026-11-01** (решение передано манором, подтверждено в слоте — `-016`).

**Сейчас.** Цены каталога и чипы берут процент только из оффера кошелька (`useFirstSessionOffer`). При живой
кампании человек с потраченным оффером видит полную цену, а бронь выйдет на 20 % дешевле.

**Правило** (как у сервера, `aura-bff` `session-discount.ts`): действующий процент — **большая** из двух:
оффер (если `firstSessionOffer.active`) и `app-config.discount.pct` (если часть живая по своему `endsAt` и
биллинг включён). Сумма — никогда; ничья → кампания. Ставка со скидкой — `floor`, как `discountedMinor`.

**Где** (брони не трогаем — там цифры сервера):
- список Advisors (`AdvisorRow`): зачёркнутая ставка + чип;
- AdvisorProfile: `StatsCard` (ставка) и чип у кнопки брони, подпись для скринридера;
- чат: `SessionInviteCard` — строка «50% OFF First Session — …».
Home ставок не показывает — не трогаем.

**Подписи:** выиграл оффер — как сейчас («−50%», «50% OFF First Session»); выиграла кампания — чип «−20%»,
строка «20% OFF · Winter sale», без слов о первой сессии; скидки нет — без зачёркивания и чипа.

**Как (FSD):** `lib/catalog-discount.ts` — чистая функция выбора; `useCatalogDiscount(offerPct)` в
`entities/campaign` (оффер приходит снаружи, как в `useOfferTicket`); значение считается один раз на экран и
передаётся в `React.memo`-строки готовым. `PriceTag` / `OffChip` о кампании не знают.

**Тесты:** правило (ничья, оффер неактивен, кампания истекла, биллинг выключен, `floor` на нечётных центах),
чип / строка в трёх вариантах, список советников при кампании и потраченном оффере. **На устройстве:** каталог
при winter −20 % — аккаунт с оффером (50 %) и с потраченным (20 % · Winter sale).
