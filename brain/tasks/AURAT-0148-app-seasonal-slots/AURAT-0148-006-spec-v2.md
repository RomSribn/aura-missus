# AURAT-0148-006 — Спека v2: сезонные места в приложении

Дата: 2026-10-31 · Статус: **draft — ждёт одобрения владельца**
Заменяет `-005`. Внесены замечания манора и решения владельца (сообщение манора 2026-10-31):
A1 ничья 50 = 50 → discount; A2 409 `session_price_changed`; A3 `discount.kind` — строка, схемы не strict;
A4 неполная палитра = нет сезона; A5 проверка кода из пуша; B1 мёрж до тега — только запасной;
B2 кэш в `CachesDirectoryPath`.
Фича: `AURAF-0022` строка 006 · Дизайн: `SEASONAL.md` (экраны 67–81) · Контракт: `AURAT-0147-007` + `-010`
Слот: `aura-app-manor` slave-1, `feature/AURAT-0148-app-seasonal-slots` от `develop` @ `234c500`.

## 0. Главное

- Клиент рисует сезон **из палитры** (17 токенов) и текстов с сервера; `preset` — только имя, на
  отрисовку не влияет. Без сезона (`season: null`, нет ответа, 404 у старого BFF) — всё как сейчас.
- **Анимация — встроенный `Animated` (`useNativeDriver`), без `react-native-reanimated`.** Так и
  предлагает `SEASONAL.md` §6; движения простые (падение, покачивание, поворот — по таймлайну),
  новая нативная зависимость в ту же сборку — лишний риск без выигрыша.
- **Кэш — JSON-файл через `@dr.pogodin/react-native-fs`** (уже в зависимостях) в
  **`CachesDirectoryPath`** (B2): Documents на iOS уходит в бэкап iCloud, а конфиг всегда можно
  скачать заново. Ни MMKV, ни AsyncStorage не добавляем → в сборке нет нового натива.
- **До тега `v0.27.0`** — локальный тип и zod-схема, совпадающие со спекой 0147 **с правкой
  `-010`** (9 ключей `copy`, `promo.amountMinor`). **`-010` владелец ещё не одобрил** — при её
  изменении локальный тип правится следом (B1). После тега — замена на импорт из
  `@aura/contracts` (`AppConfigResponse`, `fillSeasonCopy`, `formatSeasonAmount`) в этой же ветке.
- **Схемы не strict** (A3): новые необязательные поля в `app-config` и в цене брони не ломают
  разбор у выпущенной сборки — лишнее отбрасывается.
- **Палитра — всё или ничего** (A4): нет хоть одного из 17 токенов или hex невалиден → сезон не
  рисуется вовсе, как «нет сезона», а не частично. `promo` и `discount` при этом живут сами по себе
  (билет кода / скидки — в коралловой коже по умолчанию).

## 2. Hero на Home — `entities/season/ui/SeasonHero.tsx` + частицы

- Место: между шапкой и `DailyCardBanner`; отступы 16 / 12 (`SEASONAL.md` §1). Высота **164**,
  радиус 24, фон `linear-gradient(120deg, heroFrom, heroTo)` (через `shared/ui/gradient`) +
  встроенное белое свечение 16% → 0, Ø 220, снизу справа.
- Арт 132 × 132, справа −10, снизу −12, клип по углам; появляется opacity 400 мс после загрузки.
  Нет арта / не загрузился — только фон и свечение (экран 70).
- Колонка текста ≤ ширина − 118: заголовок Bricolage 800 20/22.4, 2 строки; текст Hanken 500
  13/17.5, 2 строки, многоточие. С кодом — `heroBody` + кнопка `cta` (высота 34, радиус 12, нажатие
  0.975); без кода — `heroBodyNoCode`, без кнопки (экран 69).
- Вход: opacity 0→1 + translateY 12→0, 320 мс ease-out; при Reduce Motion — только opacity.
- **Частицы** (`SeasonParticles`): 14 штук, слой между артом и текстом, детерминированный ГПСЧ с
  зерном, размеры / времена / покачивание / поворот / прозрачность — §6 таблицей; над колонкой
  текста × 0.45; цвет `effectTint`; формы — пути из `effects/*.svg` в `config/`. Один проход
  ≤ 12 с при каждом фокусе Home, без петли. Reduce Motion — частиц нет. Неизвестный `effect` — нет.
- Кнопка открывает `PromoCodeSheet` **с подставленным кодом** (экран 79). Шторку хостит Home.
- Новые токены размеров/движения hero — в `theme.ts` (`theme.season`), правило 3 build-rules.

## 3. Билет — `CouponTicket` получает варианты и сезонную кожу

- Геометрия и движение без изменений. Кожа (`ticketStub`, `ticketStubLabel`, `ticketSoft`,
  `ticketEyebrow`, тень `ticketStub` 22%, глиф `art.ticket` 23 pt; без арта — `percent` / `tag`)
  приходит пропом; без сезона — нынешние coral-цвета.
- Варианты: `welcome` (как сейчас), `discount` («20% OFF sessions», Auto-applied, экран 74),
  `code` («$5 on your balance», чип `[WINTER5]`, «Tap to apply ›», весь билет — кнопка → шторка с
  кодом; экраны 73, 80). «Auto-applied» / «You save» — teal всегда.
- Правило `pick-ticket` (§2 сдачи): бронь/оплата → welcome, если −50% активен, иначе ничего;
  иначе −50% активен и **50 > сезонного %** (строго, A1) → welcome в сезонной коже (75); иначе есть
  скидка → discount; иначе есть код → code; иначе ничего.
- **Ничья 50 = 50 → discount** (решение владельца, A1): сервер 0147 при равенстве берёт скидку
  кампании и оффер не тратит, значит welcome обещал бы то, чего не будет. Тест на равенство.
  В `.claude/design_handoff_aura/SEASONAL.md` (строка 98) `50 ≥` → `50 >` с пометкой о решении
  владельца — правит эта задача.
- Где: Advisors (место `CouponTicket`), AdvisorProfile, PromoCodeSheet — по правилу; бронь
  (Book / Review / QuickBook) — только welcome в коже.

## 4. Орб, баннер, таб-бар

- `Orb` / `PulsingOrb`: кроме `coral` / `teal` — тон `{ base, soft }`. Сплэш берёт `orbBase` /
  `orbSoft` **из кэша прошлого запуска** (первый запуск сезона — coral, так задумано). Пульс 2.6 с,
  Reduce Motion — статично (уже так).
- `DailyCardBanner`: фон `150deg bannerFrom → bannerTo`; `bannerAccent` — eyebrow, рамки веера,
  звёзды боковых карт; искра центральной карты — gold; заголовок белый, подзаголовок 70%.
- `AuraTabBar`: `tabActive` — только активная иконка и точка.
- Всё остальное (paper, card, ink, цены, первичные кнопки вне мест, вся teal-семья) не меняется.

## 5. Шторка кода и пуш `promo`

- `usePromoCode(visible, onRedeemed, initialCode?)`: при открытии поле заполняется `initialCode`
  (иначе пустое, как сейчас). Остальное — как в `AURAT-0144`.
- Пуш: `action: 'promo'` + `code` → открывается Home и шторка с кодом (параметр маршрута Home).
  Без `code` — просто Home.
- **Код из пуша проверяется** (A5): нормализация **как у сервера и веба** — верхний регистр,
  убрать все пробелы (и внутри) и дефисы; затем только `A–Z0–9`, 4–20 символов. Одна чистая
  функция в `lib/` (`winter 5`, `Winter-5`, ` WINTER5 ` → `WINTER5`). Неверный — шторка
  открывается с пустым полем. Код из `app-config` (hero, билет)
  пришёл с нашего сервера и подставляется как есть. Промо-пуши по topic ждут `AURAT-0140`; разбор действия едет в этой
  сборке, чтобы потом не ждать релиза.

## 6. Скидка в брони и 409 `session_price_changed` — после тега `v0.27.0`

**Подписи.** `SessionPricing.blocks[].discount {kind, pct, label}`, `kind` — **строка** (A3):
- `campaign` → подписи брони (`DurationPicker`, `BookSessionScreen`, `BookReviewScreen`,
  `QuickBookSheet`) показывают `label · pct% off` и **не** рисуют welcome-билет;
- `first_session` → как сейчас;
- неизвестное значение → нейтральное «−$X» (как сейчас без оффера);
- поля нет (старый BFF) → нынешнее поведение (`offerPct` при `creditMinor > 0`).

Это закрывает «известное ограничение» `AURAT-0147-007` §3.

**Цена поменялась** (A2, решение владельца, контракт через 0147). Бронь (слот, «сейчас», Quick
book) передаёт в `BookSessionRequest` необязательное `expectedCostMinor` — `costMinor`
показанного блока. Если цена в транзакции другая (край окна кампании, кампанию выключили, пока
открыт экран подтверждения), сервер отвечает **409 `session_price_changed`** и ничего не списывает. Клиент
перезапрашивает цену, показывает новую и просит подтвердить ещё раз (текст — в спеке исполнения
по образцу «слот занят», экран 59). Продление не трогаем — оно без скидки.

Обе части требуют контракта (поля отбрасываются схемой 0.25), поэтому — вторым этапом в этой же
ветке.

## Решения в спеке (поправь, если не так)

1. `Animated` вместо Reanimated; кэш в файле через `react-native-fs` в `CachesDirectoryPath` —
   новых нативных зависимостей нет. *(манор: без замечаний; путь — B2)*
2. Локальный тип — по правке `0147-010` (9 ключей `copy`, `amountMinor`), хотя она ещё не одобрена;
   слежу за ней. *(B1)*
3. Шторку кода из hero и пуша хостит Home; пуш `promo` + `code` ведёт на Home; код из пуша
   проверяется по формату. *(манор: без замечаний; проверка — A5)*
4. Билет в брони — только welcome; скидка кампании в брони — подписью, не билетом. Ничья 50 = 50 →
   discount. *(A1 — решение владельца)*
5. Конфиг тянется на старте и при возврате на передний план (≥ 60 с между запросами), без опроса.
   *(манор: без замечаний)*
6. Неполная или невалидная палитра → сезона нет целиком. *(A4)*
7. 409 `session_price_changed` с `expectedCostMinor` — вторым этапом, после тега. *(A2 — решение владельца)*

## Поправка к §6 (2026-11-01, решение владельца по рекомендации манора, финальное ревью `-013` M-2)

- «You save» и зачёркнутый итог в футере Book Session — при любой скидке (оффер или кампания), не только
  при оффере.
- Подпись «{label} · {pct}% off» при скидке кампании — на Review, в Quick book и в футере Book Session.
  В карточках длительности — только зачёркнутые цены, без подписи.
- После брони: «You saved $X with Winter sale» / «with your welcome offer» / просто «You saved $X» (вид
  незнаком); в Session detail — нейтральное «Saved» (сессия не несёт вида скидки).
- Неизвестный вид скидки в разбивке — строка «Discount»; «First-session credit» — только у BFF без поля.
