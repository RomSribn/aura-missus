# AURAT-0189-007 — spec v2: тексты сезона и подпись скидки на языке запроса

Дата: 2026-11-07 · Статус: **draft — решение 1 принято, решения 2–6 ждут владельца**
Заменяет `005-spec.md`. Учтены 16 замечаний ревью (`006-review.md`).
Фича: `AURAF-0023` строка 011 (сезонные тексты), `AURAF-0022`. Образцы: `AURAT-0171`, `0173`, `0184`.
Репо: `aura-bff` + `aura-contracts` (решения 3, 6). Факты — `004-context.md`; поправка к нему: «$5 во всех языках»
**не** решение `AURAT-0174` — там суммы по CLDR (fr / bg «5 $», nl «$ 1,90»), см. решение 6.

## Что получится

- `GET /v1/app-config?lang=de`: девять текстов сезона (`season.copy`) и подпись скидки (`discount.label`) по-немецки,
  если для них есть перевод. Иначе по-английски, как сейчас. Ответ говорит, на каком языке пришли тексты:
  `season.copyLanguage`, `discount.labelLanguage` (решение 3).
- `GET /v1/advisors/:id/sessions/pricing?lang=de`: та же подпись в `discount.label` тоже по-немецки, с
  `labelLanguage`.
- Без `lang`, с неизвестным или выключенным языком — английский (резолвер `0171`).
- Переведены пресеты дизайнера (winter, valentine) и их подписи скидки. Свой текст владельца остаётся английским,
  пока его не добавят в разговорник. Бэкофис показывает, что переведено и при каком коде.
- `promo.headline` не меняется: английский текст оператора, его не показывает ни один клиент.

## 1. Где живут переводы — **решение 1 = А (владелец, 2026-11-07)**

Разговорник в коде по **месту и английскому тексту**. Если текст кампании в этом месте совпал с фразой
разговорника, сервер отдаёт перевод. Сравнение для девяти текстов терпит мелочи: NFC, пробелы по краям и двойные
пробелы, `’` / `'`. Регистр и знаки — строго. Подпись скидки сравнивается **без учёта регистра**: на билете её
рисуют капсом, и владелец может набрать «WINTER SALE». Свой текст владельца добавляется в разговорник небольшой
задачей, выкатывается только BFF, без релиза приложения. Позже перекрытие из бэкофиса или машинный черновик
(`AURAI-0012`) встанут перед разговорником в одной точке, `translateCampaignText`.

## 2. Набор целиком или по полю (решение 2)

Hero и билет показывают по 2–3 текста рядом.

- **А (рекомендую).** Девять текстов переводятся **набором**: на языке есть все девять или все девять английские.
  Половина карточки по-немецки, половина по-английски — хуже, чем целиком английский. Исключение — кнопка при
  длинном коде (решение 5): она остаётся на языке, только без кода. Подпись скидки стоит в другом месте и
  переводится сама по себе.
- **Б.** По полю. Тогда свой заголовок владельца (английский) соседствует с переведённым телом пресета.

**Сколько это покрывает.** Пресет, вставленный без правок, — все 23 языка, если код и сумма в пределах гарантии
(решение 5, таблица §6). Сумма с центами ($5.50) в de не помещается в заголовок билета (§6) — при 2 = А весь
немецкий сезон уйдёт в английский. Один свой текст — все 23 языка по-английски.

## 3. Код

- **`src/modules/campaigns/texts/`** (по образцу `advisors/texts/`):
  - `season-phrases.ts` — фразы: `{ id, place, text, sensitive }`, где `place` — `SeasonCopyKey` или
    `'discountLabel'`. «Winter sale» — две фразы: надзаголовок (`ticketDiscountEyebrow`) и подпись (`discountLabel`).
    У них разные переводы: el-надзаголовок пишется капсом, подпись — обычным регистром. Для кнопки при длинном коде
    (решение 5 = А) — короткая форма без кода (`ctaShort`), по одной на язык. Шапка — откуда тексты (пресеты
    `AURAT-0150`, `SEASONAL.md` §11).
  - `<lang>.ts` × **23**: `Readonly<Record<PhraseId, string>>`. В шапке — обращение языка и отступления от глоссария
    с причиной.
  - `index.ts` — `SEASON_TEXT_TRANSLATIONS: Readonly<Record<TranslatedLanguage, …>>`. Правила перевода
    комментарием: `reader` → слово консультанта без рода; `reading` → слово консультации; `session` / `balance` /
    `sale` / `off` / `applied` / `checkout` — формы глоссария; плейсхолдеры не переводятся.
  - `translate-campaign-text.ts` — `translateCampaignText(place, english, language): string | null`, чистая,
    нормализация по §1.
  - `season-texts.spec.ts` (§6).
- **Четыре общие фразы** (`Apply {code}`, `{amount} on your balance`, `{pct}% OFF sessions`, `Any advisor · applied
  at checkout`) берутся из переводов приложения: `entities/campaign/config/locales` (`codeTitle`, `discountTitle`,
  `discountSub`) и `features/promo-code` (`apply`). `{{x}}` превращается в `{x}`. Любая правка записывается в шапке
  языка с причиной: кнопке нужен короткий глагол (решение 5), заголовку — место под сумму. Тогда сезонный и
  обычный билеты говорят одно и то же одними словами.
- **`localize-campaign.ts`** — чистые функции:
  - `localizeSeasonCopy(copy, language, live) → { copy, language }`. `en` или не все девять в разговорнике →
    английский набор. Иначе переведённый набор с замером **живыми** значениями: кодом и суммой показанного
    промокода, процентом показанной скидки (без скидки — 70, как `copyTooLong`). Лимиты перевода —
    `SEASON_COPY_LIMITS`, кроме `ticketDiscountSub`: у него **40**. Это `@max` приложения: строка сжимается по
    ширине (`CampaignTicket.tsx:18-29`), на вебе переносится. Сумма меряется формой, которую рисует клиент
    (решение 6). Кнопка не уложилась → короткая форма без кода (решение 5 = А). Что-то ещё не уложилось →
    английский набор.
  - `localizeDiscountLabel(label, language) → { label, language }` — без замера: плейсхолдеров у подписи нет, длину
    проверяет spec.
- **`buildAppConfig(live, context, language)`** — season / discount через функции выше, `headline` — как в базе.
- **`AppConfigService`:** кэшируются **прочитанные кампании** (тот же срок, `generation`, граница по `endsAt`), ответ
  собирается на каждый запрос с `now` и языком. Сборка чистая; чтение из базы — одно на 30 с, не одно на язык.
- **`AppConfigController`:** `@RequestLanguage()` + `@ApiLanguageQuery()`. Комментарий (сейчас `:11-13`): «публичный;
  ответ одинаков для всех, кто спросил на одном языке (`?lang`)». ETag — по телу (свой у каждого языка),
  `max-age=60` — как есть, `?lang` — часть URL.
- **Цена:** `SessionsController` pricing — `@RequestLanguage()`. `SessionsService.getPricing(auth, advisorId,
  language)` переводит подпись на выходе. `priceBlock` и списание языка не знают; сессия хранит
  `discountCampaignId`, а не подпись — в базе ничего не меняется.
- **Бэкофис** (§4); «Вставить пресет» (`campaign-preset.ts`) заполняет **пустую** подпись скидки из
  `ticketDiscountEyebrow` пресета.
- **`src/contracts/openapi.ts`:** описание app-config (`:861` «the same for everyone») → «the same for everyone who
  asks in the same language (`lang`); cache per language». `copy` / `label` (app-config и pricing) — «in the request
  language when the server has a translation, English otherwise (AURAT-0189)». `copyLanguage` / `labelLanguage`
  (решение 3). `headline` — «the operator's own text, English».
- **Общие проверки текстов** переносятся в `src/common/language/*.spec-fixtures.ts`: `WRONG_ADDRESS`, `QUOTE_PAIRS`,
  `GLOSSARY_AVOID`. **`GLOSSARY_AVOID` расширяется** запретными формами v3 для `session` (de Session, cs relace, el
  συνεδρίαση, et sessioon, fr, hu, lt, sk…) и `balance` (de Saldo, nl saldo), тип `term` — шире. Каждый spec
  проверяет свои термины: подписи и персоны — `reader` / `reading`, как сейчас, сезон — все четыре. Импорты
  `0173` / `0184` правятся, их проверки не меняются.
- Миграций нет, сид не меняется, английские тексты в базе не трогаются.

## 4. Бэкофис

- **Форма кампании:** под каждым из девяти текстов и под подписью — «Перевод: N из 23» (N считается по
  разговорнику) или «Нет перевода — покажем по-английски». Под блоком текстов — «Сезон на языке человека — только
  если переведены все девять (сейчас: N языков)» и «**Код на всех языках — до K знаков**». K считается по
  разговорнику, а не берётся из таблицы. Обновляется после сохранения и после «Вставить пресет».
- **Подтверждение включения** — предупреждения, не блокеры, **в обе стороны** (как `copyBlockers`,
  `campaign-enable-check.ts:176-185`):
  - при включении сезона рядом с живым промокодом и при включении промокода рядом с живым сезоном — «С кодом
    VALENTINE (9) в fr, hu кнопка будет без кода: «Activer»»;
  - «de: с суммой $5.50 сезон не помещается — покажем по-английски»;
  - «Без перевода (покажем по-английски): heroTitle, подпись скидки».
- Журнал кампании (`CampaignEvent`) не меняется.

## 5. Длина кода и суммы (решение 5)

Английская кнопка `Apply {code}` (лимит 16) вмещает код до 10 знаков. Длиннее английское включение не пропустит.
Переводной глагол длиннее «Apply», поэтому места под код у перевода меньше (таблица §6).

- **А (рекомендую).** Разговорник **гарантирует 8 знаков** кода во всех языках: тест кнопки с 8-знаковым кодом
  (WINTER10). Где язык не может, он записан исключением со своим максимумом (кандидат — hu, 7). Для кода 9–10 знаков
  и для исключений — **кнопка без кода** на том же языке: «Activer», «Einlösen». Шторка промокода открывается с
  кодом, как сейчас, остальные восемь текстов на месте. **Совет владельцу:** публичные коды сезона — не длиннее
  8 знаков (WINTER5, LOVE10, SPRING10).
- **Б.** Гарантия 8, но длиннее — весь набор на этом языке английский.
- **В.** Гарантия 7 (WINTER5, тест как в v1). Длиннее — весь набор английский: при WINTER10 по-английски окажутся
  около половины языков (таблица, колонка «приложение»).

Сумма — гарантия **до $25 целыми** («$25», а при 6 = Б — «25 $»). Суммы с центами и от $100 меряются в рантайме. Не
помещается (заголовок билета: de, при 6 = Б ещё el) → английский набор.

**Разговорник** (`season-texts.spec.ts`):
- все 23 языка; в каждом — ровно фразы `season-phrases.ts`;
- плейсхолдеры перевода — те же, что у английского, и разрешены для места (`SEASON_COPY_PLACEHOLDERS`); `ctaShort`
  — без плейсхолдеров;
- **длина:** с `WINTER5` / `$5` / `70` — каждое место в своём лимите (`ticketDiscountSub` — 40, подпись — 22, как
  надзаголовок). При 5 = А кнопка — ещё и с 8-знаковым кодом (исключения — списком `lang → максимум`, каждое
  нужно). Тексты с `{amount}` — с «$25» в форме решения 6;
- непусто, без пробелов по краям, NFC, без U+00AD / U+02BC; U+202F — только перед `%` (fr, как в приложении); ro —
  ș ț; fr — U+00A0 перед ? ! : ; и в «»;
- **el:** переводы `ticketCodeEyebrow` / `ticketDiscountEyebrow` — капсом без тонуса (`toUpperCase` и без U+0301 после
  NFD); подпись — не капсом;
- кавычки — пары языка (`QUOTE_PAIRS`); перевод не совпадает с английским (исключения — с ключом `lang:id`, сейчас
  пусто);
- `GLOSSARY_AVOID` — `reader` / `reading` / `session` / `balance`; обращение — `WRONG_ADDRESS`, исключения с ключом;
- **совпадение с приложением:** четыре общие фразы равны переводам приложения (`{{x}}` → `{x}`) или записаны в

- нормализация: `Valentine's week` с `'` находит `Valentine’s week`; подпись «WINTER SALE» находит «Winter sale»;

## 7. Контракт (решение 3)

- **А (рекомендую), `v0.30.0` с тегом:**
  - `AppConfigSeason.copyLanguage`, `AppConfigDiscount.labelLanguage`, `SessionPriceDiscount.labelLanguage` — простые
    строки с `default('en')`, как `disabledLanguages`: старый сервер не ломает новый клиент;
  - документ модуля (`app-config.ts:9` «the same answer for everyone») → «the same for everyone who asks in the same
    language (`lang`); cache per language»;
  - JSDoc `copy` / `label` — «in the request language when translated, English otherwise; the language is
    `copyLanguage` / `labelLanguage`»; `headline` — «the operator's own text, English»; `SEASON_COPY_KEYS` — убрать
    «English»;
  - при 6 = Б — `fillSeasonCopy(template, { …, amount?: string })` (готовая строка суммы от клиента).

  Правка в `aura-contracts`, пуш и тег — с одобрения. BFF переходит на тег в этой задаче.
- **Б.** Только JSDoc в `main` без тега. Клиенты берут язык интерфейса и ошибаются, когда сервер откатил к
  английскому. Подпись без сезона не описана ничем.

Для Android решение 3 не блокирует: `accessibilityLanguage` есть только на iOS.

## 9. Сумма в текстах сезона (решение 6)

`fillSeasonCopy` всегда пишет «$5» / «$5.50». Приложение без сезона пишет сумму по CLDR (`formatUsdMinorCompact`,
`ticket-content.ts:66-71`; `AURAT-0174`): fr «5 $ sur votre solde». После перевода fr-сезон скажет «$5 sur votre
solde», а соседние строки цены — «5 $».

- **А.** «$5» во всех языках в текстах сезона. Отступление записывается, владелец соглашается. Ничего не меняется у
  клиентов.
- **Б (рекомендую).** Клиент подставляет `{amount}` своим форматтером на языке `copyLanguage`. Контракт: `amount?:
  string` в `fillSeasonCopy` (решение 3). Сервер меряет на 1 знак шире «$5»: худшая форма CLDR «5 $» / «$ 5» на
  знак длиннее. Таблицу чисел в BFF не копирую. Сумма в сезоне и вне его одна и та же. Цена — строка-другая у
  клиентов.
