## 2. Какой билет (один, всегда)

Логика `ticketKind` из прототипа:

```
вариант брони (Book sheet, savingMinor)    → welcome, если действует −50 %, иначе ничего
иначе −50 % действует и 50 > pct скидки    → WELCOME (сезонная шкурка, если сезон)
иначе есть discount                         → DISCOUNT («20% OFF sessions», Auto-applied)
иначе есть promo                            → CODE («$5 on your balance», [WINTER5] Tap to apply ›)
иначе                                       → нет билета
```

- **Ничья 50 = 50 → DISCOUNT** (решение владельца, манор 2026-10-31): при равенстве сервер 0147
  берёт скидку кампании и оффер не тратит, поэтому welcome — только при `50 > pct`, строго. В
  прототипе `SEASONAL.md` стоит `50 ≥` — его правит 0148. Тест на равенство обязателен.
- Места с полной логикой: Home (side), Advisors, Advisor (aside), Match, `/me` Account и Coupons.
  Book sheet — вариант брони. Вход (шаг телефона) — только welcome (это уже сам вход).
- **CODE** — весь билет ссылка на `/promo/<CODE>`; код в чипе (пунктир `ticketEyebrow`).
- Тексты DISCOUNT / CODE — из `season.copy.ticket*`. Скидка или код **без сезона** (напр. «Black
  Friday» только со скидкой): шкурка по умолчанию, eyebrow — `discount.label` с сервера / «Gift
  code», заголовок и подпись — наши строки на 24 языках («{{pct}}% OFF sessions», «Any advisor ·
  applied at checkout», «{{amount}} on your balance», «Tap to apply»).

## 3. `/promo/:code`

- Публичный маршрут. Код нормализуется как на сервере (регистр, пробелы внутри, дефисы, невидимые
  символы) и проверяется по формату
  `A–Z0–9`, 4–20 символов (манор, A5). Неверный — тот же путь, но **без кода**: поле пустое, сам
  ничего не гасится. Адрес сразу заменяется на `/` (код не остаётся в истории), поверх Home открывается **шторка
  промокода** (`<Sheet>`, новый вид диалога `promo`, ленивый):
  «Promo code», строка пояснения, поле с кодом (можно править), **Apply code**; успех — «{amount}
  added to your balance», «Code X applied. It’s used automatically on your next session.», **Done**.
  Отказы, 429, повтор, биллинг выключен — тексты и логика `AURAT-0145` (`features/redeem-promo-code`
  получает `apply(code)` и шторку; поле в `/me` не меняется).
- **Гость:** сразу вход с новой причиной **`promo`** (заголовок / подпись / кнопка имени на 24 языках,
  напр. «Sign in to get your gift»), после входа открывается шторка. **Сама гасит только публичный
  код витрины:** нормализованный код из URL равен `app-config.promo.code` (если `app-config` ещё в
  пути — шторка ждёт его). Любой другой код, прошедший формат, просто стоит в поле и ждёт Apply —
  одноразовые коды гасятся только осознанным действием (правило `AURAT-0143-005` §1; манор,
  2026-10-31). Попытка переживает перезагрузку (как остальные причины).
- **Вошедший:** шторка с кодом, одно нажатие Apply (как в дизайне; случайный переход по ссылке ничего
  не начисляет без нажатия).
- Ссылки на `/promo/…` веб строит **только** из `app-config.promo.code` (публичный код). Одноразовые
  коды по-прежнему вводятся только в поле (правило `AURAT-0143-005` §1). Код из URL не пишется в
  логи.
- Hero CTA и билет CODE — `<Link>` на `/promo/<CODE>`.

## 4. Подпись скидки в брони

`SessionPricing.blocks[].discount` (`v0.27.0`): `kind: 'campaign'` → вместо «{pct}% OFF First Session
— applied for you» строка «{{pct}}% OFF · {{label}}» (`label` с сервера, напр. «Winter sale»).
`first_session` или поля нет (старый сервер) — как сейчас. `kind` — строка, не enum (манор, A3):
неизвестное значение → нейтральная подпись «{{pct}}% OFF» без названия. `offerPctFromPricing` считает только
скидку первой сессии, так что «50% OFF First Session» больше не врёт при скидке кампании. Цены
на списках советников (`PriceTag`, `OffChip`) скидку кампании не показывают — её показывает билет
(«applied at checkout») и цена брони от сервера.

**Второй этап, после тега — `409 session_price_changed`** (решение владельца, контракт `v0.27.0` через 0147,
манор A2). `BookSessionRequest` получает необязательное `expectedCostMinor`: веб передаёт
`costMinor` блока, который человек видел. Если в транзакции брони цена другая (край окна кампании,
кампанию выключили, пока открыта шторка), сервер отвечает `409 session_price_changed` и ничего не списывает.
Веб перечитывает цену, показывает новую с пояснением («The price has changed — please check and
confirm again», 24 языка) и ждёт повторного подтверждения. Ключ идемпотентности для новой попытки
— новый.

## 5. Как устроено

- **`entities/season`** (новый слайс): `api/` — `getAppConfig` (`injectEndpoints`, `public: true`,
  `transformResponse` разбирает части **по отдельности**: схема не strict, новые необязательные поля
  терпит (A3). `season` не прошёл разбор — нет хотя бы одного из 17 токенов, невалидный hex — тогда
  `season: null` целиком, без частичной окраски (A4), а `promo` и `discount` остаются); `model/` — `useSeason()` (сезон / promo /
  discount, каждая часть гаснет сама по своему `endsAt` одним таймером), `useSeasonTicket(offerPct,
  variant)` (страницы передают свой `offerPct` — без кросс-импорта `entities/wallet`); `lib/` —
  `ticketKind`, частицы (сид), запись переменных на `<html>`; `ui/` — `SeasonHero`,
  `SeasonParticles`. `CouponTicket` (shared) получает виды `welcome | discount | code`.
- **Рендер не ждёт сети** (манор, 2026-10-31). В `localStorage` лежит последняя палитра + `endsAt`
  сезона (всё в `try/catch`; это удобство одного зрителя, не данные). Первые строки `main.tsx`, до
  `createRoot`, синхронно ставят на `<html>` `data-season` и 17 переменных `--season-*`, если
  `endsAt` ещё впереди и кэш разбирается схемой палитры. Истёкший кэш не применяется, битый
  удаляется. `app-config` грузится параллельно, рендер ждёт только `initI18n` (как сейчас). Ответ
  пришёл — сезон применяется или снимается, кэш обновляется (`season: null` → кэш стирается).
  Первый заход без кэша: рендер без сезона, сезон появляется по приходу ответа (hero входит
  анимацией, перекраска остальных мест на первом заходе допустима). Перечитывается при возврате
  на вкладку, если прошло > 5 мин.
- **CSS:** в `tokens.css` у каждого `--season-*` значение по умолчанию = сегодняшний токен места
  (`--season-ticket-stub: var(--accent-strong)` …) — без сезона ничего не меняется, места читают
  только `--season-*`. Тени `--shadow-orb-accent`, `--shadow-coupon` — на `color-mix()` от токенов
  вместо зашитого rgba. `[data-theme]`-блоков с пресетами нет: палитра — данные (решение владельца).
- **Контраст — на фонах контракта** (решение владельца через манор, 2026-10-31): веб ставит места
  на те же фоны, что проверяет сервер, и своих пар не добавляет.
  - нижний бар на телефоне при сезоне — ровно `#F4EFE5` (P17); без сезона — как сейчас;
  - активный пункт на desktop — на `--card` `#FFFFFF` (P18), как сейчас;
  - подпись баннера при сезоне — белый 0.70 (P13–P14), а не `--on-plum-2` 0.72;
  - кольцо фокуса на баннере при сезоне — белое (пары P11–P12 ≥ 4.5 уже покрывают порог 3), к
    `bannerAccent` нового требования нет;
  - `contrast.test.ts` гоняет палитры **обоих** пресетов (фикстуры из `presets/winter.json`,
    `valentine.json`) по P1–P18 и фиксированным фонам контракта — **той же функцией
    `checkSeasonPalette`**; плюс: места читают только `--season-*`, тени без rgba коралла;
  - в работе клиент проверяет палитру той же функцией (`seasonPalettePasses`) и не показывает
    сезон, который её не прошёл (сервер такой не отдаёт — это страховка).

  **Место, которому нужен фон вне P1–P18 — решает владелец.** На теле билета (`ticketSoft → card`)
  стоят ещё заголовок (`--ink`) и «Auto-applied» (`--teal-ink`), у кода — чип с текстом. Сервер
  проверяет на `ticketSoft` только `ticketEyebrow` (P9). Тёмный `ticketSoft`, при котором eyebrow
  ещё проходит, а `--ink` уже нет, теоретически возможен. В приложении то же самое. Предлагаю
  добавить через 0147 пары «`#221F1A` ink → `ticketSoft` ≥ 4.5» и «teal-ink → `ticketSoft` ≥ 4.5».
  Пресеты сдачи: ink — 13.44 (winter) / 13.52 (valentine), teal-ink `#1E726B` — **4.68 / 4.71**,
  то есть проходит еле-еле: чуть более насыщенный `ticketSoft` следующего пресета «Applied» уже
  провалит. До решения веб ничего своего не проверяет.

## Решения в спеке (поправь, если не так)

4. **Рендер не ждёт `app-config`**: палитра из `localStorage` (с `endsAt`) ставится до `createRoot`,

   кольцо фокуса белое). Открыто для владельца: пары ink / teal-ink → `ticketSoft` на теле билета

6. **Мёрж — после тега `v0.27.0`** и 0147 на bff-dev; до того работа идёт на локальном типе.
