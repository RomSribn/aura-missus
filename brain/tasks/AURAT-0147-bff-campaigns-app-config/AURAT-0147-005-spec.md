# AURAT-0147-005 — Спека: кампании, `GET /v1/app-config`, скидки как данные

Дата: 2026-10-31 · Статус: **draft — ждёт одобрения владельца**
Фича: `AURAF-0022` строки 003–005 · Решение: `AURAD-0022` (пишется в этой задаче, §6)
Тип: задача (фича уже есть). Репо: `aura-bff` + `aura-contracts` `v0.27.0`.

## 1. Сущность «кампания»

Одна запись = одно окно дат и до трёх частей, которые включаются и выключаются **вместе**:

| Часть | Поля | Где действует |
|---|---|---|
| **Оформление** | пресет (`winter` / `valentine` / `halloween`), картинки hero и баннера (ключи в бакете), тексты hero (заголовок ≤ 60, текст ≤ 160, кнопка ≤ 24, en), эффект (`snow` / `leaves` / `hearts` / нет) | `app-config.season` |
| **Витрина кода** | код (`WINTER5`) + строка-призыв (≤ 80, en) | `app-config.promo` |
| **Скидка** | процент 5–70, подпись (≤ 24, en: «Black Friday») | цена сессии + `app-config.discount` |

Общие поля: название для операторов («Black Friday 2026»), `startsAt` / `endsAt` (вводятся в
`SESSION_SLOT_TIMEZONE`, на форме подписан пояс; конец — исключительно), статус.

**Статусы:** `черновик` → `включена` → `выключена`. «Идёт» / «запланирована» / «завершена» —
вычисляется из окна для включённой. Правка — только черновика или выключенной (у включённой
кнопки «Изменить» нет: сначала выключить). Удаления нет — журнал должен ссылаться на запись.

**Пересечения:** нельзя включить кампанию, если у уже включённой есть **та же часть** в
пересекающемся окне (две темы или две скидки сразу). Зато «Зима» (только оформление,
20.11–07.01) и «Black Friday» (скидка + код, 27–30.11) живут одновременно — это и есть
реальный сценарий. Проверка — в транзакции включения под advisory-lock.

**Палитра — только пресетом.** Цвета пресетов живут в клиентах и проходят их тесты контраста
(веб ≥ 4.5:1); hex из бэкофиса не принимаем. Новые пресеты — бриф `AURAT-0150` + релиз клиентов;
картинки, тексты, эффект и скидка меняются без релиза. (Отступление от наброска `AURAI-0009` §4,
где было `palette?` — причина: оператор с полем hex может сломать контраст, а проверить его
сервер не может, не зная пар токенов клиента.)

**Картинки:** оператор вводит **ключ** объекта (`campaigns/winter-2026/hero.webp`), BFF отдаёт URL
`CAMPAIGN_ASSETS_BASE_URL + ключ` (правило «каталог хранит ключи, не URL», как у советников).
Переменная **необязательная**: без неё поля картинок на форме выключены, а в `app-config`
картинок нет. Загрузка файлов в бакет — вне задачи (дизайнер, `AURAT-0150`).

## 2. `GET /v1/app-config` (контракт `v0.27.0`, `src/app-config.ts`)

Публичный, без токена, одинаковый для всех (как каталог советников). `Cache-Control: public,
max-age=60`, слабый `ETag` по телу, `If-None-Match` → 304. Отдаёт **только то, что действует
сейчас**; `endsAt` нужен клиенту, чтобы погасить кэш сам.

```ts
AppConfigResponse = {
  season: null | {
    campaignId: string,
    preset: string,            // известные: SEASON_PRESETS; неизвестный клиент игнорирует
    endsAt: string,            // ISO
    art: { heroUrl: string | null, bannerUrl: string | null },
    copy: { heroTitle: string | null, heroBody: string | null, ctaLabel: string | null },
    effect: string | null,     // известные: SEASON_EFFECTS; неизвестный — без эффекта
  },
  promo: null | { campaignId: string, code: string, headline: string, endsAt: string },
  discount: null | { campaignId: string, label: string, pct: number, endsAt: string },
}
```

- `preset` и `effect` в ответе — **строки, не enum**: иначе новое значение уронит разбор всего
  конфига в уже выпущенном клиенте. Списки известных значений экспортируются константами.
- `promo` и `discount` — `null`, пока `BILLING_ENABLED=false` (это деньги кошелька и сессий).
- `promo` гаснет и сам, если код отключили или он истёк (проверка при чтении, см. §4).
- `discount` — только витрина; цену считает сервер (§3).
- Кэш в процессе на 30 с, сбрасывается при включении / выключении кампании.

## 3. Скидка в цене сессии

- На каждый блок: `firstMinor` (−50%, если оффер доступен) и `campaignMinor` (по проценту кампании,
  тот же floor в пользу клиента). Берётся **большая**, не сумма. **При равенстве — кампания**: оффер
  первой сессии тогда не тратится и остаётся на потом.
- Действует на **бронь** (по слоту и «сейчас»), для всех пользователей и всех советников. На
  продление (`extend`) не действует — как и оффер первой сессии сегодня.
- Право на оффер по-прежнему решается под замками в транзакции брони; кампанию читает сервис
  перед транзакцией и передаёт в репозиторий готовую цену (как сейчас `firstSessionPrice`).
- `Session.discountCampaignId` (новая колонка, nullable): чья скидка лежит в `creditMinor`.
  Предикат `firstSessionOfferUsed` добавляет `discountCampaignId = null` — скидка кампании **не**
  считается использованным оффером. Старые строки — `null`, их смысл не меняется.
- Уже забронированные сессии цену не меняют (выключение кампании действует на новые брони).
  Отмена и возврат — по существующим правилам от `costMinor`.
- Контракт: в `SessionPricing.blocks[]` добавляется необязательное
  `discount: null | { kind: 'first_session' | 'campaign', pct: number, label: string | null }`
  — чтобы клиент подписал скидку верно. Старые клиенты видят верную сумму и цену, но `%` и
  «First Session» могут быть неточны, пока не выйдет `AURAT-0148` / `AURAT-0149`.
- `GET /v1/wallet` `firstSessionOffer` не меняется.

## 4. Витрина кода

При сохранении кампании код нормализуется и проверяется по `promo_codes`: существует, не
отключён (код и партия), действует **до конца окна** кампании. Иначе — ошибка на форме. При чтении
`app-config` то же условие проверяется снова (код могли отключить) — тогда `promo: null`.
Связь с `AURAT-0146`: после её мёржа добавится условие «партия публичная»; формат vanity-кода
(`WINTER5`) появляется тоже там. До её мёржа витрину можно заполнить только существующим кодом.

## 5. Бэкофис — вкладка «Кампании»

Видна всегда (оформление не зависит от биллинга); блоки «Скидка» и «Код» на форме — только при
`BILLING_ENABLED`.

- **Список:** название, окно, части (иконки/метки), статус, кто включил.
- **Создать / Изменить:** форма по §1, ошибки по полям (422), `creationKey` против двойной
  отправки (как у партий промокодов).
- **Страница кампании:** что увидит приложение (кусок `app-config` JSON, который даст кампания),
  кнопки «Включить» / «Выключить» / «Изменить», журнал.
- **Включить** → страница подтверждения человеческим языком: «С 27.11 00:00 до 30.11 23:59
  (America/New_York) на все брони −30% (если у клиента доступна первая сессия −50% — берётся
  она); в приложении и на вебе — тема `winter`, витрина WINTER5». Проверка пересечений и
  свежести кода — на подтверждении и повторно при записи. Включение кампании, окно которой уже
  закончилось, запрещено.
- **Выключить** → подтверждение → действует сразу (через ≤ 60 с у клиентов из-за кэша).
- **Журнал** (`campaign_events`, только добавление): создана / изменена / включена / выключена,
  оператор (id + снимок логина, без FK — как у партий), время, снимок полей кампании на момент
  действия. Показывается на странице кампании.

## 6. `AURAD-0022` — решение (кратко; файл создаётся при исполнении)

Скидки на сессии бывают двух видов: **политика** (−50% первой сессии — константа в коде, как и
правила возврата; комментарий «policy is not config» остаётся для них) и **кампании** — данные в
базе, которые оператор включает в бэкофисе с подтверждением и журналом. Довод старого решения
(«staging и prod не должны расходиться в правилах») относился к env-конфигу; кампания — запись с
аудитом, а не переменная окружения. Сочетание — большая из двух, не сумма; при равенстве —
кампания. Скидка — уменьшение списания, не кредит (`AURAT-0018`). Предел — 70%. Откат —
«Выключить» (новые брони сразу по обычной цене, старые не трогаются).

## 7. Модель данных (миграция — только добавления)

- `campaigns`: поля §1, `status` (`DRAFT` / `ENABLED` / `DISABLED`), `creationKey @unique`,
  `createdBy*`, `enabledAt/By*`, `disabledAt/By*`, `createdAt`, `updatedAt`; индекс `(status, endsAt)`.
- `campaign_events`: `campaignId` (FK), `action`, `operatorId`, `operatorLogin`, `snapshot Json`,
  `createdAt`.
- `sessions.discount_campaign_id` (nullable FK на `campaigns`).
- Env: `CAMPAIGN_ASSETS_BASE_URL` (необязательный, URL, без хвостового `/`).

## Решения, принятые в спеке (поправь, если не так)

1. Одна кампания = оформление + код + скидка, включаются вместе; пересечения запрещены по частям.
2. Палитра только пресетом в клиенте, без hex из бэкофиса.
3. Скидка 5–70%, все пользователи, все советники, только бронь; при равенстве с −50% — кампания.
4. Окно вводится в `SESSION_SLOT_TIMEZONE`; включённую кампанию нельзя править — сначала выключить.
5. Картинки — ключи + необязательный `CAMPAIGN_ASSETS_BASE_URL` (его надо будет задать в Coolify).
