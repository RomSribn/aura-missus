# AURAT-0147-007 — Спека v2: кампании, `GET /v1/app-config`, скидки и палитра как данные

Дата: 2026-10-31 · Статус: **draft — ждёт одобрения владельца**
Заменяет `-005` (замечания и решение владельца — `-006`).
Фича: `AURAF-0022` строки 003–005 · Решение: `AURAD-0022` (§7) · Бриф полей: `AURAT-0150-005`.
Репо: `aura-bff` + `aura-contracts` `v0.27.0`. **Строится поверх `AURAT-0146`** (мёрж 0146 → 0147).

## 1. Сущность «кампания»

Одна запись: окно дат и до трёх частей, которые включаются и выключаются **вместе**.

| Часть | Поля | Куда идёт |
|---|---|---|
| **Сезон (оформление)** | `preset` (id, напр. `winter`), **палитра** (17 токенов брифа, `#RRGGBB`), картинки `hero` и `ticket` (ключи в бакете), тексты `heroTitle` ≤ 28, `heroBody` ≤ 60, `cta` ≤ 16 с `{code}` (en), эффект `snow` / `leaves` / `hearts` / нет | `app-config.season` |
| **Витрина кода** | **публичный** код (`kind = PUBLIC`, из `AURAT-0146`) + призыв (≤ 60, en) | `app-config.promo` |
| **Скидка** | процент 5–70, подпись (≤ 24, en: «Winter sale») | цена брони + `app-config.discount` |

Общие поля: название для операторов («Black Friday 2026»), окно **по дням** «с … по …
включительно» в `SESSION_SLOT_TIMEZONE` (как срок кодов в 0146: `startOfZonedDay`; хранится
`startsAt` / `endsAt` — полночи пояса, конец исключительный), статус.

- **Статусы:** `черновик` → `включена` → `выключена`. «Запланирована / идёт / завершена» — из
  окна. Править можно черновик и выключенную; включённую — только выключив. Удаления нет.
- **Пересечения по частям:** нельзя включить, если у уже включённой кампании та же часть в
  пересекающемся окне. «Зима» (сезон + `WINTER5`, 20.11–07.01) и «Black Friday» (скидка, 27–30.11)
  живут вместе. Проверка — в транзакции включения под advisory-lock.
- **Лимиты символов** — константы контракта `v0.27.0` (`SEASON_COPY_LIMITS`): `heroTitle` 28,
  `heroBody` 60, `cta` 16. Это ориентир брифа; **числа уточняются по `SEASONAL.md` до тега
  `v0.27.0`**. Длина `cta` считается **после подстановки `{code}`**: кодом своей витрины и кодом
  витрины включённой кампании, пересекающейся по окну. Публичный код бывает до 20 символов,
  поэтому длинный код с текстом в 16 не влезет: «Apply {code}» оставляет коду 10 символов. Такая
  пара отклоняется на форме, и ошибка называет код. Без кода клиент кнопку не рисует.

### Палитра и контраст (решение владельца 2026-10-31)

Цвета сезона — **данные**: новый сезон выходит без релиза клиента. `preset` — только id для
журнала и подсказка клиенту; неизвестный id ничему не мешает, рисуется по палитре.

Токены (бриф, «TOKEN WHITELIST»): `heroFrom`, `heroTo`, `heroTitle`, `heroBody`, `heroCta`,
`heroCtaLabel`, `ticketStub`, `ticketStubLabel`, `ticketSoft`, `ticketEyebrow`, `orbBase`,
`orbSoft`, `bannerFrom`, `bannerTo`, `bannerAccent`, `tabActive`, `effectTint`. Для включения нужны
**все 17**; черновик может быть неполным.

Пары — **P1–P18 из брифа `AURAT-0150-005` как есть** (передний план / фон / порог), WCAG 2.x
relative luminance:

| Пары | Передний план → фон | Порог |
|---|---|---|
| P1–P4 | `heroTitle`, `heroBody` → `heroFrom`, `heroTo` | 4.5 |
| P5 | `heroCtaLabel` → `heroCta` | 4.5 |
| P6–P7 | `heroCta` → `heroFrom`, `heroTo` (край кнопки) | 3 |
| P8 | `ticketStubLabel` → `ticketStub` | 4.5 |
| P9–P10 | `ticketEyebrow` → `ticketSoft`, `#FFFFFF` (card) | 4.5 |
| P11–P12 | `#FFFFFF` → `bannerFrom`, `bannerTo` (заголовок баннера) | 4.5 |
| P13–P14 | `#FFFFFF@0.70` → `bannerFrom`, `bannerTo` (подзаголовок; альфа-композит поверх фона пары до расчёта) | 4.5 |
| P15–P16 | `bannerAccent` → `bannerFrom`, `bannerTo` | 4.5 |
| P17 | `tabActive` → `#F4EFE5` (таб-бар) | 4.5 |
| P18 | `tabActive` → `#FFFFFF` (пункт навигации веба на card) | 4.5 |

Градиенты проверяются по обоим концам. `orbBase`, `orbSoft`, `effectTint` в пары не входят: они
обязательны, но контраст у них не проверяется. Белый список и P1–P18 становятся контрактом
`v0.27.0`. Менять их после сдачи дизайнера — только через `AURAT-0147` (новая минорная версия).

Расчёт — **чистая функция в `@aura/contracts`** (`checkSeasonPalette(palette) →
[{pair, ratio, min, ok}]` + `contrastRatio(a, b)` + список пар и фиксированных фонов), чтобы веб и
приложение перепроверяли тем же кодом. Бэкофис считает на сохранении (таблица пар с числами на
форме и странице кампании) и **ещё раз на включении**. Не прошла хоть одна пара — сохранить
черновиком можно, включить нельзя.

**Импорт пресета:** на форме поле «Вставить `presets/<id>.json`» (формат брифа). Сервер разбирает
его и заполняет форму, ничего не сохраняя; ошибки по полям. Так 17 цветов не набираются руками.
В JSON все 17 токенов обязательны, умолчаний нет: неполная палитра — ошибка импорта.
`id` — только имя для журнала. Новый пресет (например, `autumn` с эффектом `leaves`) — это данные,
релиз не нужен.

### Картинки

Оператор вводит **ключ** (`seasonal/winter/v1/hero.webp`), BFF отдаёт
`CAMPAIGN_ASSETS_BASE_URL + ключ`. Ключ обязан иметь сегмент версии `/v<N>/` и окончание `.webp`
или `.png`: приложение кэширует по URL, поэтому **новая картинка — новый путь, файл по старому
ключу не перезаписывается** (правило для того, кто кладёт файлы; сервер проверяет только форму
ключа). `CAMPAIGN_ASSETS_BASE_URL` необязательна: без неё поля картинок выключены, в ответе
`null`, клиент рисует «без картинки» (состояние из брифа). Загрузка в R2 — вне задачи.

## 2. `GET /v1/app-config` (контракт `v0.27.0`, `src/app-config.ts`)

Публичный, без токена, одинаковый для всех. `Cache-Control: public, max-age=60`, слабый `ETag`,
`If-None-Match` → 304. Только то, что действует сейчас.

```ts
AppConfigResponse = {
  season: null | {
    campaignId: string,
    preset: string,                            // id; неизвестный — не ошибка
    endsAt: string,
    palette: SeasonPalette,                    // 17 токенов, #RRGGBB, все прошли проверку
    art: { hero: string | null, ticket: string | null },   // абсолютные URL
    copy: { heroTitle: string, heroBody: string, cta: string | null },  // cta с {code}
    effect: string | null,                     // известные: SEASON_EFFECTS; неизвестный — без эффекта
  },
  promo: null | { campaignId: string, code: string, headline: string, endsAt: string },
  discount: null | { campaignId: string, label: string, pct: number, endsAt: string },
}
```

- `preset` и `effect` — строки, не enum: новое значение не уронит разбор у выпущенного клиента.
  Новые токены палитры позже — необязательными полями (старые клиенты их отбросят).
- `{code}` в `cta` подставляет клиент из `promo.code`; `promo: null` → кнопки нет.
- `promo`, `discount` — `null` при `BILLING_ENABLED=false`.
- `promo.endsAt` — меньшее из конца кампании и срока кода; код отключили — `promo: null`.
- Кэш в процессе — 30 с, сбрасывается при включении/выключении.

## 3. Скидка в цене брони

- На блок: `firstMinor` (−50%, если оффер доступен) и `campaignMinor` (floor в пользу клиента).
  Берётся **большая**, не сумма; при равенстве — кампания (оффер не тратится).
- Бронь по слоту и «сейчас», все пользователи и советники. Продление — без скидки.
- **`getPricing` и `book` читают активную кампанию из базы** на каждый запрос, не из кэша
  `app-config`: у края окна цена переключается ровно по `startsAt` / `endsAt`. Выбор оффер/кампания
  — в транзакции брони под замками (как сейчас); готовую цену кампании передаёт сервис.
- `Session.discountCampaignId` (nullable): чья скидка в `creditMinor`. `firstSessionOfferUsed` +
  `discountCampaignId = null` — скидка кампании не тратит оффер. Старые строки не меняют смысл.
- Забронированные сессии цену не меняют; отмена и возврат — от `costMinor`, как сейчас.
- Контракт: `SessionPricing.blocks[].discount?: null | { kind: 'first_session' | 'campaign',
  pct, label: string | null }`. `GET /v1/wallet` не меняется.
- **Известное ограничение до `AURAT-0148`:** прод-приложение 1.0.9 при скидке кампании ≥ 50% и
  живом оффере рисует «50% OFF First Session» и ставку /min как −50%
  (`use-booking-confirm.ts` / `BookSessionScreen`: `offerPct = useFirstSessionOffer()` при
  `creditMinor > 0`); итог к оплате верный. Без оффера — нейтральное «−$X». То же на вебе до
  `AURAT-0149`.

## 4. Порог публичного кода при скидке кампании

`AURAT-0146` разрешает публичный код без галочки, пока он меньше самой дешёвой сессии
(`cheapestSessionCostMinor`, сейчас $11 при −50%). Скидка кампании > 50% этот порог снижает:
код $10 + −70% → сессия $6.60, каждый новый аккаунт — бесплатная сессия.

- Порог считает `SessionPriceFloor` (`sessions/session-price-floor.ts` из 0146, минимальная цена по
  **всем** советникам × минимальный блок). Он получает процент кампании: от
  `cheapestSessionSubtotalMinor` берётся большая из −50% и скидки кампании. При проценте кампании
  ≤ 50 порог не меняется. (Сверено с кодом 0146, сообщение манора 2026-10-31.)
- **Включение кампании со скидкой:** порог пересчитывается с её процентом; если есть **любой
  живой публичный код** (не отключён, срок пересекает окно кампании, не только код из витрины)
  с суммой ≥ порога — подтверждение показывает список таких кодов и требует галочку «понимаю:
  код оплатит сессию целиком» (формулировка из `AURAT-0146-006`). Проверка на подтверждении и на
  записи; галочку проверяет сервер.
- **Обратная сторона:** форма публичного кода `AURAT-0146` считает порог с учётом включённой
  кампании со скидкой, окно которой пересекает срок кода. Иначе код $10, созданный во время
  −70%, обойдёт проверку.

## 5. Витрина кода — только публичный код

На сохранении и на включении: код нормализуется (`AURAT-0146`), существует, партия
`kind = PUBLIC`, не отключён (код и партия), срок кода не раньше конца окна кампании. Одноразовый
код в витрину не берётся: его погасит первый же человек. Проверка — по моментам времени. **На
форме срок кода показывается в поясе кампании**, ошибка — с обоими временами: «код `WINTER5`
действует до 31.12 23:59 UTC (31.12 18:59 America/New_York), а кампания — до 31.12 23:59
America/New_York».

## 6. Бэкофис — вкладка «Кампании»

Видна всегда; блоки «Скидка» и «Код» — только при `BILLING_ENABLED`.

- **Список:** название, окно, части, статус, кто включил.
- **Форма:** §1, импорт пресета, таблица контраста, ошибки по полям (422), `creationKey`.
- **Страница кампании:** превью куска `app-config`, который даст кампания; таблица контраста;
  кнопки «Включить» / «Выключить» / «Изменить»; журнал.
- **Включить** → подтверждение обычным языком: окно в поясе кампании, что увидят клиенты, правило
  «большей скидки», предупреждение §4 с галочкой. Перепроверки на записи: контраст, пересечения,
  витрина, порог. Кампанию, окно которой уже закончилось, включить нельзя.
- **Выключить** → подтверждение → действует сразу (у клиентов — до 60 с из-за кэша; цена брони —
  сразу).
- **Журнал** (`campaign_events`, только добавление): создана / изменена / включена / выключена,
  оператор (id + снимок логина, без FK), время, снимок полей.

## 7. `AURAD-0022` (файл создаётся при исполнении)

1. **Скидки:** −50% первой сессии остаётся политикой в коде («policy is not config» — для политики
   и правил возврата). Сезонные скидки — **данные** в базе: оператор включает их с подтверждением
   и журналом. Старый довод («staging и prod разойдутся») был про env-конфиг; кампания — запись
   с аудитом. Сочетание — большая, не сумма; при равенстве — кампания. Скидка — уменьшение
   списания (`AURAT-0018`). Предел — 70%. Откат — «Выключить».
2. **Палитра — данные с серверной проверкой контраста.** Довод «оператор сломает контраст»
   закрывается тем, что включение невозможно, пока все 18 пар брифа не держат порог (4.5 / 3).
   Проверка та же, что у клиентов (одна функция в контрактах), и правило брифа (rule 4) становится
   условием сервера, а не только приёмки дизайна. Фиксированные фоны (card, таб-бар, белый на
   баннере) зашиты в список пар.
3. **Публичный код и скидка:** порог «код меньше самой дешёвой сессии» считается с учётом
   скидки кампании (§4).

- Реализация начинается сразу. Части, зависящие от 0146 (`kind = PUBLIC`, нормализация vanity,

  смёржится в `develop`. Тогда ветка этой задачи вливает `develop` в себя, а миграция получает
  имя после миграции 0146.

  Push / тег — только с разрешения владельца. В BFF до тега — проверка на собранном `dist`.

## Решения в спеке (поправь, если не так)

1. Одна кампания = сезон + код + скидка, включаются вместе; пересечения запрещены по частям.
2. ~~Палитра только пресетом~~ → **палитра — данные с серверной проверкой контраста** (владелец);
   для включения нужны все 17 токенов; импорт `presets/<id>.json` на форме.

4. Окно — в `SESSION_SLOT_TIMEZONE`; включённую кампанию сначала выключить, потом править.
5. Картинки — версионные ключи + необязательная `CAMPAIGN_ASSETS_BASE_URL` (задать в Coolify).
