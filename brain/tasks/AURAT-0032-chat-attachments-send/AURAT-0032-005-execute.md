# AURAT-0032-005 — Сделано: BFF принимает вложения от устройства

Дата: 2026-08-21
Состояние: код написан, не закоммичен; 530 тестов; в маноре не проверено
Пакет: `@aura/contracts` **v0.10.0**, тег запушен

## Что теперь работает

`POST /v1/advisors/:advisorId/messages` принимает multipart. Один маршрут, две
формы тела: JSON для текста, multipart когда есть файл. Тип определяется по
содержимому, размер ограничен нами, а повтор отправки больше не удваивает файл.

## Решения, принятые по ходу

**`idempotencyKey` необязателен — и это несущая деталь.** Спека говорила
«добавляется ключ»; при написании выяснилось, что сделать его обязательным
значит **отклонять каждую отправку с уже установленных телефонов**: сервер
валидирует по этой же схеме, а выпущенное приложение поля не шлёт.

**Байты буферизуются, а не текут насквозь.** `001` требовал не держать их в
памяти. Отступаю осознанно: у потока, оборванного на середине, всё равно
закрывается корректная multipart-граница, поэтому Chatwoot сохранил бы
**обрезанный** файл и ответил 201 — та же тихая порча, ради прекращения которой
заведена фича, только в другую сторону. Буфер ограничен теми же 25 МБ, то есть
два решения держат друг друга.

**Сниффер написан руками, а не взят из `file-type`.** Пакет уже стоит
транзитивно, но он чисто ESM, а сервис компилируется в CommonJS — достать его
можно только динамическим импортом, который TypeScript опустит в `require`, и
под Jest он потребует флага, которого в репозитории нет. Тест, который не может
загрузить сниффер, ничего о нём не доказывает. Список типов закрыт и мал.

**Заявленный тип допущен ровно к одному — уточнению внутри доказанного
контейнера.** `.docx` действительно zip; какой именно zip — вопрос ярлыка, а не
безопасности. Решать, *чем является* файл, ему не позволено нигде.

**Принятая загрузка никогда не докладывается как неудача.** Если стол вернул id,
но эхо не нормализовалось (у вложения без подписи это одна строчка `if
attachments.present?` в шаблоне Chatwoot), сообщение **уже доставлено** — и
ответить «непонятный ответ» значило бы соврать с последствиями: приложение
предложит повтор, и файл уедет второй раз. Собираем сообщение из того, что
отправили.

**Пайп валидации был типизирован по входной форме схемы.** С `.default()` вход и
выход расходятся; это не ловилось, пока результат уходил прямо в декоратор.
Починено в общем коде.

## Тесты: 493 → 530

- **`attachment-sniffer.spec.ts` (9)** — форматы телефона; RIFF по тегу; шесть
  типов ISO-BMFF по бренду; Opus против Ogg; AAC против MP3, у которых общее
  слово синхронизации; и главный: **заявленный тип не решает, чем файл является**
  (jpeg, объявленный как pdf, остаётся jpeg; исполняемый файл под видом фото —
  не распознан).
- **`attachment-intake.spec.ts` (11)** — отказы с кодами; нулевой файл; **U+202E
  вырезается** (подмена расширения); разделители пути и CR/LF; заявленный тип
  **не возвращается** в теле ошибки.
- **`chat.service.spec.ts` (+7)** — ключ уезжает в стол; ключ из **любого** пути
  приёма сохраняется; **повтор возвращает уже отправленное и не грузит файл**;
  поиск в пределах разговора; без ключа отправка работает как раньше; пустое
  сообщение отвергается до провижининга.
- **`chatwoot.client.spec.ts` (+10)** — `attachments[]` массивом; имя и
  сниффнутый тип; пустая подпись; `source_id`; **Content-Type не ставим руками**;
  и обе стороны неудачи — принятая загрузка не докладывается как провал, а
  невнятный ответ без файла по-прежнему отвергается.

## Ошибка по ходу

`npm install` контрактов выполнился внутри репозитория контрактов, а не BFF —
пакет на секунду прописался сам в себя. Поймано сразу, откачено, тег и коммит не
затронуты. Из той же серии, что и промах v0.9.0: команда через `cd &&` уносит
рабочий каталог дальше, чем ожидаешь.
