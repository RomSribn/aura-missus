# AURAT-0105-005 — Spec: чат в aura-web

Date: 2026-10-20
Type: task (строка `AURAF-0020-005`, колонка UI). Новой фичи нет.
Status: done 2026-10-20 (`014`) — все рекомендации `006`; таро-пикер — открытие как в приложении (`008`–`011`)

## Цель

Вошедший человек открывает `/chats` и видит те же чаты, что в приложении; открывает
`/chats/:advisorId` и переписывается с советником в реальном времени. В треде работают таро-пикер и
приглашение на сессию. Данные и правила — как в приложении (`AURAF-0007`, `-0012`, `-0013`, `-0018`).
BFF и contracts **не меняются** (`004` п. 1–8); пробелы — ниже, владельцу и в бэклог.

## Что делаем

### 1. Сокет — `shared/api/ws-client.ts` и жизненный цикл

- **Backoff не сбрасывается на `open`.** BFF закрывает 4401/4403 уже после `open` (`004` п. 5),
  поэтому сброс — только после того, как сокет продержался открытым 10 с (кадра «зарегистрирован»
  нет). Сейчас отказ крутит переподключение раз в ~1 с.
- **4403** (`forbidden origin`) — фатально: сокет останавливается, без переподключений (это
  конфигурация `WEB_ALLOWED_ORIGINS`, повтор не поможет). В лог ничего не пишется.
- **4401** (`unauthorized`) — следующая попытка берёт токен через `getIdToken(true)`.
  `ACCOUNT_DELETED` — как сейчас (выход).
- Жизненный цикл — в `app/session` рядом с `onIdentityChange`: сокет запущен, пока человек вошёл;
  выход — `stop()`; смена человека — `stop()` + `start()` (кэш сбрасывается уже сейчас).
- `ws-client` — порт из приложения; у приложения тот же сброс backoff на `open`. Исправление «на обе
  стороны» — задача для `aura-app-manor` (ID — там, см. «Пробелы» п. 3).

### 2. Данные чата — `entities/message`

- **api** (`injectEndpoints`, всё через `Schema.parse`):
  - `getThread(advisorId)` — кэш треда: `GET …/messages?limit=50` (самая новая страница) →
    `{ messages, reachedStart }` (`reachedStart` — страница короче 50).
  - догон треда (`after` = последний серверный id, `deletedFrom` = самый старый серверный id,
    `limit=50`, циклом до неполной страницы) и подгрузка назад (`before` = самый старый id) —
    кладутся в тот же кэш через `updateQueryData`;
  - `sendMessage` — `POST …/messages {content, idempotencyKey}` → `Message.parse`.
- **lib** — чистая логика, порт `ChatProvider` приложения в функции над массивом (шапка
  `// Ported from aura-app src/features/chat/model/ChatProvider.tsx (AURAF-0007)`):
  слияние серверной страницы (дедуп по id, без удалённых), урегулирование своих по
  `idempotencyKey` (AURAT-0037), удаление (`deletedIds`, `message.deleted`; курсор не двигается;
  поздний `message.new` удалённого id игнорируется), ответ отправки (замена локального или удаление,
  если сервер уже вернул его историей). Тесты — сценарии `ChatProvider.test.tsx` и
  `ChatProvider.send.test.tsx` без вложений.
- **Перенос копией с тестами**: `features/chat/lib/map-message.ts` (AURAT-0037, AURAD-0002) и
  `screens/chats/lib/preview.ts` (AURAF-0007). Одно отличие по правилам веба (как с форматтерами в
  `AURAT-0103`): `time` «HH:MM» руками не строится — модель хранит `createdAt`, время и дата
  форматируются `Intl` на языке интерфейса (иначе нет разделителей дней). Отличие записано в шапке.
- **Список диалогов** (как приложение, `/v1/conversations` нет): `useConversations()` — `getThread`
  по каждому советнику каталога (8 запросов при входе на `/chats`, кэш общий с тредом); строки —
  треды с сообщениями; **порядок — по `createdAt` последнего сообщения, новые сверху** (в
  приложении порядка нет — порядок появления).
- **Живые события** (`message.new`, `message.deleted`, `typing.update`, `presence.update`) → кэш RTK
  Query (`updateQueryData`), не отдельный store: тред — в `getThread`, presence и typing — в своих
  записях кэша (`queryFn` без сети). `session.updated` игнорируется (платная сессия — не здесь).
- **Догон по REST** (у веба нет FCM, свои сообщения по WS не приходят): все треды — при каждом
  открытии сокета, на `visibilitychange` → видимо, на `online`; открытый тред — перечитка самой новой
  страницы при открытии (обновляет выбор карты, сделанный в приложении) и опрос `after` раз в 30 с,
  пока вкладка видима. Бюджет: ~8 запросов на событие + 2/мин — с запасом под 120/мин на IP.
- **`:advisorId` — только из каталога.** Каталог грузится — скелет; советника нет — NotFound внутри
  страницы чатов, ни одного запроса в BFF (иначе BFF создаст диалог на любой id). Тред создаётся
  первым сообщением, `PUT …/conversation` не вызывается.
- **Presence**: `true` — точка и «Online»; `false` или нет данных — ничего (presence приходит только
  по советникам с диалогом и только при подключении — «нет данных» не значит offline).

### 5. Тред — `widgets/chat-thread`

- **Шапка**: «назад» (телефон), фото 40 + точка, имя (ссылка на профиль), статус («Online · free
  chat» / «Free chat»), иконка календаря → `paths.advisor(id, { book: true })` — только при
  `billing === 'on'` (без биллинга бронировать нечего; Book sheet — строка 006).
- **Лента** (`role="log"`, новые входящие объявляются вежливо): пузыри — мои коралловые справа,
  советника — карточка слева, без аватара; время внутри пузыря (`Intl`, 11 px); разделители дней по
  `createdAt` («Today», «Yesterday», дальше дата `Intl`); системные строки — пилюля по центру (маркер
  «started» — teal, остальные — приглушённые; язык — решение 8). Индикатор typing — решение 2.
- **Приветствие** персоны (`greeting`) — первый пузырь советника, только в UI, когда достигнуто
  начало истории (`reachedStart`), чтобы не оказаться посреди переписки.
- **Подгрузка назад**: при доскролле к верху — `before`, 50 штук, позиция прокрутки сохраняется;
  «Loading…» сверху; `reachedStart` — больше не просим.
- **Прокрутка**: у низа (≤ 80 px) — новые сообщения держат вид внизу; прокрутил выше — не дёргаем,
  кнопка «New messages ↓». Открытие треда — сразу внизу.
- **Мои сообщения**: отправляется — полупрозрачный, «Sending…»; доставлено — только время (без ✓✓ —
  прочтения нет); не доставлено (сеть, 5xx, 429, ответ без кода) — «Not delivered · Click to resend»,
  кнопка повтора **с тем же ключом**; отказ с кодом — текст отказа, без повтора: `message_empty` —
  «Nothing to send», `refused_by_agent_desk` и прочие — «The advisor's desk wouldn't take it».
- **Входящие вложения** (отправка — v2): картинки — превью через `fetch` с Bearer → blob URL,
  лениво при появлении в виде (`IntersectionObserver`), кэш в памяти по id, `revokeObjectURL` при
  уходе; размер — из `width/height`, иначе 4:3, высота ≤ 1.4 ширины; клик — открыть в новой вкладке.
  Остальное (файл, аудио, видео) — строка «иконка · имя · размер», клик скачивает через тот же
  `fetch` (имя — из `fileName`). 404 — «No longer available», прочая ошибка — «Couldn't load · Retry».
  Ни пустых пузырей, ни падений.
- `message.deleted` — сообщение исчезает без следа (`AURAF-0018`).

### 6. Отправка — `features/send-message`

- `<textarea>` с авторостом до 6 строк, плейсхолдер «Write a message…», подпись для скринридера.
  Enter / Shift+Enter — решение 7. IME-композиция (`isComposing`) никогда не отправляет.
- Отправка — оптимистично: локальный пузырь с новым `idempotencyKey` (UUID, один на сообщение,
  тот же на повторах, `AURAT-0032`), текст `trim`. Пусто — кнопка неактивна (серая; teal — когда
  есть текст).
- Лимит 4000 — и на клиенте: счётчик `N / 4000` появляется с 3800, больше 4000 — красный, отправка
  неактивна. Обрезки при вставке нет.
- Скрепки нет (вложения — v2; правило 5 — без заглушек).

### 7. Таро-пикер — `features/tarot-pick`

- Сообщение со `spread` рисуется картой пикера вместо пузыря (как приложение): плум-карточка 560
  (на телефоне — во всю ширину), эйбрау «Tarot · from {advisor}», «Choose a card», «Take a moment
  and choose the one you're drawn to.», веер из 7 рубашек (геометрия веб-хендоффа: desktop шаг 56,
  карта 92×144, наклон 7°; телефон — 30, 66×104, 4°).
- Наведение — карта поднимается на 18 px, соседи на 5 px; клик / тап / Enter / Space выбирают;
  стрелки ←/→ двигают фокус; каждая рубашка — кнопка «Card N of 7». Подсказка: «Hover to explore ·
  click to choose» (desktop) / «Tap to choose» (телефон).
- Выбор: карта в центр, остальные гаснут (450 мс), `POST /v1/tarot/spread/:messageId/pick
  {position}`; через 520 мс после ответа — переворот (600 мс) на карту **из ответа**
  (`card.imageUrl`, `<img>` с `alt` = имя карты). Пока ждём — «Revealing…». Двойной клик не
  отправляет второй запрос.
- Итог (и для `spread.picked` из истории): перевёрнутая карта остаётся, «Your card», «You chose
  {card}», ключевые слова + «· {advisor} will read it for you». Выбор окончателен (повтор на
  сервере вернёт первый).
- Ошибка — веер возвращается, «That didn't go through — click a card to try again.»; 404 —
  сообщение удалено, исчезнет с `message.deleted` / догоном.
- `prefers-reduced-motion` — без полёта и переворота, сразу итог.

## Решения (владельцу)

**1. Бейдж непрочитанного** (шапка «Chats» и строки). Данных нет ни на сервере, ни в приложении.
- А. Нет бейджа — как приложение.
- Б. **«Новое за этот визит»**: в памяти — тред получил сообщение советника (по WS или догоном) и не
  открыт → бейдж; открыл — сброшен; перезагрузка — сброшен. Без хранения и без ложных срабатываний,
  но пришедшее, пока вкладки не было, не помечается.
- В. Локально в браузере (`localStorage`: последний прочитанный id по советнику, база при первом
  визите = «всё прочитано»). Помечает пришедшее между визитами, но не знает о прочтении в
  приложении — бейдж «висит» на прочитанном с телефона.
- Г. Серверная отметка прочтения — contracts + BFF + приложение (ID — в `aura-app-manor`); одинаково
  везде.
- **Рекомендация: Б сейчас + Г в бэклог** (В даёт расхождение с приложением, которое нельзя
  исправить на клиенте).

**2. Typing.** BFF шлёт, приложение рисует, веб-хендофф — нет.
- **Рекомендация: рисовать в треде** три точки пузырём советника (как приложение, `blink` 1.2 с,
  без анимации при reduced motion); гаснет на `typing:false`, на `message.new` этого советника и при
  обрыве сокета. В списке не показываем. Альтернатива — не рисовать (как хендофф веба).

**3. Search chats.**
- А. **Не рисовать** — у человека не больше 8 диалогов (по персоне), фильтр по имени бесполезен,
  поиска по тексту на сервере нет; вернуть вместе с `GET /v1/conversations`.
- Б. Фильтр строк по имени советника на клиенте.
- **Рекомендация: А.**

**4. `/chats` без id на desktop.**
- А. **Открыть самый свежий тред** (`replace` на `/chats/:id`), как в прототипе, где тред всегда
  открыт; тредов нет — пустое состояние. На телефоне `/chats` — список, как задано.
- Б. Тред-заглушка «Pick a conversation» с орбом, rail пуст.
- **Рекомендация: А.**

**5. Раскладка 761–1180** (в хендоффе нет; на 761 третья колонка оставляет треду ~100 px).
- А. **2 колонки: список 300 · тред**, rail скрыт; его содержимое достижимо из шапки треда (имя →
  профиль, календарь → бронь). Граница — существующий брейкпоинт 1180 (новый 1100 не вводим —
  правило 3: брейкпоинты только из `breakpoints.ts`). Так же предлагал Plan.html для планшета.
- Б. 3 колонки до 761 с ужатыми ширинами.
- **Рекомендация: А.**

**6. Таб-бар в треде на телефоне.**
- А. **Скрыть** (тред — pushed flow, как профиль и Pay; назад — стрелкой): больше места под ленту и
  поле, когда открыта клавиатура; как приложение.
- Б. Оставить (веб-хендофф).
- **Рекомендация: А.**

**7. Enter / Shift+Enter.**
- **Рекомендация:** desktop (точный указатель) — Enter отправляет, Shift+Enter — новая строка, как
  Ask на Home; телефон / сенсорный ввод — Enter = новая строка, отправка кнопкой (на экранной
  клавиатуре нет Shift). Альтернатива — Enter отправляет везде (как приложение).

**8. Язык маркеров сессии** (BFF пишет только «Your session has started / finished»).
- А. Показывать текст сервера как есть (как приложение) — английская строка в немецком интерфейсе.
- Б. **Узнавать два точных текста и переводить** ключами `message:marker.started|finished`;
  незнакомый системный текст — как есть. Цвет по-прежнему от `started`.
- В. Машиночитаемый вид маркера в contracts + BFF (+ приложение) — убирает разбор текста.
- **Рекомендация: Б сейчас + В в бэклог.**

**9. Цена и минуты в приглашении.** Заглушка просит «цену из pricing»; `AURAF-0013` (решение
владельца, в контракте) — без цены и минут: карточку называет бронь, которую открывает CTA.
- А. **Как приложение и `AURAF-0013`**: без цены и минут, только оффер.
- Б. Как веб-хендофф: самый короткий блок — «30 min» + `PriceTag` (зачёркнутая и с оффером).
- **Рекомендация: А** (один мозг — одно правило; цена `/min` и так в rail).
