# AURAT-0105-001 — Initial (заглушка; исполняется в `aura-web-manor`)

Date: 2026-10-20
Выдан в `aura-app-manor` для `AURAF-0020` (веб-клиент), этап 1 — строка 005 scope
(колонка UI), шаг «Chat» (порядок — Р5 `AURAD-0019`). Опирается на `AURAT-0101`
(`shared/api/ws-client.ts` — `BffSocket` пока без потребителя, `server-clock`,
`refusal-code`), `AURAT-0103` (каталог `GET /v1/advisors` в кэше RTK Query) и `AURAT-0104`
(вход, `onIdentityChange`, gate с resume: Free chat → `/chats/:advisorId`; бейдж чатов
отнесён к этой задаче — `AURAT-0104-005` §5).

Что нужно: человек видит те же чаты, что в приложении, переписывается в реальном времени,
открывает таро-пикер и приглашение на сессию — README §4.5, §6, §8, NAVIGATION §1.1, §2.8,
§3.3, §3.4, §4 веб-хендоффа. Данные и правила — как в приложении (`features/chat`,
`features/tarot-spread`, `screens/chats`, `screens/chat-thread`; `AURAD-0001…0003`,
`AURAF-0007`, `AURAF-0012`, `AURAF-0013`, `AURAF-0018`).

- **Данные — BFF как есть.** Списка диалогов нет (`GET /v1/conversations` — долг BFF,
  `AURAT-0009`): список, как в приложении, собирается историей по советникам каталога, в
  нём только треды с сообщениями. История — `GET /v1/advisors/:id/messages` с
  `after | before | limit | deletedFrom` (`HistoryResponse`; курсоры — id, страницы по
  возрастанию, `hasMore` нет — добор циклом до неполной страницы; `deletedIds` убирают
  удалённое). Отправка — `POST …/messages` с `idempotencyKey`: оптимистично, повтор с тем же
  ключом, отказы `SendRefusalCode`, лимит 4000 символов проверять и на клиенте. Новый тред —
  `PUT /v1/advisors/:id/conversation` (в контракте ошибочно `POST`) или первое сообщение;
  `greeting` персоны — пузырь только в UI. `:advisorId` — только из каталога, иначе
  NotFound: BFF создаст диалог на любой валидный id.
- **Реальное время.** `/ws?token=`, только server→client: `message.new`, `message.deleted`,
  `typing.update`, `presence.update`, `session.updated`. Свои сообщения по WS не приходят, а
  FCM у веба нет — догон по REST: открытие сокета, `visibilitychange`, `online`, редкий опрос
  открытого треда; с запасом под лимит BFF 120 запросов/мин на IP. `ws-client.ts` доработать:
  backoff не сбрасывать на `open` (BFF отказывает уже после upgrade — сейчас 4401/4403
  крутят переподключение раз в секунду), 4403 — фатально, на 4401 — `getIdToken(true)`;
  сокет живёт со входом и закрывается при выходе и смене человека.
- **Список и тред.** Desktop — 3 колонки (список · переписка · rail советника), телефон —
  список, затем тред. Строка: фото, имя, время, превью. Тред: пузыри, системные строки
  (маркеры сессий от BFF), разделители дней по `createdAt`, composer, подгрузка истории
  назад (`before`). Presence приходит только по советникам с диалогом и при подключении:
  нет данных — не значит offline. Входящие вложения приходят и сейчас (отправка — v2):
  без падений и пустых пузырей; как показывать (имя файла или превью через `fetch` с
  Bearer) — в спеку.
- **Таро-пикер** — сообщение со `spread`: веер из 7, `POST /v1/tarot/spread/:messageId/pick
  {position}`, карта — из ответа (`card.imageUrl`), выбор идемпотентен и окончателен.
  События выбора по WS нет: выбор, сделанный в приложении, веб увидит при перечитке
  истории.
- **Приглашение на сессию** — сообщение с `sessionInvite: {}` (минут, цены и состояния в
  контракте нет): карточка с ценой из `…/sessions/pricing` и оффером, как в `AURAT-0103`.
  CTA, иконка календаря в шапке и Quick book в rail ведут в бронь — это строка 006; до неё
  — deep link `?book=1` профиля советника, без обработчиков-заглушек (правило 5). Без
  биллинга (404 у pricing) — решить в спеке.
- **Решить в спеке** (хендофф шире данных): бейдж непрочитанного в шапке и в строках — на
  сервере нет ни счётчика, ни отметки прочтения (без бейджа, как в приложении / локально в
  браузере / задача contracts + BFF + приложение); typing (BFF шлёт, веб-хендофф не
  рисует); «Search chats»; `/chats` без id на desktop; раскладка 761–1100; таб-бар в треде
  на телефоне; Enter / Shift+Enter; язык маркеров сессии (BFF пишет только по-английски).
- Раскладка — по скиллу `fsd`, ориентир — `AURAI-0007` (entities `message`, features
  `send-message` и `tarot-pick`, widgets `conversation-list`, `chat-thread`,
  `advisor-rail`). Перенос из aura-app только нужного, копией с тестами и шапкой
  `// Ported from aura-app <path> (<ID>)`: `features/chat/lib/map-message.ts`,
  `screens/chats/lib/preview.ts`; логика `ChatProvider` (слияние, дедуп по ключу, удаление,
  повтор) — в RTK Query / slice, сценарии — из `ChatProvider.test.tsx` и
  `ChatProvider.send.test.tsx`. Новые строки — сразу на все 24 языка (правило 9).

BFF ожидается без изменений. Найденные пробелы — владельцу и в бэклог, ID выдаётся в
`aura-app-manor`: CORS не открывает `Date` и `Retry-After` — `serverNow()` веба молча идёт
по часам устройства (касается и слотов `AURAT-0103`); свои `message.new` не рассылаются на
другие устройства; нет кадра «сокет зарегистрирован»; нет события выбора карты; системный
маркер не машиночитаем; нет `GET /v1/conversations` и отметки прочтения. Прод — веб-домен в
`WEB_ALLOWED_ORIGINS`.

Вне задачи: отправка вложений (v2), бронь и оплата (Book sheet, Quick book — строка 006),
платная сессия в треде (баннер, таймер, Extend), отзыв в треде, Home и «Recent chats»,
колокольчик, web push.

Проверка в маноре: вход с ключами Firebase Web App (`.env.local` манора), чат против
bff-dev. Отвечают чаттеры из Chatwoot (`AURAD-0001`); таро и приглашение — токенами
`::CUPS_02::` и `::SESSION::` с их стороны. Старт — `wts-task` в `aura-web-manor`, спека на
одобрение владельцу.
