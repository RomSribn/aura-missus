# AURAT-0158-035 — spec: точные правила тяги (ревью 034)

Дата: 2026-11-05. Рецензент проверил 034:
- первый ревьюер прогнал по его правилам 18 сценариев;
- второй сверил новые утверждения и тесты с исходниками;
- к каждому — скептик.

Итог: ревью 033 перенесено верно, но к коду шаг не готов — 1 блокер, 3 серьёзных, 6 мелких. Это правки точных
правил, не новая схема. Разбор с path:line — `wf034-review.md` рецензента. Блокер (снятие listener'ов при
`__detach`) я сверил по `AnimatedNode.js`; поведение `setOffset` / `flattenOffset` — по `AnimatedValue.js`.

**034 + 035 — схема.** 035 переписывает пункты 034, названные ниже; остальное в 034 в силе.

## 1. Свои listener'ы — при каждом открытии (блокер, CONFIRMED)

После закрытия лист рендерит null. Значение, потерявшее последнего ребёнка, идёт в `__detach` →
`removeAllListeners`; RN заново вешает только свой скрытый listener. Если вешать свои один раз при монтировании,
то после повторного открытия на Android `travel` застынет на 0. Тогда каждое отпускание без закрытия запишет
`gestureY = 0`, и лист прыгнет домой на всю тягу.

Правило:
- listener'ы на `gestureY` (Android) и `drag` вешать в эффекте открытия, рядом с `setValue(0)`; там же `travel = 0`,
  `restingDrag = 0`;
- `removeListener` вручную не звать: после автоснятия счётчик уйдёт в минус, и `__makeNative` больше не подпишется;
- двойное добавление при visible true → false → true до конца slide-out безвредно.

Тест (`BottomSheet.android.test.tsx`): открыть, закрыть до конца slide-out, открыть; `nativeMove(60)`, медленный
END 60 → `sheetY` до и после END одинаков.

## 2. Закрытие — только по тяге этого касания (заменяет 034 §3.3, CONFIRMED)

Иначе флик по прокрученному списку во время пружины от грипа закроет лист: стоп на `c ≈ 28` (до ~50) плюс скорость
1500. Так же закроется лист, который хост держит за 0,3H.

- `ownPull = max(shownPull, rerunPull)`.
- Закрытие, если одновременно: END, `ownPull > 0` и `releaseDismisses(restingDrag + ownPull, velocityY, sheetHeight)`.
- `restingDrag` только добавляется к тяге касания и сам закрытия не вызывает.

## 3. restingDrag — свой ref (заменяет 034 §3.3, CONFIRMED)

JS `setOffset` / `flattenOffset` listener не зовут. Эхо есть только на Android и только от `setOffset`, и listener'ы
видят старый `_offset`. Поэтому на iOS после фолда без пружины значение из listener'а старое.

- `restingDrag` — ref, 0 при открытии;
- в каждом фолде `restingDrag += shownPull`, в том же такте;
- listener на `drag` обновляет его во время пружины и по колбэкам стопа и конца.

## 4. Липкий старт вне списка (уточняет 034 §2, CONFIRMED)

На Android движения склеиваются (`canCoalesce` для NATIVE_ANIMATED_EVENT; очередь Fabric заменяет событие). Первое
услышанное может быть −2. Тогда `listPullStart(null, 0, −2, true) = null` → парковка, затем старт −2: две ступеньки.

- `listPullStart(..., sticky)`: при `sticky` → `start ?? 0`, без учёта знака движения и `listAtTop`.
- В `follow`: `sticky = !onList.current`; `at = pullStart ?? NOT_PULLING`; `placePull` только при `at !== pullFromAt`.
- Взведён — за всё касание ни одной записи. NOT_PULLING — одна запись 0 на первом услышанном движении (догон).
- `decisionStart` на END — тот же вызов. Вне списка `rerunPull = END.translationY`.
- Касания на списке не трогать: старт 0 прижал бы список, пока палец идёт вверх. Взвод у верха с первым услышанным
  движением ≤ 0 → парковка и новый старт через JS — в «Остаётся», посчитать на замере.
- iOS: если движение придёт раньше START списка, касание на прокрученном списке посчитается вне списка. Так уже
  сегодня — проверить на iPhone.

## 5. Один предикат «тяга жива при отпускании» (заменяет «onList и старт был» в 034 §3.5, CONFIRMED)

```
endStart = wasActive ? listPullStart(pullStart, lastMove, END/CANCELLED.translationY, …) : null   // чистый вызов
pulling  = onList && (state === END || oldState === ACTIVE) && (endStart !== null || shownPull > 0)
```
*Исправлено после ревью кода 036 (R036-1):* в первой редакции стояло `pullStart !== null || …`. На Android END
приходит раньше движений вверх за старт, и устаревший `pullStart = 0` считал законченную тягу живой: `toTop` обрывал
флик списка.
- Для FAILED / CANCELLED из BEGAN — всегда false.
- Считается до `onFinish`. Один и тот же предикат решает:
  - `toTop` и `settling` (034 §3.5);
  - цель `pullFrom` в фолде (034 §3.4): 0, если `pulling` или `listY <= 0`, иначе NOT_PULLING.
- `toTop` лист получает через `onListTouch(toTop)` и хранит в ref касания; зовёт при отпускании, обнуляет в
  `onFinish`. Оба `toTop` стабильны и на размонтированном списке — no-op, поэтому `SheetListLink` не регистрирует
  и не снимает.

## 6. Дрейф при подхвате — обе платформы (уточняет 034 «Остаётся» и §10, CONFIRMED)

Стоп на BEGAN — круг через JS и на Android: своя пачка, дренаж раз в кадр. Пружина идёт ещё 0,5–1,5 кадра под
неподвижным пальцем:
- отпущен на 80, подхват через 60 мс — 5–16 px;
- отпущен на 20 — 1,5–4 px.

Это дрейф, не прыжок. В «Остаётся»: «Android и iOS: стоп пружины на BEGAN — круг через JS». Цель строки «повтор
< 0,3 с»: дрейф ≤ 1,5 кадра хода пружины, ступеньки после подхвата нет.

## 7. JS-синк-коммит — все источники (дополняет 034 §6, PLAUSIBLE)

Источники:
- стоп на BEGAN;
- конец slide-in (timing `progress`, 320 мс) под тягой, начатой во время выезда;
- естественный конец пружины `drag` раньше, чем JS услышал BEGAN.

Обход, если замер подтвердит, — сразу на все: `isLooping` и у `progress`, или флаг Android. Он не публичный, поэтому
с решением владельца. Строка в §10: «тяга во время slide-in, идущая через 320 мс — нет отката».

034 §3.4: на iOS «d + S в каждом блоке» верно без идущей native-анимации. Во время slide-in маунт между flatten и
`pullFrom` может дать кадр d + 2S; окно — микросекунды.

## 8. iOS: settling и эхо toTop (дополняет 034 §4, PLAUSIBLE)

На iOS один `toTop` шлёт `onScroll` на 0 дважды: из `setContentOffset` и из `_handleFinishedScrolling`, плюс
`onMomentumScrollEnd`. Склейка этих событий в очереди не гарантирована. Если торможение переживает
`setContentOffset`, каждое повторное прижатие даёт своё эхо 0. Поэтому правило «снимается на событии ≤ 0» на iOS
снимет флаг эхом, а «игнорировать только первое» — вторым эхом. Обе версии ненадёжны: CONFIRMED по исходникам,
рецензент сверил `RCTScrollViewComponentView.mm`.

Правило:
- **iOS:** пока `settling`, события ≤ 0 флаг не снимают вовсе, без счёта эха. Снимают только BEGAN, открытие и
  закрытие.
- **Android:** без изменений — флаг снимает событие ≤ 0. Порядок FIFO: 0 приходит после всех событий > 0, а повторный
  `toTop` на 0 события не шлёт.
- **Обе платформы:** события ≤ 0 при `settling` не трогают `listY` и `pullFrom`. Взвод уже сделан фолдом, цель —
  по предикату `pulling` (§5).

Правило безопасно при обоих исходах:
- гасит `setContentOffset` торможение — событий больше нет, и флаг ждёт BEGAN;
- не гасит — каждое событие > 0 прижимается к верху, пока торможение не кончится.
Ни один consumer не передаёт `onScroll`. `toTop` к текущему смещению на iOS возвращается сразу (`CGPointEqualToPoint`),
петли нет. Замер iPhone (строка в §10: «отпускание тяги при катящемся списке — offset на следующем BEGAN») покажет,
нужен ли флаг на iOS вообще.

Тест (iOS-путь, общий файл): тяга за список, END, события 0, 0, 3, 0 → на 3 вызван `toTop`, `settling` true до
следующего BEGAN.

## 9. scrollToChecked (уточняет 034 §8)

`onLayout` вешать на строку над выбранной (индекс `max(0, k − 1)`) и в нём же звать
`scrollTo({ y: её layout.y, animated: false })` и `flashScrollIndicators`. Для «Язык устройства» и English это строка
0, y = 0. Порядок `onLayout` между строками тогда не важен.

## 10. Тесты (заменяет «Прежние» в 034 §9)

**Список тестов 032 отменён** (тесты про `caught` отменены в 033). Его тест «до активации: к верху → снова взведён»
противоречит 034 §1. Замена: «вверх → парковка; обратно к верху → `pullFrom` остаётся NOT_PULLING, старт ставит
`follow`».

Мок пресета завершает нативные анимации без `value`, и JS-значение пружины не двигается. Сегодняшние тесты доходили
до покоя через пружину `pullFrom`, которую 034 удаляет. Поэтому переписать:
1. возврат домой — мок, где пружины кончаются значением `toValue`;
2. пружина домой, затем подхват — ожидать c + путь, c подаёт мок остановки;
3. тап во время пружины — стоп и рестарт (034 §5);
4. «move после END» — только в `BottomSheet.android.test.tsx`, через `__getHandler()` без `setValue`.

Мок пружин:
- `NativeAnimatedModule.startAnimatingNode`:
  - для `config.type === 'spring'` — запомнить id и через 16 мс `cb({finished: true, value: toValue, offset: 0})`;
  - для остального — исходная реализация. Timing `progress` двигать нельзя: сдвинет покой на высоту окна;
- `stopAnimation` — `clearTimeout` и `cb({finished: false, value: c, offset: 0})`;
- исходную реализацию восстанавливать в `afterEach` вручную: `restoreAllMocks` мок пресета не вернёт.

Прочее:
- `mockClear` у `stopAnimation` перед «без пружины — без стопа». «Без пружины» — свежее открытие или после
  `advanceTimersByTime(≥ 16)`.
- `change()` в тестах передаёт `oldState`.
- «`!visible` — фолд без пружины»: фильтр `config.type === 'spring'`.
- Запись в `pullFrom` или `gestureY` различать по `mock.instances` шпиона `setValue`.
- `travel` и эхо — только в Android-файле. У каждого теста ниже указан файл:

## Остаётся (дополнение к 034)

- Касание на списке у верха, где первое услышанное движение ≤ 0: парковка и новый старт через JS (§4).
- Окно при открытии: открытие взводит 0, а `scrollToChecked` прокручивает лист языка через несколько кадров. До этого
  тяга за грип взведена против списка не у верха, а касание на списке может ехать вместе с прокручиваемым списком,
  пока его не запаркуют.
- Строку «iOS: стоп пружины — круг через JS» заменяет §6.

## Шаг шапки (034 §7, когда владелец решит)

- `translateY = slide + rubber(drag + headerTravel + listPull)` — тогда ни один фолд не меняет вход `rubber` при
  любом знаке `drag`. Иначе шапка, потянутая вверх на −100, плюс повторный захват за список дадут прыжок ~92 px.
  Заметка «фолд считает, что drag ≥ 0» (034 §3.4) тогда уходит.
- `T` шапки — из её listener'а, END — запасной.
