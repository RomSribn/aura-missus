# AURAT-0158-034 — spec: тяга листа со списком, итог ревью 033

Дата: 2026-11-05. Рецензент проверил 033 по исходникам RN 0.85.3 / RNGH 3.0.1 (4 ревьюера, к каждому скептик):
в главном схема верна, но к коду не готова. Полный разбор с path:line — `wf033-review.md` рецензента. CONFIRMED —
доказано по исходникам, PLAUSIBLE — нужен замер. Ключевые места кода (`BottomSheet.tsx` `follow`, `settle`,
`onDragState`, `onListScroll`; `LanguageSheet.tsx` `scrollToChecked`) я сверил сам.

**034 — единственный источник схемы.** 032 остаётся источником замера и мотивации. 033 в силе, если 034 его не
переписывает: снятие «одной пачки», нативный фолд вместо `caught` / `getValue`, отказ от `max(END, lastMove)`,
сброс hold-check на BEGAN, фолд по показанному пути.

## 1. Кто пишет pullFrom (заменяет таблицу 032)

| состояние | pullFrom | кем |
|---|---|---|
| открытие | список у верха → 0; `gestureY = 0`, `drag = 0` | эффект открытия: сбрасывает и `settling`, `holdCheck`, все флаги касания |
| простой (`!panActive`) | `listY <= 0` → 0, `> 0` → NOT_PULLING | `onListScroll`, только при изменении |
| касание активно | старт пишет **только** `follow`, вместе с `pullStart`, чтобы включилось прижатие | `follow` |
| касание на списке, список ушёл от верха, `pullStart === null` | NOT_PULLING | `onListScroll` |
| `settling` (после отпускания тяги со списка) | не трогать | — |
| отпускание | фолд (§3) | `onDragState` |

- Внутри касания `onListScroll` не взводит (CONFIRMED). Свой slop ScrollView (~8 dp) доводит список до 0 рядом с
  активацией пана. Взвод из JS приходит на 2–3 кадра позже, и лист прыгает на весь `gestureY` (10–75 dp). Кроме того,
  `scrollTo(0)` прижатия сам шлёт событие 0 и переписал бы старт 60 → 0.
- Внутри касания парковка из `onListScroll` — только для касаний, начатых на списке. Тяга за грип не обрывается
  катящимся списком.
- `placePull` — только при `at !== pullFromAt`. Сегодня `follow` пишет и при переходе `null → 0`, когда 0 уже стоит.

## 2. Старт тяги — «липкий» для касаний вне списка

- Касание вне списка (грип, заголовок): первый старт, поставленный в касании, держится до конца касания. Без сброса
  и без нового старта при развороте пальца.
  - Если старт взведён до касания, JS ничего не пишет.
  - Если NOT_PULLING (список прокручен, тяга за грип), старт ставится один раз, на первом движении, которое услышал
    JS. Это догон, его снимет шапка (§7).
- Касание на списке — как сейчас: при развороте ставится новый старт, отрицательный (`drag.ts`) тоже.
- Реализация — параметр `sticky` у `listPullStart`, чистая функция с тестами в `drag.test.ts`.
- `onList` в ветке BEGAN не читать. На Android `onTouchStart` списка (Fabric) обычно приходит после BEGAN (device-событие).
  В `follow` и `onListScroll` он надёжен.
- Короткий тап, чей START пришёл после `onFinish`, не должен пометить следующее касание. Способ выберу в реализации
  по исходникам часов событий. Если надёжного нет — оставлю как сейчас и запишу в «Остаётся».

## 3. Отпускание — все концы касания (END / CANCELLED / FAILED)

Порядок (CONFIRMED, п. 4–7 ревью):
1. `shownStart = pullFromAt`.
2. `travel` — путь пальца, который показан на экране:
   - Android: значение своего `addListener` на `gestureY`. Это `onAnimatedValueUpdate`, тот же канал, что смена
     состояния RNGH, поэтому на END оно равно нативному. Резерв — `END.translationY`, у которого ни одного move нет
     (PLAUSIBLE);
   - iOS: `lastMove`.
   `shownPull = shownStart === NOT_PULLING ? 0 : max(0, travel − shownStart)`.
3. Только на END — решение «закрыть / вернуть»:
   - `decisionStart = listPullStart(...)` — чистый вызов, без `placePull` и записей Animated;
   - `rerunPull = max(0, END.translationY − decisionStart)`, 0 при `null`;
   - `decisionPull = restingDrag + max(shownPull, rerunPull)`.
   `restingDrag` — JS-значение `drag` из своего listener'а на `drag`, 0, если ничего не пришло. Оно точное:
   `setOffset` / `flatten` обновляют JS `_value`, а после стопа на BEGAN его синхронизирует колбэк остановки.
   Без `restingDrag` лист, подхваченный на 80 px и дотянутый за 0,3H, вернулся бы назад (18 из 44 тяг замера).
   У листов без списка решение не меняется.
4. Фолд одним тактом, в таком порядке:
   `drag.stopAnimation(); drag.setOffset(shownPull); drag.flattenOffset(); pullFrom = NOT_PULLING; gestureY.setValue(0);`
   `pullFrom = 0`, если список у верха или его возвращают к верху (п. 5).
   - На iOS `setOffset` / `flatten` уходят одним блоком с флашащимся `pullFrom = NOT_PULLING`. Все промежуточные
     состояния равны `d + S` при любом знаке старта.
   - На Android это не атомарно, но кадра `|p|` и мёртвой зоны нет.
   - Отрицательный старт не ограничивать: правка 033 «старт ≥ 0» снимается.
   - Фолд считает, что `drag ≥ 0`: у листа со списком `drag` пишут только пружина (SETTLE, `bounciness: 0`, без
     перелёта) и фолд, поэтому резина не участвует.
5. Тяга, начатая на списке (`onList` и старт был): список к верху (`toTop`), безусловно, и `settling = true`.
   - Список отдаёт свой `toTop` в `SheetListLink`.
   - На Android команда `scrollTo` сначала зовёт `abortAnimation()` и тем гасит флинг. Гасит ли iOS торможение — покажет
     замер.
6. Дальше, без условий:
   - END и закрытие по `decisionPull` → закрытие с hold-check;
   - иначе пружина `drag → 0`;
   - при `!visibleRef.current` — только фолд, без пружины.
   - CANCELLED / FAILED из ACTIVE (`oldState` есть в событии: `enabled = false`, системный ACTION_CANCEL) — фолд и
     пружина, без закрытия.
   - FAILED / CANCELLED из BEGAN (тап) — путь 0, пружина `drag` с места.
   Иначе отказанное закрытие, а за ним тап оставят лист внизу.
7. `onFinish`.
- Колбэк `start` пружины при `!finished` — без побочных эффектов: никаких `placePull` и `onFinish`. Пружина `pullFrom`
  и флаг `springing` удаляются.
- Шаг перерасчёта передачи («после перезапуска» в 032) убирается. Сегодня `follow` на END пишет `pullFrom` до фолда:
  при флике со прокрученного списка это кадр с листом на 120 px ниже.

## 4. settling (заменяет правку 1 из 033)

Флаг «до первого scroll-события после END» неверен (PLAUSIBLE):
- на iOS `scrollTo(animated:false)` сам синхронно шлёт `scrollViewDidScroll` и `onMomentumScrollEnd` на 0;
- на Android флинг идёт 1–3 кадра до abort.

Правило:
- Пока `settling`, событие с offset > 0 → ещё раз `toTop`; `listY` и `pullFrom` не трогать. `isPulled()` возвращает
  true и при `settling`, это то же прижатие, что в `useSheetListProps`.
- Флаг снимается на событии с offset ≤ 0 (тогда `listY = 0` и взвод по §1), на следующем BEGAN, при открытии и при
  закрытии.
  - Без сброса при открытии флаг, оставшийся после свайп-закрытия, прижал бы `scrollToChecked`, и лист открылся бы
    сверху.
- `onMomentumScrollEnd` как сигнал не годится: iOS шлёт его на каждый `toTop`.

Источник случая «список на 1–15 px ниже» — два пути, оба от JS-записи незадолго до отпускания:
- (а) флинг самого ScrollView на ACTION_UP: его VelocityTracker видит сдвиг листа как прыжок пальца вверх;
- (б) незакреплённые поздние события.

Какой из них главный, покажет замер (§9). При нативной тяге у верха список видит почти 0 относительного движения,
поэтому после этой схемы случай должен почти уйти сам. `settling` — страховка.

## 5. BEGAN

- Scrollable: `drag.stopAnimation()` — всегда, без флага «пружина идёт» (CONFIRMED). Без анимации он ничего не делает
  ни в JS, ни в native. С флагом новая пружина, запущенная поверх старой, сбросила бы флаг в колбэке старой. Тогда
  flatten под живой пружиной затёрся бы, и лист прыгнул бы вверх на весь путь.
  - Тест «без пружины — без стопа» проверяю по моку `NativeAnimatedModule`, а не по флагу.
- Все листы: сбросить hold-check. Сейчас он сбрасывается только у scrollable, и только пропуском пресета.
- Снять `settling`. Больше на BEGAN ничего не пишется: пресета `gestureY` / `pullFrom` нет.

## 6. Android: JS-синк-коммит от стопа (PLAUSIBLE, сначала замер)

Пустой listener на `gestureY` из 033 (правка 4) снимается: RN уже вешает такой listener сам (`createHandler` →
`createAnimatedPropsHook`).

Реальный риск — другой:
- колбэк остановки на BEGAN вызывает `node.update()` и коммит JS-значений примерно через 2 кадра после касания;
- если коммит обгоняет нативный `gestureY`, будет кадр отката на 5–20 px при быстром повторе.

Проверка — строкой протокола §9. Оба обхода не публичные, поэтому в код только после подтверждения и с решением
владельца:
- `isLooping: true` в конфиге пружины;
- флаг `overrideBySynchronousMountPropsAtMountingAndroid`.

Также после замера: парковка прямыми опами `pullFrom.setOffset(NOT_PULLING − pullFromAt); flattenOffset()`.

## 7. Шапка — решает владелец (рекомендация рецензента и моя: отдельным шагом после замера этой схемы)

Схема рецензента записана для того шага:
- шапка и тело — два соседних `PanGestureHandler` под листом, не вложенные;
- у шапки своё значение `headerTravel` (native `Animated.event`):
  `translateY = slide + rubber(drag + headerTravel) + listPull`;
- END шапки: `drag.stopAnimation(); setOffset(T); flattenOffset(); headerTravel = 0`, где `T = END.translationY`;
- тем же путём — листы без списка: уйдёт их прыжок при повторном захвате;
- цена средняя: слот заголовка в `BottomSheet`, перенос заголовков `LanguageSheet` и `CountryPickerSheet`, тесты.

## 8. Попутно в этой задаче — `scrollToChecked`

Сейчас `y − rowHeight` предполагает одинаковые строки. Но строка «Язык устройства» с подсказкой — 61 dp, а строка
без подсказки — 54. Когда выбран English на телефоне с другим поддерживаемым языком, лист открывается на 7 dp ниже
верха. Тогда первая тяга каждого такого открытия попадает в случай 3.

Правка: прокручивать к верху предыдущей строки, по её `y` из `onLayout` строк; для English это 0. Тест — на разной
высоте строк.

## 9. Тесты (дополнение к 033; Jest не видит нативных пачек)

- Старт −40 (разворот), отпускание: положение до и после фолда одно и то же.
- Тяга с прижатием и стартом 60, затем scroll-событие 0: `pullFrom` остаётся 60.
- `END.translationY` меньше старта: до фолда ни одной записи `pullFrom`.
- Два и больше scroll-событий > 0 после END: список на 0, зеркало не тронуто, флаг снят на событии 0.
- Свайп-закрытие со списка и повторное открытие: первое событие 300 не прижато.
- CANCELLED из ACTIVE: фолд и пружина, без закрытия. При `!visible` — фолд без пружины.
- Отказанное закрытие, затем тап: пружина идёт.
- Повторный захват на 80, тяга до 0,3H: закрытие (`restingDrag`).
- Липкий старт на грипе: разворот не ставит новый старт.
- BEGAN без пружины: нет `stopAnimation` в моке native-модуля.
- `scrollToChecked` при English: прокрутка к 0.
- Прежние: передача, гонка END, прижатие, тап по строке, guard на v3.

## 10. Протокол замера (A50: Android 11, SDK 30, плотность 2,625; slop и min fling записать)

| строка | цель |
|---|---|
| у верха, свежее касание | дрожь > 3 px — ≤ 10% тяг |
| повтор < 0,3 с, отпущен на ~20 и ~80 px | лист под пальцем, без прыжка |
| повтор < 0,3 с с немедленным быстрым движением | нет однокадрового отката сразу после подхвата (§6) |
| касания, начатые со списком не у верха | (а) доля после тяги ~0; (б) дрожь не хуже сегодняшней (~17 px, макс 63) |
| источник случая 3 | `velocity.y` в `onScrollEndDrag`, offset на следующем BEGAN |
| шапка сразу после открытия | записать выбранную строку и язык телефона |
| отпускание на ходу вверх | нет прыжка вниз |
| точка отпускания | лог `END.translationY`, значение listener'а, `lastMove` — медленно, обычно, флик |
| повтор на 80, тяга за 0,3H | закрывается |

iPhone:
- свежее касание у верха;
- повтор < 0,3 с (~20 и ~80 px);
- список на 5 и 12 px ниже верха;
- отпускание на ходу вверх;
- разворот на коротком списке CountryPicker (старт < 0).

## Остаётся

- **Список на L > 0, даже 1 px.** Подхват идёт через JS `follow`, и такое касание ведёт себя как сегодня: прыжок
  ≈ v × 1–2 кадра плюс дрожь списка того же размера. Схема делает такие касания реже, но не лучше.
- **Тяга за грип при прокрученном списке** — догон, пока у шапки нет своего жеста (§7).
- **iOS:**
  - вся тяга через JS;
  - стоп пружины — круг через JS: за кадр задержки лист проезжает под неподвижным пальцем. Отпущен на 21 px,
    подхват через 50 / 100 мс — 2,8 / 1,7 px; отпущен на 79 px — 10,5 / 6,3 px;
  - нативная тяга — отдельный эксперимент под флагом, с защитой от эха `gestureY = 0`.
- **Android:** фолд не атомарен (замер).
- **Тяга, активированная раньше, чем дошли опы фолда** (≤ 2–3 кадра после отпускания), теряет первый путь
  (PLAUSIBLE).
- **Повторный захват, который так и не тянет**, держит лист на месте подхвата до отпускания. Это обычная прерываемая
  анимация.
- **Вне 033:** каждый рендер `BottomSheet` строит новый граф Animated и заново подключает событие жеста. Мемоизация —
  отдельным шагом.
- **Полное решение** — логика на UI-потоке (Reanimated) после обновления RN.
