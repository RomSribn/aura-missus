# AURAT-0158-032 — spec: тяга листа со списком без JS в момент подхвата

Дата: 2026-11-05. Замер рецензента на A50 (develop `1ec88fc`, 75 с, 44 живые тяги владельца):

| случай | тяг | дрожь > 3 px | обычно | макс |
|---|---|---|---|---|
| список ровно у верха, свежее касание | 10 | 3 | ~12 px | — |
| повторная тяга < 0,3 с после отпускания (идёт пружина) | 18 | 16 | ~21 px | 79 px |
| список не у верха на 1–15 px | 15 | 12 | ~17 px | 63 px |

Синтетические медленные свайпы — чисто. Причина во всех трёх: JS на критическом пути (пресет на BEGAN не успевает
к первым нативным движениям живого пальца; во время пружины пресет пропускается; при `listY > 0` пресета нет).
Владелец: переделать так, чтобы в момент подхвата JS не было. Схема — рецензента, с моими поправками (*).

## Формула (без изменений)
Сдвиг листа = slide + drag + max(0, gestureY − pullFrom). `gestureY` — путь пальца от активации (native на Android,
JS-событие на iOS). Меняется только, кто и когда пишет `drag` / `gestureY` / `pullFrom`.

## Кто пишет pullFrom — по состояниям

| состояние | pullFrom | кем |
|---|---|---|
| открытие | список у верха → 0 (взведён) | эффект открытия; `gestureY = 0`, `drag = 0` |
| простой, касание до активации | повторяет список: `listY <= 0` → 0, `> 0` → NOT_PULLING | `onListScroll`, только при изменении |
| тяга активна, передача со прокрученного списка | старт = последний путь пальца | JS `follow`, как сейчас |
| тяга активна, палец выше старта | не трогать (clamp держит 0) | — |
| тяга активна, касание **на списке**, список ушёл от верха (не прижат) | NOT_PULLING | `onListScroll` |
| отпускание | по списку: 0 / NOT_PULLING; `gestureY = 0`; `drag = P` | `onDragState`, один такт |

Пресет на BEGAN убирается. На BEGAN ни `gestureY`, ни `pullFrom` не пишутся.
* (поправка) Парковка при уходе списка от верха во время тяги — только если касание началось **на списке**: при тяге
  за грип / заголовок список может ещё катиться после флика, и парковка оборвала бы тягу.

## Отпускание и возврат — через drag, без пружины pullFrom
- После перезапуска передачи по END: видимая тяга `P = caught + max(0, releasedAt − pullFromAt)`, где
  `releasedAt = max(END, lastMove)`, запаркованный `pullFrom` даёт 0. Закрыть / вернуть — по `P`.
- В одном JS-такте: `drag = P`, `gestureY = 0`, `pullFrom` по списку — лист на месте (проверено: записи одного такта
  уходят одной пачкой `queueAndExecuteBatchedOperations`).
- Дальше — как у листов без списка: закрытие или пружина `drag → 0`; hold-check как был. `springing` и пружина
  `pullFrom` удаляются.

## Повторная тяга во время пружины
- BEGAN (только scrollable): `drag.stopAnimation(v => caught = v)` — лист замирает где стоит; `pullFrom` и `gestureY`
  взведены с отпускания, так что лист с первого нативного движения = caught + путь.
- * (поправка) `stopAnimation` при native driver отдаёт значение асинхронно (`NativeAnimatedAPI.getValue`). Если касание
  отпущено раньше, чем пришло `caught`, расчёт отпускания ждёт его (отложенный вызов) — иначе `drag = P` без `caught`
  дал бы прыжок.
- Тап во время пружины: остановка → отпускание с `P = caught` → пружина `drag → 0` продолжается с места.
- `caught` сбрасывается в `onFinish` и при открытии.

## Остаётся (известно)
Передача со всерьёз прокрученного списка и тяга за грип при прокрученном списке — через JS, небольшой догон (его
гасит прижатие для списка). Полностью — логика на UI-потоке (Reanimated) после обновления RN.
Листы без списка, прижатие (`isPulled = onList && pullStart !== null`), `panActive`, перезапуск на END — без изменений.

## Тесты
Простой: прокрутка > 0 → запаркован, к 0 → взведён. Android: BEGAN без `setValue`; нативная запись `gestureY = 9`
→ +9 до и после JS. До активации: вверх → парковка, к верху → снова взведён. Отпускание: положение до и после END
одинаково, дальше пружина `drag`, решение по `P`. Повторная тяга во время пружины: остановка, caught + путь, `P`
включает caught; отпускание раньше `caught`. Закрытие при катящемся списке — без прыжка. Тяга за грип при катящемся
списке не обрывается. Прежние: передача, гонка END, прижатие, тап по строке.

Цель замера после мёржа: дрожь > 3 px в ≤ 10% тяг у верха, без прыжка при повторной тяге.
