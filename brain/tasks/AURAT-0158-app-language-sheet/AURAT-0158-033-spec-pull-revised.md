# AURAT-0158-033 — spec revised: тяга листа со списком (ревью схемы 032)

Дата: 2026-11-05. Рецензент (по исходникам RN 0.85.3 / RNGH 3.0.1): свежее касание у верха на Android 032 закрывает,
два из трёх замеренных случаев — нет. Схема 032 с правками ниже; остальное в 032 — в силе.

**Поправка к 032:** «записи одного такта уходят одной пачкой» — неверно и снимается. При наших флагах
(`animatedShouldUseSingleOp = false`, `cxxNativeAnimatedEnabled = false`) каждый `setValue` — свой вызов
(`NativeAnimatedHelper.js`, проверено мной); на iOS offset-операции едут со следующей флашащейся.

## Правки схемы
1. **Список на 1–15 px ниже верха** (12/15 в замере). Источник — предыдущая тяга: END обгоняет scroll-события, `onFinish`
   снимает прижатие, поздние события оставляют список чуть ниже верха. При отпускании тяги, начатой на списке, —
   вернуть список к верху (`toTop`) и держать прижатие до первого scroll-события после END (флаг `settling`, снимается на
   нём или на следующем BEGAN). Остаток случая — в «Остаётся» со своей целью на замере.
2. **Без `caught` / `getValue` / отложенного отпускания** (на iOS `getValue` сам не флашится — `caught` мог не прийти до
   следующего свайпа). Вместо этого нативный фолд:
   - BEGAN (scrollable): `drag.stopAnimation()` без колбэка и только если пружина `drag` идёт (флаг ставится в `settle`,
     снимается в колбэке её `start`);
   - отпускание: `drag.setOffset(показанный путь)` → `drag.flattenOffset()` → `gestureY = 0` → `pullFrom` по списку →
     пружина `drag → 0` или закрытие. Native flatten — value += offset без изменения вывода; setOffset анимацию не
     останавливает; нативная пружина стартует с текущего нативного значения;
   - тап (FAILED из BEGAN): путь 0 — просто перезапустить пружину `drag`; `onFinish` — сразу.
3. **releasedAt по платформе:** Android — `END.translationY` (там `lastY` обновлён до END, а JS-`lastMove` старше);
   iOS — `lastMove` (= JS-`gestureY`).
4. (PLAUSIBLE) Android: конец нативной анимации вызывает синк-коммит с JS-значениями, JS-`gestureY` = 0 → кадр отката.
   Пустой listener на `gestureY` (Android, scrollable), чтобы JS-значение следовало за нативным.
5. **Порядок записей фолда:** `setOffset` / `flattenOffset` до `gestureY = 0` (iOS — offset едет со следующей); `pullFrom`
   после `gestureY = 0` невидим, только если старт ≥ 0 — старт листа ограничить снизу 0. Android — без обёртки
   `setWaitingForIdentifier` (приватное API); риск принимается и замеряется.
6. **Шапка (решает владелец).** Лист языка открывается прокрученным к выбранному языку, так что «грип при прокрученном
   списке» — его обычное состояние. Вариант: у шапки (грип + заголовок) свой `PanGestureHandler` с native
   `Animated.event` в `drag`, как у листов без списка — без JS при любом положении списка.
7. **Палец выше старта:** для касаний на списке — как сейчас (`follow`, новый старт в точке разворота; разворот внутри
   касания — остаток JS); для касаний вне списка — держать исходный старт.
8. **Hold-check:** на BEGAN сбрасывать таймер hold-check — иначе он запустит пружину под пальцем повторного захвата.
9. **Перезапуск передачи на END:** фолдить по показанному пути (`pullFromAt` до перезапуска); перезапуск — только для
   решения «закрыть / вернуть».
10. **iOS** — вся тяга по-прежнему через JS (`list-pull`, native = false): в «Остаётся».

## Тесты (Jest не видит нативных пачек и порядка каналов)
JS: END < lastMove (Android) — положение до и после фолда одно; BEGAN при идущем фолде; разворот на грипе и на
списке; scroll после END тяги за список → список на 0, взведён; hold-check при повторном захвате; нет `stop` /
`getValue` без идущей пружины; прежние.
Протокол на устройстве, цель для каждого: у верха свежее; повтор < 0,3 с; список на 5 и на 12 px ниже верха; шапка
сразу после открытия; отпускание на ходу вверх; iOS — тап, затем свайп.

## Остаётся
Передача со всерьёз прокрученного списка и разворот пальца внутри касания на списке — через JS; iOS — вся тяга через
JS; Android-фолд не атомарен (замер). Полностью — логика на UI-потоке после обновления RN.
