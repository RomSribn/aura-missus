## 1. Метка платной сессии

**Имя: `paid-session`** (вместо «payed»: правильное английское *paid*, kebab-case как
требует формат меток Chatwoot). Цвет `#F5A623` (янтарный, заметен на карточке),
`show_on_sidebar: true`, описание «Paid session running now. Set and cleared by Aura
automatically — do not edit».

**Правило:** метка на диалоге ⇔ у диалога есть сессия `ACTIVE`. Вычисляется в той же
точке, что и атрибуты (`syncState` → `syncSessionState`, статус `active`), т.е.:
- start (по таймеру или «начать сейчас») → `announce started` → метка **ставится**;
- extend → `sync`, статус всё ещё `active` → метка **остаётся**;
- finish (выработан, досрочно), cancel → `announce finished` / `sync` → **снимается**;
- booking/reschedule будущего слота → `scheduled`/`none` → метки нет.

**Запись, не затирая чужие метки** (эндпоинт заменяет весь набор):
`GET /conversations/:id/labels` → если желаемое уже выполнено — **ничего не пишем**
(большинство синков — no-op) → иначе `POST` полного списка = текущие ± `paid-session`.

**Гонки (принимаем, документируем):**
- Чаттер меняет метки в ~100 мс между нашим GET и POST — его правка теряется. Окно
  крошечное и бывает только в момент start/finish (запись только при смене). Атомарного
  «добавить метку» в API Chatwoot нет.
- Чаттер вручную снял `paid-session` посреди сессии — вернётся при следующем синке этого
  диалога (extend/finish), не мгновенно. Повесил вручную без сессии — снимется при
  следующем синке. Метка «наша», это сказано в её описании.

**Побочка Chatwoot:** каждое изменение метки рисует в ленте диалога серую строку
«<сервисный юзер> added/removed paid-session». Видна только чаттерам (на устройство не
уходит — нормализатор отбрасывает активности). Отключить через API нельзя; заодно это
аудит. Маркеры «session started/finished» остаются как есть.

Метки по адвайзорам — не делаем (решение владельца).

## 2. Кастомные атрибуты диалога и их definitions

Ключи существующих атрибутов **не меняем** (только дописываем definitions). Порядок —
порядок показа в панели.

| Ключ | Подпись в панели | Тип | Значение | Почему этот тип |
|---|---|---|---|---|
| `advisor_name` **(new)** | Advisor | text | `Olivia Flores` | поиск «contains» |
| `advisor_category` **(new)** | Advisor category | list: `love`, `tarot`, `psychic` | `psychic` | фильтр «равно» выпадающим списком |
| `advisor_role` **(new)** | Advisor role | text | `Psychic Reader · Medium` | — |
| `advisor_price_per_minute` **(new)** | Advisor price, $/min | number | `3.20` | `currency` в фильтре Chatwoot не поддержан (падает) |
| `aura_session_status` | Session status | list: `active`, `scheduled`, `none` | как сейчас | фильтр «равно» |
| `aura_session_starts_at` | Session starts (UTC) | text | `2026-10-12 14:30 UTC` | см. ниже |
| `aura_session_ends_at` | Session ends (UTC) | text | `2026-10-12 15:00 UTC` | см. ниже |
| `aura_paid_minutes_total` | Paid minutes total | number | `45` | фильтр больше/меньше |
| `advisor_id` | Advisor ID | text | `olivia` | технический, в конце |

Не берём из `advisors`: tagline, bio, specialties, greeting, avatar, rating/reviews —
длинные тексты или маркетинг, чаттеру в боковой панели не нужны.

**Время начала/конца — `text`, а не `date`** (рекомендую): тип `date` в панели
показывает **только дату** (время сессии теряется), а при нашем пустом значении `''`
ломает весь фильтр в Postgres. Поэтому `text` в читаемом виде «YYYY-MM-DD HH:mm UTC» (как
в заметке `AURAT-0084`). Фильтровать по времени не получится — для фильтра есть
`paid-session` и `Session status`. Сейчас значение — сырой ISO
(`2026-10-12T14:30:00.000Z`); формат меняем, кроме BFF его никто не читает. Неприменимые
значения перестаём слать пустой строкой — **ключ опускаем** (панель покажет `---`).

**Цена** — текущая цена адвайзора из каталога (что клиент заплатит за следующий блок), а
не цена брони. Строкой с двумя знаками из целых центов (`320 → "3.20"`), без float.
Если строки `advisors` нет (адвайзор снят) — адвайзорские ключи опускаем, `advisor_id`
остаётся.

**Когда пишутся:** при создании диалога (`createConversation` — сразу advisor-блок +
`aura_session_status: none`, `aura_paid_minutes_total: 0`) и при каждом синке сессии
(полный хеш, как сейчас). Правка/стирание значения чаттером переписывается при
следующем событии (read-only флага в Chatwoot нет) — принимаем.

**Где живёт код:** всё — в адаптере `chatwoot` (build rule 1). `ChatwootMessagingService`
сам читает адвайзора через `AdvisorsRepository` (chatwoot импортирует `AdvisorsModule`,
цикла нет); порт `syncSessionState` и `SessionsService` по сигнатуре не меняются. Метка —
там же, константа адаптера, не env.

## 3. Бутстрап (метка + definitions) и бэкфилл — одна операторская команда

`npm run desk:setup` (в проде `node dist/desk-setup.js`), по образцу
`contacts:push-names`, на `OperatorCliModule`. Аккаунт — из `CHATWOOT_ACCOUNT_ID`
окружения (prod — 1, dev — 2), так что одна команда на окружение. Идемпотентна:

1. **Метка:** `GET /labels` → нет `paid-session` — создать; есть, но расходится
   цвет/описание/`show_on_sidebar` — обновить (`PATCH /labels/:id`).
2. **Definitions:** `GET /custom_attribute_definitions?attribute_model=conversation_attribute`
   → недостающие создать; у существующих с нашим ключом выровнять подпись/описание/
   список значений (`PATCH`). Тип у существующего definition, если вдруг расходится, —
   тоже выровнять. Чужие definitions не трогаем.
3. **Бэкфилл:** поставить в очередь синк **для каждого диалога** из нашей таблицы
   `conversations` (новый job `sync-conversation {conversationId}` в очереди сессий;
   `syncState` по сессии сводится к нему). Воркер приложения пересчитывает состояние из
   БД и пишет атрибуты + метку. Так:
   - старые диалоги получают advisor-блок и человеческие даты;
   - диалоги с идущей сейчас сессией получают `paid-session`;
   - переименование адвайзора / смена цены в каталоге лечится повторным запуском.

Почему не на старте приложения: старт не должен зависеть от доступности Chatwoot и прав
администратора, а бэкфилл нужен один раз; команда — тот же подход, что у остальных
операторских действий. Без запуска команды метка всё равно вешается (просто без цвета и
пункта в сайдбаре), атрибуты пишутся, но не видны — значит, команда входит в чек-лист
релиза (dev, потом prod).

Нагрузка бэкфилла: N диалогов × (1 POST атрибутов + 1 GET меток [+ 1 POST]) через
очередь с её обычной конкурентностью — для текущих объёмов несущественно.

## 4. Тесты (slave — только pure unit)

- адаптер: желаемый набор меток — добавить, не дублировать, снять, не трогать чужие,
  no-op без POST; полный хеш атрибутов с advisor-блоком; адвайзор не найден; форматы цены
  (`320→"3.20"`, `5→"0.05"`) и времени UTC; опускание неприменимых ключей;
- `createConversation` пишет advisor-блок;
- `syncState` по сессии → тот же путь, что `sync-conversation`;
- бутстрап: создаёт недостающее, выравнивает расходящееся, повторный запуск ничего не
  пишет, чужие definitions/метки не трогает;
- CLI: отказ на лишних аргументах (как `contacts:push-names`).
Живая проверка (метка в списке/сайдбаре, панель, фильтры по label / status / price /
category, бэкфилл) — в маноре на dev (аккаунт 2) после мержа.
