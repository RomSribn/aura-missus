## A. Повтор отпускается строкой первого, а не записью его кэша

- **Удержание ключа на всю отправку.** У отправки с `idempotencyKey` и включённым переводом `forDesk` берёт
  удержание: `SET chat-translation:desk-busy:<sha(conversation, key)> <token> PX (totalMs + 130 с) NX`. Это до
  перевода.
  - Ключ — без текста: повтор — то же сообщение.
  - 130 с покрывают пост с загрузкой (`UPLOAD_TIMEOUT_MS` 120 с). Удержание, брошенное умершим процессом, истекает
    само.
- **Снятие** — `DeskTranslation.release()`. `ChatService.sendMessage` зовёт её в `finally`: после upsert и
  постановки заметки, а также при отказе поста или раннем ответе по ключу.
  - Снимает только своё удержание: сверяет `token`, перехваченное после истечения не трогает.
  - Bounded, не бросает.
- **Ждущий** (удержание чужое) раз в 200 мс спрашивает `findByIdempotencyKey`:
  - строка появилась → `none`; отправка проверяет ключ ещё раз и отвечает строкой первого без поста;
  - удержание снято без строки (первый упал) → берёт его сам, сразу;
  - кончился собственный срок → `note` (п. B).
- **Кэш перевода больше не отпускает ждущего:** его читает только тот, кто держит удержание.
- **P2002 по частичному индексу `(conversationId, idempotencyKey)`** в `upsertByChatwootMessageId`:
  - если по `chatwootMessageId` строки нет, ищется строка по ключу;
  - найдена → `{ record: победитель, inserted: false }` вместо 500;
  - отправка отвечает строкой победителя;
  - сверка на незаписанном дубле больше не падает: та же ветка отдаёт `inserted: false`, проход идёт дальше.
- Без Redis удержания нет (`held`, снимать нечего): поведение — как до задачи.
- **Тесты:**
  - ждущий отпускается строкой — один вызов модели, без поста;
  - запись кэша первым его **не** отпускает (500 мс без ответа);
  - снятие — после upsert, а также при отказе поста и при раннем ответе;
  - чужое удержание не снимается;
  - репозиторий: P2002 по ключу → строка победителя; дубль того же сообщения стола по-прежнему находится по
    `chatwootMessageId`; без ключа — бросает.

## C. Пробой становится только вызов с почти полным сроком

- `breaker.admit(timeout, waitUntil, mayProbe)`. В `translate()`:
  `mayProbe = left() ≥ (timeoutMs вызова или профиля) − PROBE_POLL_MS`.
  - Без `totalMs` (кампании, задачи чата) — всегда.
  - Отправка — только пока у неё есть почти весь срок.
  - Остальные лок не берут: ждут чужую пробу до `waitUntil` и получают повторяемый отказ без оплаты.
- **Тесты:**

    повторяемый, 0;
