## Из живой проверки

8. **Статус и категория ошибки в лог.**
   - У `TranslationUnavailableError` новое поле `detail: { status?, errorType? }`.
   - `claudeErrorDetail` берёт `error.status` и `error.type` SDK. Категорию — только как snake_case до 64 знаков;
     `message` не берётся никогда.
   - Строка `translation` (`failed`) несёт `status`, `errorType`.
   - Тесты: 400 `invalid_request_error`, 529 `overloaded_error`, соединение без деталей, сообщение провайдера в
     `detail` не попадает.

   **Дополнение — время раздельно.** Строка `translation` теперь несёт:
   - `waitMs` — слот, бюджет, предохранитель и ожидание пробы;
   - `callMs` — только вызов провайдера, по нему считается p95 задачи 6;
   - `ms` — всё вместе, как раньше.

   Тест на обе строки, `translated` и `failed`.
9. **Проба предохранителя — выбран первый вариант: ждать итога пробы.**
   - `TranslationBreaker.admit(timeout, waitUntil)`: пока проба в полёте, вызов раз в 250 мс спрашивает Redis:
     - проба закрыла предохранитель → вызов идёт;
     - проба открыла снова → отказ с её причиной;
     - проба кончилась без решения (429) → лок свободен, вызов пробует сам;
     - после `waitUntil` → отказ, как раньше, повторяемый.
   - `waitUntil` в `translate()`:
     - без `totalMs` — `now + timeoutMs`;
     - с `totalMs` — `started + totalMs − MIN_CALL_MS`.
   - Если ожидание съело остаток, проба отдаёт лок (`breaker.release`) и вызов кончается `timeout`, 0.
   - Для чата: ответ советника в окне пробы ждёт её итога. Если не дождался — отказ повторяемый, задача повторит.
     Окончательный `FAILED` — только после последней попытки.
   - Тесты:
     - старый «остальные получают отказ» переписан: три параллельных после паузы → все три переведены, одно
       «restored»;
     - проба провалилась → ждущий получает её причину и до провайдера не доходит;
     - отправка с `totalMs` 1,5 с не ждёт пробу дольше своего срока.
   - Кампании (`AURAT-0192`) получают это без правок своего кода.

## 10. Правка кода `AURAT-0196`: `recordSendLanguage` с предельным сроком

**Причина.** Тот же путь отправки и тот же класс дефекта, что п. 1. `ChatSettingsService.recordSendLanguage` при смене
языка ждал `contactAttributesQueue.add` без срока. Соединение очереди повторяет бесконечно
(`maxRetriesPerRequest: null`), поэтому при сбое Redis отправка висела ещё до перевода.

Координатор: «recordSendLanguage (0196) — правь здесь, в 0198 … Больше ничего не трогай».

**Правка** (`src/modules/profile/chat-settings.service.ts`): `contactAttributesQueue.add` обёрнут в `bounded` (1 с) —
как `enqueueDeskNote`. Сбой и превышение срока по-прежнему только в лог: копия языка на столе не стоит зависшей
отправки.

**Тест** (`chat-settings.service.spec.ts`): «add никогда не завершается → `recordSendLanguage` возвращается меньше
чем за 3 с».
