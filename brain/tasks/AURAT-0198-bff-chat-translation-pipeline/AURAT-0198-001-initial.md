# AURAT-0198-001 — initial (заглушка)

Дата: 2026-11-08
Репо: `aura-bff`. Выдан координатором (сессия «Локализация i18n для aura-app»). Фича `AURAF-0024`, задача 5 разбивки
`AURAI-0012` — конвейер перевода сообщений чата.

Владелец: «а когда будет работать перевод для чаттеров?» → на предложение координатора «Запустить задачу конвейера так:
два направления с отдельными выключателями, сначала «человек → чаттер»?» — «да, запускай конвейер».

## Что нужно

Два направления, **у каждого свой выключатель** (env, по умолчанию выключены), включаются по очереди — сначала
«человек → чаттер» (решение 8 `AURAI-0012`):

1. **Человек → чаттер (отправка):** сообщение человека переводится на `en` до `postUserMessage`; в Chatwoot —
   `content` = оригинал, `content_attributes.translations.en` = перевод (проверка стола 2026-11-07: пузырь показывает
   перевод, «View original» — оригинал, превью списка — оригинал). Кэш по `idempotencyKey`, `desk-note` при сбое,
   отправка не ломается ни при какой ошибке перевода (`AURAI-0012` §1.2).
2. **Чаттер → человек (приём):** строка советника пишется сразу; `MessageTranslation` (`messageId → Message onDelete
   Cascade`, `language`, `status`, `content?`, `engine?`, `@@unique([messageId, language])`); `pending` — в той же
   транзакции; очередь `chat-translation`, сторож в сверке; `message.translated` — через доставку из сохранённой строки,
   без пуша; `Message.translation` в `toDto` (история, `message.new`, сверка) — только у советника, без `engine`;
   `translatedFrom` → `translations` с пределом, как `DELETED_IDS_LIMIT` (`AURAI-0012` §1.3).

**Условие перевода (обе стороны):** `translationActive(user)` (`AURAT-0196`), `chatLanguage` не `null` и не `en`
(решение 4), язык не выключен `DISABLED_LANGUAGES` в момент перевода, профиль `chat` модуля перевода не `off`, выключатель
направления включён.

**Профиль `chat`** в `translation-config.ts` (модуль `AURAT-0191`): модель, бюджет, предохранитель, параллельность.
Модель и месячный бюджет чата — решения 1, 2 владельца (открыты): предложить в спеке; ключ — решение 9.

**Из ревью `AURAT-0197` (клиент, смёржен):**
- `failed` не должен быть вечным для догонки: клиент якорит `translatedFrom` на самом старом `pending | failed` —
  окончательный `failed` (сторож сдался) должен быть отличим от дозаполняемого (или иное решение — в спеке);
- порядок `HistoryResponse.translations` — «старые первыми», как `deletedIds` (JSDoc / OpenAPI).
