`012` — запись координатора о живой проверке. Она лежит в брейне манора, на этой ветке её нет.

## Пункты

1. **[главное, A] Ждущему кончается свой срок — и он постит копию, пока первый ещё держит ключ.**
   - `hold()` возвращает `note` по своему сроку (`now + totalMs`), хотя удержание живёт `totalMs + 130 с`.
   - Окна: (а) подпись с вложением: первый грузит файл десятки секунд, повтор приходит во время загрузки;
     (б) медленный перевод почти на весь срок плюс быстрый повтор.
   - Это противоречит п. A `010`. Фраза «истёк срок → note» из п. B писалась под старую схему с кэшем — промах
     координатора.
   - Правка: пока ключ держит другой, `hold()` не даёт `note` и не даёт постить:
     - появилась строка → `none`;
     - ключ исчез без строки → взять его → `held`.
   - Граница ожидания — срок жизни удержания с запасом, опрос с отступом (200 мс → ~1 с). Если граница всё же
     достигнута — warn и `none`.
   - `note` даёт только владелец удержания.
   - Тесты:
     - пост первого дольше `totalMs + 1 с` → один пост;
     - первый упал на посте → ждущий берёт ключ, перевод из кэша, второго вызова модели нет;
     - тест «600 мс → note» переписать.

   Обновить JSDoc `hold()` и фразу о PTTL в `011`.
2. **[low] Пост прошёл, upsert упал → `finally` снимает удержание → ждущий постит копию.** Если пост вернулся, а
   upsert бросил, удержание не снимается и истечёт само; строку запишет сверка. Тест.
3. **[low] Ошибка базы в `findByIdempotencyKey` внутри `hold()`** уходит во внешний `catch` → `none` → пост рядом с
   владельцем. Нужен `try/catch` вокруг опроса: ошибка значит «ещё нет». Тест.
4. **[low] Заметка на чужую строку.** При `note` и строке победителя (P2002 по ключу) — лишняя платная заметка.
   - Заметка ставится только для своего поста: `record.chatwootMessageId === posted.id`. Не по `inserted`: свою строку
     могла записать сверка.
   - Чужая строка → warn с `conversationId` и обоими id стола.
   - Тесты: чужая строка → заметки нет, release есть, warn есть; своя, уже записанная → заметка есть.
5. **[low] Таймаут `SET` в `hold()`** даёт `held` без снятия. Если `SET` всё-таки дошёл, удержание повиснет на 136 с.
   Нужно `release = giveBack(busy, token)`: сверка токена делает это безопасным. Тест.
6. **[low, repo] Ветка P2002 по ключу не смотрит направление.** Применять её только к сообщению человека, найденному
   у человека; иначе rethrow. Тесты: `findFirst → null` бросает; не-человек бросает.
7. **[low, C] Непробный вызов ждёт до `waitUntil`, даже когда пробы нет, и держит слот.**
   - Правка в `admit`: `!mayProbe()` и лока пробы нет → сразу отказ, повторяемый, с причиной `tripped`.
   - Тесты:
     - конфигурация чата (таймаут = `totalMs` = 3000): свежий вызов пробует и закрывает; после ≥ 300 мс в очереди
       лок не берёт и получает отказ за один опрос;
     - юнит брейкера: `() => false` лок не ставит, `() => true` ставит;
     - поправить «C: too little time left».
8. **[low, доки] JSDoc `timings()`:** `ms` — весь `translate()`, учёт после вызова включён.

**Не надо:** после захвата ключа перевод получает полный `totalMs`, и повтор может занять до ~2× срока. Это только
задержка, оставляем.

**К проверке в маноре:** две одновременные отправки одного сообщения с медленным постом (вложение с подписью) → один
пост, один вызов модели, один ответ, без 500 и без лишней заметки.
