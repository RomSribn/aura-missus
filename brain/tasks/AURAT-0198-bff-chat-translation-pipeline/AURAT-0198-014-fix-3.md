## 1. [главное] Ждущий не постит, пока ключ держит другой

`hold()` отдаёт теперь только два ответа:
- `held` — ключ взят этим запросом;
- `none` — найдена строка по ключу; отправка отвечает ею.

`note` из `hold()` больше нет: его даёт только владелец удержания, когда его перевод упал с повторяемой ошибкой.

Как ждёт:
- **Граница** — срок жизни удержания: `totalMs + DESK_POST_HOLD_MS` (130 с) + `DESK_HOLD_MARGIN_MS` (2 с). Свой
  `totalMs` больше не граница.
- **Опрос с отступом:** 200 мс × 1,5 до 1 с.
- Удержание снято без строки или истекло → `SET NX` его берёт → `held`. Перевод тогда берётся из кэша первого, если
  тот успел.
- Граница всё же достигнута (не должна) → warn без текста и `none`: пост как есть.

JSDoc `hold()` обновлён.

Тесты:
- первый держит ключ дольше `totalMs + 1 с` (срок 600 мс, ждём 1,6 с) → ждущий не ответил. Появилась строка →
  `none`, вызов модели один;
- первый упал на посте (снял удержание без строки) → ждущий берёт ключ, получает английский из кэша первого, второго
  вызова нет;
- тест «600 мс → note» удалён: он закреплял неверное поведение.

## 2. Пост прошёл, upsert упал — удержание остаётся

`ChatService.sendMessage` помнит `posted` и `stored`. В `finally` удержание снимается, только если ничего не
запостили (ранний ответ, отказ поста) или строка записана. Иначе оно истекает само, а строку под тем же ключом
пишет сверка из `source_id`; ждущий её находит (п. 1).

Тест: upsert бросает после поста → `release` не вызван, пост один.

## 3. Ошибка базы при опросе — «ещё нет»

Вокруг `findByIdempotencyKey` в цикле `hold()` стоит `try/catch`, опрос продолжается в той же границе.

Тест: `findByIdempotencyKey` бросает → через 500 мс ответа нет. Строка появилась → `none`.

## 4. Заметка — только к своему посту

- В `ChatService` заметка ставится при `desk = note` и только если `record.chatwootMessageId === posted.id`. Признак
  `inserted` не годится: свою строку могла записать первой сверка.
- Строка чужая (поглощённый дубль стола) → warn с `conversationId`, `postedChatwootMessageId`,
  `storedChatwootMessageId`, без текста. Ответ — DTO победителя.

Тесты:
- победитель с другим id стола, `inserted: false`, `note` → DTO победителя, заметки нет, `release` вызван, warn есть;
- своя строка, уже записанная (тот же id стола, `inserted: false`) → заметка ставится.

## 5. Таймаут `SET` удержания

В `catch` у `SET` возвращается `held` с `release = giveBack(busy, token)`, а не пустышка. Сверка токена делает это
безопасным: дошёл `SET` или нет.

Тест: `SET` не ответил в срок, но дошёл → после `release` удержания нет.

## 6. Ветка P2002 по ключу — только «человек к человеку»

`upsertByChatwootMessageId` ищет строку по ключу, только если записываемое — сообщение человека, и принимает только
строку человека. Иначе rethrow, как до `0198`.

Тесты репозитория:
- ключ есть, `findFirst → null` → бросает;
- записывается сообщение советника → бросает, `findFirst` не вызывается;
- ключ совпал со строкой советника → бросает.

## 7. Непробный вызов без пробы — отказ сразу

В `TranslationBreaker.admit`: если `!mayProbe()` и лока пробы нет, отказ сразу — повторяемый, с причиной `tripped`.
Слот семафора не держится зря.

Тесты:
- **брейкер:**
  - `() => true` ставит лок;
  - `() => false` лок не ставит и без пробы отказывает меньше чем за 100 мс;
  - `() => false` ждёт чужую пробу и проходит, когда она закрыла предохранитель;
- **конфигурация чата** (таймаут профиля = `totalMs` = 3000):
  - свежий вызов пробует и закрывает;
  - после 350 мс в очереди за слотом, без пробы → отказ меньше чем за 800 мс, адаптер не вызван;
- **«C: too little time left» поправлен:** `totalMs` 3000, `waitUntil` 2 с, лок освободился на 100 мс → отказ меньше
  чем за 1 с, на следующем опросе.
