# AURAT-0088-005 — Спек: SDK Meta на Android, три события

Дата: 2026-10-14
Тип: задача (без отдельного `AURAF`: объём закрыт, одна поставка)
Статус: **draft — ждёт решения владельца по D1 и Client Token**

## Что меняется в декларациях — сначала это

Задача делает ложными поданные заявления. Ниже — что именно, когда и кто.

| Где | Сейчас заявлено | Станет правдой после задачи | Когда переподать | Кто |
|---|---|---|---|---|
| Play → App content → **Advertising ID** | «Нет», AD_ID в манифесте нет | **«Да»**: AD_ID вливается из `facebook-core` (проверено в AAR 18.3.0). Цели: Analytics, Advertising or marketing | **В той же отправке**, что и первая сборка с SDK (versionCode 23+). Раньше — ложь в обратную сторону; позже — Play блокирует выпуск сборки с AD_ID при ответе «нет» | владелец, Play Console |
| Play → **Data safety → Data shared** | «Ничего» | **Device or other IDs** (рекламный ID), **App interactions** (события), **Purchase history** (сумма/валюта покупки) — передаются Meta, цель Advertising or marketing + Analytics | там же, одной отправкой | владелец |
| Play → Data safety → Data collected | эти типы есть, но без рекламной цели | добавить цели Advertising or marketing / Analytics к тем же трём типам | там же | владелец |
| Play → App content → **Ads** | «Нет» | **без изменений** — рекламы в приложении нет, мы её покупаем снаружи | — | — |
| Политика `aura-app.cc/privacy/` | Meta отсутствует | запись в списке третьих лиц: Meta Platforms — атрибуция рекламы установок на Android: рекламный ID, события регистрации/пополнения/покупки | до публикации сборки в Play | правка сайта (не этот репо) |
| **App Store → App Privacy** | 10 типов, **трекинга нет** | **без изменений — и это гарантируется кодом**, см. «iOS» ниже | не переподаётся | — |

**Порядок выпуска на Android:** политика обновлена → сборка 23 в internal →
проверка в Events Manager → в той же production-отправке: сборка + Advertising
ID + Data safety. Ни одна сборка с SDK не уходит в production при старых
ответах.

## iOS — что именно гарантирует «не тронут»

Не обещание, а три механизма:

1. **Нативно не линкуется.** `react-native.config.js`:
   `dependencies['react-native-fbsdk-next'].platforms.ios = null`. Следующий
   `pod install` не добавит `FBSDKCoreKit` — его privacy manifest заявляет
   трекинг-домены, и он сам по себе сделал бы App Privacy неверным.
   Проверка: `ios/Podfile.lock` и `project.pbxproj` в диффе не меняются.
2. **JS пакета на iOS не загружается.** Корневой `index` пакета на импорте
   создаёт `NativeEventEmitter` — на iOS без модуля это краш при старте.
   Поэтому пакет импортируется **только** из `attribution.android.ts`;
   `attribution.ts` (iOS и Jest) — пустые функции без импорта. Metro
   разрешает платформенный файл сам.
3. Ни ATT, ни `NSUserTrackingUsageDescription`, ни `Info.plist` не трогаются.

Обе загруженные сборки (`1.0.0 (2)` на ревью, `1.0.1 (3)`) собраны до ветки.
Будущие iOS-сборки из `develop` останутся честными по отношению к текущему
App Privacy. Атрибуция на iOS — отдельная задача (ATT + App Privacy + пакет
в Podfile).

## Что делается в коде

### 1. Пакет и Android-настройка
- `react-native-fbsdk-next@13.4.3` — точная версия, без `^`.
- `android/build.gradle` → `ext.facebookSdkVersion = "18.3.0"`: пакет
  по умолчанию тянет плавающий `18.+`, то есть сборка завтра ≠ сборка сегодня.
- `strings.xml`: `facebook_app_id = 4422398391357112`, `facebook_client_token`.
- `AndroidManifest.xml` → `meta-data` `com.facebook.sdk.ApplicationId`,
  `ClientToken`; `AutoInitEnabled`, `AutoLogAppEventsEnabled`,
  `AdvertiserIDCollectionEnabled` — через `manifestPlaceholders` от флага
  (п. 2). `AD_ID` **не** удаляем (`tools:node="remove"` убил бы атрибуцию),
  явно комментируем, откуда он и какую декларацию тянет — как уже сделано
  для `READ_EXTERNAL_STORAGE`.

### 2. Только prod шлёт в Meta
Новый флаг `AURA_META_ATTRIBUTION_ENABLED` (bool, по умолчанию `false` во всех
целях, как флаги биллинга). Включается в `aab:prod` / `apk:prod`. Без него:
SDK не инициализируется нативно (автоинит выключен в манифесте), JS-обёртка
ничего не вызывает. Иначе события с эмулятора и staging-APK попадут в
статистику, по которой Meta оптимизирует показы. Флаг документируется в
`env/README.md`.

### 3. Обёртка — `shared/lib/attribution/`
Публичный API из `@/shared`, три функции и больше ничего:
- `trackRegistrationCompleted()` → `AppEvents.CompletedRegistration`;
- `trackTopUpOpened()` → `AppEvents.InitiatedCheckout`;
- `trackPurchase({ creditedMinor, currency, sku })` →
  `logPurchase(creditedMinor / 100, currency, { fb_content_id: sku,
  fb_content_type: 'product' })`.

Файлы: `attribution.android.ts` (импорт пакета, проверка флага, `try/catch`
вокруг каждого вызова — аналитика не имеет права уронить оплату),
`attribution.ts` (no-op). Никакого `setUserID`, телефона, uid, purchaseToken —
Meta получает только рекламный ID (от SDK) и три события.

### 4. Точки вызова
- **Регистрация:** `use-create-account.ts`, после `saveProfile` = успех,
  перед `enterApp`. Оговорка: переустановивший без имени тоже проходит этот
  экран и тоже даст событие — редкий случай, принимаю.
- **Открытие пополнения:** `use-profile.ts`, на переходе `activeSheet` →
  `'topup'` (ловит оба входа: кнопку и `sheet: 'topup'` из пикера блоков).
- **Покупка:** `use-store-topup.ts` → `redeem()`, **после** успешного ответа
  BFF и `walletStore.setBalance`, только если `Platform.OS === 'android'` и
  `result.replayed === false`. Сумма — `result.creditedMinor`, валюта —
  `result.currency` (контракт: literal `"USD"`). Ответ магазина в событии не
  участвует ни одним полем, кроме SKU.

«Ровно один раз» держится на `replayed` из BFF: повторная доставка той же
покупки (листенер + свип незавершённых, перезапуск) отвечает `replayed: true`
и события не даёт. Обратная сторона: если ответ BFF на первый redeem потерялся
в сети, повтор придёт `replayed: true` и покупка в Meta **не попадёт**. Недосчёт
вместо двойного счёта — осознанно.

### 5. Консоль Meta — шаг владельца, без него задача неверна
**Выключить «Log in-app events automatically»** (App Dashboard → Settings).
В SDK 18.3.0 есть автологгер покупок Play (`com.facebook.appevents.iap`,
обёртки над BillingClient v2–v7), он шлёт покупку **по ответу магазина** в
местной валюте. С нашим ручным событием в USD дедупликация не совпадёт —
двойной счёт и ровно то, что задача запрещает. Автологирование установок и
запусков (`AutoLogAppEventsEnabled`) при этом **остаётся** — без него не будет
атрибуции установок.

### 6. Тесты и проверка в слэйве
- Юнит: обёртка (флаг выключен → ни одного вызова; невалидная сумма не
  уходит), `redeem` (событие только при `replayed: false`, с `creditedMinor`;
  при ошибке BFF — нет события), create-account (событие только при успехе),
  profile (событие на открытие листа).
- `lint`, `tsc`, `jest`, `./gradlew assembleDebug` (сборка — проверка interop
  и слияния манифеста); `aapt dump permissions` на APK — увидеть AD_ID и
  adservices своими глазами и записать в execute.
- Живая проверка (Events Manager, сумма = журнал BFF) — после мёржа, на
  prod-сборке из internal testing.

## Чего НЕ делаем
- iOS, ATT, App Privacy.
- Facebook Login/Share — пакет их содержит, но не используем.
- `setUserID`, `setUserData`, advanced matching, Conversions API с BFF.
- Другие события (просмотр советника, начало сессии и т. п.).
- Ограниченная обработка данных (LDU) для штатов США — вне объёма.

## Решения, нужные от владельца

**D1. Согласие в ЕС.** 34 страны Play — ЕС-27, ЕЭЗ, Великобритания,
Швейцария, Украина, США. Передача рекламного ID и событий Meta для
рекламы в ЕС/UK требует согласия пользователя (GDPR + ePrivacy), и условия
Meta Business Tools перекладывают получение согласия на нас. Варианты:
- **A. Без согласия.** Самое простое и полная атрибуция; юридический риск
  на владельце, политику переписать честно.
- **B. Согласие до инициализации.** SDK стартует только после явного «да»
  (переключатель на экране создания аккаунта рядом с маркетинговым, по
  умолчанию выключен — как его выровняли в `AURAT-0042-108`). Атрибуция
  неполная (часть скажет «нет», установка до согласия не видна) — +экран,
  +поле в профиле, объём растёт.
- **C. Без рекламного ID.** `AdvertiserIDCollectionEnabled=false` и удаление
  AD_ID: атрибуция только через install referrer, оптимизация Meta слабее,
  Advertising ID в Play остаётся «нет». Согласие по ePrivacy формально всё
  равно нужно для событий.

Мой совет: **B**, но отдельной задачей впереди этой — сейчас довести код до
состояния «флаг выключен по умолчанию», а включать в prod после того, как
вопрос согласия решён. Если владелец берёт A — фиксирую это решением
`AURAD` с его формулировкой.

**Итог (2026-10-14): A** — `AURAD-0018`. Сначала было выбрано B (ниже
оставлено для истории), после сравнения с PsychicBook владелец перешёл на A.
Следствия: флаг `AURA_META_ATTRIBUTION_ENABLED` **включается** в
`aab:prod` / `apk:prod`; AD_ID остаётся; декларации Play переподаются с первой
сборкой с SDK, как в исходном спеке; в политике — Meta и способ отказа по
почте. Автоинит в манифесте по-прежнему выключен, SDK стартует из JS по
флагу — это оставляет дорогу к B без переделки.

~~Решение владельца (2026-10-14): B.~~ Следствия для этой задачи (отменены):
- код SDK и событий делается здесь, но `AURA_META_ATTRIBUTION_ENABLED` в
  `aab:prod` / `apk:prod` **не включается** — флаг выключен во всех целях;
- нативный автоинит выключен в манифесте безусловно (не от флага), чтобы до
  согласия SDK не стартовал и не читал рекламный ID; запуск —
  `Settings.initializeSDK()` из JS, когда задача согласия даст «да»;
- AD_ID в манифесте всё равно появится с этой сборкой → декларации Play
  (Advertising ID, Data safety) переподаются при первом выпуске сборки с SDK
  даже при выключенном флаге: декларация описывает возможность, а не
  текущий трафик;
- переключатель согласия, его хранение и включение флага — отдельная задача.

**D2. Client Token** из App Dashboard → Settings → Advanced → Client token.
Без него SDK не отправит события. Не секрет (лежит в APK), коммитится в
`strings.xml`.

## Критерии приёмки (из 001, уточнённые)
- Установка из Play видна в Events Manager (prod-сборка из internal testing).
- Покупка приходит с `creditedMinor/100 USD` из журнала BFF, один раз;
  автологирование покупок в консоли Meta выключено.
- Advertising ID и Data safety переподаны той же отправкой, что сборка.
- Meta в политике приватности.
- iOS: `Podfile.lock`, `pbxproj`, `Info.plist` в диффе без изменений, App
  Privacy не тронута.
