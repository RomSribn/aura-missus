# AURAT-0035-004 — Контекст: что проверено в коде

Дата: 2026-08-21
Ground truth — `project/manor/master/aura-app` @ `dc8ab27`, не документация.

## Почему сообщения приходят пустыми — корень найден

`package.json:14` → `"@aura/contracts": "github:RomSribn/aura-contracts#v0.7.0"`.
Проверено на **установленном** пакете: `grep attachments node_modules/@aura/contracts/dist/`
не даёт ни одного совпадения.

Zod у объектных схем по умолчанию **срезает неизвестные ключи**. Значит
`Message.parse(body)` в `features/chat/api/chat-api.ts` молча выбрасывает
`attachments` из ответа BFF ещё до того, как их кто-либо мог бы увидеть.
Это не «UI не нарисовал» — это данные не доходят до UI. Бамп контракта —
первый шаг, без него остальное работает вхолостую.

## Что придётся тронуть

| Место | Сейчас |
|---|---|
| `package.json:14` | контракты `v0.7.0`, нужен `v0.9.1` |
| `features/chat/model/types.ts` | `ChatMessage` = `{id, from, text, time, status?, tone?}` — вложений нет |
| `features/chat/lib/map-message.ts` | `mapMessage` не переносит `attachments` |
| `shared/api/bff/http-client.ts` | `bffRequest` умеет только JSON (`response.json()`), бинарного пути нет |
| `screens/chat-thread/ui/MessageBubble.tsx` | рисует только `<Text>{message.text}</Text>` |
| `screens/chats/ui/ChatListRow.tsx:24` | `previewOf` берёт `message.text` — у вложения без подписи это `''`, строка пустая |

`features/chat/model/ChatProvider.tsx` хранит треды **в памяти**, на диск ничего
не пишет. То есть кэш вложений — первое персистентное хранилище в приложении.

## Что трогать НЕ нужно

Пуш: `features/push/model/message-notification.ts` показывает статичную
`MESSAGE_NOTIFICATION_BODY` без текста сообщения (PII через FCM не идёт,
`AURAD-0001`). Вложение ничего в пуше не меняет.

## Дизайна нет — это отдельная часть работы, а не «дорисовать»

В `.claude/design_handoff_aura/` вложения упомянуты **ровно один раз**:
`MOTION_AND_ICONS.md:113` — «Chat: `send`, `plus` (attach), `back`, `paperclip`».
Ни макета баббла с картинкой, ни строки файла, ни плеера, ни полноэкранного
просмотра, ни состояний загрузки/ошибки. Иконки при этом есть: `paperclip`,
`mic`, `video` (последние две числились неиспользуемыми — «продукт только
текстовый»; для голосовых и видео они наконец пригодятся).

## Зависимостей под это в проекте нет

В `dependencies` нет ни файловой системы, ни плеера аудио/видео, ни кэша
картинок. Скачивание в файловый кэш и воспроизведение — новые нативные
зависимости, то есть пересборка обеих платформ.

## Расхождение документа с реальностью

Таблица скоупа в `AURAF-0011` держит `BE` = `✗` на строках 001–005, хотя
BFF-половина закрыта и развёрнута. Причина механическая: шаги `AURAT-0031-005…011`
лежат в незамёрженной ветке слэйва bff-манора, а на `master` общего брейна их
нет. Таблицу правит эта задача на шаге post-execute.

## Риск, унаследованный от BFF

`GET /v1/attachments/:attachmentId` **не вызывался ни разу** — так и записано в
`AURAT-0031-011-verified.md`. BFF ходит за байтами в
`http://chatwoot-rails:3000/rails/active_storage/...`, в маршрут Rails, куда этот
сервис никогда не ходил (host authorization, `FORCE_SSL` — поведение неизвестно).
Первый запрос из приложения и будет первой настоящей проверкой чужой половины.
Планировать с допуском, что она там же и сломается.
