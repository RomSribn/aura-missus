# AURAT-0113-006 — Approval

Дата: 2026-10-20

Спека `005` **одобрена владельцем** с одной поправкой и одним расширением (зафиксировано и в
`aura-app-manor/active-work.md`):

1. **Перенос** — `userOverlapping()` и замок кошелька — ок. Поправка: баланс в ответе — из
   `lockWallet` внутри транзакции (как `book`/`extend`/`cancel`), не из чтения кошелька до
   неё. Репозиторий `reschedule` возвращает `{ session, balanceMinor }`; до транзакции сервису
   нужен только `walletId`. Причина: приложение кладёт `balanceMinor` из ответа переноса в
   общий стор (`use-reschedule.ts:142`) — раннее чтение может отдать устаревший баланс.
2. **Продление — в этой задаче.** В `extendLocked` после проверки советника и до денег —
   `userOverlapping()` на `[session.startsAt, новый endsAt)` с `id: { not: session.id }` →
   `UserBusyError`, тот же 409, что у брони. Повтор (`replaysExtend`) — раньше всех проверок;
   замки — «советник → кошелёк» (уже так); `userId` — в репозиторий, как в переносе; перехват
   `isOverlapViolation → ExtendOverlapsNextBookingError` не трогать. Клиенты не меняются.
   Тесты: пересечение со следующей сессией человека у другого советника → `UserBusyError`, в
   ledger ничего, деньги не списаны, сессия не изменилась; встык — можно; отменённые и
   завершённые не мешают; в сервисе — 409 без `scheduleFinish`, sync и push. В проверку в
   маноре — шаг на продление.
3. **Вне задачи:** пересчёт `endsAt` в `activate` при позднем старте — отдельный долг в
   `aura-app-manor`.

Merge — только с подтверждения владельца. Дальше — `007-execute`.
