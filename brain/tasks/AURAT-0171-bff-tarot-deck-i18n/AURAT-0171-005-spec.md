# AURAT-0171-005 — Спека: колода таро на языке пользователя + резолвер `?lang`

Дата: 2026-11-06 · Статус: **draft — ждёт одобрения владельца**
Фича: `AURAF-0023` строка 010 · Решение: `AURAT-0137-006` §3A · Устройство резолвера: `AURAT-0168-007` §2
Тип: задача. Репо: `aura-bff` (+ одна строка JSDoc в `aura-contracts`, §6).

## Что получится

- `GET /v1/tarot/daily?lang=de` → карта дня по-немецки: `name`, `keywords`, `daily`. `imageUrl` и арт — те же
  (английские надписи на картинках остаются, решение владельца 2026-11-06).
- То же для `POST /v1/tarot/spread/:messageId/pick?lang=…` и для карты открытого расклада в
  `GET /v1/advisors/:advisorId/messages?lang=…`.
- Без `lang`, с неизвестным кодом, `DE`, двумя `lang` или выключенным языком → английский, как сейчас. Старые
  сборки ничего не замечают.
- Заметка чаттеру «Card chosen: …» — по-английски, как сейчас.

## 1. Перевод колоды

78 карт × `name` / `keywords` / `daily` × 23 языка (≈ 5,4 тыс. строк, ≈ 230 тыс. знаков).

- **Названия** — устоявшиеся в каждом языке для колоды Райдера–Уэйта, не дословные: de «Der Narr», «Die
  Hohepriesterin», «Zwei der Kelche»; fr «Le Mat», «La Grande Prêtresse»; es «El Loco», «Dos de Copas»; it «Il Matto»,
  «Due di Coppe»; pl «Głupiec», «Dwójka Kielichów». Масти и ранги — одни на все 14 карт масти; в шапке каждого файла —
  таблица «Wands / Cups / Swords / Pentacles, Page / Knight / Queen / King → язык».
- **Термины** из глоссария v2: `tarot` (it «tarocchi», bg «таро», et/lt/lv «taro»), `tarot-card`.
- **Обращение** — по таблице `AURAF-0023-glossary.md` (формальное: bg, cs, el, fr, hr, lt, lv, pt, sk, sl; pl «Ty» с
  заглавной; остальные на «ты»).
- **Правила английской колоды — на всех языках:** ровно три слова через « · »; одно-два предложения; **никаких
  предсказаний** (ни «ты встретишь», ни обещаний) — совет на сегодня; тяжёлые карты (Смерть, Башня, Дьявол, Десятка
  мечей) названы честно, рядом — что можно сделать сегодня; семь карт дизайна переведены тоже по смыслу, без
  посимвольной привязки.
- Перевожу сам, пачками по 4 языка параллельно (6 агентов), потом сверяю масти, повторы и длины. Ревью носителями —
  желательно, не обязательно (не `@sensitive`).

## 2. Хранение — **решение 1**

- **А (рекомендую).** Таблица `tarot_card_translations`: `(cardId, language)` — первичный ключ, `name`, `keywords`,
  `daily`, FK на `tarot_cards`. Английский остаётся в `tarot_cards` — источник и запасной вариант; строк `en` в
  таблице переводов нет. Данные — `src/modules/tarot/deck-translations/<lang>.ts` (23 файла, `Record<cardId, {name,
  keywords, daily}>`), сид — upsert по ключу при каждом деплое, как колода (1 794 строки), ничего не удаляет. Это то,
  что предусмотрено в `schema.prisma` над `TarotCard` («a translations table, not `name_ru` columns»): все тексты
  карты — в одном месте с одним жизненным циклом.
- **Б.** Переводы только в коде: `localizeCard(card, language)` при сборке DTO, без таблицы и миграции. Проще (ни
  миграции, ни языка в репозиториях), но английский — в базе, переводы — в коде: два источника текста карты.

Дальше — для А.

- Миграция — одна новая таблица, без изменения старых: деплой без простоя, старая версия её не замечает.
- Чтение: репозиторий получает `language` и подтягивает перевод тем же запросом
  (`card: { include: { translations: { where: { language } } } }`), без второго запроса и без N+1.
  `toCardRecord` берёт перевод, если он есть, иначе английский — карта, добавленная в колоду раньше перевода,
  не ломает ответ. `TarotCardRecord` и `toTarotCardDto` не меняются.
- `TarotRepository`: `findDailyCard`, `dealDailyCard`, `pickSpreadCard` — с `language`; `findCard` (заметка
  чаттеру) и `listDeck` (выбор карты) — без, английские.
- `MessagesRepository.listPage` — с `language`, только для карты расклада; остальные чтения сообщений (upsert,
  удаление) — английский include: их результат уходит в сокет / ответ отправки, а там карты нет (§4).

## 3. Резолвер `?lang` — по `AURAT-0168-007` §2, без отступлений

- `src/common/language/request-language.ts` — чистое ядро:
  `languageFromQuery(raw: unknown, disabled: readonly Language[]): Language | null` (код из `LANGUAGES` и не
  выключенный, иначе `null`: нет параметра, неизвестный, `DE`, массив `?lang=de&lang=fr`, выключенный);
  `languageOrDefault(language) → SOURCE_LANGUAGE` при `null`.
- `RequestLanguagePipe` (`@Injectable`) — берёт провалидированный `DISABLED_LANGUAGES` из `ConfigService`;
  `@RequestLanguage()` = `Query(LANGUAGE_QUERY_PARAM, RequestLanguagePipe)`; `@ApiLanguageQuery()` — одно описание
  параметра для Swagger. `Accept-Language` не читается.
- Маршруты: контроллер получает `Language | null`, передаёт в сервис `languageOrDefault(…)`.
  - `TarotController.getDaily`, `TarotController.pickSpreadCard`, `ChatController.getHistory`.

## 4. Сокет, кэш, заметка

- Сокету язык не нужен: `fanOut` — только новые вставки, у нового расклада карты нет; ответ `pick` в сокет не
  уходит. Закрепляю тестом `toDto`: нераскрытый расклад — без `card`.
- HTTP-кэша у этих маршрутов нет — смена языка = перезапрос (клиенты, `0169` / `0170`).
- `announceSpreadPick` → `findCard` → английское имя (`001` п. 4).

## 5. Тесты (чистые, без БД)

- `deck-translations.spec.ts` на все 23 языка: ровно 78 карт, те же id, лишних нет; ни одного пустого поля; три слова
  через « · »; `daily` ≤ 220 (английский ≤ 160 + запас на длинные языки); 78 разных `daily` и 78 разных `name` в
  языке; `daily` и `keywords` не совпадают с английскими (непереведённое не проходит); каждая карта как
  `TarotCard` проходит `tarotCardSchema`.
- Ядро резолвера: нет параметра, неизвестный, `DE`, массив, выключенный `mt` при `DISABLED_LANGUAGES=mt` → `null`;
  `languageOrDefault`.
- `toCardRecord`: с переводом / без перевода → английский.
- Сид: строки переводов = 23 × 78, ключ `(cardId, language)`.
- `tarot.service.spec`, смоук `tarot.smoke.spec`: `?lang=de` → язык доходит до репозитория; `?lang=DE`, без
  параметра, выключенный → `en`. История: `language` доходит до `listPage`.
- `npm run lint`, `typecheck`, `build`, `test`.
