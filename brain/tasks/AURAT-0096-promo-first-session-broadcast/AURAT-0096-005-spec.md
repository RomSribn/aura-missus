# AURAT-0096-005 — spec

Тип: task (разовая операторская команда). Фичи не заводим — это рассылка по
существующему офферу `AURAF-0017`. Status: **draft**, ждёт одобрения.

## Команда

```
npm run promo:first-session -- --dry-run            # только счётчики
npm run promo:first-session -- --only <userId>      # одному юзеру (тест)
npm run promo:first-session -- [--limit <n>]        # прогон (n — первые n юзеров)
# прод/dev-контейнер: node dist/promo-first-session.js …
```

Аккаунт/inbox — из env контейнера (`CHATWOOT_ACCOUNT_ID`): в `bff-dev` это
аккаунт 2, на проде — 1. Аргументы проверяются до загрузки модуля (как у соседей).

## Кому
1. Юзеры: `erasure = null`, есть ≥ 1 диалог; порядок — `createdAt` по возрастанию.
2. `SessionsRepository.hasUsedFirstSessionOffer(userId) === false`.
3. Диалог: среди диалогов юзера с **активным** советником — самый свежий по
   последнему сообщению (иначе по созданию). Нет такого — пропуск.
4. На диалоге нет метки `promo-first-50` — иначе пропуск («уже отправлено»).

`--only <userId>` — тот же путь, но **без** п. 2 (чтобы владелец мог проверить на
себе, даже если сам оффер использовал); метка соблюдается.

## Как отправляется
По одному юзеру, последовательно, пауза 1 с между отправками:
1. **Сначала метка** (read → add → write, весь набор сохраняется) — «занимаем»
   диалог. Повторный прогон его пропустит, даже если процесс упадёт между шагами:
   лучше потерять одно сообщение, чем отправить промо дважды.
2. Затем публичное `outgoing` от service-user. Дальше — штатный путь
   webhook → store → FCM+WS.
3. Ошибка отправки → строка в отчёте (внутренние id, без PII), метка остаётся,
   прогон идёт дальше; exit 1 в конце, если были ошибки.

Перед прогоном (и в `--dry-run` — только проверка) — метка `promo-first-50` на
уровне аккаунта создаётся, если её нет (описание «Promo: first session −50%,
sent by Aura»), чтобы её было видно и по ней фильтровались чатеры.

Отчёт: кандидатов / оффер использован / нет диалога с активным советником / уже
помечен / отправлено / ошибок; `--dry-run` дополнительно — сколько без устройства
для пуша (им сообщение ляжет в тред без пуша).

## Текст (утверждён владельцем)

> Good news — your first session with me is now 50% off ✨
> It's applied automatically, no code needed. Update Aura in Google Play to see it right on the booking screen, then pick a time that suits you.

## Решения для владельца
- **D1. Кнопка записи под текстом.** Дописать в сообщение `::SESSION::` — в
  приложениях с поддержкой приглашений текст станет карточкой с кнопкой
  бронирования, старые сборки увидят тот же текст. Рекомендую **да**, с проверкой
  рендера на dev (staging-сборка); не понравится — одна константа.
- **D2. `--only` без проверки оффера** (выше) — рекомендую **да**.

## Тесты (slave, чистые)
Выбор диалога; разбор аргументов; сервис на фейках: метка до отправки, пропуск
помеченных/использовавших оффер, `--only` минует оффер, ошибка отправки не роняет
прогон, `--dry-run` ничего не пишет; клиент — тело `outgoing` запроса.

## Проверка (после мержа)
**dev (`bff-dev`, аккаунт 2):** `--dry-run` → `--only <тестовый юзер>`: пуш, персона
и текст/карточка в треде, assignee и статус диалога в Chatwoot **не изменились**,
метка стоит → полный прогон → повторный = 0 отправок.
**прод:** мерж `develop` → `main` (отдельное «да») → выкатка → `--dry-run` →
`--only` себе → полный прогон днём; чатеров предупредить о волне ответов.
