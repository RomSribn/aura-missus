## Что нужно

Третий режим старта — `ui: 'elements'`. Это та же Checkout Session, но для Stripe Elements на нашей
странице:
- `ExpressCheckoutElement` — кнопки Apple Pay / Google Pay / Link в шторке Book;
- `PaymentElement` — шаг карты с нашей кнопкой;
- `CurrencySelectorElement` — выбор валюты, его требует Adaptive Pricing.

Зачисление, вебхук, сверка, статус, отмена, возвраты и диспуты не меняются.

1. **Сессия.** В `stripe-card-payments.ts` к `returnParams` добавляется режим `elements`:
   - `ui_mode: 'elements'` и `return_url` — тот же `/checkout?payment=<id>`. На него уходит банковский
     метод;
   - `redirect_on_completion` для `elements`, видимо, не задаётся — у него редирект решает клиент
     (`confirm({ redirect: 'if_required' })`). Сверить по закреплённой версии API `2026-09-30.endive`;
   - остальное как сейчас:
     - USD и `adaptive_pricing.enabled`;
     - 3DS `any`;
     - `STRIPE_TERMS_CONSENT` (`consent_collection`);
     - metadata, `expires_at` 60 мин, `integration_identifier`;
     - `customer_email`, если он есть у аккаунта, и `locale`;
   - тела `hosted` и `embedded` — байт в байт как сейчас.
2. **Ответ старта.** Рекомендация — тот же `{ kind: 'embedded', clientSecret, publicKey }`: форма ответа
   совпадает, контракт меняется меньше. Решение 1.
3. **База.** `StripeCheckoutUi` + `ELEMENTS`, миграция. Тот же `paymentId` с другим `ui` — 409, как
   сейчас.
4. **Контракты `v0.34.0`.**
   - `CardCheckoutUi` + `'elements'`;
   - JSDoc: что клиент рисует сам, Currency Selector обязателен при Adaptive Pricing, согласие с Terms
     — `TermsElement`.

   Тег — только с «да» владельца.
5. **Частота старта.** Веб будет создавать сессию заранее: кнопкам кошельков она нужна до нажатия.
   Это происходит при открытии шторки с нехваткой баланса и при смене длительности, то есть суммы.
   - Ненужные сессии веб закрывает `cancel` в фоне, остальные истекают сами.
   - Решение 2: лимит частоты `POST /v1/wallet/top-ups/card` на пользователя.
6. **Согласие с Terms в live** (замечание координатора к спеке веба v2).
   - В live согласие обязательно для всей сессии, в том числе для оплаты кошельком.
   - В sandbox его проверить нельзя: там нет ссылки на Terms, `STRIPE_TERMS_CONSENT=none`.
   - Сверить по документации Stripe, как согласие собирается в Elements (`TermsElement`) и блокирует
     ли его отсутствие `confirm` кошелька. Записать в шаги выката, что этот путь проверяется перед live
     на sandbox со ссылкой на Terms.
7. **Тесты** — на моке Stripe:
   - параметры сессии `elements`;
   - `hosted` и `embedded` без изменений;
   - 409 на другой `ui`;
   - лимит частоты, если он будет.

## Решения для спеки (с рекомендацией)

1. **Вид ответа для `elements`.**
   - А — тот же `kind: 'embedded'` с `clientSecret` и `publicKey`;
   - Б — новый `kind: 'elements'`.
   - **Рекомендация: А**: форма та же, а имя `kind` можно привести в порядок, когда `hosted` и
     `embedded` снимут.
2. **Лимит частоты старта.**
   - А — на пользователя, например не больше N стартов в минуту, сверх — 429;
   - Б — без лимита.
   - **Рекомендация: А**, число — в спеке.
