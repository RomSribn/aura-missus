# AURAT-0038-002 — Разведка: постановка была права в диагнозе и неправа в цене

Дата: 2026-08-21
Слейв: `slave-0`, ветка `feature/AURAT-0038-paste-image-into-chat`

## Что подтвердилось

**`onPaste` у `TextInput` в RN 0.85.3 нет.** Проверено в установленном пакете:
ни в `TextInput.d.ts`, ни в `TextInput.js`, ни в нативной спецификации. Без
замены компонента вставка невозможна — ровно как сказано в `001`.

## Что не подтвердилось: «придётся писать нативный код»

`001` оценивал настоящую вставку как «замена `TextInput` на нативный с
`onPaste`, тянется нативный код». Готовая замена существует и живая:

| | версия | издана | peer | зависимости |
|---|---|---|---|---|
| `@mattermost/react-native-paste-input` | 2.0.1 | 2026-05-09 | RN ≥ 0.76.0, **Fabric only** | нет |
| `@react-native-clipboard/clipboard` | 1.16.3 | 2025-06-28 | RN ≥ 0.61.5 | — |

Fabric-only — это ровно наш стек (RN 0.85.3, Новая архитектура). Лицензия MIT,
JS-зависимостей нет. Заметим обратное про «дешёвый» путь: библиотека буфера
старше нашей RN на поколение и писалась под старую архитектуру.

## Что это меняет по существу

**Буфер отдаёт файл, а не байты.** `onPaste` даёт
`Array<{ fileName, fileSize, type, uri }>` — форма, из которой наш
`DraftAttachment` собирается один в один, как из ассета галереи. Отпадают два
пункта «что учесть» из `001`:

- не нужно класть байты в собственный кэш — `uri` уже есть;
- не нужно выдумывать имя файла и расширение — они приходят.

**Бонус на Android:** тот же колбэк срабатывает при выборе картинки или GIF из
клавиатуры, а не только при вставке.

## Куда это ложится у нас

`ChatInputBar` — это восемь пропсов и один `TextInput`; замена drop-in-ом
затрагивает один файл экрана. Библиотека объявляет «все свойства `TextInput`
плюс свои».

Шлюз черновика (`useAttachmentDraft.accept`) уже делает всё, что нужно вставке:
отказ по размеру и по `text/*`, отказ с причиной вместо молчания, единственное
место, где черновик становится черновиком. `pastedAsDraft` — почти копия
`assetAsDraft`, никакой новой логики отказа.

## Чем платим — честно

1. **Ещё один нативный модуль рядом с Nitro и рельсом Google Play.** Именно на
   этом сломалась запись голосового (`TECH-DEBT` 5). У этого пакета нет
   JS-зависимостей, так что конфликт версий менее вероятен, но **доказывается
   сборкой, а не рассуждением** — обе платформы.
2. **Одна строка нативного кода на iOS**: `PasteInputModule.setup(...)` в
   `AppDelegate`. Наш `AppDelegate` уже правился под Firebase, файл знакомый.
   Без этого вызова события вставки не доезжают. Android — автолинковка.
3. **Паритет пропсов.** У нас `submitBehavior` (имя из RN 0.85); README
   библиотеки показывает старый `blurOnSubmit`. Пройдёт ли новый проп насквозь
   — проверяется сборкой.
4. **`uri` из буфера может оказаться временным или security-scoped**, как
   документ из пикера. Тогда понадобится тот же `keepLocalCopy`, что уже
   написан для файлов (`AURAT-0036`).

## Решение по объёму, которое я принял сам

Владелец переформулировал задачу словами «вставка файла путём paste **в
input**». Это снимает продуктовый вопрос из `001` («устраивает ли кнопка вместо
жеста») — просили жест, и он теперь дешевле, чем предполагалось. Пункт
«Вставить» в шите вложений не делаем.
