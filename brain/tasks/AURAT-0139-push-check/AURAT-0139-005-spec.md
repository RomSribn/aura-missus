### 1. Сборка и BFF

Пуш придёт только от BFF, в котором зарегистрирован токен, и только на ответ из Chatwoot этого BFF.

| Телефон | Сборка | BFF | Откуда отвечать |
|---|---|---|---|
| Android | Play (internal) или release `AURA_ENV=prod` | `bff.aura-app.cc` | прод-Chatwoot |
| iPhone | TestFlight (`aps-environment: production`) | `bff.aura-app.cc` | прод-Chatwoot |
| (вариант) | `AURA_ENV=staging` | `bff-dev.aura-app.cc` | dev-Chatwoot |

Debug-сборка из Xcode подписана `development` и ходит в sandbox APNs — тоже работает (ключ на
оба окружения), но **не смешивать**: токен от debug-сборки не получит пуш через production.
Рекомендация: одна и та же прод-сборка на обоих телефонах.

### 2. Подготовка телефона

- [ ] iPhone: Settings → Aura → Notifications включены; **Background App Refresh — вкл.**;

### 3. Сценарии (на каждом телефоне)

Действие везде одно: написать советнику из приложения, оператор отвечает в Chatwoot.

| # | Состояние приложения | Ожидание |
|---|---|---|
| 1 | Открыт этот же тред | сообщение приходит в тред, **уведомления нет** — так задумано |
| 2 | Открыт, другой экран | уведомления нет, тред обновился (сокет) |
| 3 | Свёрнуто (Home) | уведомление: имя персоны, «sent you a new message» |
| 4 | Экран заблокирован | уведомление на экране блокировки |
| 5 | Тап по уведомлению из 3/4 | открывается тред этого советника |
| 6 | Свайп из недавних (Android) / force-quit (iPhone) | Android — уведомление есть; **iPhone — нет**, это ограничение тихого пуша (см. «Риски») |
| 7 | Холодный старт тапом (после 6 на Android) | открывается тред |
| 8 | iPhone, Low Power Mode вкл. | скорее всего, нет — зафиксировать |
| 9 | Выход из аккаунта, ответ оператора | уведомления нет (токен отвязан) |

Записывать: телефон, сборка, № сценария, пришло ли, через сколько секунд, куда привёл тап.

### 4. Если пуш не пришёл — где смотреть (манор)

1. Есть ли `DeviceToken` у пользователя → нет: регистрация не дошла (на iOS — см. риск «токен до APNs»).
2. `bull:fcm-fanout`: задача `completed` / `failed`.
3. Лог BFF: `FCM rejected delivery: configuration or credentials` → ключ / проект / bundle id;
   `FCM tokens pruned` → токен протух, перезапустить приложение.
4. Задача `completed`, а уведомления нет → доставку решила ОС (троттлинг iOS, энергосбережение
   Android).
5. Изоляция трубы: Firebase Console → Messaging → **Send test message** по токену из `DeviceToken`
   (берёт манор). Это notification-пуш — проверяет FCM/APNs, но не наш обработчик.

## Риски, которые проверка покажет

- **iOS доставляет тихий пуш ненадёжно** (`content-available`, приоритет 5): троттлинг, нет
  доставки после force-quit и в Low Power Mode. Если сценарии 3–4 на iPhone проваливаются через
  раз — нужен видимый alert-пуш от BFF (имя персоны + общий текст, без содержимого сообщения —
  сверить с решением 3 `AURAT-0005` и `AURAD-0001`), плюс в приложении тап по системному
  уведомлению (`messaging().getInitialNotification` / `onNotificationOpenedApp`). Это **две новые
  задачи** (BFF в `aura-bff-manor` + приложение), ID — из `aura-app-manor/active-work.md`.
- **iOS: `getToken()` до APNs-токена падает молча** (`push-registration.ts` глотает ошибку).
  Проявится как «нет `DeviceToken` с `ios`» после перезапуска уже вошедшего пользователя.

## Правка приложения в этой задаче (решает владелец)

- **A (рекомендую): только проверка.** Кода нет, итог — заполненная таблица сценариев; правки
  заводим по фактам.
- **B: проверка + страховка регистрации на iOS.** В `push-registration.ts` перед `getToken()` на
  iOS дождаться `getAPNSToken()` (несколько попыток с паузой), юнит-тест. Небольшая правка,
  но нужна новая iOS-сборка, чтобы она попала в проверку.

Экран/кнопку с FCM-токеном не делаем: токен для Console берётся из BFF, а показ токена в
приложении — лишняя поверхность для утечки.

## Вне задачи

- Alert-пуш / NSE (BFF) — только по итогам сценариев, отдельной задачей.
- Слот не запускает телефоны и стек; живая проверка — владелец и манор.
