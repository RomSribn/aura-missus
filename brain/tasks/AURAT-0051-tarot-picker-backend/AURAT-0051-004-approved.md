# AURAT-0051 — принято владельцем, слот закрыт

Дата: 2026-09-01

Код ушёл в `develop` двумя мержами (`c5a9160`, затем `f40414b` с правкой канала
уведомления), `aura-contracts` v0.13.0 (`695629e`) в origin. Владелец
распорядился освободить слот сегодня.

## Что принято

Серверная половина выбора карты в чате целиком, как описано в
`AURAT-0051-002-execute.md`: таблица `tarot_spreads`, разбор `::CUPS_02::` на
приёме с вырезанием токена, `POST /v1/tarot/spread/:messageId/pick`, заметка
оператору отдельной джобой.

**Прогон по живому стеку выполнен** — `AURAT-0051-003-manor-run.md`: миграция,
токен в тексте и отдельным сообщением, `::CUPS_99::` (не сохранено, оператору
ошибка), три пика подряд без дублей, заметки в ленте оператора, и отдельно
`UPDATE` прогнан прямо по Postgres в транзакции с откатом (чужой пользователь —
0 строк, второй тап — 0 строк, в базе остаётся первая позиция). Не проверен
только повторный тап по уже открытому вееру через API — владелец каждый веер
трогал по одному разу, а на уровне SQL этот случай закрыт.

Прогон изменил две вещи, и обе уже в `develop`: сигнал оператору переведён с
activity-строки на приватную заметку (activity рисуется мелкой серой строкой по
центру, владелец её в дашборде не заметил), и дев-стеку проставлен
`target: build`, без которого он не поднимался вовсе.

## Чем эта запись отличается от того, что стояло в `active-work.md`

Запись в `active-work.md` к моменту закрытия **устарела в двух местах**, и обе
неправды были блокирующего вида:

- «Код готов, **не смержено**» — смержено ещё в `f40414b`; на ветке слейва
  относительно `develop` не было ни одного коммита.
- «`aura-contracts` v0.13.0 не запушен, **блокирует манор**» — запушен;
  проверено при выпуске v0.14.0, которая встала поверх него.

Слот держался не работой, а отсутствием файла приёмки. Записи исправлены при
освобождении.

## Что остаётся открытым

- **Половина приложения** — `AURAT-0053`. По наблюдению из прогона она у
  владельца уже работает (`POST …/pick` приходил из приложения), что расходится
  с `AURAT-0051-001`, где она числится отдельным невыполненным шагом.
- **Наблюдения из прогона, не входившие в задачу** и не закрытые ничем:
  приложение дёргает `GET /v1/horoscope?date=…`, которого в BFF нет вовсе (404);
  `AURAS-0001` устарел в разделе доступа; оператор видит свои токены в дашборде
  как есть — вырезание касается только того, что уезжает в приложение.
