## Дефекты

**1. Устаревший перевод больше не становится годным** — `campaigns-admin.service.ts` `saveTranslation`,
`views/campaign-translations.view.ts` `placeField`.
- Поле считается неизменённым, если `stored.text === typed`, без сравнения `source`. Такое место пропускается и остаётся
  каким было: машинным или владельческим, годным или устаревшим.
- Устаревший перевод в поле не подставляется. Он показан подсказкой рядом: «устарел — английский изменился; был «…» для
  «…». Перевести заново или вписать новый».
- Пустое поле рядом с устаревшим переводом ничего не удаляет: поле и не было заполнено. Удаляет только пустое поле у
  годного перевода.
- Тесты:
  - `campaigns-admin.translations.spec` — устаревший `too_long`, отправлен пустым и тем же текстом → `set: {}`,
    `remove: []`, без 422;
  - `campaigns.view.spec` — поле пустое, подсказка на месте.

**2. 422 больше не обходит версию.**
- `saveTranslation` сверяет `version` со строкой языка **до** проверки полей. Не совпала → `stale` (409), поля не
  судятся. Под замком версия сверяется ещё раз: прогон может записать язык между двумя сверками.
- Страница 422 несёт присланную версию (`TranslationLanguageData.version`), а не свежую версию строки.
- Страница 409 показывает язык, каким он стал. Набранный текст стоит рядом с полем («Вы вписали: «…» — не сохранено»), а
  не в поле: иначе повторное сохранение записало бы его поверх текстов, которых владелец не видел. Это тот же класс
  ошибки, что в п. 2.
- Тесты:
  - admin — устаревшая версия с ошибочным полем → `stale`, а не `invalid`; запись не вызывается;
  - smoke — 422 с `version="0"`, 409 с подсказкой и без `value=` набранного.

**3. Сбой прогресса больше не обрывает прогон** — `campaign-translation.service.ts` `report()`.
- `job.updateProgress` обёрнут в try/catch, в лог идёт предупреждение без текста.
- Прогон доходит до конца, `TRANSLATED` пишется, дедупликация снимается только с завершением задачи.
- Тест: `progress` отклоняется на каждом языке → 23 записи и одна строка журнала.

**4. Таблица языков — все 23** — `campaign-translations.view.ts` `languagesTable`.
- Все 23 языка с «Править» — при `off`, у новой кампании, и для языков из `DISABLED_LANGUAGES`.
- `languages()` нужен только прогону. Язык, который прогон пропускает (выключен в окружении или переводчик его не
  знает), помечен «без машины», под таблицей — пояснение.
- Тесты:
  - smoke — при `off` у новой кампании 23 ссылки на правку;
  - view — 23 строки, 22 «без машины» при одном языке у машины.

**5. Версия кампании — только когда записан текст** — `prisma-campaigns.repository.ts` `writeMachineTranslation`.
- `campaigns.updatedAt` и `translatedAt` меняются только при `written.length > 0` (v2 §1.6).
- Отказ (`failure`) и ответ, все места которого остались за владельцем (`kept`), версию не трогают. Подтверждение
  включения больше не устаревает 23 раза за прогон.
- Тест: отказ fr и ответ только по месту владельца в de → `update` не вызывается, `translatedAt` нет. Положительный
  случай — в тесте порядка блокировок.

**6. `/translate` — `.strict()`** — `backoffice.forms.ts` `campaignTranslateSchema`. Тест smoke: лишнее поле
`languages` → 400, задача не ставится.

**7. Чтения — выбрано так:**
- **Цена** (`prisma-campaign-discounts.ts`) берёт только подпись. Второй маленький запрос
  `SELECT "language", "texts" -> 'discountLabel' … WHERE … IS NOT NULL` идёт только при включённой скидке. Весь JSON
  всех языков ради одной строки цены больше не читается.
  - Тест `prisma-campaign-discounts.spec` (новый): подпись по языкам, `en` и битая форма отброшены, SQL берёт только
    `discountLabel`, без скидки запроса нет.
- **Кампания** (`CAMPAIGN_SELECT`): вложенный `translations` без preview `relationJoins` — это **отдельный SQL Prisma**.
  Принято осознанно и записано в комментарии:
  - его читают все, кому нужна кампания: кэш app-config на 30 с и бэкофис;
  - строк — до 23, и они маленькие.

  Утверждение «одна выборка» из 005 §3 и 009 неверно: на деле два запроса.
- **Страница кампании** читает строки ещё раз через `translationRows`, теперь с метаданными (кто, когда, engine,
  `failure`). Это третий запрос на страницу бэкофиса. Принято: страница редкая, а смешивать метаданные с
  `CampaignRecord` ради одного запроса значило бы таскать их в app-config и цену.

## Вердикт координатора — оговорка записана

После сбоя процесса BullMQ поднимает зависшую задачу один раз. Повторный запуск снова отправит языки, у которых нет
годного перевода: с блокирующей проблемой (`too_long` и т. п.) или с отказом. Они оплачиваются второй раз. Уже годные
языки не уходят. Худший случай — один лишний прогон по таким языкам.

## Runbook отката (дефект 8)

Миграция аддитивна и вниз не откатывается: значение enum на месте не удалить. Если после первого «Перевести» или первой
правки языка нужно откатить **код** BFF на версию до 0192:
1. Старый клиент Prisma не знает `TRANSLATED` / `TRANSLATION_EDITED`. `events()` на странице такой кампании упадёт. Всё
   остальное работает: app-config, цена, список кампаний, другие кампании. Таблицу `campaign_translations` старый код не
   читает.
2. Варианты, в порядке предпочтения:
   - катить вперёд с исправлением, а не откатывать;
   - откатить и не открывать в бэкофисе переведённые кампании до возврата 0192;
   - если журнал нужен на старой версии, вручную, с одобрения владельца: строки `campaign_events` с этими действиями
     не трогать (таблица append-only, триггер). Старая страница для таких кампаний недоступна.
3. Повторный выкат 0192 миграцию не повторяет, данные переводов на месте.
