## Дефекты

1. **[важно] Устаревший перевод снова становится годным** — `campaigns-admin.service.ts:468`,
   `views/campaign-translations.view.ts:239`.
   - Форма языка подставляет `stored.text` и для устаревшего перевода, у которого `source` ≠ нынешний английский.
   - «Не изменено» требует ещё `stored.source === english`. Поэтому неизменённое устаревшее поле уходит в review и
     пишется как `origin: 'owner'` с `source` = новый английский.
   - Итог: оно отдаётся в `?lang`, пометка «устарел» пропадает. С блокирующей проблемой — 422 за поле, которого
     владелец не трогал.

   Правка: неизменённым считать `stored.text === typed`, без сравнения `source`. Устаревший текст в поле не
   подставлять — показывать подсказкой рядом. Тест.
2. **[важно] 422 обходит проверку версии** — `campaigns-admin.service.ts:484`,
   `backoffice-campaigns.controller.ts:357-363`.
   - Проверки полей идут до сверки версии, а страница 422 рисуется со свежим `row.updatedAt`.
   - Сценарий: открыл de с пустым `cta` → прогон записал de → сохранил с ошибкой → 422 со свежей версией, без «перевод
     изменился» → исправил и сохранил → пустое `cta` стёрло машинный перевод, 409 не было.

   Правка: сверять версию до проверок или отдавать 422 с присланной версией. Тест.
3. **[важно] Ошибка `job.updateProgress` обрывает прогон** — `campaign-translation.service.ts:175`.
   - Redis моргнул или задачу удалили → `Promise.all` отклоняется, `TRANSLATED` не пишется (:203), задача `failed`,
     дедупликация снята.
   - Языки в полёте продолжают писать → повторное нажатие платит за них второй раз.

   Правка: прогресс в try/catch, лог без текста. Тест.
4. **При `off` правка языков недоступна** — `campaign-translation.service.ts:84`,
   `campaign-translations.view.ts:112-116`.
   - `languages()` = [] → в таблице только уже имеющиеся строки. У новой кампании «Переводов пока нет», ссылки
     «Править» нет. А спека требует «правка работает при `off`».
   - Так же не видны языки из `DISABLED_LANGUAGES` без строки.

   Правка: в таблице все 23 языка, `languages()` — только для прогона.
5. **`campaigns.updatedAt` трогается при любой машинной записи** — `prisma-campaigns.repository.ts:347`.
   - Трогается и при `failure`, и когда все места за владельцем (`kept`). `translatedAt` ставится и при неудаче (:339).
   - Подтверждение включения устаревает 23 раза за прогон.

   v2 §1.6 — только если что-то записано, то есть только при `written.length > 0`.
6. **`/translate` без `.strict()`** — `backoffice.forms.ts:260`. v2 §3: лишнее или битое → 400. `.strict()` + тест.
7. **«Одна выборка» — на деле два SQL** — `prisma-campaign-discounts.ts:33`, `prisma-campaigns.repository.ts:68`.
   - `relationJoins` в Prisma 7.8 — preview и в схеме не включён, поэтому вложенный `translations` идёт отдельным
     запросом.
   - В `getPricing` и `book` — лишний запрос, и он тянет весь JSON всех языков ради одной подписи.
   - Страница кампании ещё раз читает те же строки через `translationRows`.

   Правка на выбор исполнителя, записать:
   - принять осознанно и поправить комментарий и спеку в 009;
   - или брать только подпись (`texts->'discountLabel'`).
8. **[вероятно] Откат после первого перевода** — `migration.sql:7-8`.
   - Старый клиент Prisma не знает `TRANSLATED` / `TRANSLATION_EDITED` → `events()` старой версии упадёт на журнале
     такой кампании. Комментарий «running version neither reads…» неточен.
