# AURAT-0031-003 — Реальная форма вложения в вебхуке

Дата: 2026-08-20

Снято с живого Chatwoot (`Message#webhook_data` на сообщении с вложением), а не
взято из документации.

## Что приходит

Верхний уровень сообщения при вложении без текста:

```
content: null          ← именно null, не пустая строка
content_type: "text"
message_type: "outgoing"
attachments: [ … ]
```

Форма одного вложения:

| поле | пример | годится для показа |
|---|---|---|
| `id` | `3` | нет — это id Chatwoot, границу не пересекает |
| `file_type` | `image` | да — `image` / `audio` / `video` / `file` |
| `content_type` | `image/jpeg` | да |
| `extension` | `jpg` | да |
| `file_size` | `3154` | да |
| `width` / `height` | `null` | да, когда Chatwoot их вычислил |
| `data_url` | `http://…/rails/active_storage/blobs/redirect/<signed_id>/shape.jpg` | **нет, наружу нельзя** |
| `thumb_url` | `…/representations/redirect/…` | нет, там же |

## Две находки, влияющие на реализацию

**Имени файла в payload нет** — только `extension`. Но оно восстанавливается из
**последнего сегмента `data_url`**: `…/shape.jpg`. Иначе пользователю пришлось бы
показывать «файл .jpg» вместо имени.

**`content` приходит как `null`, а не пустая строка.** Нынешняя проверка
нормализатора (`typeof content !== 'string'`) отсекает такое сообщение первой же
строкой — это и есть место, где вложения терялись.

## Что из этого следует для контракта

Правка **чисто добавляющая**: в `Message` появляется `attachments`, а `content`
трогать не нужно — он уже `z.string()`, то есть пустую строку принимает. Значит
приложение на `v0.7.0` не сломается: оно просто не увидит нового поля, пока не
обновится.

`SendMessageRequest.content` с `.min(1)` мешает отправке вложения без текста — но
это `AURAT-0032`, не здесь.

## Как приложение получит байты (следствие AURAD-0011)

BFF проксирует. Забирать байты он будет **по `data_url` со своей стороны** —
адрес публичный, и это ровно то, ради чего он не выдаётся наружу: сервер по нему
ходит, устройство — нет. Отдельные учётные данные R2 при этом не нужны вовсе,
что снимает целый пункт из плана.

Хранить придётся сам `data_url` рядом с сообщением. Это того же класса, что уже
хранимые `chatwootConversationId` и `chatwootMessageId`: идентификатор чужой
системы в нашей таблице, которым пользуется только адаптер.
