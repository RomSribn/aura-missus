# AURAT-0031-001 — Приём вложений: от чаттера до экрана

Дата: 2026-08-20
Фича: `AURAF-0011` (строки 001–005)
Статус: заведена, разблокирована, не начата

## Запрос владельца

> «Давай заведем задачу для фронта, чтобы он отображал все что оператор может
> прислать ему»

## Что именно нужно

Всё, что чаттер отправляет вложением из Chatwoot — изображение, файл, голосовое,
видео — доходит до приложения и отображается в переписке.

## Важно: это не только фронт

Приложению нечего отображать: **BFF отбрасывает такие сообщения на входе**, они
не сохраняются и до устройства не доезжают. Задача — вертикальный срез через оба
репозитория, и порядок жёсткий: сначала BFF начинает их переносить, потом
приложение начинает их рисовать.

### Сторона BFF (`aura-bff`, этот манор)

1. Снять отбрасывание в `message-normalizer.ts` — сегодня сообщение без текста
   отсеивается условием `content.length === 0`. Оба пути, вебхук **и** REST
   опроса, идут через один нормализатор; поправить надо так, чтобы подстраховка
   опросом сохранилась.
2. Хранение: вложение при сообщении — тип, имя, размер, что нужно для отдачи.
   Идемпотентно по идентификатору сообщения Chatwoot (жёсткое правило 6).
3. Отдача байтов **своим аутентифицированным путём**: эндпойнт вида
   `GET /v1/attachments/:id`, проверяющий Firebase-токен и право этого
   пользователя на это сообщение, читает объект из бакета Chatwoot и стримит его.
   Ссылку Chatwoot отдавать нельзя, она публичная (`AURAD-0011`).
4. Контракт `@aura/contracts`: `messageSchema` сейчас требует
   `content: z.string()`, а у сообщения-вложения текста нет. Форму править в
   пакете, не копировать в приложение (жёсткое правило 7).
5. Доставка: пуш и сокет кормятся тем же сохранённым сообщением (жёсткое
   правило 5). Отдельного пути для вложений быть не должно.

### Сторона приложения (`aura-app-manor`)

6. Отрисовка в ленте по типам: изображение с превью и полноэкранным просмотром,
   файл с именем и размером, голосовое с проигрывателем, видео.
7. Поведение при недоступном вложении: понятная заглушка вместо пустоты.

## Предусловие — снято

Решение о доставке байтов принято: **BFF проксирует** (`AURAD-0011`). Задача
разблокирована.

Что из него следует для реализации: в сообщении едет `attachmentId`, а не адрес;
подписанный URL в тело сообщения не кладём — он протухнет в кэше ленты; BFF
нужен **read-only** токен R2 на бакет Chatwoot, потому что доступа к хранилищу у
него сейчас нет ни одной переменной.

## Проверка результата

Не «код написан», а: чаттер отправляет картинку из Chatwoot — она появляется в
приложении; приложение свёрнуто — приходит пуш; вебхук намеренно сорван —
вложение всё равно подхватывается опросом.
