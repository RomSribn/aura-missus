## Порядок работ

1. **Контракт (пакет).** Добавить `MessageAttachment` и поле `attachments` в
   `Message`. Правка **чисто добавляющая**: `content` уже `z.string()` и пустую
   строку принимает, трогать не надо. Выпустить `v0.9.0`, обновить зависимость
   BFF. Приложение остаётся на `v0.7.0` и не ломается.
2. **Хранение.** Миграция Prisma: вложения при сообщении — `chatwootAttachmentId`
   (для идемпотентности), `kind`, `contentType`, `fileName`, `fileSize`,
   `width`, `height`, `sourceUrl`.
3. **Нормализатор.** Снять отсев в `message-normalizer.ts`: сейчас
   `typeof content !== 'string'` отбрасывает сообщение, потому что при вложении
   `content` приходит **`null`**. Поправить **оба** пути — вебхук и REST опроса
   идут через один `buildMessage`, и опрос обязан подхватывать вложения так же,
   иначе подстраховки у них не будет.
4. **Отдача.** `GET /v1/attachments/:id`: проверить Firebase-токен и право
   пользователя на это сообщение, забрать байты по `sourceUrl` **со стороны
   сервера** и отдать. Отдельные креды R2 не нужны — адрес публичный, ходит по
   нему только сервер.
5. **Доставка.** Ничего нового: пуш и сокет кормятся тем же сохранённым
   сообщением (жёсткое правило 5).
6. **Тесты.** Обязательно: вложение без текста доходит; повторный вебхук не
   создаёт второе вложение (жёсткое правило 6); чужой пользователь получает
   отказ на `/v1/attachments/:id`.

## Ловушки, на которые уже наступали сегодня

- **Сверять не имена, а ограничения.** При объединении контрактов первый проход
  сравнил имена полей и сказал «всё совпадает»; три расхождения нашёл только
  второй, по самим ограничениям.
- **Не проверять свой выход строже чужого входа.** `SessionId` на поле ответа
  отверг бы наши же данные при смене генератора id.
- **Сборка образа — отдельная реальность.** Прод чуть не упал на git-зависимости:
  в alpine нет `git`, а `prod-deps` ставит с `--ignore-scripts`. Если задача
  добавит новую зависимость, собрать образ **до** мержа.
- **Логи умеют врать.** Rails писал «Uploaded file to key» про упавшую загрузку.
  Проверять по факту (`exist?`), а не по строке в логе.
