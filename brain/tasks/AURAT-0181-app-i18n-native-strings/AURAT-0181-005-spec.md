# AURAT-0181-005 — spec (Android)

Дата: 2026-11-07 · Status: **draft — ждёт ревью координатора и решения владельца** · Тип: task (фича `AURAF-0023`,
строка 007 и часть 002). Код — только после одобрения.

## Итог в двух словах

На Android 13+ у Aura появляется «Настройки → Приложения → Aura → Язык» с теми же 24 языками. Выбор там и выбор в
Profile → Language — **одна и та же настройка** (её хранит Android), поэтому они не спорят: что поменяли последним,
то и действует, в обе стороны. Смена языка не пересоздаёт экран (навигация остаётся). Нативные тексты фреймворка
(меню выделения текста, подписи TalkBack у RN) идут на языке приложения. Ниже 13 — системного выбора нет, всё как
сейчас. Всё видимое — под флагом `AURA_I18N_ENABLED`: с флагом выключен пункта в настройках нет.

## Решения владельцу

1. **Где хранится выбор на Android 13+** — *рекомендую А*.
   - **А.** В системной настройке языка приложения (`LocaleManager`). Profile → Language пишет туда же; «Язык
     устройства» = «Как в системе». Файл `aura-language.json` на 13+ не нужен (остаётся для Android 12 и ниже и для
     iOS). Это уточняет решение владельца 1 (`AURAI-0010`): выбор по-прежнему только на телефоне, «последнее
     изменение побеждает» — но обеспечивает это сама система, без сравнения языков. Побочно: Android сам восстанавливает
     язык приложения из бэкапа устройства при переносе на новый телефон.
   - **Б.** Как сейчас: файл + «последнее изменение побеждает» по смене системного языка; системную настройку
     приложение только читает. Минусы: (1) система en, в приложении выбран de, потом в настройках выбран English —
     приложение остаётся на de (en = en, «смены» нет); (2) после выбора в приложении настройки Android показывают
     «Как в системе», а меню выделения и TalkBack — на языке устройства.
2. **Когда появляется пункт «Язык» в настройках Android** — *рекомендую А*.
   - **А.** Вместе с флагом: `localeConfig` попадает в манифест, только когда `AURA_I18N_ENABLED` = `true` (как
     Meta-флаг, через `env/flag.js`). До запуска (`AURAT-0182`) сборки в Play не показывают 24 языка у
     английского приложения.
   - **Б.** Сразу с этой задачей. Тогда до запуска человек может выбрать Deutsch в настройках — меню выделения
     станет немецким, приложение останется английским.
3. **Язык, выключенный сервером (`disabledLanguages`), в системном списке** — *рекомендую А*.
   - **А.** Список в настройках постоянный (24). Выбран выключенный язык — приложение на английском, настройка не
     трогается и вернёт язык, когда его включат (то же, что делает приложение сейчас со своим выбором).
   - **Б.** Прятать выключенные из списка (`setOverrideLocaleConfig`, только Android 14+, на 13 не выйдет) — лишний
     код ради аварийного выключателя.

Принято мной по умолчанию (владелец может отменить):
- Португальский в системном списке — `pt-PT` («Português (Portugal)»): наш pt — европейский.
- Языковые сплиты AAB выключены (`bundle { language { enableSplit = false } }`): иначе язык приложения, которого нет
  среди языков устройства, остаётся без нативных ресурсов. После `localeFilters` это килобайты.
- `configChanges` += `locale|layoutDirection` — всегда, не под флагом: смена языка устройства сейчас тоже
  пересоздаёт Activity и теряет навигацию.
- TalkBack-подписи ролей RN для ga и mt — английские: в `react-android` их нет. Перевести 25 нативных строк на два
  языка — отдельная маленькая задача, если нужно.

## Что делаю (при А / А / А)

**Нативная часть (`android/`)**
1. `res/xml/locales_config.xml` — 24 языка в порядке `LANGUAGES` (`pt` как `pt-PT`).
2. `res/values-<lang>/strings.xml` × 23 — `app_name` = «Aura» (бренд не переводится). Нужны, чтобы язык был среди
   языков ресурсов APK: иначе Android подберёт другой язык устройства (у ga и mt нет ни одной библиотечной папки —
   `[ga, en]` дал бы en) — `AURAI-0010` §2.
3. `app/build.gradle`: `localeFilters` = 24 языка (APK перестаёт нести ru / uk / ar… из библиотек → `[ru, es]` даёт es,
   арабская система — английский и слева направо); `bundle.language.enableSplit = false`; проба
   `env/flag.js AURA_I18N_ENABLED` → при `true` подключается манифест-оверлей `src/i18n/AndroidManifest.xml` с
   `android:localeConfig="@xml/locales_config"` (Variant API AGP 8.12, `sources.manifests`; проверю
   `./gradlew :app:processDebugMainManifest` в слоте, если Gradle тут собирается без устройства; запасной вариант —
   плейсхолдер на конфиг из одного `en`).
4. `AndroidManifest.xml`: `MainActivity.configChanges` += `locale|layoutDirection`.
5. `AppLanguageModule.kt` + `AppLanguagePackage.kt` (legacy-модуль через interop, как `DeviceCountryModule`), имя
   `AuraAppLanguage`:
   - `getLocales()` → `{ app: string | null, system: string[] }`: 13+ — `getApplicationLocales()` и
     `getSystemLocales()`; ниже — `app: null`, `system` — список языков устройства.
   - `setAppLanguage(tag | null)` — 13+ `setApplicationLocales` (`null` → пустой список = «Как в системе»); ниже —
     ничего.
   - константа `appLocalesSupported` (API ≥ 33).
   - `MainApplication.kt`: `add(AppLanguagePackage())` рядом с `DeviceCountryPackage` — **та же строка, что трогает
     `AURAT-0188`** (`KeyboardFramePackage`): конфликт в одну строку, решает тот, кто мёржит вторым.

**JS (`shared/lib/i18n`, `app/i18n`)**
6. `shared/lib/i18n/native-locales.ts` — обёртка над модулем (iOS и Jest без модуля → `null`).
7. `start.ts` — два режима:
   - **система хранит выбор** (Android, API ≥ 33, флаг включён): язык = язык приложения из системы, если он из
     `LANGUAGES`, иначе первый наш из списка устройства; `chooseLanguage` пишет в систему (выбор языка устройства =
     «Как в системе», как и сейчас); `currentLanguageChoice` = `'device'`, пока в системе пусто; файл удаляется при
     старте (в релизах его нет — флаг был выключен).
   - **файл** (Android < 13, флаг выключен, iOS) — как сейчас; на Android системный язык берётся из списка устройства
     модуля, а не из Hermes (весь список, а не один тег; не зависит от того, перечитывает ли Hermes язык на лету).
     iOS не трогается.
8. `app/i18n/use-system-language-sync.ts` (рядом с `use-disabled-languages-sync`): при возврате приложения на
   передний план (`AppState` → `active`) перечитать языки и применить, если изменились — так выбор в настройках Android
   или смена языка устройства подхватываются без перезапуска. `disabledLanguages` действует поверх, как сейчас.

**Тесты (Jest)**
9. `app/i18n/__tests__/native-locales.test.ts`: `locales_config.xml` = `LANGUAGES` (по базовому коду, порядок),
   `values-<lang>` есть для всех 23 и в каждом `app_name`, `localeFilters` в `build.gradle` = `LANGUAGES`, у
   `MainActivity` есть `locale` и `layoutDirection`, оверлей несёт `localeConfig`. Добавят язык в `LANGUAGES` — тест
   назовёт, чего не хватает.
10. `start` в режиме «система»: старт с языком приложения / без него (`[ru, es]` → es); выбор пишет в систему,
    «Язык устройства» → `null`; возврат из настроек с другим языком применяется; случай en → de → English из
    настроек даёт English; выключенный сервером de → на экране английский, настройка не тронута. Старые тесты режима
    файла — без изменений.
11. Документы: `aura-build-rules.md` («Translations» — строка про Android: язык хранит система на 13+, список в
    `locales_config.xml` сверяет тест); `AURAF-0023` строка 007 — пометка «Android — `AURAT-0181`, iOS — в конце»;
    при решении 1 = А — уточнение к решению 1 в `AURAI-0010`.

Проверка в слоте: `npm run typecheck`, `npm run lint`, `npm test`; Gradle — только обработка манифеста (если
получится), без сборки на устройство.
