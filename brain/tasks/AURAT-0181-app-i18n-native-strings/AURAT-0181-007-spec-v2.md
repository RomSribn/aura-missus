# AURAT-0181-007 — spec v2 (Android)

Дата: 2026-11-07 · Status: **draft v2 — ждёт одобрения владельца** · Тип: task (фича `AURAF-0023`, строка 007 и часть
002). Заменяет `005-spec.md`; ревью и решения владельца — `006-review.md`. Код — после одобрения v2.

## Итог

На Android 13+ в «Настройки → Приложения → Aura → Язык» появляются те же 24 языка. Там и в Profile → Language хранится
**одно значение** — системная настройка языка приложения, — поэтому они не спорят. Выбор в настройках доходит до
приложения сразу, в том числе в split-screen и до пушей. Смена языка не пересоздаёт экран. Нативные тексты фреймворка
(меню выделения, подписи TalkBack у RN) идут на языке приложения. На Android ниже 13 системного выбора нет, остаётся
файл. С выключенным флагом приложение английское, пункта в настройках нет, старт не ждёт ничего нового.

## Решения (владелец, 2026-11-07, через координатора)

1. **А** — на Android 13+ выбор хранит система (`LocaleManager`), Profile → Language пишет туда же. Выбор остаётся на
   этом телефоне и теряется при переустановке, как с файлом сейчас (`allowBackup="false"`). Уточняет решение 1
   `AURAI-0010`: «последнее изменение побеждает» обеспечивает сама система.
2. **А** — пункт «Язык» в настройках Android появляется только вместе с флагом `AURA_I18N_ENABLED`.
3. **А** — список в настройках постоянный (24). Если сервер выключил язык, выбранный в настройках, то приложение
   показывает английский и в шторке отмечен English, а в настройках Android остаётся выключенный язык, и нативные меню
   (выделение текста, роли TalkBack) — тоже на нём. Включат язык — вернётся без перезапуска.
4. **iOS — отдельная задача `AURAT-0190`** (на самый конец). 0181 закрывается после мёржа Android-части.

Принято по умолчанию: португальский — `pt-PT` («Português (Portugal)»); языковые сплиты AAB выключены;
`configChanges` += `locale|layoutDirection` всегда (не под флагом); роли TalkBack для ga и mt — английские (в
`react-android` их нет).

## Режимы JS

| Режим | Когда | Где выбор | Язык устройства |
|---|---|---|---|
| **off** | флаг выключен | нигде — английский | не читается; старт синхронный, как сейчас |
| **system** | флаг, Android API ≥ 33 | системная настройка (`LocaleManager`) | модуль: `getSystemLocales()` |
| **file** | флаг, Android < 33 или iOS | `Documents/aura-language.json`, как сейчас | Android — модуль (список устройства); iOS — Hermes, без изменений |

## Нативная часть (`android/`)

1. `res/xml/locales_config.xml` — 24 языка в порядке `LANGUAGES`, голыми кодами, кроме `pt-PT`.
2. `res/values-<lang>/strings.xml` × 23 — `app_name` = «Aura». Нужны, чтобы язык был среди языков ресурсов APK
   (иначе `[ga, en]` даёт en: у ga и mt нет ни одной библиотечной папки).
3. `app/build.gradle`:
   - `localeFilters` = 24 языка. Тогда `[ru, es]` даёт es, а `[ar, en]` — английский.
   - `bundle { language { enableSplit = false } }`.
   - Проба `env/flag.js AURA_I18N_ENABLED`, рядом с пробой Meta. При `true` через Variant API подключается оверлей
     `src/i18n/AndroidManifest.xml` с `android:localeConfig="@xml/locales_config"`
     (`sources.manifests.addStaticManifestFile`, AGP 8.12).
   - Если оверлей не заработает, запасной вариант: атрибут всегда в манифесте, а по той же пробе
     `sourceSets.main.res.srcDirs` выбирает папку — с 24 языками или с пустым `<locale-config/>` (0 языков → пункта
     нет). Проверка в слоте: `./gradlew :app:processDebugMainManifest` с флагом и без, если Gradle тут собирается без
     устройства.
4. `AndroidManifest.xml`: `MainActivity.configChanges` += `locale|layoutDirection`.
5. `AppLanguageModule.kt` + `AppLanguagePackage.kt` — legacy-модуль через interop, как `DeviceCountryModule`. Имя
   `AuraAppLanguage`, **без констант** (они устаревают).
   - `getLocales(): Promise<{ app: string | null; system: string[] }>`.
     - API 33+: `app` — первый тег `getApplicationLocales()` или `null`; `system` — `getSystemLocales()`.
     - Ниже 33: `app: null`; `system` — `Resources.getSystem().configuration.locales`.
   - `setAppLanguage(tag: string | null): Promise<void>` — API 33+: `setApplicationLocales`. `null` → пустой список
     («Как в системе»). Ниже 33 — ничего не делает.
   - Событие `AuraAppLanguageChanged` `{ app, system }`. Модуль регистрирует `ComponentCallbacks` на application
     context (в `initialize`, снимает в `invalidate`). В `onConfigurationChanged` сравнивает с прошлым чтением и
     шлёт событие через `emitDeviceEvent` только при изменении.
   - `MainApplication.kt`: `add(AppLanguagePackage())` рядом с `DeviceCountryPackage`. Ту же строку меняет
     `AURAT-0188`: конфликт в одну строку при втором мёрже.

## JS

6. `shared/lib/i18n/native-locales.ts` — обёртка над модулем и кэш последнего чтения.
   - **Теги:** запись `pt` → `pt-PT`, остальные — голым кодом. Чтение — по базовому коду (`detectLanguage`).
   - `deviceLanguage()` — синхронная, из кэша: первый из `LANGUAGES` в `system`. Без кэша (iOS, флаг выключен) —
     Hermes, как нынешний `systemLanguage()`.
   - `deviceLocale()` (`shared/lib/device-locale.ts`) на Android с кэшем = `system[0]`, иначе как сейчас
     (`I18nManager`). Регион системы к языку приложения не приклеивается.
7. `start.ts`:
   - **off**: модуль в `boot` не вызывается, `isI18nReady()` сразу `true`.
     - Защита: на API 33+ после первого кадра один раз прочитать `getLocales()`; если `app` не пуст → очистить. Так
       сборка без флага поверх сборки с флагом не оставляет немецкие нативные меню в английском приложении.
       Срабатывает только на 33 — на 34+ установка поверх сбрасывает сама.
   - **system / file**: `getLocales()` читается внутри существующего `Promise.all` вместе с файлом и
     `disabledLanguages`.
   - **system**:
     - Язык: `app`, если он из `LANGUAGES`, иначе `deviceLanguage()`.
     - Миграция: если `app` пуст, а в файле не устаревший выбор (`osLanguage === deviceLanguage()`), один раз
       `setAppLanguage(file.language)`. Файл удаляется в любом случае; если в системе уже есть язык, система главнее.
     - `chooseLanguage('device')` → `setAppLanguage(null)`. Любой явный язык пишется как есть, даже равный языку
       устройства (так делает пикер Android).
     - `currentLanguageChoice()` = `'device'` только при пустом `app`. Выключенный сервером → язык на экране, как
       сейчас.
   - **file**: логика как сейчас, но `system` = `deviceLanguage()` — на Android из модуля.
   - Все вызовы `systemLanguage()` → `deviceLanguage()`: `start.ts`, шторка (`use-language-sheet.ts`, подсказка
     «Язык устройства»), dev-меню.
8. Перечитывание — `syncLocales()` в `start.ts` и хук `app/i18n/use-system-language-sync.ts`, рядом с
   `use-disabled-languages-sync`.
   - Источники: событие `AuraAppLanguageChanged` (основной путь) и `AppState → active` (запасной, `getLocales()`).
   - Порядок: обновить кэш → посчитать язык по режиму → если отличается от `wanted`, применить через
     `allowedLanguage`.
     - Псевдоязык на экране не трогается: кэш обновляется, язык — нет.
     - В режиме **file** на Android устаревший выбор сбрасывается на ходу (`isStaleChoice`), а не только при старте.
   - Порядковый номер: результат чтения, начатого до последнего `chooseLanguage`, отбрасывается.
   - `i18nSettled()` = `i18nReady()` + текущее перечитывание. Его ждут `ensure*Channel` и сборка текста пуша — пуш
     сразу после смены языка в настройках выходит уже на новом.

## Тесты (Jest)

9. `app/i18n/__tests__/native-locales.test.ts`, по файлам на диске:
   - `locales_config.xml` = `LANGUAGES` по порядку, `pt` записан как `pt-PT`;
   - `values-<lang>` есть для всех 23, в каждом `app_name`;
   - `localeFilters` = `LANGUAGES`;
   - у `MainActivity` есть `locale` и `layoutDirection`;
   - `localeConfig` в основном манифесте нет, в оверлее есть (или, в запасном варианте, конфиг для флага off пустой).
10. `start` / шторка, модуль замокан:
    - **off**: модуль не вызван в `startI18n`, `isI18nReady()` сразу `true`; защита очищает непустой `app`.
    - **system**:
      - `app = de`, `system = [en]` → на экране de; подсказка «Язык устройства» — English; черновик Deutsch;
        «Язык устройства» не отмечен;
      - пустой `app`, `system = [ru, es]` → es;
      - `choose('fr')` → `setAppLanguage('fr')`; `choose('pt')` → `'pt-PT'`; `choose('device')` → `null`;
      - устройство fr, `choose('fr')` → пишется `'fr'`, выбор — Français, не «Язык устройства»;
      - en-устройство, de в приложении, событие с `app = en` → English;
      - миграция: файл `{de, en}`, пустой `app` → `setAppLanguage('de')`, файл удалён, на экране de; устаревший
        файл → только удалён; непустой `app` → файл удалён, система главнее;
      - выключенный сервером de при `app = de` → на экране en, в шторке English, `setAppLanguage` не вызван;
      - событие и возврат применяют смену; псевдоязык переживает возврат; чтение, начатое до `chooseLanguage`, выбор
        не отменяет;
      - `i18nSettled()` ждёт перечитывания;
      - `app = en`, `system = [en-US]` → `englishDateLocale() === 'en-US'`.
    - **file** на Android: язык устройства из модуля; при возврате с другим языком устройства устаревший выбор
      сбрасывается на ходу.
    - Старые тесты режима файла (iOS-путь) проходят без изменений.

Проверка в слоте: `npm run typecheck`, `npm run lint`, `npm test`; Gradle — только обработка манифеста.
