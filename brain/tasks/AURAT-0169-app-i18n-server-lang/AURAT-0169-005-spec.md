# AURAT-0169-005 — spec: приложение и серверный шаг 5 (`lang`, `disabledLanguages`, `marker`, таро)

Дата: 2026-11-06 · Status: **draft** — ждёт одобрения владельца
Фича: `AURAF-0023` строки 009, 010. Контракт: `AURAT-0168-007-spec-v2` (`v0.28.0`, заморожен; тега ещё нет).
Тип: задача (фича `AURAF-0023` уже есть). Новых строк интерфейса нет — переводить нечего.

## Что получится

1. Каждый JSON-запрос и каждая загрузка файла к BFF несут `?lang=<язык на экране>`. Сервер начнёт на него отвечать с
   `AURAT-0171`; слать раньше безопасно.
2. Сервер может выключить язык без релиза: язык из `disabledLanguages` не открывается (выбранный или системный → английский),
   в листе Profile → Language его нет. Включили обратно — приложение вернётся к выбранному языку само.
3. Маркеры «сессия началась / закончилась» узнаются по полю `Message.marker`, текст — запасной путь для старых сообщений.
4. Таро: карта дня и карты раскладов в чате перезапрашиваются при смене языка; фразы с именем карты проверены на
   переведённых именах из `AURAT-0171`. Надписи на самих картинках не трогаем (решение владельца).

## A. `lang` в запросах

- Новый чистый помощник `shared/api/bff/language-query.ts`:
  `withLanguage(path: string, language: Language): string` — дописывает `lang=<код>` через `?` или `&` (в путях уже бывает
  query: `?tz=`, `?after=…`). Строкой, не `URLSearchParams` — в RN он неполный.
- `http-client.ts` `performRequest` — адрес `withLanguage(path, currentLanguage())`: покрывает `bffRequest` и
  `bffPublicRequest`, в том числе повтор после 401. `upload.ts` `send` — так же.
- `currentLanguage()` — язык на экране; псевдоязык → `en`; с выключенным флагом `AURA_I18N_ENABLED` — всегда `en`.
- **Не** в адреса картинок и вложений (`attachment-cache.ts`, `entities/user/api/avatar-api.ts` — адрес = ключ кэша)
  и не в сокет (`ws-client.ts`).
- `/v1/app-config` тоже несёт `lang` (рекомендация — **решение 2**): ответ сейчас одинаков для всех, но строка 011
  (сезонные тексты на языке) его потребует; одно правило без исключений.
- `LANGUAGE_QUERY_PARAM` — локальная константа до тега, на этапе C — из контрактов.
- Тесты: `withLanguage` (без query, с query, псевдоязык → `en`); `http-client` и `upload` шлют `lang`; адрес вложения
  и аватара — без `lang`.

## B. `disabledLanguages`

**Разбор** — `entities/campaign/api/parse-app-config.ts`: ещё одна часть, `disabledLanguages: partOf(AppConfigDisabledLanguages,
…) ?? []` (до тега — локальная `z.array(z.string())` с пометкой «заменить на контракт»); `NO_CAMPAIGN` и ответ 404 →
`[]` (все языки включены). Строки остаются строками; фильтр в известные коды без `en` — в i18n.

**Старт** (i18n запускается в `index.js` раньше React и раньше app-config; `shared` не видит `entities`):
- `startI18n(all, { readDisabledLanguages })` — app-слой (`app/i18n/start.ts`) передаёт функцию из `entities/campaign`
  (`readCachedDisabledLanguages` — тот же кэш-файл, что у сплэша, через тот же разбор). `boot` читает её параллельно
  с выбором пользователя, ошибка → `[]`. Так выключенный язык не мелькает на первом кадре, и пуши в фоне — тоже на
  английском (**решение 4**; альтернатива — переключать после чтения кэша в React, ценой мелькания на сплэше).
- `resolveLanguage({ enabled, stored, system, disabled })`: прежнее правило, затем «результат выключен → `en`».
  Сохранённый выбор **не стирается** — включили язык обратно, и он вернётся.

**На ходу:**
- `applyDisabledLanguages(codes)` в `shared/lib/i18n/start.ts`: оставляет коды из `LANGUAGES` без `en`; тот же список —
  ничего; иначе запоминает и пересчитывает язык (`resolveLanguage` с текущим выбором и системой). Отличается от языка на
  экране — переключает, ничего не сохраняя. Псевдоязык на экране не трогает.
- App-слой: `useDisabledLanguagesSync()` в `app/` — берёт список из `entities/campaign` (новый публичный хук
  `useDisabledLanguages()`, `useSyncExternalStore` по `campaignStore`) и зовёт `applyDisabledLanguages`. Конфиг
  обновляется на запуске и при возврате в приложение (не чаще раза в минуту) — так выключатель дойдёт до открытого
  приложения. Плюс сервер сам отвечает по-английски на выключенный `lang` (`0168` §2).
- `chooseLanguage(choice)`: что применить — через тот же фильтр (выбор «Язык устройства» при выключенном языке телефона
  → английский); хранение не меняется.

**Лист языка** (`features/app-language`) — выключенных строк **нет** (рекомендация — **решение 1**; альтернатива —
неактивные строки, но им нужна строка-причина на 24 языках, а выключатель — аварийный, для сломанного перевода).
`languageOptions` получает список выключенных; у «Язык устройства» подпись — язык, который реально откроется
(телефон на выключенном `de` → «English»).

**Тесты:** разбор (нет поля, мусор, строки); `resolveLanguage` (выключен выбранный / системный / `en` в списке не
действует); `applyDisabledLanguages` (выключили язык на экране → `en`; включили → обратно к выбору; псевдоязык не
трогается); `chooseLanguage('device')` при выключенном системном → `en`; `languageOptions` без выключенных строк.

## C. Тег `v0.28.0` и `Message.marker`

Пока пин — `v0.27.0`, `HistoryResponse.parse` (zod strip) выбрасывает `marker`; поэтому маркер — только с тегом.
- `package.json` → `github:RomSribn/aura-contracts#v0.28.0`, `npm install`, lock с настоящим sha.
- Локальные `AppConfigDisabledLanguages` и `LANGUAGE_QUERY_PARAM` → из контрактов; `type AppConfig = AppConfigResponse`
  снова без дописок. `shared/config/languages.ts` остаётся своим (литерал `SOURCE_LANGUAGE` нужен `TranslatedLanguage`),
  плюс тест: `LANGUAGES` приложения === `LANGUAGES` контрактов, порядок тоже.
- `features/chat/lib/map-message.ts` (после мёржа `0167`): типизированная таблица `Record<MessageMarker, ключ>` —
  `session_started → started`, `session_finished → finished`; маркер важнее текста; неизвестное значение → маркера нет,
  рисуется `content`; совпадение текста (`0167`) — запасной путь для старых сообщений. Тесты на все четыре случая.

## D. Таро на языке пользователя

- **Карта дня:** `useDailyCardSync` на смену языка (только реальную — не псевдоязык, не тот же язык) при входе в аккаунт
  зовёт `dailyCardStore.load(true)`; старая карта остаётся на экране, пока идёт ответ (store уже так делает). Подписка
  на смену языка — маленький помощник в `shared/lib/i18n` (`onLanguageChange`).
- **Расклады в чате:** дельта-синк (`after`) уже показанные сообщения не перечитывает, а `mergeServerMessages` берёт
  только новые id. На смену языка `ChatProvider` перечитывает последнюю страницу каждого треда и **заменяет `spread`**
  у сообщений с теми же id; карта из ответа сервера важнее карты из `spread-store` текущего сеанса. Старые страницы
  (подгрузку делает `AURAT-0172`) — по той же замене, когда их перечитают; сверить с `0172` при мёрже.
- **Фразы с именем карты** — `daily-card` `bridge.title` / `draft` во всех 23 языках, `home` (имя — заголовком, уже
  отдельно). Падежные языки уже пишут «karta {{card}}» / «ez a kártya: {{card}}». Сверить с настоящими именами колоды
  `0171` (с артиклем или без): известный риск — de `draft` («Ich habe heute {{card}} gezogen» → «Der Turm» в
  аккузативе) → форма «die Karte „{{card}}“». «You chose {{card}}» в `tarot-spread` — у `0167`.
- **Длина имён:** самое длинное имя каждого языка из колоды `0171` — в `CardReveal` (34 pt, по центру, переносится) и в
  заголовке `DailyCardBanner` (должно останавливаться перед веером) — тест рендера / проверка в маноре.
- `imageUrl` и арт не меняются.

## Не здесь

Перевод маркеров по тексту, превью `spread` / `sessionInvite`, строки `tarot-spread` — `AURAT-0167`. Резолвер `lang` и
колода — `AURAT-0171`. Веб — `AURAT-0170`. Персоны и сезонные тексты — строка 011.

## Решения владельца

1. Выключенный язык в листе: **скрыть** (рек.) или показать неактивным.
2. `lang` и в `/v1/app-config`: **да** (рек.) или только там, где сервер отвечает по-разному.
3. Мёрж: **один, после перехода на тег `v0.28.0`** (рек.) или A+B раньше на локальных типах, если тег задержится.
4. Список выключенных на старте: **читать кэш до первого кадра** (рек.) или переключать после загрузки конфига.
